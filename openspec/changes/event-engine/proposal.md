# Event Engine — 事件处理引擎

## 目标

实现比赛事件的处理管道：数据源轮询 → 去重 → 节流 → 优先级排序 → 冷却检查 → 上下文增强，输出标准化的 AI 生成指令。

## 范围

| 模块 | 内容 |
|------|------|
| 数据源轮询 | api-sports.io 每 3s 轮询一次比赛事件 |
| 事件去重 | Redis 滑动窗口去重（30s 窗口） |
| 事件节流 | 按事件类型控制最小间隔（进球 0s / 射门 15s / 角球 60s） |
| 优先级排序 | P0 进球/红牌/点球 → P3 角球/越位 |
| 冷却机制 | 两条语音间至少 8s，P0 可打断 |
| 上下文增强 | 比赛状态快照、帽子戏法检测、绝杀识别 |
| 比赛状态管理 | 内存中维护 MatchState，随事件更新 |

## 不在范围

- LLM 调用（ai-pipeline）
- TTS 合成（ai-pipeline）
- 用户语音打断（Phase 2）
- 话痨动态调节（Phase 2）

## 依赖

- `phase-0-foundation` — Go 后端骨架、Redis

## 里程碑

- [ ] 数据源事件成功到达事件管道
- [ ] 去重：同一事件 ×3 → 仅 1 条通过
- [ ] 节流：10s 内 3 次射门 → 仅 1 条通过
- [ ] P0 打断冷却：冷却期间进球立即触发
- [ ] 上下文增强：帽子戏法/绝杀/扳平正确识别
