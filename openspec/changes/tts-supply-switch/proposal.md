# 语音供给开关:本地 TTS 腿留口 + 运营端三态切换

## Why

TTS 走 Provider 缝(ADR-0012 修订,tts/synthesizer.go:25 调用面唯一),现役 MiMo 云 API。情感表现力(兴奋解说/惋惜)是陪看体验的核心轴,调研结论自托管最优解为 Fun-CosyVoice3-0.5B(Apache-2.0,instruct 情感指令,流式首包 ~150ms,4-6GB 显存可推理)——但**用户开发机/部署机当前无卡**,云 API 继续现役。

用户裁决(grilling Q5):**本地腿把口子全建好**——后端 adapter + 运营端开关 + 健康探测门控,装在有卡的机器上即可切换,没卡则选项置灰但口子在。属 ADR-0023 第 4 条战略性预埋(用户显式裁决通过)。

**开关放运营端**(架构事实:TTS 合成在后端,客户端只收音频流;供给是部署级事实非用户偏好)——运营台 MatchSettings 同款先例(幂等写+审计+即时生效)。

## What Changes

- **本地 TTS adapter**:OpenAI 兼容 `/v1/audio/speech` 端点形态的 Synthesizer 实现(voice/instruction 映射情感参数);config 增本地端点 URL/音色;**部署文档随附不强制**(CosyVoice3 docker 起法,密钥只记环境变量名)。
- **运营端三态设置**:「语音供给」=云 API(默认)/ 本地引擎(仅健康探测通过可选)/ 本地优先·失败回云;走 operator write + 审计;全局单值(不按比赛)。
- **健康探测门控**:后台探测本地端点(模型加载 + 试合成一句短句),连续通过才亮选项;不通置灰并显示原因;运行中本地失败自动回云(三态 c)或保持并告警(三态 b)。
- **客户端零改动**。

## Non-goals

- 音色定制/用户选声音(客户端面,另一轴,后置)。
- 韵律盲测门——**等有卡硬件再过**(UTMOSv2 粗筛+人耳,eval-tooling 备好工具);本 change 上线即暗,无用户影响。
- IndexTTS-2(表现力天花板但商用授权+≥12GB)——记录为高情感离线通道备选,不实施。
- ASR/情绪链路任何改动。

## Success Criteria

- 三态切换 eval:健康门控(不通过不可选/通过可选)/回退(本地失败回云,句子不断流)/审计落账;
- adapter 单测(httptest:正常/失败/超时/非 200);
- 云 API 路径行为与现状逐字节一致(默认态回归);
- 部署文档:有卡机器 30 分钟内可切换(验收走一遍文档)。
