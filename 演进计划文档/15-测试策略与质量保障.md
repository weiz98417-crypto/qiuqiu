### 10.1 延迟预算回归测试

```bash
# 合并前必须通过 — 失败则阻止PR
test_latency_budget:
  script:
    - go run cmd/bench/main.go --events=1000 --duration=10m
    - python scripts/check_latency.py --p50-max 1500 --p95-max 2000 --p99-max 2500
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
```

各环节延迟门禁：

| 环节 | p50上限 | p95上限 | p99上限 | CI行为 |
|------|---------|---------|---------|--------|
| 事件处理 | 200ms | 400ms | 600ms | 超p95→警告，超p99→阻断 |
| LLM生成 | 800ms | 1200ms | 1500ms | 超p95→警告，超p99→阻断 |
| TTS首包 | 700ms | 1000ms | 1200ms | 超p95→警告，超p99→阻断 |
| 端到端总计 | 1500ms | 2000ms | 3000ms | 超p95→阻断 |

### 10.2 延迟恶化检测

- 每次PR合并后对比baseline
- p95延迟增长 > 10% → 自动创建issue，标记为P1
- p95延迟增长 > 30% → 自动回滚

## 12. 90分钟耐久测试（NEW — CEO审查补全）

> 球球的核心场景是"连续陪看90分钟"。不能在第89分钟崩。

### 12.1 测试设计

```python
# 用预录脚本回放一场完整比赛（90分钟）
# 包含：开球、5次射门、2个进球、3张黄牌、1次VAR、半场、结束
class FullMatchSoakTest:
    def test_90_minute_match(self):
        mock_ds = MockDataSource()
        mock_ds.load_script("testdata/fixtures/full_match_90min.yaml")

        start_time = time.time()
        events_processed = 0
        errors = 0
        memory_samples = []

        for event in mock_ds.replay():
            try:
                result = pipeline.process(event)
                events_processed += 1
                memory_samples.append(get_memory_usage())
                assert result.latency_ms < 2000, f"Delay exceeded: {result.latency_ms}ms"
            except Exception as e:
                errors += 1
                log_error(e, event)

        duration = time.time() - start_time

        # 通过标准
        assert duration >= 5400, f"Test too short: {duration}s"  # ≥90min
        assert events_processed >= 30, "Too few events"
        assert errors == 0, f"{errors} errors during match"
        assert memory_growth_rate(memory_samples) < 0.1, "Memory leak detected"  # <10%增长/小时
```

### 12.2 多场连续测试

```
世界杯场景：一天4场比赛
- 测试：连续回放4场×90分钟 → 6小时无重启
- 通过标准：第4场的延迟 < 第1场的110%（无性能衰减）
```
