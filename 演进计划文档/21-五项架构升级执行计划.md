# 球球五项架构升级执行计划

> 状态：五项升级主链已完成，当前以代码、契约和本机端到端验证作为完成口径；真实设备、真实供应商故障演练和两周发布环境 Journey 暂时不需要实现  
> 范围：事实账本、陪看回合编排、实时会话与投递、客户端会话状态、互动账本与纵向评测

## 目标

把足球数字人的关键体验收敛到一条可回放、可解释、可测试的主链：

`Match Fact → Grounding → TurnPlan → Realtime Session → Client ViewState → Interaction Ledger`

保持 Go + Flutter 模块化单体。模块通过真实 seam 协作；Memory、PostgreSQL、ASR、LLM、TTS、WebSocket 和平台音频均是 Adapter，不把进程拆分当作架构升级目标。

## 已确认的不变量

1. Match Fact Ledger 是唯一事实源；事实只追加，不覆盖历史。
2. 外部数据源写入 `provisional`；运营负责 `confirm / reconcile / revoke`；用户 Fact Claim 不直接写事实。
3. 所有 Watch Turn 都经过 `Signal → TurnPlan`；LLM 不能决定事实、关系阶段、边界、主动性或 Chosen Silence。
4. 投递采用至少一次语义；`delivery key` 幂等，客户端不得重复可听播放。
5. 逻辑 Watch Session 按 `(UserID, MatchID)` 恢复；WebSocket 只是短暂的 transport attachment。
6. 原始音频不持久化；转写、Trace、投递细节遵守当前默认 30 天保留；Relationship Memory 可单独删除、导出和撤销。

## 阶段与停止条件

### 阶段一：Fact Ledger 收敛

**目标**：让 `matchstate` 成为唯一的事实命令、冲突、revision、回放和投影 module。

- 保留 `matchstate` 外部 seam；拆出领域命令处理、投影器、冲突规则和回放内部 module。
- `Store` 与 `PostgresStore` 只负责存储、事务、锁、订阅和 Outbox Adapter 行为。
- 统一 `Create / Correct / Confirm / Revoke / Reconcile / ResolveConflict` 的命令结果和错误分类。
- 记录 projector 版本与 `recordedSequence`，支持从任意序号重放。
- 完成内存/PostgreSQL 契约测试、回放性质测试、冲突和撤回测试。

**停止条件**：同一事实序列在两种 Adapter 上快照、公共事件、revision 和冲突结果完全一致；无投影 shadow mismatch。

### 阶段二：TurnPlan 接管

**目标**：让用户回合、比赛主动回合、首次见面和播放结果共用一个规划接缝。

- 保留 `companion.Agent` facade，内部拆分 Grounding、事实回答、赛程、观察/修复和 realization 策略。
- `relationship.Director` 只由 Turn Planning module 调用，外部不拼接 Decision。
- 固定 `Grounding → Director → TurnPlan → Realizer` 顺序；确定性事实不交给自由改写。
- critical `FactRevision` 只允许同 Signal ID 刷新一次；旧结果标记 stale。
- 旧并行 `AIPipeline / WatchSession` 只保留测试 Adapter，接管后删除。

**停止条件**：场景测试覆盖事实主张、沉默、主动回合、User Boundary、Repair、记忆 pending；同一 Signal ID 只产生一个最终 Decision。

### 阶段三：Realtime Session 与 Delivery

**目标**：把连接内的抢话、排队、媒体、回执、TTL、重连和回放变成一个 Session module。

- `conversation` 吸收 Scheduler、delivery tracker、媒体编排和恢复状态机。
- `server/cmd` 只负责 WebSocket 协议 Adapter、鉴权和连接生命周期。
- Delivery 状态固定为 `planned → text_delivered → audio_started → completed`，或进入 `interrupted / skipped / failed` 终态。
- 用户回合最高优先；critical 事件只替换未播放普通主动回合；普通主动回合过 TTL 丢弃。
- 事实按 cursor replay；仅恢复未终态且未过期的关键回复，不恢复已完成音频。
- ASR、LLM、TTS 使用独立 deadline、fallback 和熔断状态。

**本轮停止条件**：自动化测试覆盖打断后的本地静音、队列清理和状态收敛；事件到客户端事实更新 p95 `<500ms`；重复包、断线、TTS 失败和播放超时状态测试通过；无重复可听播放。真实设备上的打断响应 `<150ms`、弱网、权限和后台切换验证列为暂缓目标，不阻塞本轮完成。

### 阶段四：Flutter MatchSessionController

**目标**：让 `MatchScreen` 只渲染不可变 ViewState。

- 新增纯 Dart Controller，归一化 Socket、Transcript、MatchFact、Presentation、Playback 输入事件。
- 输出 ViewState 和副作用命令；WebSocket、VAD、Audio、Live2D 保持 Adapter。
- 逐类迁移消息处理、流式 ASR、音频队列、事实撤回、Presentation、时钟和重连逻辑。
- 迁移一类就删除对应 Widget `setState` 分支，禁止双写。
- 服务端 PresentationPlan 权威；客户端只做安全白名单与平台能力检查。

**停止条件**：纯 Dart 测试覆盖 `listening → speaking → interrupted → reconnecting → recovered`；Web/移动端均无协议分支回归；Widget 不再持有传输状态机。

### 阶段五：Interaction Ledger 与纵向评测

**目标**：把“为什么这么说、为什么没说、为什么没播”变成可回放证据。

- 以 signal、decision、fact revision、media delivery、playback result 作为不可变事件。
- Trace、运营查看、Journey、指标和审计均由 ledger 派生；不再用 UpdateTrace 改写历史。
- 关联 `Signal ID / Decision ID / Trace ID / Delivery Key / Fact Revision`。
- 评测覆盖事实正确性、用户控制、投递完整性、关系边界、Repair、隐私和延迟。
- 自动化纵向 Journey 覆盖多场比赛、关系阶段变化、跨比赛记忆和事实更正后的撤回；真实发布环境连续两周运行列为暂缓目标。

**本轮停止条件**：任意回合可从 ledger 重建输入、决策、事实版本、表现和最终投递；自动化审计发现任何 blocker（事实错误、越界、重复播放、错误记忆推进）都阻止本轮完成。真实发布环境连续两周 Journey blocker audit 在恢复为发布门禁后再执行。

## 迁移策略

每阶段先以 shadow 方式双跑新旧路径，比较结果后按开发、测试、灰度、生产逐级启用。现有公开 WebSocket 字段保持兼容；新增字段版本化。契约稳定后删除旧 Adapter、兼容分支和 feature flag，避免形成永久双轨。

## 当前完成口径与暂时不需要实现的目标

本轮五项架构升级以代码实现、自动化契约、本机真实 PostgreSQL + pgvector、真实 WebSocket 和浏览器端到端验证作为完成条件。以下三类明确列为暂时不需要实现的目标，不属于本轮门禁，不阻塞本轮升级完成，也不得表述为已经验证：

- 真实 Android、iPhone、桌面浏览器及蓝牙音频设备上的打断 `<150ms` 与弱网/权限/后台切换验证。
- 使用真实 ASR、LLM、TTS 供应商密钥执行超时、429、5xx、断网和空音频故障演练。
- 在真实发布环境连续两周执行跨比赛关系、记忆、事实更正、隐私和重复播放 Journey blocker audit。

未来决定发布真实语音或进入正式 GA 时，再单独评估是否把对应项恢复为发布门禁；恢复前可继续保留现有自动化模拟、指标接口和运行手册作为准备证据。

## 首轮实现证据

- Fact Ledger：`backend/internal/matchstate/fact_ledger.go` 提供 append 校验、projector 版本、sequence replay；Memory/PostgreSQL 共用命令校验。
- TurnPlan：`backend/internal/companion/agent.go` 将用户、比赛事件、首次见面、投递结果统一为 `Agent.Plan`。
- Realtime/Delivery：`backend/internal/conversation` 提供 Scheduler、Delivery Ledger、WatchSession、`ResponseDeliveryService` 和关键回复恢复选择；用户回合、主动反应、观察修复、赛程补答与首次见面共用同一文字/TTS/媒体投递状态机，按业务 `delivery key` 跨 Trace、跨 Service 并发去重，状态帧失败可在不重发文字的前提下重试，TTS 不可用/失败/空音频均写入媒体状态与原因；PostgreSQL 使用 `031`/`032`/`034`/`036`/`037` 迁移持久化幂等键和失败证据。
- Flutter：`client/lib/services/match_session_controller.dart` 归一化连接、转写、字幕、比赛快照、版本化时钟、按 Fact 独立 revision、撤回集合、Presentation 返回、安全白名单、音频设备、播放和 `lobby → entering → active → leaving → left` 生命周期，并输出音频队列清理副作用命令；`match_screen.dart` 只执行平台 Adapter 与计时触发器。
- Interaction：`backend/internal/interaction` 提供追加式事件、PostgreSQL Adapter、稳定游标分页、`ProjectTurns` 和 `ProjectJourney`；API 的 `events` 保持分页，但 `journey/audit` 从内存锁或 PostgreSQL repeatable-read 一致性快照重算并标注 `projectionScope: all`；单回合可重建输入、输出、Decision、Presentation、Fact Revision、媒体状态、失败原因和播放结果，隐私导出、删除、过期清理由 privacy service 处理；`035` 为审计游标查询增加表达式索引。

## 用户端比赛生命周期补齐

为避免用户只能“进入后被动停留”，客户端现在把比赛生命周期作为显式交互：

- 目录公开展示可用比赛，支持搜索、状态筛选、下拉刷新、空态和失败重试。
- Web 端支持 `?matchId=` 深链直达指定比赛；退出深链比赛仍回到比赛目录，而不是停在无返回路径的根页面。
- 选择直播或已结束比赛后通过 `matchId` 建立对应 Watch Session；未开始比赛先进入赛前大厅，由用户明确点击进入，避免误触建立会话。
- 观赛页提供统一比赛菜单：切换比赛（有二次确认）、陪看设置、退出本场；系统返回同样经过退出确认。
- 退出前停止麦克风、音频、转写和 WebSocket，再回到比赛目录；赛后显示返回列表入口。
- 正常退出先发送 `session_closed`，后端显式释放 Watch Session；网络断线不再与用户主动离场混为同一语义。
- 目录按直播中、未开始、已结束排序，确保当前可看的比赛优先；未开始卡片明确显示“查看赛前”。

验证证据：Flutter `77` 项测试、`dart analyze lib test`、`flutter build web --release`、`flutter build apk --debug`、真实 PostgreSQL + pgvector Go 全量测试和 13/13 评测用例均通过；Playwright `65` 项通过、`1` 项真实 TTS 场景按条件跳过。
