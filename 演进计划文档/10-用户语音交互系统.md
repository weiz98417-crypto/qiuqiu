# 10 — 用户语音交互系统

> 所属阶段：Phase 2 · 依赖：06-ASR、04-LLM、05-TTS · 优先级：P1

---

## 1. 概述

用户语音交互系统实现球球与用户之间的双向对话。用户可以随时说话、提问、吐槽，球球实时回应。

核心要求：
- 用户说话 → 球球回复 < 2s（整体延迟）
- 支持打断（用户说话时球球立刻安静）
- 上下文连贯（记住刚才说的内容）

---

## 2. 交互模式

### 2.1 两种触发方式

| 方式 | 操作 | 适用场景 |
|------|------|---------|
| 按住说话 | 按住🎤按钮说话，松开发送 | 嘈杂环境、简短发言 |
| 自由对话 | 点击🎤进入持续收音模式 | 安静环境、多轮对话 |

### 2.2 按住说话流程

```
用户按住🎤
    │
    ▼
VAD检测到声音 → Live2D切为listening状态
    │
    ▼
用户说话中...（实时显示识别文字）
    │
    ▼
用户松开🎤
    │
    ▼
最终识别结果 → LLM生成回复 → TTS合成 → 球球说话
```

### 2.3 自由对话流程

```
用户点击🎤 → 进入持续收音模式
    │
    ▼
VAD持续检测
    │
    ├→ 检测到说话 → ASR识别 → 检测静音800ms → 视为一句话结束
    │       │
    │       ▼
    │   LLM生成回复 → TTS合成 → 球球说话
    │
    ├→ 球球说话中用户插话 → 打断
    │       │
    │       ▼
    │   球球停止 → 识别新话 → 回复
    │
    └→ 用户再次点击🎤 → 退出自由对话模式
```

---

## 3. 打断机制

### 3.1 打断流程

```
球球正在播放语音
    │
    ▼ 检测到用户语音活动
    │
    ├── [0ms]   音频淡出开始（100ms线性淡出）
    ├── [50ms]  停止音频播放
    ├── [50ms]  Live2D切为listening
    ├── [100ms] 开始接收用户语音
    ├── [100ms+user_speech_duration] 用户说完
    ├── [+200ms] ASR识别完成
    ├── [+600ms] LLM回复生成
    ├── [+800ms] TTS首包
    └── [+1200ms] 用户听到回复

总打断响应延迟：从用户说话到球球停止 < 150ms（用户侧感知）
从用户说完到球球回复：~1200ms
```

### 3.2 打断策略

- 打断后，被中断的内容不再恢复（不"刚才说到..."）
- 如果在说重要事件（进球），给用户一个简短回应后再继续
- 频繁打断（30s内>3次）→ 球球："你今天话好多呀～"

## 4. 对话管理

### 4.1 对话上下文

维护最近 N 轮对话作为上下文：

```python
conversation_history = [
    {"role": "user", "text": "这球会进吗", "time": "78:30"},
    {"role": "qiuqiu", "text": "姆巴佩今天状态好，我觉得有机会！", "time": "78:32"},
    {"role": "event", "text": "进球了！皇马2:1", "time": "78:45"},
    {"role": "qiuqiu", "text": "进了！！我就说吧！", "time": "78:47"},
    {"role": "user", "text": "你神了", "time": "78:50"},
    # ...保留最近3轮用户发言 + 球球回复 + 中间事件
]
```

### 4.2 话题管理

| 场景 | 处理 |
|------|------|
| 用户闲聊 | 配合闲聊1-2轮，然后自然带回比赛 |
| 用户追问 | 保持同一话题，不做话题跳转 |
| 比赛发生重要事件 | 插入事件回应，然后回应用户 |
| 用户沉默>5分钟 | 不主动说话（除非有重要事件） |

## 5. 回复策略

### 5.1 提问类回复

| 用户问 | 回复策略 |
|--------|---------|
| "谁进的球？" | 查比赛数据，准确回答 |
| "会进吗？" | 自由发挥，不做绝对预测 |
| "比分多少？" | 查数据准确回答 |
| "还有多久？" | 查比赛时间回答 |
| "XXX厉害吗？" | 基于已知信息评价 |

### 5.2 评论类回复

| 用户说 | 回复策略 |
|--------|---------|
| "好球！！" | 共鸣："是啊！！" |
| "这都不进..." | 共鸣 + 小吐槽 |
| "裁判眼瞎" | 轻回应，不附和攻击裁判 |
| "无聊" | "确实有点沉闷...再看看？" |

### 5.3 指令类回复

| 用户说 | 回复策略 |
|--------|---------|
| "安静点" | 切换安静模式："好～我少说两句" |
| "说句话" | 基于当前比赛状态主动说一句 |
| "换一场" | 引导切换比赛 |

---

## 6. 多模态输入（Phase 3+）

除了语音，支持文字输入作为降级方案：

- 语音不可用（嘈杂环境、用户不方便说话）
- 文字输入 → LLM生成回复 → TTS语音播放（球球还是说话的）
- 聊天框在观赛页底部，可展开

## 7. 接口定义

```
客户端 → 服务端:
WS /ws/chat/{session_id}
{
  "type": "user_speech",
  "text": "这球会进吗",
  "intent": "提问-预测",
  "confidence": 0.95,
  "input_mode": "voice" | "text"
}

服务端 → 客户端:
{
  "type": "qiuqiu_reply",
  "text": "姆巴佩今天状态好，我觉得有机会！",
  "audio_url": "...",
  "expression": "normal",
  "latency_ms": 850,
  "reply_to": "user_speech_id"
}
```

## 8. 验证标准

- [ ] 用户说话到球球回复总延迟 < 2s
- [ ] 打断响应（球球停止说话）< 150ms
- [ ] 连续 20 轮对话不掉上下文
- [ ] 嘈杂环境（60dB）下可用
- [ ] 文字输入降级可用
