# 02 — 比赛数据源集成

> 所属阶段：Phase 0 · 依赖：无 · 优先级：P0

---

## 1. 概述

球球需要实时获取足球比赛事件（进球、射门、犯规等），作为AI语音输出的触发器。

核心要求：
- 事件延迟 < 15s（比直播画面快更好）
- 覆盖主流联赛（英超、西甲、德甲、意甲、法甲、欧冠、世界杯）
- 事件类型完整（进球、射门、黄牌、红牌、换人、角球等）

---

## 2. 数据源选型

### 2.0 选型原则

> ⚠️ 优先使用官方API。非官方API有随时被封/法律风险，仅作为短期验证手段。

### 2.1 主数据源：api-sports.io (API-Football)

| 维度 | 说明 |
|------|------|
| 覆盖范围 | 全球 150+ 联赛，足球覆盖最全 |
| 事件粒度 | 进球、射门、犯规、角球、越位、阵容等 |
| 延迟 | 5-10 秒 |
| API 方式 | 官方 REST API |
| 成本 | 免费 100次/天，Pro $18/月（无限） |

**接入方式**：

```
GET https://v3.football.api-sports.io/fixtures/events?fixture={match_id}
Headers: x-apisports-key: {API_KEY}

Response:
{
  "response": [
    {
      "time": { "elapsed": 78 },
      "team": { "name": "Real Madrid" },
      "player": { "name": "K. Mbappé" },
      "type": "Goal",
      "detail": "Normal Goal",
      "comments": "Mbappé scores! 2:1"
    }
  ]
}
```

### 2.2 备选：SofaScore（短期验证）

| 维度 | 说明 |
|------|------|
| 覆盖范围 | 全球 20+ 运动 |
| API 方式 | ⚠️ 非官方 API（需逆向或第三方代理） |
| 成本 | 免费（有频率限制） |
| 风险 | API 变更/反爬升级/法律灰色地带 |

> SofaScore 仅用于 Phase 0 快速验证。正式开发切换到 api-sports.io。

### 2.3 兜底：ESPN / football-data.org

| 来源 | 覆盖 | 延迟 | 成本 |
|------|------|------|------|
| ESPN API | 主流联赛 | 3-8s | 付费申请 |
| football-data.org | 欧洲联赛 | 5-10s | 免费 10次/分钟 |

## 3. 数据获取策略

### 3.1 轮询机制

```
比赛进行中：每 3 秒轮询一次
中场休息：  每 30 秒轮询一次
比赛结束：  停止轮询
未开始：    每 60 秒轮询一次（检查是否开始）
```

### 3.2 多源冗余

```
优先级：api-sports.io > football-data.org > SofaScore（仅验证用）
策略：主源可用则只用主源，主源超时（>10s无响应）切换备源。
去重：基于 (match_id, minute, event_type, team) 去重
```

### 3.3 事件标准化

不同数据源的事件格式不同，需要统一为内部事件模型：

```json
{
  "event_id": "uuid",
  "match_id": "string",
  "source": "sofascore | espn | thesports",
  "timestamp": "ISO8601",
  "minute": 78,
  "minute_extra": 3,
  "half": 2,
  "event_type": "goal | shot | yellow_card | red_card | foul | corner | offside | substitution | var_check",
  "team": "home | away",
  "player": {
    "name": "string",
    "id": "string"
  },
  "related_player": { "name": "string" },
  "score": { "home": 2, "away": 1 },
  "description": "原始文本描述",
  "raw_data": {}
}
```

## 5. 比赛信息获取

### 5.1 赛程获取

```
GET /api/v1/fixtures?date=2026-05-06
→ 返回当日所有比赛列表（联赛、球队、时间、状态）
```

### 5.2 比赛详情

```
GET /api/v1/match/{match_id}
→ 返回：阵容、统计、事件时间线
```

### 5.3 实时比分

```
GET /api/v1/match/{match_id}/score
→ 返回：当前比分、比赛时间、比赛状态
```

## 6. 数据库设计

### 6.1 比赛表 (matches)

```sql
CREATE TABLE matches (
    id VARCHAR PRIMARY KEY,
    source_id VARCHAR NOT NULL,
    source VARCHAR NOT NULL,
    home_team VARCHAR NOT NULL,
    away_team VARCHAR NOT NULL,
    league VARCHAR NOT NULL,
    start_time TIMESTAMP NOT NULL,
    status VARCHAR NOT NULL, -- 'upcoming' | 'live' | 'finished' | 'postponed'
    home_score INT DEFAULT 0,
    away_score INT DEFAULT 0,
    minute INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

### 6.2 事件表 (match_events)

```sql
CREATE TABLE match_events (
    id VARCHAR PRIMARY KEY,
    match_id VARCHAR REFERENCES matches(id),
    source_event_id VARCHAR NOT NULL,
    source VARCHAR NOT NULL,
    event_type VARCHAR NOT NULL,
    team VARCHAR NOT NULL,
    minute INT NOT NULL,
    player_name VARCHAR,
    raw_data JSONB,
    created_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(match_id, source_event_id)
);
```

## 7. 异常处理

| 异常场景 | 处理策略 |
|---------|---------|
| 数据源超时 | 切换备源，记录告警 |
| 数据源返回空 | 重试 3 次，间隔 2s |
| 事件乱序 | 基于 minute 排序，丢弃明显错误数据 |
| 网络断开 | 指数退避重连（1s, 2s, 4s, 8s, 最大 30s） |
| 数据源限流 | 降级到低频轮询（10s → 30s） |

---

## 8. 验证标准

- [ ] SofaScore 数据可用：连续 3 场直播比赛事件不丢失
- [ ] 事件延迟：从实际比赛事件发生到系统收到 < 15s
- [ ] 多源切换：主源断开后 < 5s 切换到备源
- [ ] 去重准确性：同一事件不重复出现
