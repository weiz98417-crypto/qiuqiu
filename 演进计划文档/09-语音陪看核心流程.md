# 09 — 语音陪看核心流程

> 所属阶段：Phase 1 · 依赖：03-事件处理、04-LLM、05-TTS、07-Live2D · 优先级：P0

## 1. 概述

语音陪看核心流程是球球的"主循环"，把事件处理、LLM生成、TTS合成、Live2D展示串联成完整的陪看体验。

## 2. 端到端流程

### 2.1 主循环

```
┌──────────────────────────────────────────────┐
│                语音陪看主循环                    │
│                                               │
│  数据源 Poll (每3s)                            │
│       │                                       │
│       ▼                                       │
│  事件到达 ─→ 去重 ─→ 节流 ─→ 优先级排序         │
│       │                                       │
│       ▼                                       │
│  事件通过 ─→ 比赛上下文增强                     │
│       │                                       │
│       ▼                                       │
│  LLM生成文本 (目标<1s)                         │
│       │                                       │
│       ▼                                       │
│  句式去重检查 ─→ 通过 ─→ TTS合成 (目标<800ms)   │
│       │                    │                  │
│       ▼                    ▼                  │
│  Live2D表情更新    音频流下发客户端             │
│       │                    │                  │
│       ▼                    ▼                  │
│  客户端：嘴型同步 + 表情渲染 + 音频播放          │
│                                               │
│  冷却8s ─→ 等待下一个事件                       │
└──────────────────────────────────────────────┘
```

### 2.2 时序图（进球场景）

```
时间轴 →

0ms    数据源推送进球事件
50ms   事件处理：去重✓ 节流✓ 优先级P0，直接通过
60ms   上下文增强：{team: "皇马", player: "姆巴佩", minute: 78, score: "2:1"}
70ms   LLM请求发送
650ms  LLM返回："姆巴佩！！第七十八分钟！皇马反超了！！"
660ms  句式检查：通过（无重复）
665ms  TTS请求发送
670ms  Live2D指令：expression=excited
1200ms TTS首包返回 → 客户端开始播放 "姆巴佩——"
1500ms 播放完成
       进入8s冷却期

总延迟：事件到达 → 用户听到 = ~1200ms ✓（目标<2s）
```

## 4. 会话管理

### 4.1 会话生命周期

```python
class WatchSession:
    session_id: str
    user_id: str
    match_id: str
    status: str  # 'waiting' | 'watching' | 'paused' | 'ended'
    talkativeness: str  # 'quiet' | 'normal' | 'active'
    started_at: datetime
    ended_at: datetime
    event_count: int
    ai_speak_count: int
    user_speak_count: int
```

### 4.2 会话状态机

```
waiting ──→ watching ──→ ended
               │
               ├──→ paused ──→ watching
               │
               └──→ (用户切换比赛) → ended + 新会话
```

    │

## 6. 异常流程处理

### 6.1 比赛中断（网络断开）

```
检测到数据源断连（>15s无数据）
    │
    ▼
球球："嗯？信号好像断了...稍等一下～"
    │
    ▼ 重试连接（指数退避）
成功 → 继续陪看
    │
失败 (>60s)
    │
    ▼
球球："连接不太稳定，可能暂时没法陪你看球了。等网络好了叫我～"
Live2D切为idle状态
显示"重试连接"按钮
```

### 6.2 AI服务异常

```
LLM超时 (>2s)
    │
    ▼
使用兜底句式模板
    │
    ▼
标记异常，不影响后续事件

TTS不可用
    │
    ▼
仅显示文字气泡，提示"球球嗓子不舒服～"
```

### 6.3 比赛延期/取消

```
数据源返回 match.status = 'postponed'
    │
    ▼
球球："啊，这场比赛延期了...要不要看看其他比赛？"
    │
    ▼
显示比赛列表供用户切换
```

### 6.4 LLM输出异常（NEW — CEO审查补全）

```
LLM返回后
    │
    ▼ 输出校验（每次LLM响应必经）
│ 1. 文本长度检查（>0 且 <200字）
│ 2. JSON残片检测（是否包含```或{）
│ 3. 比赛相关性检查（是否与当前比赛无关）
│ 4. 安全底线检查（脏话/政治/赌博关键词）
    │
任一失败
    │
    ├── 安全底线失败 → 静默丢弃，不播放
    ├── 格式/相关性失败 → 重试1次（增大temperature）
    └── 重试仍失败 → 使用兜底句式模板
         │
         ▼
    标记异常，上报error_occurred（error_type=llm_output_invalid）
```

### 6.5 TTS音频异常（NEW — CEO审查补全）

```
TTS返回音频
    │
    ▼ 音频校验
│ 1. PCM数据长度 > 0
│ 2. 音频时长 > 0.3s 且 < 15s
│ 3. 非全静音（RMS振幅 > 阈值）
    │
任一失败
    │
    ├── 重试1次
    └── 重试仍失败 → 仅显示文字气泡，标记error_occurred
```

### 6.6 WebSocket断连时用户语音保护（NEW — CEO审查补全）

```
WebSocket断连检测
    │
    ▼
检查是否正在录音
    │
    ├── 是 → 用户语音缓存到本地，不丢失
    │        重连成功后自动补发语音数据
    │        Live2D显示"正在重新连接..."提示
    │
    └── 否 → 自动重连（指数退避：1s → 2s → 4s → 8s）
              最大重试5次
```

### 6.7 事件去重增强（NEW — CEO审查补全）

```
事件去重逻辑增强：
1. 事件ID精确匹配（原有）
2. 新增：(事件类型 + 比赛分钟数 + 球队) 时间窗口去重
   同一事件类型/分钟/球队在3s内只通过一次
3. 新增：连续重复检测窗口
   同一事件类型连续触发>3次 → 跳过后续，标记异常
```

### 6.8 内容安全输出过滤（NEW — CEO审查补全）

```
LLM输出 → 安全过滤层
    │
    ├── 关键词黑名单匹配（脏话/政治/宗教/种族/赌博）
    │   命中 → 静默丢弃，重试生成
    │
    ├── 正则模式匹配（比分预测绝对化："必赢"/"肯定输"）
    │   命中 → 替换为柔和表达（"有很大优势"/"不太乐观"）
    │
    └── 通过 → 进入TTS

## 7. 数据埋点

### 7.1 关键埋点事件

| 事件 | 时机 | 参数 |
|------|------|------|
| session_start | 进入观赛页 | match_id, talkativeness |
| session_end | 离开观赛页 | duration_s, ai_speak_count |
| event_trigger | AI因事件说话 | event_type, latency_ms |
| user_speak | 用户说话 | duration_s |
| ai_reply | AI回复用户 | latency_ms, intent |
| talkativeness_change | 调整话痨 | from, to |
| error_occurred | 任何异常 | error_type, context |

## 8. 验证标准

- [ ] 端到端流程：从打开App到听到球球说话 < 5s
- [ ] 事件响应延迟：从数据API事件到TTS首帧播放 < 2s（可接受降级 < 3s）
- [ ] 连续陪看 90 分钟无崩溃
- [ ] 比赛切换 < 3s 完成
- [ ] 网络恢复后 < 10s 自动重连
- [ ] LLM输出校验：100句输出中0句触犯安全底线
- [ ] TTS音频校验：空音频/全静音自动降级
- [ ] WebSocket断连时用户语音缓存不丢失
- [ ] 事件去重增强：同一事件3s内不重复触发
