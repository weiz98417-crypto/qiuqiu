# 03 — 事件处理引擎

> 所属阶段：Phase 1 · 依赖：02-数据源集成 · 优先级：P0

---

## 1. 概述

事件处理引擎是球球的"神经系统"，负责将原始比赛事件转化为AI行为指令。

核心职责：
- **去重** — 防止同一事件被处理多次
- **节流** — 控制AI说话频率，避免"太吵"
- **优先级排序** — 确保重要的先说

---

## 2. 处理管道

```
原始事件 → [去重] → [节流] → [优先级] → [冷却检查] → 生成指令 → NATS
```

### 2.1 去重 (Deduplication)

**策略**：基于 Redis 的滑动窗口去重

```
Key:   dedup:{match_id}:{event_type}:{team}:{minute}
TTL:   30s
逻辑:  写入前检查 Key 是否存在，存在则丢弃
```

**特殊情况**：
- 同一分钟多事件（如连续射门）：用 sequence_id 区分
- 多数据源重复：标准化后统一去重

### 2.2 节流 (Throttling)

**目标**：防止高频事件（如连续射门）导致AI轰炸用户。

| 事件类型 | 最小间隔 | 说明 |
|---------|---------|------|
| goal | 0s（不节流） | 进球必须说 |
| shot | 15s | 射门太频繁 |
| foul | 30s | 犯规多说无益 |
| yellow_card | 0s（不节流） | 黄牌有信息量 |
| corner | 60s | 角球不重要 |
| offside | 60s | 越位不重要 |

**实现**：

```
Redis Key: throttle:{match_id}:{event_group}
TTL: 对应的间隔时间
策略: Key 存在则丢弃事件
```

**动态节流**（Phase 2+）：

根据话痨程度调节节流参数：
- 安静模式：所有间隔 ×2
- 标准模式：默认间隔
- 活跃模式：所有间隔 ×0.5

### 2.3 优先级排序

当多个事件同时到达时，按优先级处理：

| 优先级 | 事件 |
|--------|------|
| P0（必发） | 进球、红牌、点球、比赛开始/结束 |
| P1（高频） | 射门、射正、黄牌 |
| P2（中频） | 犯规、换人、VAR |
| P3（低频） | 角球、越位 |
| P4（不发） | 控球率变化、传球统计 |

**实现**：优先队列，P0 事件立即处理，P1 及以下排队等待。

### 2.4 冷却机制 (Cooldown)

防止短时间内连续输出多条语音。

```
规则：
- 两条语音之间至少间隔 8s
- P0 事件可打断冷却
- 冷却期间收到的事件排队，冷却结束后取优先级最高的
```

## 3. 事件到AI指令的映射

```json
// 输入：标准化事件
{
  "event_type": "goal",
  "team": "home",
  "minute": 78,
  "player": { "name": "Mbappé" },
  "score": { "home": 2, "away": 1 }
}

// 输出：AI生成指令
{
  "instruction_type": "event_reaction",
  "event": "goal",
  "context": {
    "team_name": "皇家马德里",
    "player_name": "姆巴佩",
    "minute": 78,
    "score_before": "1:1",
    "score_after": "2:1",
    "significance": "反超球",
    "half": 2
  },
  "expression": "excited",
  "priority": 0
}
```

## 4. 上下文增强

在发送给LLM之前，为事件补充上下文：

```python
def enrich_context(event, match_state):
    """为事件补充比赛上下文"""
    context = {
        "score_before": match_state.previous_score,
        "score_after": match_state.current_score,
        "is_equalizer": match_state.current_score.home == match_state.current_score.away,
        "is_winner": event.minute > 85 and is_leading_after_event,
        "is_hattrick": is_player_third_goal(event.player, match_state),
        "time_context": "上半场" if event.half == 1 else "下半场",
        "minute_context": "开局" if event.minute < 10 else
                          "尾声" if event.minute > 85 else
                          "中段"
    }
    return context
```

## 5. 比赛状态管理

在内存中维护每场直播比赛的状态快照：

```python
class MatchState:
    match_id: str
    home_team: str
    away_team: str
    home_score: int
    away_score: int
    minute: int
    half: int
    status: str
    recent_events: List[Event]  # 最近 10 个事件
    last_ai_speak_time: float
    cooldown_until: float
    player_goals: Dict[str, int]  # 球员进球数
```

**状态更新**：每收到一个事件就更新状态快照。

---

## 6. 接口定义

### 6.1 输入

```
NATS Topic: match.event.{match_id}
Message: StandardizedEvent (JSON)
```

### 6.2 输出

```
NATS Topic: ai.instruction.{match_id}
Message: AIInstruction (JSON)
```

### 6.3 内部API

```
GET  /api/v1/match/{match_id}/state    → 获取比赛状态
POST /api/v1/match/{match_id}/pause    → 暂停AI输出
POST /api/v1/match/{match_id}/resume   → 恢复AI输出
```

## 7. 测试场景

| 场景 | 输入 | 期望输出 |
|------|------|---------|
| 进球去重 | 同一进球事件 ×3 | 只生成1条指令 |
| 高频射门节流 | 10s内3次射门 | 只有1条通过 |
| P0打断冷却 | 冷却期间进球 | 立即触发 |
| 优先级排序 | 同时收到射门+进球 | 先进球再射门 |
| 乌龙球 | own_goal事件 | 正确识别并标记 |
| 帽子戏法 | 同一球员第3球 | context中包含hattrick |
