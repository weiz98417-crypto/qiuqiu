## Phase 0：基础搭建（2天 · 单人+CC · 5月11-12日）

**目标**：验证三个核心技术假设+搭好脚手架。

| 模块 | 内容 | 交付物 |
|------|------|--------|
| 技术选型 | 前后端技术栈、AI服务选型 | 技术方案文档 |
| 架构设计 | 系统架构图、模块划分、接口定义 | 架构设计文档 |
| 数据源接入 | api-sports.io / SofaScore（验证用）对接 | 数据源可用性验证 |
| 开发环境 | 仓库初始化、CI/CD 流水线 | 可运行脚手架 |

**里程碑 M0**：架构评审通过，数据源联调成功，LLM+TTS延迟测试<3s，Live2D SDK可用性确认。

> ⚠️ **Phase 0 闸门**：若延迟测试/数据源/SDK任一验证失败，立即回退到"方案A"（纯语音+文字交互，推迟Live2D和ASR）。

## Phase 1：MVP 核心（7天 · 单人+CC · 5月13-21日）

**目标**：实现"AI根据比赛事件说话 + Live2D展示"的最小闭环。

| 模块 | 内容 | 交付物 |
|------|------|--------|
| 事件处理引擎 | 事件去重、节流、优先级排序 | 事件管道可用 |
| LLM 对话生成 | System Persona + Style Rules 驱动输出 | 生成文本可用 |
| TTS 语音合成 | 文本转语音，**支持情绪参数**（兴奋/低沉/正常） | 语音可播放，情绪可感 |
| Live2D 角色展示 | 待机/说话状态 + 嘴型同步 | 角色可动 |
| 人设系统 | 球球人设定义 + Prompt 模板 | 人格一致性 |
| 语音陪看主流程 | 事件→LLM→TTS→Live2D 串联 | 端到端可演示 |
| ★ 用户偏好记忆 | 主队、昵称、风格偏好（本地存储） | 球球能叫出用户偏好 |
| ★ 分享卡片 | 金句+角色形象一键生成分享图 | 分享链路可用 |
| ★ 极简身份 | 昵称+主队设置（无需注册登录） | 身份设置页可用 |

**里程碑 M1**：可用单场比赛完成端到端陪看演示，含情绪化TTS和个性化偏好。

---

## Phase 2：交互增强（5天 · 单人+CC · 5月22-28日）

**目标**：用户可以和球球双向语音交流。

| 模块 | 内容 | 交付物 |
|------|------|--------|
| ASR 语音识别 | 实时语音转文字，支持打断 | 语音输入可用 |
| 用户交互流程 | 提问→识别→生成→回复闭环 | 双向对话可用 |
| 话痨程度调节 | 安静/标准/活跃三档 | 档位切换可用 |
| 表情动作系统 | 进球兴奋/射门紧张/失误吐槽 | 全表情覆盖 |
| 打断机制 | 用户说话时AI静音，实时响应 | 打断体验流畅 |
| ★ 名人语音彩蛋 | 授权名人语音克隆版球球（需提前获取授权） | 彩蛋音色可切换 |

**里程碑 M2**：用户可与球球自由对话，体验自然不割裂。

---

## Phase 3：体验打磨（4天 · 单人+CC · 5月29日-6月5日）

**目标**：压缩延迟、提升内容质量、打磨细节体验。

| 模块 | 内容 | 交付物 |
|------|------|--------|
| 性能优化 | LLM <1s, TTS <800ms, 总延迟 <2s | 延迟达标 |
| 内容去重 | 句式池 + 相似度检测 | 不重复说话 |
| 表情丰富度 | 表情过渡动画、微表情 | 表情自然 |
| 异常处理 | 网络断了/数据延迟/服务异常的降级 | 鲁棒可用 |
| 用户测试 | 10人内测，收集反馈 | 反馈报告 |

**里程碑 M3**：延迟达标，内测 NPS > 40。

- ✅ 允许：bug修复、性能优化、TTS音色微调、赛事数据适配

- Phase 4（多比赛/用户系统）与世界杯并行——属于扩展，不阻塞核心体验

## 安全与隐私（跨阶段）

| 关注点 | 措施 |
|--------|------|
| ASR语音数据 | 不做持久化存储，仅实时转写；传输TLS加密 |
| LLM Prompt注入 | 用户输入作为data字段注入，加前缀隔离，不与system prompt拼接 |
| LLM输出安全 | 输出侧关键词过滤+敏感内容检测 |
| WebSocket安全 | 服务端校验消息类型，客户端仅订阅不可发布事件 |
| 名人语音授权 | 必须在授权协议签署后才能使用克隆语音 |

## 开发模式

**单人 + Claude Code + AI工具**

| 指标 | 传统团队（7人） | 单人+CC |
|------|----------------|---------|
| 有效产出 | 7人 × 16天 = 112人天 | 1人 × CC加速 ≈ 等效4-6人 |
| 沟通成本 | 每日站会/接口对齐/代码评审 | 零沟通成本 |
| 串行浪费 | 前端等后端接口、AI等数据源 | 可按最优依赖顺序推进 |
| 实际日历天 | 16天（含并行） | 22-28天（串行但无等待） |
| CC加速比 | — | 样板代码10-15x、集成5-8x、调试3-5x、学习SDK 1.5-2x |

> 单人开发的核心优势不是CC写代码更快，而是**没有沟通成本和任务依赖**——不需要等任何人，不需要对齐接口，想到就写。
