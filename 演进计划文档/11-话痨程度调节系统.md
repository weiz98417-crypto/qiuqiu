# 11 — 话痨程度调节系统

> 所属阶段：Phase 2 · 依赖：03-事件处理引擎 · 优先级：P1

---

## 1. 概述

话痨程度调节让用户控制球球的"唠叨"程度，适应不同观赛场景。

- **安静模式**：只在关键时刻说话（进球、红牌、比赛开始/结束）
- **标准模式**：默认节奏，PRD定义的事件触发频率
- **活跃模式**：话更多，小事件也评论，更主动互动

---

## 2. 三档定义

### 2.1 安静模式

| 参数 | 值 |
|------|-----|
| 触发事件 | 仅 P0（进球、红牌、点球、比赛开始/结束） |
| 最小间隔 | 120s |
| 冷却时间 | 30s |
| 主动说话 | 否 |
| 用户说话响应 | 正常响应 |
| 适用场景 | 深夜看球、想专注看比赛 |

### 2.2 标准模式

| 参数 | 值 |
|------|-----|
| 触发事件 | P0+P1+P2（进球、射门、犯规、黄牌、换人、VAR） |
| 最小间隔 | PRD默认值（射门15s、犯规30s等） |
| 冷却时间 | 8s |
| 主动说话 | 偶尔（比赛沉闷时可以说一句） |
| 用户说话响应 | 正常响应 |
| 适用场景 | 日常观赛 |

### 2.3 活跃模式

| 参数 | 值 |
|------|-----|
| 触发事件 | P0+P1+P2+P3（全部） |
| 最小间隔 | 默认值 × 0.5 |
| 冷却时间 | 4s |
| 主动说话 | 是（用户沉默超过3分钟主动说点什么） |
| 用户说话响应 | 积极回应 |
| 适用场景 | 聚会看球、想要热闹氛围 |

## 3. 实现方案

### 3.1 参数化配置


### 3.2 切换流程

```
用户点击话痨档位
    │
    ▼
立即生效（无需重启）
    │
    ▼
球球响应（语音+表情）：
  安静←标准："好～我少说两句，专心看球～"
  标准←安静："行，我正常陪你看～"
  标准←活跃："好嘞！今天多说点！"
  活跃←标准："那我多说两句哈！"
```

### 3.3 动态调节（Phase 3+）

基于比赛节奏自动微调：

- 比赛沉闷（0-0，射门少）→ 自动偏活跃
- 比赛激烈（对攻，事件多）→ 自动偏安静（避免太吵）
- 加时赛/点球大战 → 自动偏活跃（关键时刻）

```python
def auto_adjust_talkativeness(match_state):
    if match_state.is_extra_time or match_state.is_penalty_shootout:
        return "active"
    if match_state.shots_last_10min < 2 and match_state.minute > 30:
        return "active"  # 沉闷时多说
    if match_state.shots_last_10min > 8:
        return "quiet"   # 激烈时少说
    return "normal"
```

## 4. 主动说话策略（活跃模式）

### 4.1 触发条件

当以下条件同时满足时，球球主动说话：
- 活跃模式
- 超过 3 分钟无事件触发
- 超过 3 分钟用户没有互动
- 比赛正在进行中

### 4.2 主动说话内容池

```
- "好久没射门了...两边都在试探啊。"
- "{球队}控球挺多的，但没什么威胁。"
- "比赛有点沉闷啊，你觉得呢？"
- "马上{minute}分钟了，看看会不会有什么变化。"
- "这个时候一个进球就能改变一切。"
```

## 5. 用户偏好持久化

```sql
-- 用户偏好表
CREATE TABLE user_preferences (
    user_id VARCHAR PRIMARY KEY,
    default_talkativeness VARCHAR DEFAULT 'normal',
    auto_adjust_enabled BOOLEAN DEFAULT false,
    favorite_team VARCHAR,
    updated_at TIMESTAMP
);
```

用户每次切换话痨档位 → 更新 preference → 下次观赛默认使用。
