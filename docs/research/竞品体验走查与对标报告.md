# 球球竞品体验走查与设计质量对标报告

更新日期：2026-09-02  
研究范围：公开可访问的一手规范、官方文档与同类产品官方页面。本文只记录外部证据、可支持的设计判断和待验证假设，不引用仓库代码，也不把实现细节逆推为产品设计结论。

## 1. 研究方法与证据分级

- **规范/政府指南**：GOV.UK Service Manual、W3C WCAG 2.2、NIST AI RMF 及 Generative AI Profile。它们支持“应满足什么质量底线”，不等同于球球的用户偏好证明。
- **专业启发式**：Nielsen Norman Group（NN/g）可用性启发式。它们用于检查交互风险，不能替代真实用户研究。
- **实现能力文档**：OpenAI Realtime API 官方文档。它们说明实时语音系统可如何处理打断、语音活动检测和连接方式，不构成球球必须采用的技术方案。
- **竞品公开页面**：FotMob、OneFootball 官方首页。仅记录在访问当日可见的信息架构和内容承诺；未登录、未进入比赛详情页、未测试通知或语音功能。

访问日期均为 **2026-09-02（Asia/Shanghai）**。

## 3. 设计质量对标结论

### 3.1 任务与信息架构

1. **从用户任务而非功能列表开始**：GOV.UK 要求先理解需要、解决完整问题；FotMob 和 OneFootball 的公开首页都把实时比赛作为高显著入口。球球应把“当前比赛发生了什么、我是否错过关键事件、下一步要做什么”作为一级任务，再安排新闻、历史和设置。
2. **系统状态必须持续可见**：NN/g 的“系统状态可见”适用于比分刷新、比赛阶段、语音监听/生成/播放、网络断开和数据更新时间。状态文案要能让用户判断“是否在听、是否在说、是否已停止”。
3. **信息密度按场景分层**：竞品首页同时容纳实时、新闻、视频等内容，但比赛进行中应优先比分、计时、关键事件和语音控制；非核心内容可折叠或延后加载。这是基于启发式与页面观察的设计判断，不是用户偏好定论。

### 3.2 实时语音交互

1. **可打断是核心控制权**：Realtime 文档明确了 VAD 触发取消与截断机制；球球的播放控件应提供显式停止/暂停，并允许用户自然插话，打断后不重复朗读已听内容。
2. **听觉反馈要有视觉等价物**：将监听、思考、生成、播放、错误和静音用文字/图标/颜色同时表达，满足 NN/g 的状态可见和 WCAG 的多感官可用要求。语音不可用时保留文本比分和事件流。
3. **延迟与回退要可感知**：连接中、模型未响应、识别不确定或数据过期时，给出可理解的提示和重试/切换文本操作；这属于质量验收假设，需用延迟分档测试确定阈值。
4. **不要把模型能力当作事实来源**：AI 生成的球员、时间和事件应绑定结构化比赛数据；无法确认时明确“不确定/待核实”，并允许用户查看来源或纠正。

### 3.3 无障碍与包容性

- 按 WCAG 2.2 检查文本和状态的对比度、键盘可达性、焦点不被浮层遮挡、非拖动替代操作，以及登录/验证的可访问替代路径。
- 语音不是唯一通道：所有关键比分、事件、错误和操作结果提供可读文本；听不到或不能说话的用户仍能完成核心任务。
- 触控目标、字幕/文字稿、可调文字大小和减少动态效果应作为额外体验检查项；是否满足特定无障碍等级需要正式审计，不能仅凭本报告声明合规。

### 3.4 AI 安全、隐私与可靠性

- 依 NIST RMF 建立四步闭环：明确谁负责（Govern）、列出比赛事实/用户语音/第三方数据的风险情境（Map）、测量事实准确率、幻觉率、偏差、延迟和误触发（Measure）、设置发布门槛、人工接管、回退与事件响应（Manage）。
- 对 NIST GenAI Profile 指出的 confabulation、隐私和信息完整性风险，球球至少需要：事实数据与生成文本分离、关键断言可追溯、生成内容标识、纠错入口、最小化留存和删除机制。
- GOV.UK Service Standard 的隐私、可靠性和持续改进条目要求把权限、断线、过期数据和错误恢复纳入端到端服务，而不是只优化模型回答质量。

## 4. 竞品体验走查（公开页面层）

### FotMob

- **入口层**：Live、News、Transfers、TV schedules、Predict、Lineup Builder 并列，体现“即时比赛 + 赛前/赛后内容 + 工具”的任务分区。
- **可借鉴点**：将用户最常回访的实时入口置于首屏；把预测、阵容等低频工具与实时任务区分。
- **适用边界**：未验证登录后个性化、比赛内事件流、推送策略、无障碍和语音，不应把首页结构直接当作完整体验结论。

### OneFootball

- **入口层**：以“All the Live Action”作主承诺，同时提供 Matches、Teams、Competitions、Top News、Watch，实时内容与媒体消费并存。
- **可借鉴点**：在内容丰富时保持实时主线；使用赛事/球队/比赛多种浏览路径满足不同进入意图。
- **适用边界**：页面包含营销文案和视频导流，不能据此推断信息优先级在比赛详情页仍然成立，也不能证明用户更喜欢视频而非语音。

## 6. 明确的研究假设（尚未被本次资料证明）

以下陈述只能作为后续实验假设，不应写成既定产品事实：

1. 比赛进行中，用户更重视“当前比分/时间/关键事件”而非完整新闻流。
2. 可自然打断且不重复的语音，会比只能按按钮轮流说话更适合陪看场景。
3. 同时显示简短文字稿和语音状态，能降低用户对模型是否听见、是否说完的疑虑。
4. 在无法确认事实时明确承认不确定，会比编造流畅解说更能维持信任。
5. 一键切换到纯文本模式可显著提升嘈杂环境、听力受限或不便说话用户的任务完成率。

建议用 5–8 名目标球迷的可用性测试、不同网络/噪声条件下的语音实验，以及带标注比赛数据的离线事实评测逐项验证；在验证前，不把上述假设当作需求或 KPI。
