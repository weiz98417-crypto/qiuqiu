# 产品能力架构图集

> 文档类型：0→1 产品能力架构决策图集  
> 适用阶段：产品范围、事实规则、用户控制和资料边界已定义，准备形成工程任务契约时  
> 决策状态：首轮候选架构。图中服务、数据流和部署均为待验证设计，不描述既有实现或生产状态。  

## 1. 图集阅读方式

本图集把产品承诺翻译成可讨论的系统边界：事实不能混入角色猜测；用户控制能中断所有媒介；删除不是“隐藏一条记录”；弱网、无声音和舞台不可用时，文字任务仍可完成。每张图都对应后续的任务契约、风险、评测和 ADR，而不是把组件名称堆在一张海报上。

```mermaid
flowchart LR
    P[产品决策] --> A[架构图集]
    A --> T[工程任务契约]
    A --> E[工程 Evals]
    A --> R[风险与 ADR]
    T --> D[受限施工]
    E --> D
    R --> D
```

## 3. 客户端、实时通道与媒介适配

### 3.1 用户端页面与能力路由

用户端不是一组各自直连后端的页面。比赛页承载主任务；设置、会话和数据权利是独立路径；Live2D、音频和字幕只消费已裁决的呈现计划，不能自己判断事实、身份或权限。

```mermaid
flowchart TB
    App[Flutter 应用壳] --> Match[比赛房间]
    App --> Entry[进入与模式选择]
    App --> Settings[设置、无障碍与数据权利]
    Match --> Snapshot[事实快照与时间线]
    Match --> Controls[常驻静音、仅文字、严格保护、结束]
    Match --> Input[文字与可选语音输入]
    Match --> Reply[回复与字幕]
    Reply --> Stage[Live2D Web Runtime]
    Reply --> Audio[音频播放]
    Controls --> SessionClient[会话与投递状态]
    Input --> SessionClient
    SessionClient --> WS[同一实时会话]
    Settings --> HTTP[会话、偏好与权利 API]
    WS --> Gateway[实时网关]
    HTTP --> Gateway
    Stage -.只接收呈现合同.-> Reply
    Audio -.只接收音频与取消.-> Reply
```

### 3.2 WebSocket、HTTP 与身份边界

HTTP 适合可重试的会话、设置和权利请求；WebSocket 承载当前比赛中的双向输入、事实快照、投递和音频元数据。两条通道都从同一会话身份取得主体，运营令牌不能进入用户实时通道。

```mermaid
sequenceDiagram
    participant C as 用户端
    participant S as 会话 API
    participant W as 实时网关
    participant R as 陪看运行时
    C->>S: 建立或刷新用户会话
    S-->>C: 受限会话凭据
    C->>W: 连接比赛通道 + 会话凭据
    W->>W: 校验来源、身份与速率
    W-->>C: 欢迎、快照和能力状态
    C->>W: 文字、控制或音频元数据
    W->>R: 已裁决的用户信号
    R-->>W: 文本、呈现计划、音频资格
    W-->>C: 可见交付
    Note over C,W: 结束、取消或凭据失效时拒绝后续投递
```

### 3.4 实时投递、重连与客户端去重

```mermaid
flowchart TD
    A[服务端事实或回复] --> B[生成投递键和版本]
    B --> C[实时通道]
    C --> D{客户端连接可用？}
    D -->|是| E[发送快照或增量]
    D -->|否| F[保留可重建状态，不承诺逐条送达]
    E --> G{客户端已见过投递键或已取消？}
    G -->|是| H[消费但不重复呈现]
    G -->|否| I[更新界面、字幕、音频或舞台]
    J[重连 + last_seen] --> K[服务端发送当前快照]
    K --> G
    L[事实撤销/用户结束] --> M[清理待播队列和旧动作]
```

### 3.5 消息契约、顺序与幂等

实时通道不承诺“任何网络条件下逐条恰好一次”。它承诺的是每条可见更新都有会话范围、投递键、版本和可丢弃条件；客户端能安全重放、去重、拒绝过期或已取消的内容，并通过快照恢复当前真相。

```mermaid
flowchart LR
    Event[领域事件] --> Envelope[消息信封\nsession_id、delivery_id、version、kind]
    Envelope --> Policy{会话仍有效、版本更新且媒介允许？}
    Policy -->|否| Drop[记录原因并丢弃]
    Policy -->|是| Send[发送给客户端]
    Send --> Client{delivery_id 已处理？}
    Client -->|是| Ack[确认但不重复呈现]
    Client -->|否| Render[更新文字、字幕、音频或舞台]
    Render --> Ack
    Reconnect[重连：last_seen_version] --> Snapshot[发送当前快照]
    Snapshot --> Client
```

### 5.5 会话生命周期与终态优先级

会话不是无限期的聊天容器。建立、活跃、静默、结束、过期和删除请求要有不同的读取、写入和呈现权限；终态优先于生成、缓存、重试和舞台播放。

```mermaid
stateDiagram-v2
    [*] --> 已建立
    已建立 --> 活跃: 进入比赛并通过身份校验
    活跃 --> 静默: 用户静音、仅文字或严格保护
    静默 --> 活跃: 用户明确恢复允许能力
    活跃 --> 已结束: 用户结束、比赛结束或主动退出
    静默 --> 已结束: 用户结束或会话失效
    已结束 --> 已过期: 保留窗口结束
    已建立 --> 删除处理中: 用户权利请求
    活跃 --> 删除处理中: 用户权利请求
    静默 --> 删除处理中: 用户权利请求
    已结束 --> 删除处理中: 用户权利请求
    删除处理中 --> 已删除: 屏障建立且清理完成
    已过期 --> [*]
    已删除 --> [*]
```

### 5.6 角色上下文装配与记忆许可

角色不能读取“所有可用数据”。上下文装配只取当前任务需要的确认事实、用户当前控制、经用户明确保存且仍有效的偏好或共同记录；删除、暂停、共享设备和严格保护会让相应字段退出上下文。

```mermaid
flowchart TB
    Facts[已确认且对当前进度可见的事实] --> Context[最小角色上下文]
    Controls[当前会话控制\n静音、文字、严格保护、结束] --> Context
    Prefs[用户明确设置且未暂停的偏好] --> Check{许可、范围和删除屏障通过？}
    Memory[用户明确确认且未过期的共同记录] --> Check
    Check -->|是| Context
    Check -->|否| Exclude[不进入角色、日志或提示词]
    Context --> Guard[事实、关系与安全护栏]
    Guard --> Plan[受限回应计划]
```

### 6.5 导演配置、版本与回滚

导演台处理的是受限运营配置，不是绕过产品边界的后门。每项候选必须有目标场次、权限、理由、双人复核、版本与生效窗口；发布后如出现事实、控制或体验门失败，应直接回滚到上一个可解释版本或关闭能力。

```mermaid
flowchart LR
    Draft[候选配置\n场次、范围、理由、到期] --> Validate[结构与权限校验]
    Validate --> Review[独立复核]
    Review -->|拒绝或证据不足| Hold[保持草稿或关闭]
    Review -->|通过| Version[生成不可变版本与审计]
    Version --> Publish[仅对目标场次生效]
    Publish --> Observe[观测与抽样复核]
    Observe -->|门通过| Keep[保留至到期或下一版本]
    Observe -->|阈值越界| Rollback[回滚上一版本或关闭]
    Rollback --> Audit[记录用户影响与复盘]
```

## 生产版本设计拓展｜能力深化知识

本节描述产品成熟后的能力扩展、体验深化和治理要求，作为后续版本规划与设计决策的参考。


- **生产拓扑**：单 Agent 位于决策中心，事实、提醒、资料、语音、Live2D、通知和外部动作作为受限工具/适配器；工具无独立人格、关系或越权权限。
- **资格与护栏**：输入层做身份、年龄、隐私和注入检查；工具层做授权、事实、预算、幂等和副作用检查；输出层做进度、媒介、标识和终态检查；人工层可暂停与接管。
- **运行治理**：每次 run 具备预算、超时、循环上限、Trace、终止原因和回滚点；结束、删除、撤回和暂停优先于所有异步任务。
- **数据隔离**：公共事实、用户资料、运营配置、角色资产和 Trace 分离存储与授权；删除屏障传播到缓存、队列、索引、模型上下文和通知计划。
- **恢复与回滚**：供应商、事实源、模型、TTS、舞台资产和规则均支持版本锁定、灰度、熔断、替换和一键回退；恢复后先验证控制与事实快照，再恢复增强能力。
- **架构评测**：演练事实冲突、误提醒、记忆污染、工具副作用、跨设备越权、网络分区和人工审批超时，记录影响范围与恢复时间。

### 生产恢复场景

- **事实源故障**：停止自动发布，保留最后可确认快照和用户主动刷新；恢复后先校验版本再开放增强媒介。
- **通知队列故障**：冻结发送、保留订阅状态和取消操作；恢复时丢弃超窗消息，不补发可能剧透的内容。
- **资料服务故障**：阻断跨场读取和回写，当前会话使用最小本场状态；恢复后重新验证删除屏障。
- **模型/TTS/舞台故障**：按文字、字幕、静态状态卡逐级降级，用户看到当前可用能力和结束入口。
- **全局事故**：人工一键暂停相关版本，保留最小审计和用户告知；复盘通过后按灰度范围恢复。
### 生产架构能力卡

| 能力 | 触发与资格 | 组件职责 | 用户可见结果 | 失败、撤回与放行 |
| --- | --- | --- | --- | --- |
| 事实与呈现链 | 事实版本和用户控制发生变化 | 事实域裁决资格，Agent 生成计划，媒介适配器按版本呈现 | 用户看到当前状态、原因、模式和可停止入口 | 版本冲突取消排队计划；不以重试制造结果 |
| 权利与异步任务 | 用户暂停、删除、结束或撤回授权 | 权利域建立屏障并广播，队列/缓存/上下文拒绝旧版本 | 显示处理中、完成或例外范围 | 屏障传播失败保持阻断；恢复前先核验范围 |
| 供应商与环境恢复 | 事实源、模型、语音、存储或网络故障 | 适配器熔断、切换和灰度，Agent 回到最小能力 | 显示当前可用能力、快照、重试和结束 | 不补播过期内容；恢复需通过评测门再扩大 |

放行以事实资格、控制传播、删除隔离、故障收缩和恢复时间为硬门；架构图不替用户作价值判断。
