# 技术约束与选型原则

> 文档类型：产品设计前置的技术边界与选型原则
> 
> 适用阶段：产品承诺、体验路径和工程方案需要共同收敛时
> 
> 决策状态：首轮技术基线；具体版本、容量、供应商合同和部署参数由工程与运营文档另行确定
> 

## 1. 这篇文档为什么放在产品设计最前面

技术不是产品设计的附录。对于实时足球陪看，客户端形态、实时通道、事实存储、语音服务和角色舞台都会直接改变用户能否看懂、能否控制、能否退出以及能否在无声音条件下完成任务。

本篇只规定会影响产品承诺的技术边界：什么必须稳定、什么必须可取消、什么必须保留文字替代、什么数据不能因为方便而扩大用途。它不替代页面规格、内容设计、接口合同或工程实施文档，也不把技术名词当作用户价值本身。

## 2. 选型原则

### 2.1 关键任务保留结构化等价路径

生产版可以由用户选择语音或舞台作为主要观看出口；但比分、事实状态、错误说明、控制结果和结束状态必须保留文字或结构化等价路径。声音、角色动作、动效和舞台只能消费同一份已裁决结果，不能独立产生事实，也不能成为关闭后才可获得的唯一信息渠道。

### 2.2 用户动作优先于自动表现

静音、打断、取消、结束、删除和切换媒介必须能穿透生成、队列、缓存、重试与播放。任何供应商或渲染层出现延迟时，系统先保持可控，再考虑保持连续感。

### 2.3 事实与表达分层

比赛事实、用户观察、角色解读和情绪表达使用不同的数据语义。候选、冲突、待确认和撤销不能被语音、字幕或 Live2D 表演包装成确定结论。

### 2.4 供应商可替换，降级路径不变

外部模型、语音识别、语音合成和赛事数据服务都可能超时、限流、返回不完整或暂时不可用。选型必须允许替换供应商，并在单项能力失败时回到文字、状态卡或用户主动刷新，不扩大权限或收集范围。

### 2.5 数据最小化与可删除

持久化结构要能区分本场数据、用户主动保存的资料、运行轨迹和安全审计。删除、暂停和撤回必须能够阻断后续读取、引用、异步回写与重新投递，不能只隐藏一个页面元素。

### 2.6 可观测但不以监视换体验

系统需要记录事实版本、控制结果、取消传播、媒介状态和错误原因，以便复盘和改进；不以沉默、停留、语音时长或情绪推断扩大主动性、关系或商业触达。

## 3. 技术基线

| 技术层 | 选型 | 对产品的意义 | 必须守住的边界 |
| --- | --- | --- | --- |
| 用户端 | Flutter / Dart | 统一移动端交互、字幕、文字输入、语音入口和 Live2D 舞台 | 关键任务不能依赖特定屏幕尺寸、声音或动画 |
| 实时通道 | HTTP + WebSocket | 传递比赛状态、对话回合、语音状态和控制反馈 | 消息可识别、可取消、可去重；重连不能补发已撤销内容 |
| 服务端 | Go | 承担会话、事实、对话编排、语音流程和运营边界 | 生成服务不得绕过事实、权限、终态和删除屏障 |
| 业务持久化 | PostgreSQL（含向量扩展能力） | 保存比赛事实、关系状态、对话轨迹、偏好和隐私资料 | 按用途、范围和生命周期隔离数据；查询服从用户权利状态 |
| 运行期协作 | Redis | 支持异步任务、队列、冷却和短期协作状态 | 运行期状态不能取代可解释的会话终态和权利记录 |
| 智能服务 | 对话模型、ASR、TTS 服务 | 提供文字理解、语音识别和可选语音输出 | 每项服务可超时、可取消、可替换；文字路径始终可用 |
| 赛事数据 | 受限范围的赛事数据服务与人工运营输入 | 提供比赛时钟、事件、确认、更正和撤销所需的事实材料 | 数据源不是官方权威的默认替身；冲突必须进入调和流程 |
| 角色舞台 | Live2D/Cubism 舞台组件 | 提供可选的角色状态和轻量表演 | 舞台不能遮挡事实和控制，不能为待确认事件作结论 |

上述选型服务于产品边界，而不是反过来决定产品必须提供更多声音、动效、记忆或主动提醒。任何技术升级都要说明它改变了哪项用户任务、控制或风险边界。

## 4. 对产品设计的硬约束

### 4.1 实时体验

- 连接建立、状态同步、生成、播放和结束是不同状态，界面不得用一个“处理中”掩盖它们的差异；
- 取消和打断的优先级高于生成速度、音频完整性和舞台连续性；
- 重连先恢复会话控制和允许呈现范围，再决定是否有内容可以继续投递；
- 无法确认时序或事实资格时，宁可展示状态和等待，也不以低延迟为理由提前表达。

### 4.2 语音与媒介

- 麦克风、自动声音和连续监听分别由用户理解和授权；
- ASR 失败回到文字输入，TTS 失败保留字幕和文字回复；
- 声音、字幕和 Live2D 使用同一个表达资格，不得出现媒介之间的信息越权；
- 低动态、静音和辅助输入应是完整路径，而不是故障后的残缺模式。

### 4.3 数据与治理

- 本场会话、跨场偏好、共同记录、语音转写、风险材料和审计记录分开建模；
- 每项持久化数据都要有用途、范围、保存条件、查看方式和删除后果；
- 删除或暂停优先于队列、缓存、重试、召回和研究使用；
- 运营人员可以复核事实和配置，但不能通过运营入口绕过用户资料边界。

## 5. 选型变更的评审门

更换客户端框架、实时协议、模型供应商、赛事数据源、数据库或舞台运行时前，至少回答：

1. 用户是否仍能在文字、静音、低动态和弱网条件下完成核心任务？
2. 取消、结束、删除和撤回是否仍然优先于生成、播放和重试？
3. 事实状态、用户控制和媒介资格是否仍由同一条可解释链路决定？
4. 新方案是否扩大了身份、语音、观察、关系或跨场资料的收集范围？
5. 供应商失败、限流、断网和版本升级时，是否有明确的收缩动作与回退方案？

如果其中一项无法回答，技术变更只能进入隔离验证，不能直接改变用户侧承诺。

## 7. 设计决策记录

以下决策作为本资料包的共同基线。后续文档可以细化它们，但不能在局部页面、接口或运营流程中悄悄改变其含义。

| 编号 | 决策 | 约束结果 |
| --- | --- | --- |
| D-01 | 陪看密度、信息保护、声音方式和动态强度分开控制 | 不新增把四者合并的“沉浸”“热闹”或“智能”总模式 |
| D-02 | 文字与结构化状态是所有媒介的共同基线 | 关闭声音、角色或动效后，事实、控制和结束仍完整可用 |
| D-03 | 用户的静音、打断、取消、结束、暂停和删除优先 | 生成、播放、缓存、重试和召回不得覆盖用户动作 |
| D-04 | 事实资格先于角色表达 | 候选、冲突、待确认和撤销不能触发确定性表达或暗示性表演 |
| D-05 | 外部智能与赛事服务必须可替换 | 供应商故障时回到文字、状态或人工流程，不扩大资料和权限范围 |
| D-06 | 数据按用途、范围和生命周期隔离 | 本场处理、跨场偏好、共同记录、语音、风险和审计不得混为一类记忆 |
| D-07 | 产品质量由不可抵消门与用户证据共同决定 | 互动量、停留时长、角色好感和单次演示不能抵消控制或安全失败 |

## 生产版本设计拓展｜能力深化知识

本节描述产品成熟后的能力扩展、体验深化和治理要求，作为后续版本规划与设计决策的参考。


- **选型目标**：在保持单 Agent 的前提下，允许事实服务、提醒编排、资料服务、语音和 Live2D 作为可替换工具与适配器。
- **资格链**：事实来源确认、用户授权、观看进度、媒介能力和会话终态必须在每次输出前共同通过；任一失败即收缩。
- **生产自动化**：自动发布和提醒需要可配置频率、时间窗、赛事范围和暂停开关；默认拒绝未知场景，不以模型置信度单独放行。
- **可靠性**：为每次 Agent run 设置延迟、循环次数、费用和工具调用预算；超预算返回当前状态与下一步，不继续占用用户注意力。
- **替换与回滚**：供应商、模型、TTS、Live2D 和事实源都要支持灰度、版本锁定、熔断和一键回退到文字/结构化状态。
- **可观察性**：Trace 只记录必要关联键、版本、资格结果、工具状态和终止原因，不记录无授权原始语音或私人原文。

### 生产选型决策卡

- **事实服务**：选择可提供来源时间、确认状态、更正指向和可重放审计的供应商；只有延迟数字而无状态语义的来源不能作为自动发布唯一依据。
- **提醒服务**：必须支持幂等键、取消句柄、时间窗、安静时段和失败回执；不支持撤回的通道只能用于用户主动查看。
- **连续性存储**：必须支持字段级许可、有效期、版本、删除屏障和跨设备失效广播；向量相似度不能替代用户可读的资料来源。
- **模型与媒介**：模型、TTS、Live2D 和编排器均可替换；任何替换都要通过事实资格、控制响应、延迟、费用和安全回归。
- **决策记录**：每次选型记录用户任务增量、最坏失败、替代方案、供应商锁定范围、退出成本和回滚触发器。

### 生产选型能力卡

| 能力 | 触发与资格 | Agent/工具行为 | 用户可见结果 | 失败、撤回与退出 | 评测、阻断与回滚 |
| --- | --- | --- | --- | --- | --- |
| 事实与事件服务 | 产品允许自动事实或解释；来源达到确认标准且用户进度、赛事范围和信息保护设置匹配 | Agent 只消费资格裁决后的事实；事实工具提供状态、时间、版本和更正关系，不直接生成角色表达 | 用户看到当前事实状态、更新时间、可展开解释和不接收入口 | 来源冲突、过期或用户切换模式时停止结果型输出，回到等待、快照或结束 | 准确率、状态理解和更正收敛未达标时关闭自动发布，回退用户主动刷新 |
| 提醒与主动触达 | 用户逐项同意赛事、事件、时间窗、媒介和频率；安静时段与身份条件通过 | Agent 生成最小通知内容；提醒工具校验授权版本、幂等键、取消句柄和发送窗口 | 确认页和通知显示范围、原因、到期时间及取消入口 | 用户取消、退出或删除后清空队列；超窗不补发，发送失败转站内状态 | 取消后触达、重复发送或范围越界即阻断通道，回退为用户主动查看 |
| 有限资料连续性 | 用户主动保存低风险偏好或单条笔记并确认用途、范围和有效期 | 资料工具按字段许可提供召回；Agent 不把推断写回资料，不读取未获准原文 | 显示资料来源、作用范围、到期和“不再使用/删除”操作 | 暂停、删除、身份不明或跨场不匹配时阻断读取与回写，用户可直接结束 | 删除后再出现、跨用户泄露或防回写失败即关闭连续性，保留本场状态 |
| 语音与舞台适配 | 用户选择主媒介；设备能力、风险、控制和事实资格通过 | Agent 输出可呈现计划，语音/舞台工具只按控制版本执行并响应取消 | 用户看到当前媒介、字幕/事实状态、暂停、静音和结束路径 | 媒介故障、弱网或控制变更时取消待播并收缩为文字或结构化状态 | 任务等价、打断、延迟和退出门未通过时熔断增强媒介，回退基础呈现 |
| 版本替换与治理 | 规则、模型、供应商或资产产生候选新版本；影响范围和回滚点已定义 | 运行时按版本锁定候选能力，治理工具负责灰度、暂停和恢复，Agent 不自行切换高风险版本 | 用户只看到当前可用能力、变化说明和必要的恢复/结束入口 | 评测失败或事故发生时暂停候选版本，未完成的计划失效，不复活旧输出 | 关键任务、事实、控制和安全回归任一失败即阻断发布并恢复上一稳定版本 |
