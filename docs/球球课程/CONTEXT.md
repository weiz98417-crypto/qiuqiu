# 球球课程 · 内容层语境

这是球球教学内容层（课程与设计文档）的领域语言，与仓库根目录的陪看域词汇表（CONTEXT.md）分属两个语境。本语境定义"关于系统的文档"如何声称、举证和失效。规则见 ADR-0004。

## Language

**Claim（主张）**:
文档中一条关于系统行为的可判断陈述；它是举证的最小单位，要么携带锚点，要么显式标注为计划或概念。
_Avoid_: 观点、描述、内容点

**Anchor（证据锚点）**:
指向真实仓库位置的引用，形如 `路径:行号`，可指向代码、评测用例、迁移或事件流。主张的效力由锚点数量与质量结算。
_Avoid_: 引用、链接、出处（泛指外部网页时除外）

**Status Anchor（status 锚）**:
主张的实现状态四态之一：`implemented-at`（代码已证实）、`partial`（部分实现，写明缺口）、`planned`（有意领先于实现）、`concept`（曾被当作事实写下的设想）。`concept` 不是羞辱标记，是从虚构回到证据的入口。
_Avoid_: 已实现/未实现二元表述、"支持/具备"等模糊措辞

**Fact-Source Chapter（事实源章节）**:
一对文件：`.facts.json`（主张 + 锚点 + status 的机器可读层）与 `.md`（人可读层）。散文从事实源生成或与之同步，代码变更后重新生成而非漂移。
_Avoid_: 设计文档正文（旧范式）、Wiki

**Evidence Pack（证据包）**:
一章开始论证前收集的锚点集合，验收下限为 5 个；没有证据包的章节不得展开论述。
_Avoid_: 参考资料、背景阅读

**Trace（主线）**:
一条贯穿多层真实代码的端到端事件路径（如"佩德里进球"从事件注入到 Live2D 表演），是课程组织讲次的单元，一个 trace 教多个子系统。
_Avoid_: 案例、示例、Demo 流程

**Concept Drift（概念漂移）**:
文档描述与代码现实的不一致状态，如描述死代码、虚构不存在的服务或遗漏已上线的链路。status 锚制度的目的就是让漂移在生成时暴露，而不是在讲台上。
_Avoid_: 过时、小偏差
