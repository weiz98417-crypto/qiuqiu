# 0020 · 客户端登录凭证缝（邮箱+密码，镜像运营端）

日期：2026-09-23（grilling 共识；openspec/changes/login-credential-seam 待立）

## 背景

匿名身份是产品的默认形态（ADR-0001、CONTEXT.md），但设备标识是唯一凭据——卸载/换机即失去全部共同记忆。运营端早有密码登录+JWT（ADR-0010，migration 042/043），客户端却没有升级路径。外部事实约束了选型：国内短信签名 2025 起全面企业主体化（个人主体无法申请）；微信开放平台/小程序认证同样要企业主体（¥300）；本产品当前以本地部署为主，未来可能上云、以网页形态交付；《人工智能拟人化互动服务管理暂行办法》（2026-07-15 施行）在面向公众阶段要求年龄识别与未成年人模式。

## 决定

1. **镜像运营端模式**：邮箱+密码登录 → 复用现有 Session 签发（HMAC 访问令牌 + 刷新轮换）。客户端 `SessionService` 已消费同一字段形状，**会话机制零改动**。
2. **绑定不换 ID**：新表 `user_credentials(user_id, identifier UNIQUE, argon2id 哈希)`。登录 = 给当前 `usr_*` 原地附加凭证；画像/记忆/订阅/关系全部主键都是 user_id，**零数据迁移**。
3. **匿名是默认形态，不是试用期**：guest-first——首启不拦，登录入口在设置页 + 场景引导（换机检测、订阅保存提示）。不显示任何置灰的"即将开放"三方按钮。
4. **邮箱不验证**（无 SMTP 时受控信任输入，格式校验除外）；找回 = 运营端重置，console 重置面板后置。
5. **冲突与登出语义**：identifier 已被占用 = 验证密码后切换到那个账号（本机匿名数据不迁移，切换前明确提示）；登出 = 吊销会话、回到本机匿名态（因设备映射仍在，同一 usr_，登出不等于失忆）；不做登录时自动合并、不做自助解绑（均为后续运营端能力）。
6. **安全补强**：刷新令牌重用检测从"拒绝"升级为"吊销整条会话"（公开登录端点上线前的必要收紧）。
7. **凭证表按 credential_type 天然可扩展**：后续登录方式只新增校验器 adapter，不动缝。

## 上线资格包（后续波次，排期唯一依据）

| 能力 | 前置条件 | 触发时机 |
|---|---|---|
| SMTP 邮箱验证/自助找回 | SMTP 授权码（QQ/163 个人可开）或 Resend 免费档 | 需要自助找回时 |
| Passkey/WebAuthn | 公网域名（https 安全上下文） | 公众试点前可选 |
| 手机验证码 OTP | 企业主体 + 短信签名报备（个人不可申请） | 公众试点 |
| 微信登录 | 微信开放平台企业认证 | 公众试点（iOS 同批必须上 Apple，App Store 4.8） |
| Apple 登录 | Apple Developer + 公开域名 return URL | iOS App 公众试点 |
| 运营商一键登录 | 企业资质 + 运营商能力开通 | 转化优化期 |
| 年龄采集 + 未成年人模式 | 拟人化新规年龄识别义务（服务端列+UI+模式整套） | 公众试点闸门前 |
| Web 刷新令牌 httpOnly cookie | 上云面向公众（当前 Web 端 localStorage 存刷新令牌的风险在受控部署下接受） | 公众试点前完成（硬性迁移条件） |
| 单域名反向代理（/ 用户端、/console、/api、/ws 同源） | 云部署 | 部署时（compose 反代服务） |

## 被否决的替代方案

- **Ory Kratos / SuperTokens 自托管**：引入第二套身份主体 + WS 网关鉴权桥接重写 + 2-3 个常驻容器；在"已有完整会话机制 + 极小团队"前提下全面劣于镜像运营端。
- **一期上手机验证码**：个人主体申请不到短信签名；为登录去注册公司本末倒置。
- **登录时自动合并冲突账号**：涉及记忆冲突调和（observation 调和机制是按 Match Fact 设计的，不适用账号域）；合并是运营端人工能力。
- **flutter_login 等整页登录库**：维护状态存疑 + 中国式改造代价高；两个输入框一个按钮不需要库（用户"引用现成库"的要求在此形态下无适用对象，如实记录）。

## 后果

- CONTEXT.md 随实施新增「正式身份（Verified Identity）」词条并修订「匿名身份」（设备标识改为*默认*凭据）。
- WS 网关、画像、订阅、关系层零改动（usr_ 不变）。
- 工作量约 4 人日，单 change `login-credential-seam`（后端凭证表+登录端点+重用吊销 / 客户端登录页+设置入口+升级编排）。
- 登录页视觉：等用户提供背景图后定稿；impeccable/taste 技能本机未装，届时先装或另定设计流程。
