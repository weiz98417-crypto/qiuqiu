# 0009 · 意图路由器：关键词快速通道 + LLM 语义路由

## 背景

意图分类是 18 行关键词表（agent.go:1827-1890），单遍首中即停。实测（2026-09-18）："你在干嘛"、"明明进了" 等自然说法大量落空为 Unknown，机械回复"这句我没接明白"——陪伴产品的核心体验（闲聊与被理解）在兜底里死掉。关键词表是封闭集合，自然语言长尾无限，加词是西西弗斯工程。

实证：`mimo-v2.5` function calling 对 "明明进了，裁判瞎了吗" 正确路由为 fact_claim_persisted（置信 0.85，3.7s）；安全护栏（ForbiddenClaims、fact_language_policy、句数上限、反重复）全部已建成。

## 决定

1. **关键词快速通道原样保留**：控制命令、字面事实主张、比分正则等高精度模式零延迟零成本不变。
2. **落空回合走 LLM 路由器**（mimo-v2.5，function call 单次 6s 超时不重试）：单调用返回意图 + 槽位 + 自然回复建议。事实类意图置信 ≥0.7 才走确定性事实路径（reply 字段忽略）；闲聊类意图的 reply 经既有护栏校验后直接使用（决策与措辞在闲聊维度合并，事实维度分离不变）。
3. **置信门**：事实类意图 ≥0.7；低于则按闲聊处理 + 观察照记（证据不丢）。
4. **降级**：路由失败/超时 ⇒ 关键词行为原样（罐头 + confused/listening 一次性反应）。
5. **可观测**：每次路由 ReasonCode `router:<intent>:<confidence>` 入 trace，运营台引用审计加路由意图列。

## 被否决的替代方案

- **Rasa 等 NLU 服务**：Python 独立服务 + 训练数据管道，比一个 function call 重一个量级。
- **pgvector 嵌入语义分类**：需要额外的 embedding API；未来可作为路由器换装的第二实现。
- **只做 Unknown 闲聊兜底**：不解决语义理解——"明明进了" 会被闲聊化误接。
- **路由模型用 mimo-v2.5-pro**：同一关键样本分错为 smalltalk 且慢 3 倍（9.8s vs 3.7s）——实测淘汰。

## 后果

- 落空回合延迟 +3.7s（用户已接受：想 4 秒给对的回应 > 秒回乱接）；关键词命中回合零增加。
- CI 无 ROUTER key ⇒ 路由禁用、行为与今日一致；配置 `ROUTER_BASE_URL/KEY/MODEL` 可整体换装其他 OpenAI 兼容模型（deepseek-flash 实测分类错误被否决，key 保留作对比）。
- CONTEXT.md 新增 Intent Router（意图路由器）术语。
