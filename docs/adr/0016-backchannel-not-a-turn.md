# 0016 · 伴随反应不是发言：微反应通道的信任边界

日期：2026-09-22（第二波，openspec/changes/backchannel）

## 背景

险些进球、神扑、VAR 回看这类高情绪时刻，球球必须占一个完整回合才能"哇"一声——排队、冷却、引用码门一样不少，高频微反应实际上无路可走。市面证据（Sesame 的时机论、Hume 的情绪自适应语音）表明陪伴感恰恰来自这些微小共振。CONTEXT.md 的 Backchannel（伴随反应）词条自建立起一直未实现。

## 决定

1. **微反应不是发言**：伴随反应不占回合槽、不经回合调度器、不过 C2 引用码门、不进 open_thread/observation 管线。它是共情的身体性，本质更接近表情表演（ADR-0005/0007 管辖），而非观点输出。
2. **信任约束换形不消失**：引用码门约束的是"有据可引的观点输出"；微反应的约束是——事件白名单（big_chance/miss/save/var_check）、半场 ≤3 全场 ≤6、quiet 档禁用、用户说话让路、10 秒风暴去重、短语池轮转（≤10 字、策展于 repo、零 LLM）。
3. **全程可审计**：每条微反应写 trace（`backchannel.emit` ToolCall，Reason=backchannel）+ Interaction Ledger（`backchannel` Kind）。
4. **v1 无音频**：文字气泡 + 既有表演槽位；短 TTS 待客户端音频队列按 deliveryKey 配对（v1.1）；SSE 流式为独立任务（one-shot TTS 对 ≤10 字足够 v1）。

## 被否决的替代方案

- **微反应走完整回合**：排队/冷却/引用码把"哇"变成迟到三秒的播报，陪伴感归零。
- **微反应免审计**：无审计的主动输出违背本项目"每个主动行为可解释"的底线；换形不等于豁免。
- **LLM 生成微反应**：零延迟要求与确定性内核冲突；短语池策展即可。

## 后果

- `internal/backchannel` 纯规则决策器 + 连接内计数状态；限频参数集中一处，运营可调。
- 事件白名单外的时刻（进球等）仍走既有主动回合管线——微反应是补充不是替代。
- C2 引用码门的管辖范围自此有了明确的书面边界（发言 vs 身体性）。
