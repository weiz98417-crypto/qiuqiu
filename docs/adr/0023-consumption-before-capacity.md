# 0023 · 消费先于产能(verification & consumption 轮立项原则)

日期:2026-10-01 · 来源:生态对标轮③ CEO 审查外部声音 + 用户裁决 · 状态:已接受

## 背景

生态对标轮③交付十卡,CEO 审查的外部声音指出:其中约半数(反向 MCP server 无客户端、promptfoo 无读者、genai 改名无导出方、默认关的唤醒词、无下游的情绪管道)是「为不存在的消费者建的产能」——真正用户可感的只有流式延迟与引擎换底。同轮随后又因真机验证撤出,Phase B/唤醒词人耳/情绪标签三项验证失去数据来源而冻结,进一步印证:产能跑在消费前面的部分,连验证都排不上。

## 决定

1. **新能力立项必须指名当期消费者**:提案先回答「谁在下个迭代周期内真的用它」,答不出即不立项——不论技术上多诱人。
2. **已建未用的存量只接受两类工作**:让它被真正用起来(消费),或验证它确实能用(验收)。对存量的能力扩充(波2、Phase B 类)需先过各自的量化准入门,门开着但数据不到=继续冻结。
3. **验证依赖真实使用场景**:纸面预算、合成数据、离线评估都只作方向判断;「用户可感」的结论必须来自真实设备/真实场景的采集。真实场景不可得时,该项如实冻结,不降级凑数。
4. **例外必须显式**:战略性预埋(为可预见的需求提前铺路)允许,但须在 grilling 中单独点名并由用户裁决,不得夹带。

## 后果

- 下轮(验证与消费轮)菜单收敛为:韵律盲测(PC 版)、知识策展台真实录入、值班演练;MCP 正向维持冻结。
- 生态对标类调研轮(对比开源找差距)此后产出的是「差距清单」而非「待办清单」——差距项仍须过第 1 条。
- 本原则接受后,2026-10-01 起的立项讨论不再重复此论证;推翻须新 ADR。
