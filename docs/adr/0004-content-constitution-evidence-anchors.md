# 0004 · 内容宪法：status 锚取代禁令式文风

## 背景

2026-09 架构审计发现，`docs/球球全套资料`（108 篇，4.2MB）由同一批次生成：`必须`×2000、`边界`×1554、`退出`×1101，而 `backend/` 代码锚点为 0。根因是三条生成规则：

1. 《产品设计审查标准》§2.2 规定实现盘点「不得写回产品设计正文」——制度性禁止代码接地；
2. 《附录H》固定前言要求每章「先复述范围与风险」——布道先于内容；
3. 《资料包索引》§7 验收链把「退出/边界/停止条件」设为每章必填关键词——关键词配额。

## 决定

1. **废除「禁止代码写回」**。每个设计主张必须携带 status 锚四态之一：`implemented-at <路径:行号>` / `partial <路径:行号>` / `planned` / `concept`。领先实现合法，但必须标 `planned`，不得伪装成已验证事实。
2. **附录H 固定前言**：六条安全禁令逐字保留（陪看产品的真实底线）；「工作方式」第一条改为证据先行——先给证据包，再给计划。
3. **验收改为证据配额**：每章 ≥5 个仓库锚点、status 表完整、无锚段落 ≤30%，取代关键词命中率。
4. **教学文档入库策略**：`docs/球球课程/` 下的事实源（`.facts.json`）与生成的 `.md` 均提交入库——教学文档是交付物，不是中间产物。这与 `architecture/showcase/` 生成页不入库的决定相反且不矛盾：展示页可随时由 archify JSON 重新生成，教学文档则是持续演进的产品。

## 被否决的替代方案

- **全面重写 108 篇**：用旧配额思维做新事；市场/GTM/增长章本就不该有代码锚点。改为整套冻结 + 13 篇核心章节靶向迁移。
- **保留独立矩阵、正文继续无锚**：维护两份事实（正文与《设计—项目事实对齐矩阵》）必然漂移；32 章描述死代码而真实 PresentationPlan 链路零文档即是漂移的实证。

## 后果

- 生成器（人或 LLM）的 interface 从禁令清单变为证据规则；说教腔失去制度来源。
- 存量 108 篇冻结于 `docs/球球全套资料/`，其内部声称的 `cmd/scenario` 等服务从未存在，以 `backend/cmd/server` 单体为准。
- 后续内容工作在 `docs/球球课程/`（术语表见该目录 CONTEXT.md）。
