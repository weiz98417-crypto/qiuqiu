# 0015 · 主动调度的信任边界：提醒簿与 C2 引用码第三钥匙

日期：2026-09-22（能力波，openspec/changes/proactive-scheduler）

## 背景

主动回合此前的触发完全挂在 WS 连接生命周期上：ProactiveGate 是 watchConnection 的私有字段，「没人连接就没有任何主动回合」，时间维度的主动性（赛前提醒、定时关怀）物理上不可能发生。市面证据（Replika 主动 check-in、MLS Sidekick 学习习惯后主动推送）表明主动关怀是陪伴类产品的标配差异。同时，C2 引用码门（ADR-0003 的信任设计：每个主动回合必须「有据可引」）只认 open_thread / shared_moment 两把钥匙——用户显式请求的行为（"开球前叫我"）没有钥匙位。

## 决定

1. **提醒簿独立于连接生命周期**：`internal/proactive`（领域词：主动调度 Proactive Scheduling）持有用户级提醒记录，投递积压照抄 observation_resolution_outbox 模式（migration 020）：持久待递 → 连接时补递 / 连接内低频检查投递 → 送达翻 delivered。到点投递必须走连接内的回合调度与投递服务（socket 归连接所有），服务端节拍只做过期清理。
2. **C2 引用码第三钥匙 = reminder:<id>**：用户显式请求的提醒是比画像口味更强的正当性来源——它是用户自己要的。gate 语义不变（引用码非空即可），前缀语义归来源包所有（定义在 internal/proactive，因 conversation ← companion ← proactive 会成环）。
3. **错过即静默 + 转素材**：开球 +30 分钟仍未送达的提醒翻 suppressed，不再补发（"球球不迟到"是信任设计的一部分）；错过事实转为记忆素材（recall 可达），下次相关聊天自然回来。
4. **入口走意图注册表**：reminder_request 是能力波 #1 注册表的第一批用户（一处声明五件套）；确定性回复、置信门控（≥0.7 才信任路由）、非闲聊回复资格。
5. **命名纪律**：领域词为「主动调度 Proactive Scheduling」，Go 包 internal/proactive；不使用 Director（真人运营员，ADR-0011 语境）。

## 被否决的替代方案

- **服务端全局节拍直接投递**：socket 归连接所有，全局节拍拿不到投递通道——改为连接内低频检查 + 连接时补递，服务端节拍只做清理与素材化。
- **取消 C2 门绕行**：提醒没有引用码也能发——拒绝。引用码门只收窄不拆除是最值钱的信任设计；reminder:<id> 是加钥匙不是拆门。
- **错过补发**：迟到 40 分钟的"开球了"是打扰不是陪伴；转记忆素材让错过以更自然的方式回来。
- **订阅式提醒（关注球队每轮自动）**：涉及周期调度与管理面（列出/取消），后置为独立技能，复用意图注册表。

## 后果

- migration 045（proactive_reminders）；无库部署降级为内存提醒簿（进程重启即失，如实降级）。
- 赛程源缺席 kickoff 时提醒不落簿——球球如实说"不知道几点开球"，不假装记上。
- 提醒回合为确定性文本（对阵/时间由提醒簿拥有），不经 realizer。
- 画像口味作为引用码候选来源仍留在措辞层（能力波 #2 的"引用码候选"口）；是否升级为第四把钥匙留待订阅式提醒落地时一并裁决。
