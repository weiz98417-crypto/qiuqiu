# 0008 · 运营管理台：个人令牌身份、三层视图与所有权规则

## 背景

数字人端两波升级（agent-depth、presentation-mapping）之后，运营台（4,076 行单文件 operator.html，共享 APP_TOKEN，五标签手写页）与被运营的系统脱节：主动引用码、Open Thread 台账、话痨档位、记忆健康、画像隐私运维、投递打断反应对运营不可见；4 个权限 scope 声明了但从未按路由强制。同时产品形态要求运营台从"单场比赛指挥工具"升级为"1 对多的运营管理台"。

## 决定

1. **身份**：`operators` 表（姓名/令牌哈希/角色/scopes）+ 个人令牌（bootstrap 从 `QIUQIU_BOOTSTRAP_OPERATOR` 播种首个；创建时仅显示一次；吊销 = 删行即失效）。审计行记运营员姓名，历史保留。不做密码体系（内部工具，免去找回/轮换复杂度）。
2. **scope 强制**：四个既有 scope（MatchWrite/FactConfirm/FactCorrect/TraceRead）按路由真正强制；角色 `director`（全 scope）+ `auditor`（只读）。
3. **三层视图**：全局层（多比赛/会话/记忆健康）→ 比赛层（事件/引用审计/在线用户网格）→ 用户层（画像/话题台账/交互历史）。运营对象的基本单元是「比赛 × 用户」。
4. **单一源前端**：`console/`（Vite + React 19 + TS + antd v6 + React Router），构建产物由 Go 服务 `/console`；风格基底取 awesome-design-md 的 linear.app 结构 + `app_theme.dart` 实测色板（近黑画布、橙 FF6B35 单强调、天蓝次强调）。
5. **所有权与红线**：话痨档位对运营只读（改档是用户权利）；画像代客操作 = 条目读 + 槽位删（二次确认 + 审计），不可导出；主动回合无审批队列（实时性优先，manual 通道 + 引用审计覆盖问责）。

## 被否决的替代方案

- **完整密码登录**：内部工具不需要找回/轮换/复杂度；个人令牌 + 删行吊销已满足审计与撤销。
- **Ant Design Pro 全家桶**：管理台要的是 antd 组件而非脚手架锁定（Pro 曾长期维护滑坡，v6 刚复活需观察）；布局自建。
- **主动回合审批队列**：与看球实时性冲突；manual 通道已覆盖导演亲自发声。
- **旧 39 章五级暂停全套 / 角色分离六角色**：fiction 收敛为三档干预与两角色，按 YAGNI。
- **继续扩 operator.html**：4 千行单文件零构建已到可维护性边界；新台迁移完成前两代共存。

## 后果

- 运营台获得独立前端工程（`console/`），部署形态不变（Go 静态服务）。
- 7 个运营盲区（引用/台账/话痨/记忆健康/画像/打断/scope）全部获得运营面。
- `operator.html` 在三期内逐步降级为「仅 #live 实战导演」存续，最终随其重写波退役。
- Langfuse 等 LLM 可观测平台的 trace 树 UX 作为球球日志页的演进参考（不引入其运行时）。
