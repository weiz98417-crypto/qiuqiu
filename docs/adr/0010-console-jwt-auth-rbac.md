# 0010 · 运营管理台认证：JWT 登录 + RBAC（修订 ADR-0008）

## 背景

ADR-0008 选择个人令牌粘贴（"内部工具，不做密码"）。运营管理台升级为 1 对多管理平台后，该决定失效：共享令牌 UX 摩擦大、无登录界面、无法回答"谁做了什么"。

## 决定

1. **密码认证**：PBKDF2-HMAC-SHA256（10 万迭代，stdlib 手写实现并以 RFC 6070 向量校验）——保持零依赖纪律。director 建号发临时密码（只显示一次），首登强制改密，自助改密需旧密码。
2. **JWT**：手写最小 HS256（固定算法，alg 协商不存在，混淆攻击类结构性免疫）；15 分钟访问令牌 + 30 天刷新令牌（SHA-256 哈希存 `refresh_tokens` 表，多设备、按设备吊销）。
3. **双通道**：个人令牌 = 机器通道（evals/脚本，不动）；JWT = 人的通道。两路产出同一种 Claims，路由层零改动。
4. **v1 不做**：失败自动锁定（只记失败审计）、邮件找回（director 重置）、SSO。

## 被否决的替代方案

- **golang-jwt**：标准但新增依赖；HS256 子集手写 60 行且向量可测。
- **x/crypto/bcrypt**：同上，PBKDF2 stdlib 可实现且迭代成本可控。

## 后果

- 15 分钟内的吊销延迟（删刷新令牌后访问令牌自然过期）——运营台可接受。
- `QIUQIU_JWT_SECRET` 成为必需配置（存在任何密码账号时）。
- 修订 ADR-0008 决定 1（身份部分）；令牌与 scope 体系不变。
