# 0013 · operator.html 提前退役（修订 ADR-0011 的退役门）

## 背景

ADR-0011 规定旧实战导演页（4,076 行零构建 operator.html）与新 React 导播台并存，退役需三条件：28 条 operator-control evals 全绿 + 功能对齐清单逐项签署 + 导演真机验收。并存运行以来的真实成本集中在「同一功能两个入口」上：

- **跨页重复事件**：两页的幂等去重都是每标签页内的，同一逻辑事件从两页各发一次会落两条事件，导演自造事实冲突再自行裁决；
- **双凭证**：旧页 `?token=`（人用机令牌）与新台 JWT 并存，吊销后 JWT 残留 ≤15 分钟、旧页令牌多人共用时审计身份塌缩；
- **状态分歧**：自动化策略两侧整包 POST 且都不轮询，旧标签页的过期保存会静默覆盖新台的策略；
- **恢复语义不对称**：时钟 409 旧页自动重读、新页曾只报错（已在新台修复）。

项目唯一导演（所有者本人）拍板提前退役。

## 决定

1. **退役门修订**（语义不变，宿主与验收事实变更）：
   - ①「28 evals 全绿」→「28 条 evals 的行为断言**全部迁移**为驱动新导播台/直连 API 且全绿」——旧页不再是测试宿主，冻结形状的守护不变；
   - ②「对齐清单签署」→「功能缺口补齐」：时钟 409 自动恢复、api-sports 数据源启动、赛前配置（阵容/开赛/重置）已进新台（parity-checklist 22/29 由失实变属实）；
   - ③「导演真机验收」→ 由项目所有者拍板确认（已给出）。
2. **删除**：`operator.html`、`/operator.html` 服务端点、console 导航「实战导演台（旧版）」链接、旧页 `?token=` 人用通道。
3. **保留**：`operator-live-state.js` 继续作为事件模型的语义 oracle（byte-shape 对比脚本不变——它锁的是模型而非页面）；`/api/matches/*` 请求形状冻结不变（迁移后的 28 条 evals 继续守护）；机令牌通道保留给 evals/脚本（ADR-0010 双通道不变）。

## 被否决的替代方案

- **继续并存到完全对齐再退役**：并存税（跨页重复事件、双凭证、状态分歧）没有随时间衰减的机制，且跨页重复事件在并存期结构性无解——幂等键是每页各自生成的。
- **服务端软去重缓解并存期**：为两套页面并存这个过渡态在冻结端点上新增机制，退役后即成死代码。

## 后果

- 单一写入口：新导播台成为唯一实时运营面，跨页冲突类问题整体消失。
- 旧页独有小功能（#monitor 轮询视图、补一句提醒、quickCombinations、语音麦克风偏好记忆）随退役关闭，不再移植；若后续需要，在新台按需重建。
- evals 的 UI 旅程改走新台的 data-testid，Playwright 宿主从静态旧页换为构建后的 console/dist。
