# 环境搭建与项目骨架

> 文档性质：工程叙事——球球这个工程域的骨架是怎么设计、怎么建、怎么验证的  
> 阅读方式：文中出现的包名、路径与命令全部取自当前仓库，可边读边对照代码

## 1. 这个域要解决的问题：让新成员一天内在真实比赛数据上跑通全套

球球是一个 AI 足球陪看数字人。用户看比赛时，一个 Live2D 形象的"球球"通过 WebSocket 接收比赛事实流，用 LLM 生成锚定在事实上的口语回复，再经 TTS 变成语音、以表情动作呈现出来。这条链路把实时通信、大模型、语音合成、关系与记忆、持久化串在一起，任何一环的环境差异，都会让"昨天能复现的 bug 今天不见了"。

所以我们给自己定的骨架目标不是"把代码放整齐"，而是一条可重复的路径：一名新成员，克隆仓库、填一张环境变量清单、启动容器、跑离线评测、打开客户端和导播台，在一个工作日内看到球球对真实比赛事件做出有锚定的回复。骨架的每一层——单体的包组织、compose 的服务清单、迁移的执行机制、评测的四档分层——都是为这条路径服务的。

"跑通全套"在这里有具体清单：外部数据源或导播把比赛事件写进事实账本；确认后的事实经 WebSocket 快照与增量推送到客户端；球球对事件做门禁与锚定检查后主动发言；回复经 TTS 变成语音、映射成表情动作；用户可以用话痨档位、打断、安静控制随时干预；导播台在同一份事实流上确认、更正、审计；评测套件对以上每一段行为持有断言。这条链上任何一环在新机器上装不起来，问题都算骨架的问题，不算新人的问题。

两条原则先立在这里：

- **边界写进结构，而不是写进文档。** 事实账本与外部记忆服务的隔离、导播台的只读约束、删除后的防回写，都落在包边界、迁移和评测断言里，不依赖后人自觉。
- **配置错误要在启动时爆炸，而不是在比赛第 80 分钟。** 生产模式缺一个必需变量，进程直接拒绝启动。这是刻意选择的快速失败：把配置 review 从深夜救火提前到部署那一秒。

## 2. 真实骨架：一个单体进程，六个容器，四十六个迁移

### 2.1 单体：cmd/server 与 internal 的包组织

我们没有走微服务。整个后端是一个 Go 进程，生产入口只有一个：`backend/cmd/server`。实时 WebSocket、HTTP API、运营台、静态托管、迁移执行、隐私清理定时器，全部活在这一个进程里。这个决定后来被反复验证是对的：观赛场景里"比分确认、主动发言、语音投递"有大量进程内的时序协调（观察协调器、主动门禁、打断调度），拆成多个服务意味着先把它们全部外置化，收益却接近零。

`cmd/` 下除了 `server` 还有四个小工具，各自对应一个真实运维需求：

| 入口 | 用途 |
| --- | --- |
| `cmd/evals` | 离线评测 CLI：`go run ./cmd/evals -suite all` 输出 `artifacts/evals/offline.json` |
| `cmd/eval-audit` | 对运行中实例按 citation 前缀深查 trace，输出审计报告 |
| `cmd/latency-test` | 语音链路延迟测量 |
| `cmd/verify-datasource` | 外部比赛数据源连通性验证 |

业务逻辑全部在 `backend/internal/` 下按包组织。每个包一句话说清职责：

| 包 | 职责一句话 |
| --- | --- |
| `config` | 环境变量加载与启动校验，生产硬门在这里 |
| `auth` | 匿名会话：访问/刷新令牌的签发、刷新与吊销 |
| `ws` | WebSocket hub：握手、Origin 校验、每 IP 连接上限与读写超时 |
| `conversation` | 观赛会话编排：主动发言门禁、发言调度与打断、投递去重 |
| `companion` | 对话决策核心：意图分类、表达实现、锚定护栏 |
| `router` | LLM 意图路由：关键词 miss 时的兜底分类，双密钥回落 |
| `llm` / `openaicompat` | 模型客户端与 OpenAI 兼容传输层 |
| `asr` / `tts` | 语音识别与合成客户端；tts 负责把表演指令（style/energy/speed）拼进合成请求 |
| `matchstate` | 比赛状态机：事实账本、时钟、目录排序，以及 Postgres 存储与迁移执行器 |
| `event` | 比赛事件模型，导播行为条与事实事件的公共定义 |
| `datasource` | 外部数据源：APISports 轮询、按延迟判活、人工接管切换 |
| `observation` | 待确认观察的跨连接协调：确认、撤销、跟进与过期 |
| `interaction` | 交互账本：追加式 ledger，唯一本地事实源 |
| `memory` | 记忆抽取队列、画像合并（本地 overlay 为权威覆盖层）、开放话题、话痨偏好 |
| `relationship` | 情感状态机（事件驱动、随时间衰减回基线）与关系动作词表 |
| `privacy` | 导出、删除 job、保留期清理（每 6 小时一拍） |
| `directordraft` | 导播语音草稿：ASR 转写加 LLM 抽取成事件草稿 |
| `consoleauth` / `operatorauth` / `operatorwrite` | 运营台 JWT 登录、角色 scope、幂等写 |
| `resilience` | 对外部调用的熔断器 |

包之间没有统一的总线或框架，`cmd/server/main.go` 本身就是组装根：进程启动时按依赖顺序打开全部 Postgres 存储（会话、比赛、隐私、幂等、运营员、trace、观察协调、交互账本、记忆、投递），任何一环打开失败就 `log.Fatal`——基础设施不可用与配置缺失同罪，都走快速失败。这是单体容易被误解的地方：包边界不靠运行时隔离，靠的是 import 方向的纪律与评测锁定，`interaction`（账本）不知道 `memory`（画像）的存在，`matchstate` 的事实永远不会被 `relationship` 改写。

参数也是契约的一部分，全部集中在 `config` 包里给默认值、给注释、给边界：WS 每 IP 最多 5 条连接，读上限 1MB——注释写明这"够一条 15 秒 16kHz 单声道语音"，读超时 60 秒、写超时 10 秒。新成员问"这个 1MB 是怎么定的"，答案在代码注释里，不在某个成员的记忆里。

前端是两个独立工程：`client/` 是 Flutter 观赛端（`lib/screens`、`lib/services`、`lib/widgets` 加 `assets/live2d` 资产）；`console/` 是 Vite + React 的运营导播台，`vite.config.ts` 里 `base: '/console/'`，构建产物由 Go 进程挂载。进程还有最小健康面：`/health` 由 WS hub 直接应答，只证明进程活着——健康不是产品状态，比分可信与否永远以事实账本的确认状态为准。

### 2.2 compose 六服务

仓库根的 `docker-compose.yml` 声明六个服务，一条命令起全套：

| 服务 | 镜像 | 职责 |
| --- | --- | --- |
| `backend` | 仓库内 `backend/Dockerfile` 三阶段构建 | 唯一应用进程：API、WS、静态托管 |
| `postgres` | `pgvector/pgvector:pg16` | 唯一全量事实源；向量能力就绪（事件嵌入当前关闭） |
| `redis` | `redis:7-alpine` | 短生命周期状态：去重、冷却 |
| `memobase` | `ghcr.io/memodb-io/memobase` | 可变记忆合成（画像、事件摘要）；按约定永不写比赛事实 |
| `memobase-postgres` | `postgres:16-alpine` | memobase 专用存储，不与主库共用口令 |
| `memobase-redis` | `redis:7-alpine` | memobase 专用队列 |

依赖语义是声明出来的，不靠启动脚本：`backend` 等 `postgres` 的 `pg_isready` healthcheck 通过才启动，`memobase` 等它自己那对 pg/redis 健康。持久卷三个：`postgres_data`（唯一全量事实源，备份与恢复见 `deploy/README.md`）、`memobase_postgres_data`、`redis_data`。有个诚实的细节：主 `redis` 服务并没有挂持久卷——它上面的东西本来就该丢了不心疼，长期事实只进 Postgres 和交互账本。

memobase 单独配一对专用 pg/redis 是刻意的隔离：它是唯一的外部有状态依赖，管可变的画像合成，定位是"可重建的缓存"而非事实源——账本抽取进 memobase 失败只记日志与降级徽标，绝不影响回复；反过来它也拿不到比赛事实的写路径。独立口令、独立卷、独立健康检查，让这个外部件随时可以炸掉重建而不波及主库。

为什么是六个、而不是更少或更多：一个应用进程、一份事实存储、一个短状态缓存，是这套系统的最小充分集；memobase 是外购能力，自带存储假设，于是连本带利多出三个容器。没有再拆出网关、没有独立的迁移容器、没有为"将来可能拆分"预留的空服务——每个容器都对应今天真实运行的一段职责。

对外访问面同样收得很紧：宿主机只映射两个端口——backend 的 `8080`（可用 `PORT` 覆盖）与 memobase 的 `8019`（管理口）；postgres 和 redis 都不发布到宿主机，想碰主库就走 `docker compose exec postgres psql`。数据库不暴露端口，是这份 compose 里最便宜也最有效的一条安全边界。

### 2.3 四十六个迁移的演进史

`backend/migrations/` 下是 46 个 SQL 文件。它们不只是 schema，也是这个项目的编年史——读迁移名能读出产品认知的几次转向：

- `001_companion_match_memory.sql`：项目最早的假设叫"陪看比赛记忆"，那时我们以为跨场记忆是核心。
- `013_trusted_interaction_foundation`、`031_interaction_ledger`：认知转向"账本为本"——追加式交互账本成为唯一本地事实源，Memobase 降级为可重建的画像缓存。
- `016_privacy_lifecycle`：删除与保留期进入 schema，隐私不再是应用层约定。
- `021_match_clocks`：比赛时钟从内存态落库，服务端推进有了持久基础。
- `023`/`024` `fact_conflicts` 与 `fact_conflict_graph`：人工导播与外部数据源冲突调和的图结构。
- `026_anonymous_device_identities`：匿名身份的持久基础，迁移永不重生成 UUID。
- `040`/`041` `open_threads`、`portrait_overlays`：开放话题台账与画像覆盖层。
- `042`/`043` `operators`、`operator_passwords`：运营台双通道账号（人类走密码 JWT，机器走个人令牌）。
- `044_agent_router_trace`：意图路由轨迹，最新的一批。

迁移的执行机制值得讲清楚，因为它是"为什么四十六个文件从不需要手工跑"的答案：`internal/matchstate/postgres.go` 的 `runMigrations` 在进程启动时按文件名排序执行，先取一把 Postgres advisory lock 防并发，再按文件 basename 记入 `schema_migrations` 账本，已应用的跳过。由此推出一条铁律：**迁移只进不退，且永不改名**——改名等于在已有部署上重放。仓库里真的留着这样的"活化石"：序号 `025` 是个空档，`010`/`011`/`012` 各有一组历史重号。`scripts/lint-migrations.mjs` 对这份封闭的遗留清单向 stderr 告警但放行，今后任何新引入的重复序号一律退出 1 失败；下一个空闲序号是 045。

于是"给系统加一张表"在骨架里是三个动作：写 `045_<名字>.sql`；重启 backend，advisory lock 保证多实例下也只应用一次；评测离线档里的迁移 lint 与 Postgres 集成测试把关。没有独立的迁移工位，没有"记得在生产跑迁移脚本"这类口头流程——执行器与账本让 schema 演进和进程启动绑成同一件事。

### 2.4 静态托管的双路径

同一个 Go 进程挂两条静态路径，没有独立的静态层：

- `/` 托 Flutter web 构建产物（`resolveWebAppDir()`，默认 `../client/build/web`，可用 `QIUQIU_WEB_DIR` 覆盖）；
- `/console` 308 重定向到 `/console/`，托 Vite 构建产物（默认 `../console/dist`，可用 `QIUQIU_CONSOLE_DIR` 覆盖），hash 路由 SPA。

两个解析器都以"目录下存在 index.html"为准，找不到就回落默认路径——宁可白页也好过猜路径。`/live2d-assets/` 单独路由，CORS 全开（Web 端域名与资产分离所需），唯一特判是 `operator-live-state.js` 强制 no-cache，保证导播台的实时状态不被缓存咬住。

双路径也是一次收敛的结果：旧的 operator.html 实时运营页已整体退役，路由与服务端点一并删除，实时运营面全部收敛进 `/console` 新导播台；退役不是删完就走，旧接口的冻结形状由 28 条 operator-control 评测继续守护，谁改了契约，评测立刻红。骨架的每一次简化都带着护栏落地。

构建侧是 `backend/Dockerfile` 的三阶段：`golang:1.22-alpine` 编译后端二进制 → 按 digest 钉死的 `cirruslabs/flutter:stable` 构建 Flutter web → `alpine:3.20` 运行时。最终镜像等于二进制加 prompts 加 migrations 加 Live2D 资产加 web 构建——一个镜像一个容器，交付面收敛到极致。

## 3. 环境与配置：缺失即拒绝启动

### 3.1 两份清单，用途不同

仓库有两份环境变量模板：根目录 `.env.example` 是 compose 全集（注释明确写着与 backend 那份"用途不同，勿混用"）；`backend/.env.example` 是 `go run` 本地开发集，`ALLOWED_ORIGINS` 已预填 `http://localhost:7357`。两份清单内部都按"必填 / 条件必填 / 可选"分区注释，模板里没有一个真实密钥、真实地址或真实账号——占位就是占位，误启动会在硬门处明显失败，而不是悄悄连向未知外部服务。

变量只放部署差异、密钥引用、地址与开关；真实用户内容、比赛记录、投诉文本永远不进环境变量。判断标准一句话：环境变量里出现的东西，丢了可以重新配，泄了可以立刻轮换；做不到这两条的，不属于这里。

### 3.2 生产硬门：三层快速失败

**第一层在 compose。** 模板用 `${VAR:?}` 语法声明了六个缺失即拒绝启动的变量：`APP_TOKEN`（机器通道口令）、`SESSION_SIGNING_KEY`（会话签名密钥）、`ALLOWED_ORIGINS`、`POSTGRES_PASSWORD`、`MIMO_API_KEY`、`MEMOBASE_POSTGRES_PASSWORD`。缺任何一个，`docker compose up` 直接报错，一个容器都不会起。

**第二层在进程。** `internal/config` 的 `Validate()`：`APP_ENV=production` 时，`APP_TOKEN`、`MIMO_API_KEY`、`SESSION_SIGNING_KEY` 任一缺失即拒绝启动，签名密钥不足 32 字符同样拒绝；`PRIVACY_RETENTION_DAYS` 为负拒绝启动，为 0 视为未配置、回落 30 天默认。

**第三层在登录。** `QIUQIU_JWT_SECRET` 只要存在任何密码账号就必需——它在登录时校验而非启动时，因为"是否存在密码账号"是运行态。

分层的逻辑是：`APISPORTS_API_KEY` 这类增强型变量可以缺——没有外部源时纯人工导播照常运行；但身份、口令、数据库与模型密钥缺失时，系统假装能跑只会把故障推迟到比赛中场。快速失败让每一次"少配了一个变量"都在部署那一秒暴露，而不是在首场直播。

其余变量全部"有默认、有出处、有边界"：`PRIVACY_RETENTION_DAYS` 默认 30，`COMPANION_REALIZER_TIMEOUT_MS` 默认 5000 且被夹在 1–10000 区间，`MIMO_MODEL` 默认 `mimo-v2.5-pro`、`MIMO_VOICE` 默认"冰糖"，`PENDING_OBSERVATION_COORDINATION` 与 `FACT_LEDGER_PUBLIC_READS` 两个行为开关默认开启、可显式回退旧路径。没有配置中心，没有 YAML 层——环境变量即全部配置，`git grep os.Getenv` 就能穷尽系统的全部外部输入面。

### 3.3 开发与生产的差异

| 维度 | 开发 | 生产 |
| --- | --- | --- |
| 认证模式 | `AUTH_MODE` 默认 dual | 强制 session，身份绑定在会话令牌上 |
| 签名密钥 | 缺省时进程自动生成一把本地开发密钥 | 必填且 ≥32 字符，绝不代生成 |
| TTS | `development` 且 `QIUQIU_RUNTIME_TTS=1` 时注入 mock 客户端（固定音频），供无密钥机器跑通语音路径 | 只走 `mimo-v2.5-tts` 固定音色（默认"冰糖"），失败字幕兜底，永不注入 mock |
| 开发专页 | `test-expressions.html`、`director-prototype.html` 仅非 production 注册 | 生产二进制里根本没有这些路由 |

mock TTS 的门值得单独看一眼：判断条件是 `environment == development` 且环境变量置 1，两者缺一不可。这意味着评测脚本可以在无密钥机器上验证完整语音链路，而生产镜像无论被谁误配了什么变量，都不可能出现"假的语音"。

## 4. 如何验证：一名新成员的一天

以下是真实命令形态的完整路径，每一步都对应仓库里的脚本或配置。顺序不能换：先让容器与迁移证明"系统能起"，再让离线评测证明"行为正确"，最后才打开界面看"体验成立"。跳过中间直接看效果，是新手排查问题的最大时间黑洞。

**前置**：Git、Docker（含 Compose v2）、Go 1.22、Node（评测脚本运行时）；只有要在本地跑 Flutter 客户端时才需要 Flutter SDK。

**第一步，克隆与配置。**

```bash
git clone <仓库地址> && cd qiuqiu
cp .env.example .env    # 至少填入六个必填变量（模板里有逐项注释）
```

**第二步，构建并启动。**

```bash
docker compose up -d --build
docker compose ps       # postgres 先 healthy，backend 才启动
```

首次构建包含 Go 编译与 Flutter web 发布构建（镜像内自建，宿主机无需 Flutter）。这一步顺手验证了 compose 的 `:?` 硬门：漏填变量会立刻失败。

**第三步，确认迁移。** 迁移在 backend 启动时自动应用，没有手工步骤；想亲眼确认：

```bash
docker compose exec postgres psql -U qiuqiu -d qiuqiu \
  -c "SELECT count(*) FROM schema_migrations;"   # 46
```

**第四步，评测离线档。**

```bash
npm install          # 安装 Playwright 等评测依赖
npm run eval:offline # = node scripts/evals/run.mjs --tier offline
```

离线档会先显式清空所有模型与数据源密钥再运行——这是设计声明：不接任何外部服务，系统的全部确定性行为都必须正确。内容依次是：`go test ./...`（全量 Go 套件，含 baseline 36、boundary 38、regression 26 共 100 例黄金评测）→ `cmd/evals -suite all` → 六个结构 check 脚本（表演映射、导播事件模型、console 传输、草稿形态、Live2D 让步、迁移 lint）→ `tests/unit` 的 node 单测 → voice-ui 冒烟。全绿，意味着这台机器拥有了该项目全部可离线验证的行为基线。

离线档只是四档中的第一档。四档共用一个入口（`scripts/evals/run.mjs` 的 `--tier`），按"改了什么"选档：

| 档位 | 命令 | 在离线档之上加什么 | 什么时候跑 |
| --- | --- | --- | --- |
| offline | `npm run eval:offline` | —（零密钥基线） | 每次提交前 |
| pr | `npm run eval:pr` | 会话隔离 E2E、起真实后端跑 runtime E2E 与轨迹/交互审计、全量 Playwright 浏览器套件（18 条 spec） | 每个合并请求 |
| nightly | `npm run eval:nightly` | companion 黄金路径基准（`-bench -count=3`）；配了 `DATABASE_URL` 则加跑 Postgres 集成测试 | 每夜 |
| release | `npm run eval:release` | 要求真实 `MIMO_API_KEY`，跑真机语音冒烟 | 发布前 |

分层的判断标准写在机制里：能离线锁定的绝不推到在线，涉及浏览器的绝不混进单元档，花真钱的语音调用只在发布档出现。这一分层本身就是骨架的一部分——它让"跑全套验证"从一个模糊愿望变成四个有名字的命令。

**第五步，打开两个入口。**

- 浏览器访问 `http://localhost:8080/`：客户端自动建立匿名身份与会话，`?matchId=` 深链直达比赛；`scripts/demo-seed.mjs` 可播种演示比赛（白名单 ID，随时可演示重置）。
- 访问 `http://localhost:8080/console/`：导播台。空表时用 `QIUQIU_BOOTSTRAP_OPERATOR=名字:个人令牌` 播种第一个 director，首登强制改密。

到这里应该看到的画面：客户端里球球以待机姿态呼吸，比赛开始后随事件切换表情动作，进球时有主动发言与语音（开发档为 mock 音频）；导播台概览六格有数，比赛页能看事件流、用户网格与审计轨迹。身份是匿名的，数据落在本机卷里，删除入口真实可用——这套路径从头到尾不需要任何一个真实用户的任何一条真实数据。

**纯本地开发变体**（不跑容器、改代码热迭代时）：

```bash
cd backend && cp .env.example .env && go run ./cmd/server
#   不配 DATABASE_URL 时以进程内存态运行，签名密钥自动生成本地值
cd console && npm run dev
#   Vite 起在 5173，把 /api 与 /ws 代理到 127.0.0.1:18080 的 Go 进程
cd client && flutter run \
  --dart-define=QIUQIU_WS_URL=ws://10.0.2.2:8080/ws/match/test
#   10.0.2.2 是 Android 模拟器看宿主机的回环地址
```

**第一周容易疑惑的几个行为**（都是设计，不是 bug）：

- 浏览器拦截了首次语音？先触碰一次页面，播放会恢复；这是自动播放策略的预期路径，字幕与动作从不等待语音。
- 从比赛页退回列表后刷新，为什么不回到比赛？深链参数退出即清，防的是"刷新回赛"的失控感。
- 语音怎么是假的？开发档开了 `QIUQIU_RUNTIME_TTS=1` 会有 mock 音频，关掉它、或换生产配置，就只剩字幕兜底。
- 导播台里改不了用户的话痨档位？刻意的：档位由用户在客户端设定并持久化，console 只读——两侧不对称是红线不是缺陷。
- 演示比赛重置按钮对某场比赛报错？重置只对白名单演示 ID 开放，真实比赛 ID 一律拒绝。

**故障时的第一反应**：端口被占，改 `PORT` 而不是杀进程；postgres 起不来，先看 healthcheck 日志再谈重启；评测红了，先看是不是迁移 lint 抓到了新的重复序号。

**交付前的最后一课，备份演练**。骨架的验证不止"能起能跑"，还包括"坏了能回来"。按 `deploy/README.md` 的路径走一遍：

```bash
mkdir -p backups
docker compose exec -T postgres pg_dump -U qiuqiu -d qiuqiu -Fc > backups/qiuqiu-$(date +%F).dump
# 生产环境再加一条 crontab：每日 03:30 自动执行同样命令（% 需转义为 \%）
```

新成员应当亲手执行一次恢复（`pg_restore --clean --if-exists`，或卷重建后整库恢复），确认备份真的可恢复。没演练过恢复的备份只是心理安慰。

一天结束的验收标志：新成员能回答"球球为什么在进球后说了那句话"——他能从导播台的用户页进画像、从引用审计抽屉看到 citation、从 trace 里对上锚源。看到系统，并且能解释系统，才算跑通。

## 5. 边界与不做：单机 compose 的取舍

**没有多环境。** `APP_ENV` 只有 development 与 production 两档，没有 staging。理由很实际：导播台加白名单演示比赛本身就是"预生产"——demo 比赛可随时整场重置（清 trace、关系与观察），维护成本远低于第三套环境。

**没有 K8s，也没有多副本。** 单机 `docker compose`，六容器 `restart: unless-stopped`。这不是没评估过：我们的 WS 会话、观察协调器、主动发言调度都是单进程语义，横向扩两个 backend 之前得先把进程内状态全部外置——那是另一个量级的工程。当前单机规模下，compose 的故障面最小、可重复性最高，复杂度留在图纸上就是赚的。

**扩容路径是换更大的机器加备份恢复，不是加节点。** `postgres_data` 卷是唯一全量事实源：每日 03:30 定时 `pg_dump`（custom 格式），`deploy/README.md` 写明了两条恢复路径（覆盖恢复与卷重建恢复）。memobase 的库丢了可由账本重建，不强制定时备份——备份策略跟着"哪些数据不可再生"走，而不是一刀切。

**迁移只进不退。** 没有 down 迁移；回滚意味着恢复备份。这与"永不改名"是同一条纪律的两面：schema 的历史在生产环境里是不可变的。

**同样明确不做的**：独立静态托管或 CDN 层（单进程双路径已覆盖当前形态）、服务网格、自动扩缩容。重新评估的信号也写在这里：出现第二台机器的真实需求（高可用或地域分布），或单进程成为吞吐瓶颈。

回头看，这份骨架为团队买来三样东西：一条从克隆到看到球球说话的、可重复的命令链；一组写进结构与脚本的边界，让"不该发生的事"在编译、启动、评测三处被机器拦下而不是靠人记住；以及一份诚实的演进记录——四十六个迁移、两个前端工程、四个评测档位，每一件都长在真实需求上，没有一件是为简历写的。环境搭建真正交付的从来不是一台能跑的机器，而是让下一个进入仓库的人，从第一天就站在和所有人相同的地面上。
