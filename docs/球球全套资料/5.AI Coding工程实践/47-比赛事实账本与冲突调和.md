# 比赛事实账本与冲突调和

> **本篇已由《球球课程》同源章节取代。**
> 课程章节按"系统实际怎么工作 + 与旧设计的差异"以 status 锚重写,是本主题的唯一事实源。本页保留原篇的定位说明与阅读指引。

**原篇定位**:0→1 施工方案,计划在赛程与来源管理具备受控候选输入后,建立用户端比分、事件与角色事实回答的唯一可解释基础。当时确认门槛、冲突策略、保留期限、回放性能与人工复核范围均为待验证假设。

其核心原则已按现实兑现并写入课程章:事实账本记录"发生过哪些受控判断",而非只保存一个可被随意覆盖的最新比分;公共快照只从有效账本投影;用户观察、角色输出和缓存都不能绕过账本改写事实。

## 该主题讲什么

- **账本与回放**:追加式事件账本,每条事件带场次级单调序号(`recorded_sequence`);投影可从任意账本位置重放,输出携带 `ProjectorVersion` 与 `ProjectedSequence`,公开快照因此可解释、可重建。
- **冲突与幂等**:互斥来源候选在 45 秒时钟窗内冲突成簇(三张冲突表加无向边图),调和是图上的可行集选择;操作员写入统一走 Idempotency-Key 幂等,发布走事务性 outbox,追加前还有"追加即验证"的不变量校验。
- **隔离与真实入口**:用户观察被隔离在接口级——`observations.Record` 没有任何写账本的通路;真实入口是 `backend/internal/matchstate` 包与 `backend/cmd/server` 单体,而非旧稿设想的独立微服务。
