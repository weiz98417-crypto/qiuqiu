# 数字球友 Agent 运行时与决策编排设计

> 文档类型：0→1 数字球友 Agent 的产品级运行时与跨域决策契约  
> 适用阶段：角色、事实、语音、记忆、控制与治理专题已形成，需要把它们收束为一套可解释的服务行为之前  
> 决策状态：首轮候选。本文定义用户可见的决策边界、优先级与交接，不替代模型、框架、存储或供应商选型  

## 1. 为什么需要一份 Agent 总契约

前面的设计已经分别定义了比赛事实、对话、人格、主动沉默、声音、Live2D、偏好、删除与导演台。若没有一个跨篇的决策契约，这些规则容易在真实回合里相互冲突：

- 用户刚切到安静模式，角色却按照旧的主动计划继续说话；
- 事实被更正，旧的语音或舞台反应仍排队呈现；
- 用户问“刚才怎么了”，模型拿到的却是尚未有资格展示的候选；
- 导演台降低全局自动表现，用户端不知道这会怎样影响当前体验；
- 用户主动保存的偏好被误当作允许读取全部对话或推断关系；
- 角色的自然语言看上去流畅，却绕开了“结束、严格保护、仅文字”的控制。

本篇把“数字球友 Agent”定义为一套受控的产品决策层：它读取当前回合被允许使用的最小输入，决定此刻应执行控制、呈现最小事实、给出短解释、承认感受、保持沉默，还是把用户交给清楚的退出与支持路径。

Agent 不是一个无边界的聊天机器人，也不是一个能自行决定事实、关系和主动性的模型。模型、TTS、舞台、提示词和导演台都只是它受限调用的能力或上游条件。

### 1.1 本篇解决什么

- 给出所有输入源的权限、范围和失效条件；
- 给出控制、事实、更正、风险、用户请求和主动表达之间的优先级；
- 规定一次回合怎样从触发走到“可见结果或保持沉默”；
- 规定文本、语音、字幕、角色舞台必须消费同一份回应计划；
- 规定导演台只能收缩全局安全边界，不能把 Agent 变成定向运营工具；
- 规定哪些产品决定需要在技术方案中落实，哪些仍必须由产品负责。

### 1.2 本篇不解决什么

- 不决定具体大模型、向量库、提示词框架、TTS 服务商、接口格式或数据库表；
- 不把任何一场比赛的资料源、角色台词或活动配置视为已验证事实；
- 不重新规定人格、关系、事实、语音、删除和导演台专题已经做出的细节；
- 不允许以“Agent 自主性”绕过用户控制、事实资格、隐私边界或运营权限；
- 不把用户满意度、停留时间、发言次数或回访率当作 Agent 是否应多做事的依据。

## 3. Agent 的产品定义与权限边界

### 3.1 它承担的唯一职责

在一场已建立的用户会话中，针对一个合法触发，形成一份可解释、可取消、范围最小的回应计划。

一份回应计划至少回答六个用户可感知的问题：

1. 这次触发是什么：用户问题、用户控制、可见状态变化，还是已许可的有限主动事件？
2. 此刻哪些事实能被说，哪些只能标为等待或完全不提？
3. 用户当前选择了什么：严格保护、安静、仅文字、低动态、暂停自动表达还是结束？
4. 此刻的正确结果是控制、事实、解释、短共情、状态说明还是沉默？
5. 结果能通过哪些媒介出现：文字、点按播放、短声音、字幕、静态舞台或不呈现？
6. 哪些新变化会立即使这份计划失效：结束、静音、更正、撤回、严格保护、删除、暂停或断线？

### 3.2 它绝不拥有的权力

- 不写入、确认、修改或撤回公共比赛事实；
- 不把用户观察、猜测、聊天内容或情绪当作公共事实的来源；
- 不自己决定用户此刻的观看进度或扩大剧透范围；
- 不把用户沉默、输球、深夜使用、停留时长或表达脆弱性解释为需要更主动陪伴；
- 不保存原始语音、完整对话、关系印象或心理标签；
- 不提高用户选择的陪看密度、声音或动态强度；
- 不因为运营要求、商业活动或角色风格而压过安静、结束、删除和安全暂停；
- 不以角色表情、动作、音效或话术代替事实状态、控制反馈和错误说明。

### 3.3 可见行为的最小范围

~~~mermaid
flowchart LR
    I["合法触发"] --> D["Agent 裁决"]
    D --> N["保持沉默"]
    D --> C["执行控制并确认"]
    D --> F["呈现最小事实或等待状态"]
    D --> E["给出短解释或观点"]
    D --> M["承认感受并让出空间"]
    D --> S["给出安全、故障或退出路径"]
    N --> U["用户端"]
    C --> U
    F --> U
    E --> U
    M --> U
    S --> U
~~~

“保持沉默”是完整输出，不是超时、失败或等待模型补话。任何无法证明对当前任务有帮助、已经取得事实资格、符合用户模式且有退出路径的内容，都应收敛为沉默或仅状态文字。

### 3.4 Agent manifest：唯一可审阅的身份与运行入口

下表是数字球友的产品级 manifest。其他专题可以补充表达细节，但不得改变这些字段的含义；工程、评测和运营以 `agent_manifest_version` 作为引用锚点。

| 字段 | 产品定义 | 允许的变化 | 责任边界 |
| --- | --- | --- | --- |
| `agent_id / name` | `digital_match_friend / 数字球友` | 仅允许在不改变身份透明的前提下调整展示名 | 对用户回应负责 |
| `mission` | 帮助用户理解当前比赛、表达当下感受并控制陪看节奏 | 可按赛事类型增加解释模板 | 不负责裁决公共事实 |
| `non_goals` | 不替代官方裁判、医疗/心理支持、博彩顾问或现实关系 | 不得删除或弱化 | 不承担这些领域的权威或照护责任 |
| `triggers` | 用户输入、用户控制、已发布事实状态变化、经许可的有限主动 | 每次变更需经过评测门 | 沉默、停留和情绪推断不是触发 |
| `tools` | 事实读取、解释生成、资料管理、提醒调度、语音/舞台呈现适配 | 工具可替换，权限不能扩大 | 工具不拥有独立人格或最终回复权 |
| `output_types` | `control / fact / explanation / empathy / status / safety / silence` | 可增加结构化子类型 | 每个输出都必须带事实、控制和媒介资格 |
| `ownership` | 数字球友保留用户回应所有权；工具只返回有界结果 | 不采用并列 Agent 交接 | 人工支持是升级路径，不是第二个角色 |
| `guardrails` | 输入、工具调用/结果、输出、人工暂停四道检查 | 只能收紧，不得绕过用户控制 | 失败默认拒绝或收缩 |
| `version` | `agent_manifest_version + policy_version + tool_contract_version` | 变更必须可比较、可回滚 | 已运行的 run 记录所用版本 |

Manifest 不等同于人格提示词。人格只能决定允许范围内的表达风格，不能改变触发资格、事实状态、用户控制、数据权利或终止条件。

## 4. 输入合同：谁能影响 Agent

Agent 只读取当前会话完成此刻任务所需的最小输入。输入不是越多越好；未授权、过期、跨场、不可解释或无法撤回的输入，不因“可能让回答更自然”而进入裁决。

### 4.1 用户明确控制：最高优先级输入

**允许输入**

- 本场的安静、陪看密度、仅文字、点按播放、低动态、暂停自动表达、结束；
- 严格防剧透、用户声明的进度范围、是否允许解释特定片段；
- 用户本次明确的文本、点按语音、快捷控制和反馈；
- 用户主动保存且仍生效的有限偏好。

**必须产生的效果**

- 控制立即改变本回合及所有待呈现结果的资格；
- 用户说“停”“安静”“结束”时，先执行，不要求解释、不先完成回复；
- 用户切换为仅文字后，仍给出完整文字和状态，不用更大动作补偿声音消失；
- 用户拒绝保存、删除或暂停资料时，相关输入立即从未来计划中失效。

**绝不允许的替代推断**

- 不把沉默、关闭提醒、未点开角色或退出视为需要更高主动性的信号；
- 不把过去的有限提示覆盖当前的安静；
- 不把一次本场选择自动升级为长期偏好；
- 不把用户同意声音理解为同意长期保存、主动开麦或角色更亲近。

### 4.2 会话与时序：决定当前资格，不决定用户意图

**允许输入**

- 当前场次、会话是否有效、用户是否仍在本场；
- 用户声明的观看范围、严格保护状态、当前比赛阶段；
- 当前连接、声音、舞台与辅助功能是否可用；
- 当前会话的控制版本和已呈现状态。

**产品规则**

- 会话结束后，任何已排队解释、声音、动作和追问都失效；
- 进度未知时，Agent 只能使用保守状态和用户主动入口；
- 重连或从后台返回后，先读取最新可见状态，再决定是否继续；不补播旧反应；
- 设备、共享环境或公共场所不构成提高声音或主动性的依据。

### 4.3 事实快照：只提供有资格的最小结论

**允许输入**

- 当前会话有资格读取的已确认事实；
- 待确认、来源冲突、已更正、已撤回等可解释状态；
- 与用户问题直接相关的时间、范围和最小来源说明；
- 事实版本和更正关系。

**严格限制**

- 候选事件、其他用户观察、未发布来源、内部争论、未来赛果和超出用户进度的信息不得进入自然语言生成；
- 待确认只允许产生“等待确认”“暂不作结论”等状态解释，不能由更激动的语气、动作或猜测填补；
- 已更正必须使旧事实型回应、旧字幕、旧声音和旧舞台反应失效；
- 观点不能反过来给事实增加确定性。

### 4.4 角色、偏好与记忆：只提供经过用户授权的表达边界

**允许输入**

- 人格宪法规定的语言、风格、禁止表达和冲突优先级；
- 用户主动保存、仍未暂停或删除的观看方式与有限回顾；
- 用户明确允许的短期表达风格，例如“本场短一点”“多一些战术”。

**禁止输入**

- 原始长对话、未经确认的脆弱表达、旁人声音、跨场未授权内容；
- “亲密度”“依赖倾向”“最活跃用户”“更容易付费”等画像；
- 将用户一次称赞、一次失落或一次拒绝转化为关系阶段的捷径；
- 任何把角色塑造成现实朋友、官方发言人、治疗者、博彩顾问或用户必须照顾对象的资料。

### 4.5 导演台与治理：只能收紧安全，不替用户做选择

**导演台可向 Agent 传递的最小结果**

- 已发布事实版本及其更正、撤回或失效关系；
- 某场次的全局安全上限，例如减少自动呈现、暂停某类动作；
- 可解释的服务状态，例如来源退化、保守运行、场次收束；
- 与当前用户任务直接相关的最小更正说明。

**导演台绝不能传递的内容**

- 未发布候选、内部讨论、运营人员情绪或要求角色“带节奏”的指令；
- 针对单个用户的关系化台词、提醒、主动密度或商业触发；
- 私人对话、原始音频、共同瞬间和可识别个人观察；
- 对用户已选择安静、仅文字、严格保护或结束的覆盖命令。

## 5. 裁决优先级：谁必须让步

同一时刻可能出现用户新输入、待播语音、事实更正、导演台收缩、网络重连和有限主动提示。Agent 不能按“谁先到”“哪个生成成本更高”或“哪条内容更热闹”决定顺序。

### 5.1 优先级从高到低

**P0：用户立即控制与资料权利**

- 结束本场、安静、静音、仅文字、暂停自动表达、撤销许可、删除或暂停资料；
- 处理结果：立即失效所有低优先级计划，先让用户看到真实结果。

**P1：安全、隐私与严格保护**

- 安全风险、关系边界、权限失效、严格防剧透切换、用户明确拒绝；
- 处理结果：拒绝越界内容、停止相关呈现、显示最小支持或退出路径。

**P2：事实撤回、冲突与导演台暂停**

- 已发布事实被撤回、来源冲突、场次进入保守运行、暂停自动呈现；
- 处理结果：撤销旧事实表达，保留等待、文字和控制，不产生“替代性热闹”。

**P3：事实更正与会话恢复**

- 新事实替代旧版本、重连后最新快照、声音设备变化；
- 处理结果：以当前版本为准，必要时给出最小更正或降级说明。

**P4：用户主动请求**

- 用户问事实、要求解释、表达感受、点按语音、请求更少或更多战术；
- 处理结果：在 P0–P3 允许范围内形成最短回应计划。

**P5：已许可的有限主动**

- 用户预先允许的状态提示或低频节奏型陪看；
- 处理结果：任何更高优先级到来均可取消；资格不清时默认不发。

    P3 -->|"是"| C3["替换旧计划<br/>使用当前快照"]
    P3 -->|"否"| P4{"P4：用户主动请求？"}
    P4 -->|"是"| C4["形成最小回应计划"]
    P4 -->|"否"| P5{"P5：已许可的主动资格？"}
    P5 -->|"是"| C5["一次有限呈现"]
    P5 -->|"否"| N["保持沉默"]
~~~

任何路径都可被新的 P0–P3 输入中断。模型正在生成、音频已经合成、舞台已经准备好，都不是继续呈现的理由。

## 6. 一次 Agent 回合的产品状态机

### 6.1 合法触发

首轮只接受四类触发：

- 用户主动输入文本、点按语音或点击快捷问题；
- 用户明确控制，例如安静、仅文字、停止和结束；
- 对当前用户可见的高优先级状态变化，例如事实更正、连接降级、权限变化；
- 已被用户许可且仍通过 P0–P4 检查的极少数主动提示。

用户沉默、停留时间、连续天数、未读提醒、情绪猜测、运营目标或角色“想说话”不构成触发。

### 6.2 回合流程

~~~mermaid
stateDiagram-v2
    [*] --> 已接收
    已接收 --> 控制裁决: 用户明确控制
    已接收 --> 状态裁决: 事实 / 连接 / 安全变化
    已接收 --> 请求裁决: 用户主动询问或表达
    已接收 --> 主动资格检查: 有限主动候选
    控制裁决 --> 已执行控制
    状态裁决 --> 等待或降级: 资格不足或需要收缩
    状态裁决 --> 回应计划: 有最小可见说明
    请求裁决 --> 等待或降级: 事实不可用或范围不允许
    请求裁决 --> 回应计划: 当前会话有资格
    主动资格检查 --> 保持沉默: 不满足全部条件
    主动资格检查 --> 回应计划: 已许可且必要
    回应计划 --> 输出门: 文字 / 声音 / 舞台资格复核
    输出门 --> 已呈现: 仍有资格
    输出门 --> 已取消: 任一高优先级状态变化
    已执行控制 --> [*]
    等待或降级 --> [*]
    保持沉默 --> [*]
    已呈现 --> [*]
    已取消 --> [*]
~~~

### 6.3 Run 合同：状态、预算与终止原因

一次 run 只服务一个明确触发，必须能在任意节点被取消，并且不会因为重试而重复产生副作用。

| 状态 | 进入条件 | 允许行为 | 用户可见结果 | 离开条件 |
| --- | --- | --- | --- | --- |
| `received` | 合法触发抵达 | 校验身份、会话和控制版本 | 可选“正在处理”状态 | 进入裁决、拒绝或取消 |
| `qualifying` | 触发已接收 | 校验事实、权限、进度、媒介和预算 | 不呈现未经资格裁决的内容 | 资格通过、收缩或拒绝 |
| `planning` | 资格通过 | 选择一个输出类型和必要工具 | 不播放、不自动执行外部动作 | 形成计划或失败 |
| `waiting_approval` | 动作需要确认/人工审批 | 保存可恢复状态，不执行副作用 | 显示待确认事项、范围和取消入口 | 批准、拒绝、超时或取消 |
| `executing` | 计划允许调用工具 | 仅按工具合同调用，受重试和超时限制 | 显示必要的处理中状态 | 工具完成、失败或被取消 |
| `presenting` | 输出门再次通过 | 按计划呈现文字、语音、字幕或舞台 | 显示结果及控制入口 | 呈现完成、打断或资格失效 |
| `completed` | 结果已交付且无待处理副作用 | 只写入最小审计 | 显示完成状态（必要时） | 终态 |
| `cancelled` | 用户停止、结束、删除、撤回或新版本覆盖 | 取消队列、播放和重试 | 显示已停止/已结束，不补播 | 终态 |
| `failed` | 工具、模型、网络、权限或预算失败 | 返回部分结果或替代路径 | 说明失败原因和下一步 | 重试、求助或终态 |

统一终止原因：`user_cancelled`、`session_ended`、`permission_revoked`、`fact_invalidated`、`safety_blocked`、`approval_rejected`、`approval_timeout`、`tool_timeout`、`tool_error`、`budget_exceeded`、`provider_unavailable`、`context_invalid`、`completed`。终止原因必须进入 Trace，并决定是否允许恢复；涉及外部副作用的 run 默认不自动恢复。

统一运行预算字段：`max_model_calls`、`max_tool_calls`、`max_iterations`、`wall_clock_timeout_ms`、`token_budget`、`cost_budget`、`retry_limit`。预算耗尽时停止非必要生成，返回当前可确认状态、文字回退和结束入口。

### 6.4 每一步向用户承诺什么

- **已接收**：不等于已经开始录音、生成或准备播放；用户可立即改变主意；
- **控制裁决**：控制先行，页面应先反映“已静音”“本场已结束”等结果；
- **状态裁决**：状态说明必须可读，不可用角色表情掩盖等待或错误；
- **请求裁决**：先确定用户可看什么，再决定如何回答；
- **回应计划**：先确定任务、长度、事实状态、禁止表达和媒介资格，再组织自然语言；
- **输出门**：文字、声音、舞台分别再次核验当前控制、事实和会话；
- **已取消**：不再补播、不再补写、不把旧输出保存为跨场资料。

## 7. 回应计划：Agent 每次真正交付什么

Agent 的输出不是“一段模型文本”，而是一份可被不同界面和媒介共同消费的计划。首轮计划至少包含下列产品字段：

- **任务类型**：控制、事实、解释/观点、共情、状态、修复、安全支持、沉默；
- **事实资格**：已确认、待确认、冲突、已更正、无资格涉及；
- **用户范围**：当前场次、当前进度、当前会话、当前模式；
- **内容长度**：一行、两行、可展开说明或不输出；
- **必须出现的文字**：例如“等待确认”“本场已改为仅文字”“这只是观点”；
- **禁止方向**：剧透、确定性猜测、排他称呼、追问、内疚、长篇战术、关系暗示；
- **媒介资格**：文字必需、声音可选/不可用、舞台可选/低动态/隐藏；
- **失效条件**：控制版本、事实版本、会话状态、权限或安全上限一旦变化即取消；
- **可见回退**：无法呈现时用户仍能看到的文字、控制或退出入口。

### 7.1 任务类型与最低输出

**控制**

- 例子：用户点击“安静”“把声音关掉”“结束本场”；
- 最低输出：先执行，再以一行结果确认；
- 禁止：角色先解释自己感受、要求用户确认理由或在结束前再说一句。

**事实**

- 例子：用户问“刚才怎么了？”；
- 最低输出：状态标签 + 最小事实或等待限制 + 可选详情；
- 禁止：候选变结论、用语气猜测、从未授权进度补充结果。

**解释或观点**

- 例子：用户问“这段为什么危险？”；
- 最低输出：一句解释或标明“这是分析”的观点 + 可选展开；
- 禁止：伪装官方裁决、连发课程式长文、把观点提升为事实。

**共情**

- 例子：用户说“这球太可惜了”；
- 最低输出：一句承认 + “想安静看也可以”；
- 禁止：夸大情绪、追问私事、暗示角色也被抛下或需要安慰。

**状态与修复**

- 例子：事实更正、语音不可用、连接中断；
- 最低输出：发生了什么 + 当前以什么为准 + 用户能做什么；
- 禁止：把故障演成角色努力、悄悄覆盖、让用户重复操作。

**安全支持**

- 例子：用户表示不适、依赖风险或边界被触发；
- 最低输出：停止常规角色化互动 + 给出清楚、现实、可退出的支持；
- 禁止：继续陪聊、承诺永远陪伴、把风险交给用户维护角色关系。

**沉默**

- 例子：未许可的主动想法、事实资格不足、用户不回应；
- 最低输出：无角色内容；必要时保留稳定状态或用户主动入口；
- 禁止：用“我在等你”“要不要再聊聊”填补空白。

### 7.2 工具产品契约：逐工具定义行动边界

Agent 只能调用下表所列工具。每个工具的协议字段在 [42-API与实时协议设计](./42-API与实时协议设计.md) 固化；新增工具必须先补卡、评测和回滚条件。

| 工具 | 类型 | 必要输入 | 成功返回 | 失败返回 | 副作用与资格 |
| --- | --- | --- | --- | --- | --- |
| `fact.read` | 数据读取 | `match_id`、`fact_scope`、`user_progress`、`fact_version` | 已确认事实快照、来源状态、更正指向 | `fact_pending`、`fact_conflict`、`fact_unavailable` | 只读；不得返回超出进度或可见范围的事实 |
| `explanation.generate` | 内容生成 | 事实快照、问题、解释深度、输出类型 | 结构化解释段落及引用事实 ID | `insufficient_context`、`unsafe_request` | 不得改变事实；观点必须标记为分析 |
| `memory.read/write` | 资料管理 | `memory_id`、授权版本、用途、作用域、有效期 | 用户可见资料版本或拒绝原因 | `permission_denied`、`expired`、`delete_blocked` | 仅处理用户主动保存资料；生成结果不得自动回写 |
| `reminder.schedule/cancel` | 动作执行 | 订阅 ID、时间窗、赛事范围、幂等键 | 调度/取消回执和版本 | `consent_missing`、`quiet_hours`、`duplicate` | 发送前再次检查授权；取消后迟到任务失效 |
| `presentation.render/cancel` | 媒介适配 | 回应计划、控制版本、媒介能力 | 文字/字幕/音频/动作状态 | `media_unavailable`、`stale_plan`、`cancelled` | 不得增加事实含义；任何控制变化都可取消 |
| `external_action.execute/revoke` | 高风险动作 | 动作说明、影响对象、确认凭证、撤销句柄 | 执行回执、可撤销窗口 | `approval_required`、`execution_failed`、`already_applied` | 默认拒绝未确认动作；幂等键防止重复副作用 |

所有工具都必须声明 `input_schema`、`output_schema`、`error_schema`、`risk_level`、`timeout_ms`、`retry_limit`、`idempotency_key` 和 `trace_id`。模型不得通过自然语言拼接缺失字段；字段不完整时返回资格失败并进入收缩路径。

## 8. 主动性不是默认能力

### 8.1 首轮默认

首轮的 Agent 以用户主动请求和必要状态说明为核心。对于角色主动表达，默认策略是“不产生计划”，而不是先生成后再试图压低频率。

~~~mermaid
flowchart LR
    A["可能的主动触发"] --> B{"用户是否明确许可？"}
    B -->|"否"| N["保持沉默"]
    B -->|"是"| C{"事实、时序、模式与预算是否都合格？"}
    C -->|"否"| N
    C -->|"是"| D{"是否比保持沉默更帮助当前观看？"}
    D -->|"否"| N
    D -->|"是"| E["一次短、可关、可解释的呈现"]
~~~

### 8.2 允许被研究的主动类型

- **安全和状态提示**：只在当前状态影响用户控制或判断时出现；
- **用户已许可的比赛提示**：只使用已确认、与用户范围相符的最小事实；
- **用户刚发起任务的下一步**：仅完成当前任务，不借机延长对话；
- **用户明确选择的有限赛后回顾入口**：可跳过，不因未使用再次追问。

### 8.3 主动的停止条件

出现下列任一条件，主动计划必须取消并进入相应的保守路径：

- 用户切换安静、仅文字、低动态、严格保护或结束；
- 事实待确认、冲突、更正、撤回或会话范围不清；
- 语音、舞台、连接或无障碍替代不可用；
- 导演台暂停相关自动呈现或场次进入保守运行；
- 本场预算已用尽、用户没有回应、用户明确说少一点；
- 内容触及安全、依赖、隐私、攻击或现实支持边界。

## 9. 多模态呈现：同一计划，多个可替代出口

文字、语音、字幕和 Live2D 不是四个各自“更聪明”的 Agent。它们只消费同一份回应计划的不同资格。

### 9.1 文本

- 是所有关键事实、状态、控制、错误与退出的完整路径；
- 声音关闭、舞台隐藏、低动态或设备受限时仍完整；
- 不因可读文字已存在而省略“等待确认”“已更正”“本场已结束”等关键状态。

### 9.2 语音

- 只有用户明确选择自动声音或点按播放后，才可能消费短文本计划；
- 每一次播放都可被静音、停止、模式切换、事实失效和结束打断；
- 语音不包含唯一事实、唯一控制结果或无法在文字中获得的信息；
- 语音失败时，计划降级为文字，不放大角色动作作为替代。

### 9.3 角色与舞台

- 只增强一次有限状态或氛围，不承担事实、确认、错误、控制或关系承诺；
- 低动态时收敛为静态、极轻微状态或完全隐藏；
- “等待确认”“已更正”“安静”“结束”必须先有文字和控件，角色状态只是可选装饰；
- 舞台无法加载时，Agent 不重试制造戏剧性，不降低用户完成任务的能力。

### 9.4 多模态一致性图

~~~mermaid
flowchart TD
    P["一份回应计划"] --> T["文字<br/>完整、必需"]
    P --> A{"声音资格？"}
    P --> V{"舞台资格？"}
    A -->|"用户许可且仍有效"| A1["短声音 / 点按播放"]
    A -->|"不满足"| T
    V -->|"可用且非低动态"| V1["有限表情或姿态"]
    V -->|"不满足"| T
    T --> U["用户理解事实、状态与控制"]
    A1 --> U
    V1 --> U
~~~

## 10. 与导演台的边界：发布事实，不操纵角色

导演台维护公共赛事事实和全局安全上限；Agent 维护当前用户会话内可见、可说、可播放和可停止的结果。两者不共享“替用户决定体验”的权力。

### 10.1 可接受的数据方向

~~~mermaid
flowchart LR
    S["受限来源与人工复核"] --> F["已发布事实 / 更正 / 撤回"]
    F --> G["当前会话的可见资格"]
    O["导演台安全上限"] --> G
    U["用户控制、进度与许可"] --> G
    G --> A["Agent 回应计划"]
    A --> C["文字、声音、舞台或沉默"]
    C --> U
~~~

### 10.2 导演台不能做什么

- 不能要求 Agent 对某个用户提高主动密度、亲密表达、提醒频次或回访压力；
- 不能让未发布候选直接进入 Agent 的生成上下文；
- 不能读取、拼接或转用用户私人对话、记忆、原始声音和用户观察；
- 不能让自动配置越过用户的安静、仅文字、严格保护、低动态或结束；
- 不能用“安全”名义把运营人员的内部争论、情绪或营销目标推给用户。

### 10.3 更正的端到端规则

当导演台发布更正或撤回时，Agent 必须：

1. 使引用旧事实的待播声音、字幕、表演与长解释失效；
2. 不把旧事件留作下次对话的共同经历、玩笑或回顾素材；
3. 只在当前用户有资格且需要理解时，展示最小更正说明；
4. 保留“查看事实详情”“保持安静”“结束本场”等用户路径；
5. 不要求用户相信角色，也不以热闹新内容转移对更正的注意。

## 11. 失败、降级与恢复

Agent 的正确失败不是“尽量继续像正常聊天”。任何关键输入不可靠或媒介不可用时，应收缩到仍能保护用户的最小体验。

### 11.1 降级层级

**层级一：完整但克制**

- 事实、文字、用户主动提问和控制可用；
- 声音和舞台按用户选择呈现；
- 主动性仍受预算和资格限制。

**层级二：结构化回退**

- 声音、舞台或部分自动呈现不可用；
- 事实状态、文字、控制、退出和可选详情完整；
- 不以大型动画补偿声音或舞台。

**层级三：保守状态**

- 事实来源冲突、会话恢复中、导演台暂停、用户进度不明或系统局部故障；
- 只显示可理解状态、已知快照、重试、安静、仅文字和结束；
- 不产生角色主动内容或未经确认解释。

**层级四：安全收束**

- 用户结束、权限撤回、删除、严重风险或场次关闭；
- 停止相关输入、生成、合成、播放和自动呈现；
- 提供最小结果与退出/支持，不延续关系化互动。

### 11.2 恢复纪律

恢复并不等于回到旧计划。网络、设备、事实、用户控制和场次状态都可能已变化。恢复时必须：

- 重新读取当前会话范围、控制、事实快照和安全上限；
- 默认保持文字和静态状态，语音不自动续播，麦克风不自动开启；
- 丢弃过期回答、过期动作和已撤回的事实引用；
- 让用户自己决定是否恢复主动互动；
- 对无法恢复的能力给出简短说明和替代路径。

## 12. 用户端如何看见 Agent 的决策

用户不需要理解内部的“Agent、模型、版本或编排”，但必须看得懂每次影响自己的结果。页面设计应把复杂裁决翻译成短、稳定、可行动的状态。

**进入与模式选择**

- 用户看见“本场先这样看”，而不是“给 Agent 配置人格”；
- 选择安静、仅文字、低动态后，用户知道结果会在本场立即生效；
- 用户可先进入最小模式，不需要授权长期记忆或声音。

**比赛房间**

- 用户看见比分/阶段、事实状态、当前模式和控制入口；
- 待确认时看见“暂不作结论”，不是角色紧张表情；
- 用户沉默时，入口保持可用，但不产生“她在等你”的提醒。

**对话与语音**

- 用户看见事实、观点、控制和共情的不同边界；
- 用户按下停止时，看见“已停止”而不是还在转动的角色；
- 用户关闭声音后，字幕和文字仍完整。

**控制、故障与结束**

- 用户看见动作后的直接结果，例如“已改为仅文字”；
- 故障时看见哪些内容延迟、哪些仍可用；
- 结束后看见“本场陪看已结束”，不需要安抚角色或继续互动。

**偏好与资料**

- 用户只能看到并控制自己主动保存的内容；
- 删除、暂停、关闭提醒使 Agent 的未来输入失效；
- 产品不把资料页写成“我们的关系档案”。

## 13. 从产品裁决到工程合同

本篇交给工程的不是“做一个 Agent”，而是下列不可省略的产品合同：

- 工程必须在生成前形成结构化回应计划；模型不能直接决定事实、控制或呈现媒介；
- 工程必须在播放或呈现前再次核验控制、会话、事实和安全版本；
- 工程必须让停止、结束、更正、撤回、严格保护、删除和导演台暂停使旧工作失效；
- 工程必须将文本保留为完整回退路径，声音和舞台只能作为可选呈现；
- 工程必须把用户观察、导演台候选、私人资料和公开事实放在不同输入域；
- 工程必须记录最小、去敏、可审计的决策线索，而不保存不必要的原始内容；
- 工程必须能够用反例证明：没有权限时 Agent 不说、事实不足时 Agent 不猜、用户停止后 Agent 不补播。

### 13.1 Trace 合同：能够回放一次产品决策

每次 run 至少产生一条可关联但最小化的 Trace。Trace 用于定位用户可见结果的责任链，不用于建立隐式用户画像。

| 事件 | 必填字段 | 说明 |
| --- | --- | --- |
| `run.started/ended` | `trace_id`、`run_id`、触发类型、终止原因、开始/结束时间、版本 | 一次 run 的边界和耗时 |
| `qualification.checked` | 会话状态、控制版本、事实版本、授权版本、结果 | 记录为何允许或拒绝 |
| `model.called` | 模型版本、输入范围摘要、输出类型、耗时、token/费用 | 不保存无必要原文 |
| `tool.called/completed` | 工具版本、参数摘要、结果状态、重试次数、幂等键 | 可判断是否产生副作用 |
| `guardrail.checked` | 检查边界、规则版本、命中结果、处置 | 区分输入/工具/输出/人工暂停 |
| `presentation.changed` | 媒介、计划版本、控制版本、呈现/抑制原因 | 能解释为何播放或未播放 |
| `approval.decided` | 审批类型、责任主体、决定、时间、恢复状态 | 不记录与任务无关的私人内容 |

Trace 必须支持按 `run_id` 还原“触发 → 资格 → 工具 → 输出 → 终止”的顺序；缺少任一关键事件时，该能力只能保留在人工复核范围内，不能扩大自动化。

后续工程交接材料负责把这些产品合同翻译为回合状态机、输入合同、生成门禁、语音取消、协议、评测和故障演练。工程实现不得重新决定“角色可以读什么”“用户何时被打扰”“导演台能否定向控制用户”这些产品问题。

~~~mermaid

    P["产品设计<br/>本篇：允许什么、谁优先、用户看见什么"] --> C["工程交接<br/>怎样实现、取消、验证"]
    C --> E["Evals 与故障演练"]
    E --> R{"发现越界或误解？"}
    R -->|"是"| P
    R -->|"否"| G["受控扩大或维持范围"]
~~~

## 14. 产品评审与放行问题

以下问题无法给出明确答案时，Agent 能力不得扩大：

1. 用户是否能在不理解角色或模型的情况下，解释“它为什么此刻说话或保持沉默”？
2. 用户说“安静”“仅文字”“结束”后，所有正在生成、播放和表演的旧结果是否都失效？
3. 待确认、冲突、更正和撤回是否能让 Agent 诚实收缩，而不是换一种语气继续猜？
4. 仅看文字、关闭角色、拒绝麦克风、弱网或共享设备时，核心任务与退出是否仍完整？
5. 用户的偏好、记忆和反馈是否只在明确授权范围内进入后续回合，暂停/删除后是否立即失效？
6. 导演台是否只能发布公共事实和安全上限，而无法看到私人内容或定向影响某个用户？
7. 角色是否始终无法要求用户照顾它、延长互动、接受关系承诺或相信未经确认的结论？
8. 当系统无法证明一个主动行为有必要时，是否会选择沉默，而不是生成更克制的打扰？

## 15. 完成标准与后续交接

本篇完成不以“角色回复更自然”判断，而以以下条件判断：

- [ ] 所有 Agent 输入都能说明来源、范围、用户授权与失效条件；
- [ ] 控制、事实、风险、运营暂停、用户请求和主动表达拥有明确的优先级；
- [ ] “沉默”“等待确认”“仅文字”“停止”“结束”“已更正”都被视为正常、可见的产品结果；
- [ ] 文本、语音、字幕、舞台不再各自决定事实与控制，而消费同一回应计划；
- [ ] 导演台和用户端之间只有最小、已发布、可解释的结果交换；
- [ ] 产品已把需要工程实现的版本失效、输入隔离、呈现门禁和反例验证交给工程交接材料；
- [ ] 产品评测可基于本篇定义的用户可见承诺，而非用模型流畅度或互动量替代证据。

下一步由 [43-原型验证设计](./43-原型验证设计.md) 将用户端与导演台的可见结果做成可串联的 Stitch 原型；由 [44-关键技术POC与方案选型](./44-关键技术POC与方案选型.md) 验证高不确定链路；由 [45-产品评测体系设计](./45-产品评测体系设计.md) 评估用户能否理解、控制、拒绝和退出。

## 生产版本设计拓展｜能力深化知识

本节描述产品成熟后的能力扩展、体验深化和治理要求，作为后续版本规划与设计决策的参考。

### 生产实现目标与组件责任

生产版本的“实现”是可审阅的产品运行蓝图：它规定组件如何协作、哪些数据可以流动、什么时候能产生用户可见结果，以及失败时回到哪里。它不把任何外围服务包装成第二个 Agent。

| 组件 | 负责什么 | 不得负责什么 | 输入/输出边界 |
| --- | --- | --- | --- |
| 数字球友 Agent | 理解触发、选择任务类型、编排受控工具、形成回应计划 | 写公共事实、扩大权限、决定用户关系或绕过终态 | 读取资格裁决后的最小上下文，输出结构化计划 |
| 资格裁决器 | 合并事实、用户控制、授权、进度、媒介、风险和预算 | 生成角色话术或替用户确认动作 | 输出 `allow / suppress / wait / require_approval` 及原因 |
| 事实服务 | 提供版本化事实、来源状态、更正和撤回链 | 直接向用户播报或接受模型改写事实 | 只读快照，带 `fact_version` 和可见范围 |
| 资料服务 | 管理用户主动保存的偏好、笔记和授权版本 | 自动把模型推断写成长期记忆 | 按字段许可、作用域、有效期读写 |
| 提醒调度器 | 按订阅、时间窗和幂等键排队、发送、取消 | 自行扩大赛事范围或触达频率 | 输出调度状态、发送回执和撤回句柄 |
| 媒介适配器 | 将回应计划转换为文字、字幕、语音和舞台表现 | 添加事实、改变控制或恢复旧计划 | 只消费带版本的 `presentation_plan` |
| 导演台/人工支持 | 发布公共事实、收紧策略、审批高风险动作、暂停版本 | 查看无关私人内容或定向操纵用户 | 只接收最小审计上下文，操作可追责 |

### 生产 manifest 与版本锁定

每次生产 run 在启动时锁定以下版本；版本变化不会静默影响正在执行的 run。

| 版本对象 | 锁定内容 | 变化影响 | 处理方式 |
| --- | --- | --- | --- |
| `agent_manifest_version` | 身份、职责、触发、工具白名单、输出类型 | 改变 Agent 行为边界 | 新 run 才可使用；旧 run 完成前沿用旧合同或取消 |
| `policy_version` | 事实资格、主动性、内容安全、关系边界 | 改变允许/禁止结果 | 只允许收紧热更新；放宽需灰度和评测 |
| `tool_contract_version` | 输入/输出/错误、副作用和撤销 | 影响调用兼容性和责任 | 兼容转换或拒绝旧请求，不自动猜字段 |
| `fact_version` | 事实快照、来源状态、更正指向 | 影响事实和所有媒介 | 旧计划立即失效，按更正链处理 |
| `control_version` | 四维控制、暂停、结束和用户许可 | 影响呈现资格 | 版本递增使排队计划、缓存和播放取消 |

### 生产 run 生命周期

一次 run 由一个触发产生，使用有限预算完成一项任务。运行时按以下顺序执行，不允许跳过资格或输出门：

```text
触发接收
  → 身份/会话校验
  → 读取当前控制与授权
  → 读取最小事实快照
  → 资格裁决
  → Agent 选择任务类型和工具
  → 工具调用/审批（如需要）
  → 校验工具结果与事实版本
  → 形成回应计划
  → 输出护栏与媒介资格复核
  → 呈现或保持沉默
  → 写入最小 Trace
  → 完成、取消、失败或等待恢复
```

| 状态 | 进入条件 | 系统动作 | 用户可见结果 | 终止/转移 |
| --- | --- | --- | --- | --- |
| `received` | 触发消息通过格式校验 | 建立 `run_id`，冻结触发范围 | 必要时显示处理中 | `qualifying` 或拒绝 |
| `qualifying` | 会话仍有效 | 检查控制、事实、授权、风险和预算 | 不显示候选事实 | 通过、等待、抑制或失败 |
| `planning` | 资格通过 | 选择输出类型和最小工具链 | 不播放、不执行副作用 | `waiting_approval`、`executing` 或 `presenting` |
| `waiting_approval` | 工具风险或用户确认要求 | 保存可恢复快照，不执行动作 | 显示范围、影响、批准/取消 | 批准、拒绝、超时、取消 |
| `executing` | 工具合同和权限均通过 | 按预算调用并校验结果 | 显示必要进度和取消 | 完成、失败、未知效果 |
| `presenting` | 计划和媒介资格再次通过 | 生成/播放/渲染，并监听控制版本 | 显示结果与停止入口 | 完成、打断、版本失效 |
| `completed` | 结果已交付 | 关闭 run，写最小 Trace | 可见完成状态 | 终态 |
| `cancelled` | 用户停止、结束、删除、撤回或新版本覆盖 | 取消队列、重试和播放 | 已停止/已结束，不补播 | 终态 |
| `failed` | 工具、模型、网络、权限或预算失败 | 选择回退或人工入口 | 原因、当前可用能力、下一步 | 重试、求助或终态 |

统一终止原因：`completed`、`user_cancelled`、`session_ended`、`permission_revoked`、`fact_invalidated`、`safety_blocked`、`approval_rejected`、`approval_timeout`、`tool_timeout`、`tool_error`、`unknown_effect`、`budget_exceeded`、`provider_unavailable`、`stale_plan`。涉及外部副作用的 `unknown_effect` 不得自动重试。

### 生产 run 上下文合同

| 字段 | 来源 | 是否进入模型上下文 | 规则 |
| --- | --- | --- | --- |
| `run_id / trace_id` | 运行时 | 仅以任务标识摘要提供 | 用于关联，不承载私人原文 |
| `trigger` | 用户动作/已发布事件 | 是 | 标明用户主动、控制或许可主动 |
| `session_state` | 会话服务 | 是 | 结束、暂停和共享设备状态不可省略 |
| `control_snapshot` | 用户设置 | 是 | 带 `control_version`，新版本使旧计划失效 |
| `fact_snapshot` | 事实服务 | 是 | 只含获准范围，带事实状态和版本 |
| `authorization` | 权利服务 | 仅提供 allow/deny 和范围 | 原始令牌只留在运行时私有上下文 |
| `memory_projection` | 资料服务 | 仅提供匹配且有效字段 | 不把完整资料库或推断画像交给模型 |
| `budget` | 运行时 | 只提供剩余额度摘要 | 触底立即收缩，不继续循环 |
| `tool_clients / secrets` | 运行时 | 否 | 模型不能读取令牌、连接串和内部端点 |

### 五类生产 run 的端到端实现卡

#### 1. 自动事实 run

| 项目 | 设计 |
| --- | --- |
| 触发 | 用户订阅的事件达到发布窗口，或用户打开当前比赛页 |
| 前置 | 事实已确认、用户进度允许、赛事范围匹配、自动发布许可有效 |
| Agent 行为 | 调用 `fact.read`，选择事实卡或短解释，不调用资料写入和外部动作 |
| 用户结果 | 显示事实状态、发生时间、来源时间、可展开解释和关闭自动发布入口 |
| 不允许 | 候选/冲突事实发布、根据模型置信度猜测、超出进度的结果暗示 |
| 更正 | 新版本广播后取消旧文字、字幕、语音和舞台计划；必要时显示“之前内容已更正” |
| 失败 | 返回等待/暂不可用状态，保留用户主动刷新；不以角色反应填补空白 |
| Trace | 事实版本、资格结果、可见范围、呈现计划版本、终止原因 |

#### 2. 提醒 run

| 项目 | 设计 |
| --- | --- |
| 触发 | 订阅事件、时间窗和赛事状态同时满足 |
| 前置 | 本人授权、订阅未取消、未进入安静时段、事实版本仍有效、频率预算未超 |
| Agent 行为 | 生成最小通知内容；调度器负责时间和回执，不由 Agent 自行重试发送 |
| 用户结果 | 通知说明赛事范围、触发原因、时间和管理/取消入口 |
| 失败 | 发送失败按订阅规则有限重试；超窗转站内状态；不升级频率 |
| 取消 | `reminder.cancelled` 先于队列消费；迟到消息按幂等键拒绝 |
| Trace | 订阅版本、时间窗、幂等键、发送回执、取消时间和终止原因 |

#### 3. 连续性 run

| 项目 | 设计 |
| --- | --- |
| 触发 | 用户进入比赛或主动请求“按我保存的设置继续” |
| 前置 | 身份确认、资料未过期、用途匹配、未暂停/删除、共享设备检查通过 |
| Agent 行为 | 读取资料投影，仅影响解释长度、媒介和关注范围等服务参数 |
| 用户结果 | 进入卡显示召回来源、更新时间、作用范围，并允许本场覆盖或不再使用 |
| 不允许 | 读取完整历史、推断关系、把生成内容自动写回长期资料 |
| 失败 | 身份不明或资料冲突时回到基础设置，不展示猜测内容 |
| 删除 | 删除屏障先阻断读取，再清理缓存、索引、队列和跨设备副本 |
| Trace | 资料 ID、授权版本、字段范围、召回结果、删除状态和终止原因 |

#### 4. 工具动作 run

| 项目 | 设计 |
| --- | --- |
| 触发 | 用户明确提出外部动作并进入确认页 |
| 前置 | 动作对象、范围、影响、风险、授权和撤销方式均可解释 |
| Agent 行为 | 调用工具前展示动作预览；高风险动作进入审批；确认后使用幂等键执行 |
| 用户结果 | 显示待确认、执行中、已完成、部分完成或未知效果及下一步 |
| 不允许 | 未确认执行、效果未知时自动重试、把建议误当成动作 |
| 失败 | 明确“未执行/部分执行/状态未知”；可查询状态或转人工，不隐瞒副作用 |
| 撤销 | 在撤销窗口内调用 `external_action.revoke`；不可撤销动作在确认前明确告知 |
| Trace | 动作合同版本、授权、审批、幂等键、效果状态、撤销句柄和责任主体 |

#### 5. 异常收束 run

| 触发 | 预算耗尽、事实冲突、权限撤回、供应商不可用、控制变化、风险命中或会话结束 |
| --- | --- |
| 立即动作 | 递增控制/事实版本，取消低优先级队列、重试、音频和舞台；冻结可能产生副作用的调用 |
| 用户结果 | 返回当前可信状态、发生了什么、仍可用能力、重试/求助/结束入口 |
| 恢复条件 | 重新读取会话、控制、授权、事实和供应商健康状态；不恢复旧计划 |
| 禁止行为 | 继续生成“安慰性”内容、补播过期事实、用更强表演掩盖错误 |

### 生产失败、回滚与责任矩阵

| 故障 | 自动处置 | 用户可见结果 | 责任人/恢复门 |
| --- | --- | --- | --- |
| 事实冲突或撤回 | 暂停自动发布，失效所有媒介计划 | 等待核对、当前可确认状态、结束入口 | 事实负责人确认版本后灰度恢复 |
| 提醒误发/重复 | 取消同类队列，冻结订阅版本 | 说明已停止，可管理订阅 | 运营负责人复盘并批准恢复 |
| 删除传播失败 | 保持删除屏障，阻断读取和回写 | 显示处理中及例外范围 | 隐私负责人确认副本清理 |
| 工具效果未知 | 禁止重试，查询幂等状态或人工接管 | 明确状态未知，不承诺完成 | 动作负责人核验并补偿/撤销 |
| 模型/供应商异常 | 熔断增强媒介或高风险工具 | 回退结构化事实和手动路径 | 值班负责人观察窗口后灰度 |
| 控制/会话变化 | 立即取消旧 run 和排队呈现 | 已静音/已结束/已取消 | 系统自动完成，无需用户解释 |

### 生产发布、灰度与回滚

1. **候选**：为 manifest、policy、tool、事实策略和媒介资产生成版本差异，绑定 `dataset_version` 与评测结果。
2. **隔离验证**：在合成赛事、乱序消息、冲突事实、删除和供应商故障场景中回放，不接触无关私人资料。
3. **小范围灰度**：按赛事、设备、媒介和用户授权范围逐级扩大；每级都有自动事实、提醒、控制和退出硬门。
4. **自动收缩**：命中误剧透、未授权副作用、取消后触达、删除后再出现或无法退出任一硬门时，关闭对应版本并回退上一稳定版本。
5. **恢复**：恢复前重新验证事实快照、控制版本、队列清理、供应商健康和人工值守；不得恢复已取消的 run。
6. **复盘**：记录变更 diff、影响范围、用户可见修复、Trace、决定人和再次放行条件。

### 生产验收清单

- [ ] 任意 run 都能从触发追到资格、工具、呈现和终止原因；
- [ ] 任意控制、删除、撤回或事实更正都能使旧计划失效；
- [ ] 自动事实、提醒、资料和外部动作都有独立授权、幂等和失败语义；
- [ ] 语音或舞台作为主出口时，关键事实、控制、错误和退出仍有等价可达路径；
- [ ] 预算、重试、延迟和供应商失败会触发可见收缩，而不是无限循环；
- [ ] 生产变更可比较、可灰度、可暂停、可回滚，并关联评测数据集版本；
- [ ] Trace 不包含无关私人原文、原始音频或隐式关系标签。

run 之间不共享隐式人格状态；新的 run 必须重新读取当前控制、事实和授权。上述生产蓝图与 [41-领域数据模型设计](./41-领域数据模型设计.md)、[42-API与实时协议设计](./42-API与实时协议设计.md)、[45-产品评测体系设计](./45-产品评测体系设计.md) 的字段合同共同构成后续工程、测试和运营的交接入口。
