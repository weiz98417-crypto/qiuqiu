# 球球直播课全功能清单与演示脚本

> 适用版本：`fix/project-audit-small-issues` 分支当前版本  
> 用户端：`http://127.0.0.1:8080/`  
> 导演台：`http://127.0.0.1:8080/operator.html#setup`  
> 推荐演示时长：完整场 25～30 分钟；精简场 8～10 分钟

## 1. 一句话定位

球球不是一个“会播报比分的 Live2D 皮套”，而是一套面向足球直播陪看的数字人系统：导演或外部数据源负责提供可信比赛事实，球球负责理解用户、结合比赛上下文生成自然回应，再用 Live2D 表情动作、字幕和“冰糖”语音把回应演出来。

可以用下面这条链路概括整个项目：

```text
赛前名单 / 人工导演 / 外部数据源
              ↓
       比赛事实账本与主时钟
              ↓
       球球 Agent + 关系记忆
              ↓
   MiMo 对话与自然语言语音表演
              ↓
 Live2D 动作 + 字幕 + 冰糖音色 + 用户追问
```

## 2. 演示标记

- **主线演示**：本地环境稳定，建议直播中实际操作。
- **可选演示**：已实现，但受麦克风、浏览器权限、网络或外部服务影响。
- **口头介绍**：已实现的后台能力，现场不必为了“点全”而拖慢节奏。
- **工程保障**：测试、可靠性、安全和隐私能力，适合最后总结或答疑。

## 3. 球球全部已实现功能

### 3.1 用户端：比赛陪看界面

#### 比赛信息

- 展示主队、客队和实时比分。
- 展示比赛阶段：赛前、上半场、中场、下半场、加时、完场。
- 展示后端主时钟，客户端在两个同步点之间平滑推进。
- 展示近期比赛事件，并以轮播方式保留最近发生了什么。
- WebSocket 实时接收比分、时钟、事实修订和球球回应。
- 断线时保留当前比赛画面和字幕，并显示正在重连或暂时离线。
- 重连后恢复当前比赛状态，而不是从旧的本地比分继续猜。

#### Live2D 数字人

- 加载并显示 Live2D 球球模型。
- 支持待机、倾听、专注、说话、思考、欢迎、庆祝等动作。
- 支持 `idle`、`listening`、`focus`、`thinking`、`confused`、`excited`、`chat`、`tease`、`happy`、`nervous`、`sad`、`surprised`、`angry` 等表情状态。
- 球球说话时切换口型/说话状态，播放结束后回落到合适的静态状态。
- 比赛事件可驱动庆祝、紧张、惊讶、安慰、分析等动作。
- 模型加载失败时显示可理解的错误状态，并允许重试。
- 首次见面可触发欢迎动作；欢迎成功展示后不会每次刷新都重复。

#### 对话输入

- 连续语音对话：开启后可以直接说，不必每次按按钮。
- 按住说话：关闭连续对话后，仍可按住麦克风讲话。
- VAD 语音活动检测：区分用户开始说话、自然停顿和说完。
- 流式 ASR：边说边上传音频，接收部分转写和最终转写。
- 对自然停顿做容忍，不会在一句话中间过早截断。
- 对环境噪声做抑制，并兼顾轻声说话。
- 用户开口时可以打断球球正在播放的主动语音。
- 文字输入兜底：麦克风不可用、ASR 失败或直播环境太吵时仍能继续对话。
- ASR 失败后保留已有文字，不把用户已经输入的内容清空。

#### 麦克风与音频设备

- 默认使用系统麦克风。
- 可读取并选择外接麦克风。
- 外接设备拔出后自动回退到系统默认设备。
- 处理设备快速切换时的旧请求竞态，避免旧麦克风重新抢占。
- 麦克风权限被拒绝时给出明确提示，并提示用户改用文字输入。
- 浏览器自动播放被阻止时保留字幕，用户点击后可恢复声音播放。

#### 球球输出

- 字幕与语音同步输出。
- 字幕可拆为主句和补充句，避免一大段文字同时压在画面上。
- TTS 失败时仍保留字幕和文字回答。
- 音频播放失败时提示“声音暂时没出来”，不影响继续聊天。
- 支持比赛主动播报，也支持对用户问题的被动回答。
- 用户正在说话、回答生成中或音频播放中时，比赛事件按优先级排队。

#### 陪看偏好

- 设置昵称，球球可按用户希望的方式称呼。
- 设置话痨程度：安静、刚好、热闹。
- 开启或关闭连续对话。
- 开启或关闭字幕。
- 开启或关闭声音。
- 字幕和声音不能同时关闭，确保始终至少保留一种输出。
- 设置支持球队：利物浦、切尔西或中立看球。
- 偏好保存在本地，下次打开继续使用。

#### 可用性与无障碍

- 麦克风、发送、设置、连接状态等控件提供语义标签或提示。
- 显示连接中、已连接、离线、聆听、思考、说话等状态。
- 网络、麦克风、ASR、TTS 任一环节失败时都提供降级路径。

### 3.2 球球 Agent：理解、事实和连续追问

#### 已支持的意图类型

- 普通闲聊。
- 赛程问题。
- 当前比赛状态。
- 最近比赛事件。
- 比赛事件主动反应。
- 基于上一轮的连续追问。
- 球员相关问题。
- 情绪反应。
- 用户个人分享。
- 控制命令。
- 用户对比赛事实的声称。
- 无法归类的未知输入。

#### 比赛问答

- 回答当前比分、比赛双方和比赛阶段。
- 回答当前比赛时间。
- 回答最近发生了什么。
- 回答进球者、助攻者、策动者等参与角色。
- 回答某位球员是否有相关事件。
- 根据上一轮上下文理解“那谁策动的？”这类省略主语的追问。
- 支持今天、明天、当前或附近赛程查询。
- 赛程查询按用户时区解释“今天”和“明天”。
- 查询需要等待时，先自然说明“我帮你看看”，再返回结果。

#### 事实保护

- 回答比赛事实时读取事实账本，不让大模型凭语言习惯猜比分。
- 用户说错比分时会用当前可信事实纠正。
- 用户说错进球球队或进球者时会指出不一致。
- 没有证据时保持“暂未确认”，不会顺着用户编造。
- 能区分“德国 3 比 0 了”和“要是德国 3 比 0 就好了”。
- 玩笑、假设、情绪表达不会被误写进公共比赛事实。
- 外部源和人工事实冲突时保持不确定，不抢先猜结果。
- 用户看到的直播比公共源更快时，可建立仅属于该用户的“待确认观察”。
- 导演确认或撤销后，只向相关用户跟进，不打扰其他人。
- 用户离线后，未完成的确认结果可在重连后恢复；展示成功后不重复播报。

#### 主动互动调度

- 比赛事件可以触发球球主动开口。
- 普通事件遵守冷却时间，避免球球太吵。
- 进球、红牌、点球、VAR、中场、完场等关键事件可绕过普通冷却。
- 用户输入优先于比赛主动线。
- 用户一开口，球球可停止或让出当前主动播报。
- 用户回答生成和播放期间，后续比赛事件排队。
- 新的关键事实可刷新一次尚未播放完的用户回答。
- 当前音频完成后再释放下一条语音，避免多段声音重叠。

### 3.3 球球的人格、关系和情绪

- 区分首次见面、逐渐熟悉等关系阶段。
- 维护熟悉度、信任和是否允许调侃等关系状态。
- 记住共同看过的重要瞬间。
- 记住未聊完的话题，方便后续自然接续。
- 记住用户表达过的边界，不在后续继续冒犯。
- 支持关系修复：出现不合适表达后主动收敛。
- 支持主动沉默，不要求每个事件都必须说话。
- 记住称呼、仪式、口味、调侃证据等关系记忆。
- 情绪不是单轮贴标签，而是会随赛况和对话连续变化。
- 防止连续几轮使用相同句式。
- 防止关系尚浅时表现得过度熟悉。
- 没有许可时不随意调侃用户。
- 人格表达不能覆盖事实约束，不能为了“像真人”而编造比赛。

### 3.4 MiMo 对话与“冰糖”语音

- 对话生成使用 MiMo。
- 当前语音合成使用 `mimo-v2.5-tts`。
- 默认音色为“冰糖”。
- 客户端播放器速度保持 `1.0`，不通过机械倍速改变语速。
- 服务端根据球球的表现计划生成自然语言 TTS 指令。
- 语音指令可表达自然口语、非播音腔、轻柔、温暖、兴奋、紧张、失落等风格。
- 语速由 MiMo 在句内自然变化，而不是整段统一拉快或拉慢。
- 支持自然停顿、重音、句尾回落和情绪能量变化。
- 表现计划同时携带表情、动作、音色风格、能量、语速、保持时间和回落状态。
- TTS 日志记录文本、MIME、字节数和播放结果，但不记录原始音频内容。

> 音色生产的长期标准流程是：`VoiceDesign 设计音色 → 保存满意样音 → VoiceClone 固定音色`。当前产品运行时直接使用已经选定的“冰糖”音色，不需要在每句回复时重新做 VoiceDesign。

### 3.5 导演台：七个工作页面

#### 3.5.1 赛前配置

- 填写比赛 ID、赛事名称、开球时间和场馆。
- 填写主客队名称、阵型、主教练和事实员。
- 批量粘贴双方球员名单。
- 从每一行解析号码、姓名、位置、首发或替补。
- 实时预览首发人数、替补人数和名单内容。
- 主队和客队都必须至少有 11 名首发才能提交新比赛。
- 名单不合格时阻止提交，且不会清空当前比赛。
- 成功“提交至导演台”后开启一场全新比赛。
- 新比赛会重置比分、比赛事件和主时钟，正确初始值是 `0-0 / 赛前 / 00:00`。
- 球队和球员名单写入后端，供事实校验和球员选择使用。
- 场馆、阵型、教练、事实员当前只保存在本机浏览器中。

> 关键区别：事件表单里的 `24:10` 是“这条事件发生在第几分钟”，不是比赛主时钟。提交新比赛后，主时钟仍应是 `00:00`，只有点击开始或调整主时钟后才会推进。

#### 3.5.2 实战导演

比赛控制：

- 只读展示主客队比分，避免直接改数字破坏事实链。
- 只读展示主比赛时钟。
- 开始或暂停主时钟。
- 切换赛前、上半场、中场、下半场、加时和完场。
- 对主时钟执行 `-10 秒` 或 `+10 秒` 微调。
- 显示时钟版本，避免旧操作覆盖新状态。

球员与草稿：

- 在主队和客队之间切换。
- 按号码或姓名搜索球员。
- 区分首发和替补球员。
- 行为按钮只创建草稿，不会因为误点就直接写入事实。
- 根据事件类型显示进球者、助攻者、策动者、门将等角色槽位。
- 设置事件发生时间和强度 1～5。
- 设置候选事实或确认事实。
- 动作可以自动选择，也可以手选庆祝、紧张、分析、惊讶、安慰等表现。
- 球球处理方式可选自动反应、只记事实、人工话术。
- 填写事件描述和球球主动话术。
- 按当前事件搜索话术模板。
- 使用“补一句提醒”快速补全文案。
- 发送前预览上下文和预期比分。
- 一键清空当前草稿或重新加载比赛状态。

支持的事件类型：

- 进球、绝佳机会、射门、扑救、错失。
- 犯规、黄牌、红牌。
- VAR、VAR 结果、进球取消、点球。
- 换人、战术变化、持续压迫、伤停。
- 运营备注、比分更正。

事实工作流：

- 暂存为候选：进入事实时间线，但不改变公开比分，也不主动打扰用户。
- 确认并发送：写入确认事实，刷新公开状态，并按策略触发球球。
- 对候选事实执行确认。
- 对已确认事实执行撤回。
- 对外部源和人工源冲突执行调和。
- 更正操作必须填写原因，保留审计依据。
- 比分更正不是直接改输入框，而是生成一条独立的审计事实。
- 已确认进球可更正为“进球取消”，事实账本重放后比分自动回退。
- VAR 结果和进球取消必须引用正在检查或被修订的原事实。
- 冲突调和要求选择兼容的事实组合，不能盲目覆盖。
- 换人会校验“上场者是替补、下场者是首发”，确认后才真正交换阵容状态。
- 写入接口支持幂等，重复点击不会重复产生相同事实。

导演语音录入：

- 读取并选择导演麦克风。
- 开始/停止录音并获得转写。
- 从“德国换人，菲尔克鲁格换下哈弗茨”这类自然口述中提取草稿字段。
- 转写文本可直接手工修改。
- 语音值和现有草稿冲突时，逐项选择保留原值或采用语音值。
- 对异常字段逐项确认警告。
- 可撤回本次语音带来的所有草稿修改。
- 语音只补全草稿，绝不会绕过导演确认直接发布比赛事实。

#### 3.5.3 信号源

- 人工导演源默认可用，并始终允许接管。
- 人工录入延迟可设置为快速 5～10 秒、正常 10～20 秒、保守 20～40 秒。
- 支持回放数据源，用于联调和课堂演示。
- 支持 API-Sports 外部赛事源。
- 通过 Fixture ID 启用 API-Sports。
- 可选择是否导入启用前的历史事件；默认不导入旧事件。
- 展示当前使用的数据源。
- 展示当前轮询延迟、近 5 分钟 P95、最近轮询时间、最近事件和重连次数。
- 外部事件按供应商事件 ID 去重。
- 轮询游标可恢复，重连后避免重复扫入旧事件。
- “人工接管并暂停自动播报”会停止外部源并暂停自动主动线。
- 人工接管后，导演手写话术仍可发布。

#### 3.5.4 自动化策略

- 开启或暂停自动播报。
- 选择哪些事件允许球球主动互动。
- 可配置开球、进球、射门、绝佳机会、扑救、错失、犯规、黄牌、红牌、VAR、点球、换人、伤停、战术变化、持续压迫、中场、完场等范围。
- 普通事件冷却时间可设置为 0～300 秒。
- 关键事件绕过普通冷却，但不会打断用户正在说话。
- 清晰展示用户输入优先、事件排队、关键事实刷新和音频串行播放四级规则。
- 展示当前策略摘要。

#### 3.5.5 实时监控

- 查看后端健康状态。
- 查看比赛数据源状态。
- 查看自动播报状态。
- 查看当前比赛状态。
- 查看最近比赛事件。
- 查看最近语音链路及播放结果。
- 支持立即刷新。
- 可按 5 秒、10 秒或 30 秒自动刷新，也可以关闭自动刷新。

#### 3.5.6 球球日志

- 按全部、缺失事实、用户问题、主动线、错误筛选日志。
- 查看当前比赛记忆快照和最近可用事件。
- 查看每轮输入、识别意图、最终输出、决策原因和耗时。
- 查看本轮工具调用和检索到的比赛事件 ID。
- 查看用户比赛事实声称及其核验状态。
- 查看关系阶段、关系动作和本轮使用的关系记忆。
- 查看 ASR/TTS 状态、合成文本、MIME、音频字节数和播放结果。
- 复制事件 ID，方便定位事实链。
- 查看原始 Trace 供开发排查。
- 日志不展示 API Key、Authorization 或用户原始音频。

#### 3.5.7 工作台设置

- 设置实时监控自动刷新间隔：关闭、5 秒、10 秒、30 秒。
- 设置默认事件发布方式：按自动化策略或只记事实。
- 偏好只保存在当前浏览器。
- 展示当前导演权限状态。
- 快速跳转实时监控和信号源。
- 浏览器不保存大模型、TTS 或赛事供应商密钥。

### 3.6 后台可信事实链

- 保存比赛配置、双方名单、比赛状态、事件、主时钟、事实修订和冲突。
- 事实支持候选、确认、撤回、调和和更正状态。
- 公开比分和公开事件由事实账本重放生成，而不是由页面直接改数字。
- 校验进球、进球取消、事件顺序和比分投影。
- 检测人工源与外部源之间的冲突。
- 调和后保留来源、理由和修订关系，便于审计。
- PostgreSQL 持久化比赛与会话数据。
- 操作结果和 Outbox 在同一事务中提交，避免事实写成功但消息没发出去。
- WebSocket 可靠同步比赛事实、主时钟和球球输出。
- 抑制重复投递，同时允许事实修订穿过去重逻辑。
- 匿名设备身份，无需注册即可使用。
- 签发短期会话，并支持令牌刷新和撤销。
- 提供用户隐私状态、数据导出和异步删除接口：
  - `GET /api/me/privacy`
  - `GET /api/me/export`
  - `DELETE /api/me/data`
- 导演口令与普通用户会话隔离。
- 执行 Origin/CORS 校验。
- 提供 `/health` 健康检查。

### 3.7 工程与质量保障

- Flutter 客户端可面向 Web、Android 和 iOS。
- Go 后端承载比赛状态、Agent、语音链路和导演接口。
- PostgreSQL 保存持久事实，Redis 支持运行时协调。
- Docker Compose 提供本地一键环境。
- 对比赛事实、冲突、撤回、进球取消、换人校验和时钟做自动测试。
- 对连续追问、错误比分、无证据回答、玩笑/假设和关系边界做回归测试。
- 对导演台关键流程和语音草稿做测试。
- 提供离线、PR、夜间和发布级评测入口。
- 提供黄金集验证球球回答是否忠于事实、是否自然、是否避免重复。

## 4. 当前实现边界：直播中不要讲错

| 容易误解的点 | 当前真实实现 | 直播时推荐说法 |
| --- | --- | --- |
| 赛前提交 | 双方不足 11 名首发会拒绝；成功提交才会清空旧场次 | “只有合法首发才能开启新比赛，失败不会伤到正在进行的比赛。” |
| 提交后的比分和时间 | 必须重置为 `0-0 / 赛前 / 00:00` | “新比赛从零状态开始。” |
| 事件时间 `24:10` | 是事件自己的发生时间，不会把主时钟跳到 24:10 | “主时钟和事实时间分开管理，避免晚录事件篡改当前时间。” |
| 场馆、阵型、教练、事实员 | 当前保存在导演浏览器本机 | “比赛核心球队和名单进入后端；工作台补充信息目前是本机配置。” |
| API-Sports | 功能已接入，但现场需要有效 Fixture ID、密钥和网络 | 主线只展示配置与监控，不在直播中临时连接陌生比赛。 |
| 支持球队 | 当前客户端下拉项为利物浦、切尔西、中立 | 不演示任意球队搜索，按实际选项介绍。 |
| 音色 | 运行时是 `mimo-v2.5-tts` 的“冰糖” | 不说成每句都在跑 VoiceDesign 或 VoiceClone。 |
| 语速 | 由 MiMo 根据自然语言表演指令生成，播放器保持 `1.0` | “不是把录音机械加速，而是让模型按情绪自然说快说慢。” |
| ComfyUI | 当前核心链路不依赖 ComfyUI | “数字人是 Live2D，语音和对话是 MiMo；ComfyUI 不是运行必需。” |
| 语音录入 | 受浏览器麦克风权限和现场噪声影响 | 主线用文字保证稳定，语音作为加分项。 |

## 8. 可选加分演示

### 8.1 用户连续语音

前提：直播场地相对安静，用户端麦克风权限已授权。

1. 在用户端开启“连续对话”。
2. 直接说：`刚才谁助攻？`
3. 等待部分转写和最终转写。
4. 在球球回答到一半时说：`那谁策动的？`
5. 展示用户开口打断球球，再生成新的追问回答。

讲解点：VAD、流式 ASR、自然停顿、用户优先打断和外接麦克风回退。

### 8.2 导演语音生成事件草稿

前提：导演台麦克风权限已授权，语音转写服务正常。

1. 先手工做一个不完整草稿，例如选择德国和换人。
2. 点击“语音录入”。
3. 说：`德国换人，菲尔克鲁格换下哈弗茨。`
4. 停止录音，等待转写和字段提取。
5. 展示转写可编辑。
6. 如果字段冲突，展示“保留原值 / 采用语音值”。
7. 点击“撤回本次语音”，展示草稿恢复。

讲解点：语音只能补草稿，最终发布权仍在导演手中。

### 8.3 换人校验

1. 选择德国和“换人”。
2. 上场球员选替补菲尔克鲁格，下场球员选首发哈弗茨。
3. 暂存候选，说明阵容尚未改变。
4. 确认事实后，展示两人的首发/替补状态交换。
5. 如果把两名首发都填入，展示系统拒绝不合法换人。

### 8.4 人工接管

仅在演示环境没有真实外部源时操作：

1. 信号源先选择“回放数据”。
2. 展示当前源变化。
3. 点击“人工接管并暂停自动播报”。
4. 展示来源回到人工，自动播报变为暂停。
5. 演示结束后重新开启自动播报。

## 11. 直播答疑速查

### 球球用的是哪个 Live2D 开源项目？

项目的浏览器渲染层使用 `pixi-live2d-display` 打包运行，并加载 Live2D Cubism Core 和 Cubism 模型。Live2D 本身负责角色渲染、表情、动作和口型；比赛理解、对话和语音由项目自己的后端与 MiMo 完成。它不是用 ComfyUI 在运行时逐帧生成视频。

### 为什么不用 ComfyUI？

ComfyUI 更适合图像/视频生成工作流。球球要求低延迟、连续动作、口型和可控状态切换，Live2D 更适合实时客户端数字人。ComfyUI 可以用于前期素材创作，但不是当前直播陪看链路的必需组件。

### 语音为什么比以前自然？

当前使用 `mimo-v2.5-tts` 的“冰糖”音色。速度、能量、停顿和情绪由服务端用自然语言告诉 MiMo 如何表演，客户端保持 1.0 倍速，所以不是简单把音频拉快或拉慢。

### VoiceDesign、VoiceClone 和普通 TTS 怎么分工？

- VoiceDesign：先用文字描述设计目标音色，快速得到候选声音。
- 保存样音：选出满意的一条，作为标准声音资产。
- VoiceClone：用标准样音固定出稳定的专属声音。
- 普通 `mimo-v2.5-tts`：产品运行时按固定音色和表演指令持续合成每一句话。

### 为什么导演不能直接改比分？

直接改数字无法解释“为什么从 1-0 变成 0-0”。球球把进球、取消、更正和撤回都作为事实保存，再重放事实生成比分，因此每次变化都有来源和理由。

### 用户比导演更早看到进球怎么办？

用户的话先成为个人待确认观察，不直接进入公共比分。导演或可信数据源确认后，系统可以只向这个用户跟进；如果被撤销，也只更正对应用户的预期。

### 断网或模型失败会不会整套不能用？

系统按链路分别降级：断线保留当前比赛画面，ASR 失败可以打字，TTS 失败保留字幕，Live2D 失败仍可展示文字，重连后从后端恢复事实状态。

### 这个项目最重要的技术点是什么？

不是某一个模型，而是三件事协同：可信比赛事实链、能连续理解用户的陪看 Agent、可实时表演的 Live2D 与语音输出。缺少任何一层，都会变成不可靠的比分播报器或没有比赛理解的数字人皮套。
