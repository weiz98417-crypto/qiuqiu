# 02 路线图与产品现状

> 本篇基线：2026-06-07 仓库 a7e5100。

本篇回答两个问题：**产品现在到哪了**（第一至三节），**下一步按什么顺序做什么**（第四至五节）。版本事实以里程碑叙述，不以 CHANGELOG 为版本锚（⚖️B5，见 2.1）；市场、GTM、定价与上市计划已冻结为档案，不在本篇展开（第六节给指针）。

写法纪律：现网行为一律现在时；未实现条目一律标注「规划中（未实现）」并给优先级；模糊时态措辞不用于声明任何现网或计划行为——计划只以「规划中（未实现）」条目形态出现在第四节。

## 1. 产品阶段现状

### 1.1 一句话定位

**核心陪伴闭环已建成，合规与增长层待建。** 一场比赛单元内的完整体验链（赛前提醒 → 语音陪看 → 事实纪律 → 赛后收束 → 记忆治理）在现网运行并有评测与演练实证；面向对外服务的合规能力族（协议文本、AI 披露、防沉迷、语音退出、投诉入口、未成年人保护）与面向运营决策的数据采集面（价值面埋点）尚未建成，构成下一阶段的第一施工优先级。

### 1.2 四面现状判定

| 面 | 现状 | 依据 |
| --- | --- | --- |
| 工程面 | 核心陪伴闭环已建成：九大能力族（语音链路／事实纪律／记忆／关系／情绪舞台／知识库／主动触达／账号隐私／评测治理）全部有现网承载；发布门禁 G1-G7 已实现（评测 12 套件 249 用例、offline 聚合 234 实跑全绿、CI 双 job） | PRD 第一章 1.3、第七章 7.2 |
| 用户面 | 用户研究证据空白：三类痛点是立论假设，访谈／日记／原型研究未开展；工程验证轨道已有承载（评测 249 用例、观测面板） | PRD 1.1.2 立论地位注记；假设台账见规范 38 篇 |
| 合规面 | 不具备对外放量条件：上线就绪检查单 23 项中，P0 未完成 10 项、P1 未完成 8 项（PRD 7.3 结论口径；逐项判定以 PRD 7.3 表为准） | PRD 7.3；《办法》（2026-03-15 施行）CR-01~CR-17 |
| 增长面 | 价值面零采集：北极星候选指标（ECS）与护栏指标主体无埋点承载；运行面（Grafana 6 面板 4 告警、运营台九格）已出数——运行面已出数不等于价值面已验证 | PRD 第六章 6.1/6.2 |

四面判读的两条纪律（沿 PRD 第六章口径）：

- 运行面已出数 ≠ 价值面已验证：Grafana 与九格是工程观测，不构成「产品成立」的证据；「进入成功率/控制成功率/安全边界」三类历史目标文档点名的观测面实有面板未覆盖，计入待建、不计已达成。
- 工程验收通过 ≠ 风险已被降低：评测全绿与演练闭合是工程面事实；用户面风险（依赖、误导、越界）的降低以合规 P0 关闭与用户验证开展为准。

## 2. 版本里程碑叙述

### 2.1 版本锚口径与 CHANGELOG 停更声明

- `VERSION` 文件为 0.2.0.0；`CHANGELOG.md` 最新条目为 `[0.2.0] - 2026-05-20`。05-20 之后约 150+ 提交（其中 05-22 文档定稿后 136 提交）零入册（⚖️B5，双口径如实并记）。
- **本篇与规范全库以里程碑叙述版本，不以 CHANGELOG 为版本锚**；0.3.0 补账（按 2.3 九组）列为工程侧任务，文档不背账。
- 补账同时须决定 VERSION 是否跳 0.3.0，并重启 v2 版本篇 §1.3 的「CHANGELOG 与功能清单对账」工序（该工序自 0.2.0 起停摆）。

### 2.2 已发布里程碑

**0.1.0.0（2026-03-15）——数字人完整体验。** 回答的问题是「数字球友能不能完整陪看一场球」：

- 用户客户端：Live2D 角色、连续语音对话、首见问候、比赛状态轮播、文字降级；
- 导播台：人工比赛事实录入、外部数据源接管、自动化策略、实时监控与决策追踪；
- 事实与关系：比赛事实保护、错误赛况核验、来源冲突处理；跨比赛关系状态、共同瞬间、未完话题、边界与修复、长期偏爱记忆；
- 评测：发布级离线、WebSocket、浏览器与真实 MiMo 语音评测。

同版做了一次诚实的减法：移除未接入生产链路的旧 pipeline engine、cooldown、dedup、priority、throttle 与 watch session 实现——第一个版本同时定义了「什么算做完」和「什么不算数」。该版上线后系统开始随真实比赛运行，内部值守由此开始。

**0.2.0.0（2026-05-20）——结构收敛与体验修复。** 主线是把第一版长歪的地方扳正（ADR-0009~0013）：

- operator.html 组件化进控制台并退役（ADR-0011/0013），28 条导播评测迁至新导播页；
- 意图路由：关键词未命中改经 LLM 语义路由兜底（ADR-0009），RouterTrace 持久化，低置信控制指令一律拒绝；
- 运营台鉴权：JWT 登录与 RBAC（ADR-0010），15 分钟访问令牌+单次轮换刷新令牌；
- 传输统一：五个手写 LLM 客户端收敛到同一 openaicompat 传输（ADR-0012）；
- 表演链路、记忆管道、客户端韧性修复；门禁加厚（100 例评测套件、契约 golden、迁移 lint）。

## 7. 设计说明

1. **波次叙述与 CHANGELOG 的关系**：1.4 波次清单取自仓库提交史（每行有 commit 锚），2.3 九组表取自治理对账并经 PRD 7.1 转正。两表是同一批落地能力的两个视图：波次表回答「按什么节奏建的」，九组表回答「补账时按什么归组写」。CHANGELOG 补账（工程侧）完成后，九组表转正为 0.3.0 已发布条目，波次表保留为工程叙事。

4. **检查单计数口径**：1.2 合规面引用的「10 项 P0 未完成」为 PRD 7.3 结论行的官方口径（逐行数表为 11 项，含备案主体核对 #20——它与 #10 同属备案族，两口径差异随 PRD 下次修订收口，本篇以结论行为准并留此注记）。
5. **在途事项的来源**：第三节全部条目转正自仓库交接档（docs/handoff-20261007.md）的「用户侧待办全集」与治理对账（openspec 记账滞后清单）；交接档后续追加事项由工程侧续写交接档，本篇只在波次收口时吸收。
6. **活页约定**：第四节是本篇唯一设计为「会频繁变动」的节。条目关闭（功能合入+门禁通过+现状回写第一节）即从表中移除；新增条目必须带来源（PRD FR/CR/检查单号）与优先级，无源条目不入表——这是「文档先行」流程下防止愿望清单混入施工清单的闸门。
