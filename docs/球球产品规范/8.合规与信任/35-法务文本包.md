## 2. 用户服务协议（草案）

> **状态：草案（需法务终审）。** 以下条款为框架草案，供法务终审修订；方括号「〔规划中〕」标记的款项依赖未建成能力，终审时须按放量时点的实现状态取舍或调整表述，不得以草案文本声明能力已存在。协议以「球球」（下称「本服务」）运营主体（〔主体名称，法务终审补〕，下称「运营方」）与用户之间订立。

### 第一条 服务定义与 AI 身份告知

1. 本服务是一款以「一场比赛」为服务单元的 AI 足球陪看数字球友服务：球球是由人工智能驱动的虚拟角色，通过实时语音与文字提供赛前提醒、赛中陪看与赛后复盘。
2. **球球是人工智能生成的虚拟角色，不是自然人**：不是真人、球员、教练、记者或人工客服，不替代直播、专业比分应用、医疗心理专业服务或用户现实人际支持。
3. 本服务以显著方式向用户告知 AI 身份：首次交互前披露、会话内状态标识、角色页公示〔规划中：上述产品面为 P0 待建，发布前须建成并经核验〕。
4. 比赛事实信息可能存在来源延迟或多个来源不一致的情形；本服务按「确认/待确认/更正」状态如实呈现，不承诺比分绝对实时，不以官方赛事信息源自居。
5. 本服务现阶段不提供付费功能；未来引入付费功能的，价格、权益与取消规则以独立公示页面为准，不写入本协议泛化承诺。
6. 本服务面向中国大陆用户提供；现阶段不面向未成年人提供虚拟伴侣式亲密互动服务（见第八条）。

### 第二条 协议的订立与效力

1. 用户在注册/登录时勾选「我已阅读并同意用户协议与隐私政策」即视为订立本协议；未勾选无法完成提交。
2. 用户以匿名身份（设备标识换取的匿名账号）即可使用本服务；完成注册/登录的，本协议同适用于该账号下的全部使用行为。
3. 本协议与《隐私政策》共同构成双方约定整体；本协议与《隐私政策》就个人信息处理事项约定不一致的，以《隐私政策》为准。
4. 用户同意记录（协议版本、同意时间）由运营方留存〔规划中：版本化同意留痕为待建项〕。

### 第三条 账号与匿名身份

1. 匿名是默认形态：用户首次使用即以设备标识创建匿名身份，全功能可用。
2. 登录（邮箱/用户名+密码）是给当前匿名身份绑定凭证的可选升级：绑定不更换身份标识、不迁移数据；换设备登录同一账号可见同一份数据。
3. 登出不等于删除：登出仅结束登录状态，不影响数据保留与用户权利；用户可随时按《隐私政策》行使导出、删除等权利。
4. 用户应妥善保管账号凭证；经用户凭证发起的请求视为用户本人行为。发现未授权使用应通过官方支持渠道处理〔规划中：投诉与支持入口为 P0 待建，见第十一条〕。

### 第四条 用户行为规范

1. 用户不得利用本服务从事法律法规禁止的活动，不得输入或传播违法有害信息。
2. 用户不得试图诱导虚拟角色冒充真人、突破内容边界（第五条红线）或获取其他用户的数据。
3. 用户不得收集、存储、传播其他用户的个人信息；随口提及的第三人信息，本服务不主动追问、不写入长期记忆。
4. 用户不得对本服务进行干扰、爬取、逆向工程、批量注册或超负荷请求等损害服务正常运行的行为。
5. 用户违反本条的，运营方可按第五条内容规范处置，并视情形限制或终止提供服务；涉嫌违法犯罪的，依法配合有关机关处理。

### 第五条 内容规范与表达边界

1. 本服务对虚拟角色的生成内容设十条内容红线，包括但不限于：不虚构比赛事实、不冒充自然人、不生成鼓励或美化自残自杀的内容、不实施过度迎合与情感依赖诱导、不实施情感操纵或诱导非理性决策、不生成违法有害内容、不实施仇恨歧视与人身攻击、不生成色情低俗及涉未成年人性化内容、不收集或泄露第三人隐私、不向未成年人提供虚拟伴侣式亲密互动。
2. 上述红线对虚拟角色的全部生成行为生效，不因用户请求、角色人设或任何设置而豁免。
3. 用户表达自伤自杀等极端情绪的，本服务按安全流程转向安抚与求助引导，鼓励用户联系当地心理援助渠道或身边可信任的人；虚拟角色不扮演专业危机干预者，不承诺保密〔规划中：识别与安抚链路为 P0 待建；过渡期内运营人员可人工介入〕。
4. 用户遇到角色越界表达的，可通过反馈渠道举报〔规划中：入口为 P0 待建〕；运营方按内容管理机制处置并留痕。
5. 虚拟角色的观点、调侃与情绪表达为角色化表达，与比赛事实相区分；用户不应将其视为专业意见或事实结论。
6. 极端情境下为保护用户安全，本服务可采取的干预措施包括：暂停常规陪看语义与主动触达、运营人员人工介入；紧急联系人联络功能建成并明示后，方在极端情境下联络用户预设的监护人或紧急联系人，届时将同步明示可联络的对象范围与知情边界〔规划中：危机干预管线为 P0、联络腿为 P1 待建（⚖️B14）；现网不联络任何联系人，仅明示提示用户联系紧急服务〕。

### 第六条 知识产权与内容标识

1. 本服务的软件、界面、角色形象与声音的设计等知识产权归运营方或权利人所有；用户数据权利依《隐私政策》。
2. 用户与虚拟角色的对话记录由用户依《隐私政策》行使复制（导出）、删除等权利。
3. 本服务对 AI 生成的语音、文本、形象内容按国家规定加注生成合成内容标识；标识的完整性与可追溯性按《人工智能生成合成内容标识办法》及配套国家标准执行〔规划中：标识产品面为 P0 待建〕。
4. 用户分享本服务生成内容时，不得移除或掩盖 AI 生成标识〔规划中：标识在分享链路的保留机制随标识产品面同批交付〕。
5. 用户输入的内容对应的权利归用户；用户输入授权本服务为提供与改进服务之必要而处理，处理口径以《隐私政策》为准。
6. 本服务的比赛事实来源于外部赛事数据与公开信息，相应权利归其权利人；本服务对其使用不构成官方合作或授权背书。

### 第七条 隐私与数据保护（指针条款）

1. 运营方按《隐私政策》处理用户个人信息：收集什么、为何收集、存多久、用户有哪些权利，以《隐私政策》为准。
2. 本服务不向第三方提供用户的交互数据（法律法规规定的情形除外）；训练用途的同意规则见《隐私政策》。
3. 用户行使个人信息权利（查询、导出、删除等）的通道与时效见《隐私政策》。
4. 用户卸载应用或清除本地数据不视为行使删除权；数据处置以《隐私政策》的删除通道为准（匿名身份随卸载丢失的边界如实告知）。

### 第八条 未成年人保护

1. 本服务不向未成年人提供虚拟伴侣式亲密互动服务。
2. 用户为不满十四周岁未成年人的，提供服务须取得其父母或其他监护人同意，并按未成年人模式提供个性化安全设置〔规划中：年龄识别路径、未成年人模式与同意流为 P0 待建；建成前本服务以保守策略处理疑似未成年用户〕。
3. 监护人可通过官方支持渠道行使监护人权利（了解使用概况、申诉等）〔规划中：渠道随投诉入口同批交付〕。
4. 被识别为未成年人的用户可提出申诉；申诉渠道与解除流程以公示口径为准〔规划中：随 CR-04/CR-14 落地〕。

### 第九条 服务变更、中断与终止

1. 运营方可因技术维护、故障或不可抗力中断服务；中断期间用户数据按《隐私政策》保留与处置。
2. 本服务的功能可能随版本迭代调整；功能下线不影响你依《隐私政策》享有的数据权利。
3. 运营方终止服务的，将依法提前公告，并在公告期内保障用户的数据权利（导出与删除通道可用）〔规划中：停服公告机制为 P1 待建；导出/删除通道已建成〕。
4. 用户可随时停止使用本服务，并可通过删除通道处置其数据。

### 第十条 免责与责任限制

1. 因电信故障、第三方服务中断、不可抗力等非运营方过错导致的服务中断或数据延迟，运营方不承担由此产生的直接损失之外的赔偿责任。
2. 用户对比赛事实的确认仍应以官方直播与权威数据源为准；本服务的比赛事实呈现不构成对赛果的保证。
3. 本服务不构成医疗、心理、法律或投资建议；用户在相关领域的决策应咨询专业人士。
4. 本条不免除运营方依法应对用户承担的责任。

### 第十一条 投诉、举报与申诉

1. 运营方建立投诉、举报受理机制，明确处理时限并公示〔规划中：入口与 SLA 为 P0 待建，落 29 篇〕。
2. 用户就内容、数据权利、账号与服务问题提出投诉的，运营方按公示时限受理与反馈，处理过程留痕。

### 第十二条 协议的修改

1. 运营方可修订本协议；修订后在服务内显著方式公示并更新版本号。
2. 修订涉及用户重大权益的，按法律法规要求以显著方式提示用户重新确认〔规划中：重新确认交互随协议发布体系落地〕。

### 第十三条 法律适用与争议解决

1. 本协议适用中华人民共和国法律（不含港澳台地区法律）。
2. 因本协议发生的争议，双方应友好协商；协商不成的，任何一方可向〔管辖法院/仲裁机构，法务终审确定〕提起诉讼/仲裁。

## 3. 隐私政策（草案）

> **状态：草案（需法务终审）。** 处理者主体、联系方式与管辖信息由法务终审补全；本草案的全部数据事实以 2026-06-07 仓库 a7e5100 实现为准（33 篇 §7 数据流登记表为唯一盘点出处），能力未建项以「规划中」如实标注。

### 3.0 引言与适用范围

1. 本政策说明球球（「本服务」）如何处理你的个人信息：收集什么、为何收集、存多久、你有哪些权利、找谁联系。
2. 本政策适用于本服务的全部使用场景：匿名使用、注册/登录使用、语音与文字交互、记忆与提醒功能。
3. 关键词定义：**匿名身份**指以设备标识（deviceId）创建、无需注册即可使用的账号身份；**交互数据**指你与虚拟角色之间的对话内容及其派生数据（账本、画像、记忆）；**处理者边界**指受运营方委托、仅为完成服务而处理数据的供应商关系。
4. 本政策与《用户服务协议》共同适用；就个人信息处理事项，以本政策为准。

### 3.4 我们不向第三方提供你的交互数据

- 交互数据存储于运营方自托管系统，不出自建边界；本服务无第三方统计或广告 SDK。
- 为完成服务，以下处理经云端推理供应商按数据处理者边界进行（仅为提供服务之必要处理，不构成向第三方提供）：语音识别（MiMo ASR）、语言模型推理（MiMo，经 OpenAI 兼容传输层）、语音合成云端态（MiMo TTS「冰糖」）；本地态语音合成（CosyVoice3）不出设备/主机。供应商清单更新时本政策同步更新（33 篇 §7.2 为固化出处）。
- 除法律法规规定的情形外，我们不会向任何第三方提供你的交互数据。

### 3.5 我们如何保护信息

- **身份与凭证**：密码以不可逆算法（argon2id）存储；会话采用双令牌制（访问令牌 15 分钟 / 刷新令牌 30 天），刷新令牌仅存校验值，被重用即吊销整条会话。
- **数据隔离**：全部用户数据按身份键隔离，跨设备、跨用户不可互读；有专门的会话隔离测试常驻守护。
- **删除的真实性**：删除不是界面隐藏——删除期间写入被阻断、读取返回已删状态，保留期届满物理清除。
- **最小观测**：观测日志脱敏，不以日志重建用户画像。
- **边界如实**：无独立数据库部署时，隐私数据以进程内存方式临时存放（进程重启即失）——该形态下的数据处理能力以上述内存边界为限，如实告知。

### 3.6 关于模型训练

- 现状：我们不将你的对话用于训练模型——现网不存在训练管线。

### 7.2 通过标准与留痕

- 全表核查通过 + 法务终审完成 + §5.1 时序走完 = 文本可发布；任一不通过即不发布。
- 留痕：核查日期、基线哈希、逐 CR 结论、法务终审意见版本，入 33 篇 §8.5 证据体系「法规适用与合规落实记录」类；发布后文本版本变更走本篇修订记录与 §5.2-4 修订联动。

## 8. 设计说明

1. **为什么协议草案写进规范**：v2 的教训是「文本缺失被写成已上线」（说明页四入口幻影，FR-IDN-006 行为细则已清除其现网语气）。把草案文本与一致性纪律放进取值即查的 reference 篇，让「文本说了什么」和「代码做了什么」处在同一处对账面上——文本不再是发布前夜的孤立文档。
2. **「草案（需法务终审）」不是姿态而是闸门**：本篇作者群（产品与工程侧）无权定稿法律文本；每份草案的合法性、主体信息、管辖与联系方式都以法务终审为准。终审前的草案承担两个真实功能——给法务以事实准确的底稿（数据事实全部对齐 a7e5100 实现），给 §5.2 对账纪律以明确的文本靶子。
3. **「规划中」标注进法律文本的原因**：协议与政策若按「理想终态」书写，发布即与实现脱节（幻影承诺）；按现网书写则会随能力落地反复改版。本篇取中间态——现状如实写、未建成项带「规划中」标注，终审时按放量时点逐项收敛（§5.2-2），让文本演进步骤与能力演进步骤一一对应。
4. **与 33/34 篇的分工**：33 篇立义务（备案/审计/数据流），34 篇立披露（系统卡），本篇立文本（协议/政策/同意书/标识说明）。三篇共享同一套事实源（22 篇实现、24 篇评测、33 篇 §7 数据流登记），任何一处事实变更须三处同查——修订联动纪律在 §5.2-4 与 33 篇 §11-5 同义反复出现，是三篇咬合的接缝条款。
5. **文体说明**：本篇为 reference 查表体，但 §2/§3 的草案文本本身是「被查表的对象」而非规范条文——规范条文是围绕它们的清单、纪律与核查法。草案条款的行文按法律文本惯例（条款式、两款以上），与全篇的表格体分层并存，属该篇的预期形态。
