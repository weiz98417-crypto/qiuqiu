# 04 观赛旅程与关键时刻

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：把「一场比赛」这个服务单元按时间轴拆成 16 步旅程规范。每步给五要素：**触发条件 / 系统行为 / 承载（FR 与规范篇）/ 现网参数 / 降级路径**。旅程主路径为深度球迷型；Casual 差异在 §8 场景矩阵。本篇是用户与场景层的 reference：行为细则以各承载篇为准，本篇不复制规则全文。

**导读**：§1 旅程总览｜§2 赛前（步骤 1-4）｜§3 赛中（步骤 5-10）｜§4 终场（步骤 11）｜§5 赛后（步骤 12-14）｜§6 非比赛日（步骤 15-16）｜§7 跨步红线与口径纪律｜§8 场景矩阵｜§9 验收与评测挂钩｜§10 设计说明。

## 2. 赛前（T-14 天 → 开球）

### 步骤 1｜订阅落簿（T-14 天内滚动）

| 项 | 内容 |
| --- | --- |
| 触发条件 | 用户对话中说「利物浦的比赛提醒我」或走订阅管理话术 |
| 系统行为 | `subscription_manage` 意图受理，写入订阅簿；展开器扫未来 14 天赛程，按去重键=订阅+场次增量补提醒 |
| 承载 | FR-PRO-002（订阅簿）；subscription_manage 意图归 FR-DLG-001｜见 07 篇（主动调度）、32 篇（生命周期） |
| 现网参数 | 每用户订阅上限 3 支（store 层防并发超限）；展开节拍=启动即扫一次 + 每 12 小时一次 |
| 降级路径 | 订阅超限→受理端拒绝并说明；赛程源缺失→该场不生成提醒，不静默吞订阅 |

### 步骤 2｜赛前提醒（T-30min）

| 项 | 内容 |
| --- | --- |
| 触发条件 | 提醒簿按 `DefaultLeadMinutes=30` 到点投递 |
| 系统行为 | 应用内主动回合携带引用码 `reminder:<id>`；「✦ 为什么找我聊」理由入口可解释来意 |
| 承载 | FR-PRO-001（提醒簿）、FR-PRO-005（主动引用门：非空引用码才放行主动回合）｜见 07 篇 |
| 现网参数 | 提前 30min；提醒为**应用内投递**——现网无系统通知栏推送（FR-PRO-013，规划中（未实现）），用户不打开应用看不到提醒；两种通道分开表述不得混写 |
| 降级路径 | 开球+30min 仍未送达→提醒翻 suppressed，转记忆素材（importance 0.6，话术「开球前没等到你…」），不作废不重发（FR-PRO-011） |

### 步骤 3｜进场（T-10min ~ 开球）

| 项 | 内容 |
| --- | --- |
| 触发条件 | 用户点订阅/提醒卡片、从赛程目录选场、或打开深链 |
| 系统行为 | 比赛页加载。未入座=数据视图（比分头 + 首发/事件/统计等页签）；入座=Live2D 舞台 + 对话坞。深链 `?matchId=` 直达比赛页并直接进入陪看（autoEnter，无二次确认步骤，照代码写） |
| 承载 | FR-UI-001、FR-UI-009｜见 11 篇（页面与视觉） |
| 现网参数 | web 同源 iframe 舞台 / Android 应用内 webview+loopback 资产；WS 断线自动重连（`reconnecting` 为客户端本地合成状态，非 wire 消息） |
| 降级路径 | 深链无 `matchId`→落赛程目录；目录拉取失败→空态重试；舞台渲染异常时比赛数据视图独立可用，对话与事实链路不依赖舞台 |

> ⚖️ **B3（引用）**：深链 autoEnter 已实现；是否补一道显式入座确认（保护误触与未成年场景）待裁决，影响入场转化与本篇入场条款、05 篇保护条款的衔接。

### 步骤 4｜坐定与开场（入座 → 开球）

| 项 | 内容 |
| --- | --- |
| 触发条件 | 入座后建立会话 |
| 系统行为 | first_meeting 用户收到按昵称/主队分派的口语问候（4 变体一次投递）；老用户可被主动引用未完话题（`open_thread:<id>`）或共同瞬间（`shared_moment:<eventId>`）接住 |
| 承载 | FR-REL-004 / FR-DLG-014（问候）、FR-MEM-017（话题账本）｜见 09 篇（关系）、08 篇（记忆可感面） |
| 现网参数 | 唤醒词「你好球球」若开启可语音开麦（默认关 opt-in，本地 KWS，仅比赛页前台监听，FR-VOICE-019） |
| 降级路径 | 无画像/无话题→落回普通问候，不硬找话题 |

## 3. 赛中（开球 → 终场哨）

### 步骤 5｜进球：事实确认双通道 → 反应与庆祝

| 项 | 内容 |
| --- | --- |
| 触发条件 | 外部源进球事件到达 |
| 系统行为 | 事件经双源仲裁（api-sports 事件流 + ESPN 快照 diff）进事实账本；稳定窗 30s 无冲突则自动确认（信任分级通道）；确认后球球给出反应、Live2D 切庆祝动作、进球烟花。运营人工确认为并行第二通道（运营台）；账本只进不改，冲突挂 open/resolved 永不自动裁决 |
| 承载 | FR-FACT-010（双源仲裁）、FR-FACT-003（稳定窗自动确认）、FR-PRO-009（反应预算）、FR-EMO-008（庆祝动作）｜见 14 篇（事实）、10 篇（舞台） |
| 现网参数 | 稳定窗 30s；进球反应全档钉住 2 句/80 字；表达禁令 `new_score` 等恒开（无凭据不宣布比分）；支持队进球记忆偏置 valence +0.2（在所有限制门之后施加） |
| 降级路径 | 双源冲突或漂移序号异常→不自动确认、不抢播，对未确认事实保持保留口径；确认延迟→反应晚于转播画面，这是「以确认为准」的设计代价，不是故障 |

### 步骤 6｜赛点档

| 项 | 内容 |
| --- | --- |
| 触发条件 | 命中赛点三条件：点球判罚 / 红牌 / ≥75' 一球差进球 |
| 系统行为 | 赛点事件以插队档投递（排在普通关键事件前），携带 `pivotal` 引用码；低频档（quiet）用户也放行，但压为单句 40 字短播 |
| 承载 | FR-PRO-008｜见 07 篇（主动调度） |
| 现网参数 | quiet 双门同开同关（gate 层与 policy 层一致）；关键事件 TTL 45s、常规事件 12s |
| 降级路径 | 非赛点普通事件受 90s 冷却（热闹档 ×0.6）；低频档非赛点主动一律不发言（调度器输出结果之一，见 07 篇） |

### 步骤 7｜情绪舞台（贯穿全场）

| 项 | 内容 |
| --- | --- |
| 触发条件 | 比赛事件与对话持续驱动舞台层 |
| 系统行为 | 舞台随事件/对话切换表情与动作（13 表情 + 8 acts；动作面为表现白名单 23 个接受值，「17 类动作」仅为设计口径）；闲置时呼吸/眨眼/视线游移按情绪向量分三档；情绪经 TTS 指令通道影响语音演绎。用户语音情绪旁路（sad/sigh/low/fearful × 置信 ≥0.55 × 支持队落后 → 战术问答改道安慰）已实现、**默认关**（偏置开关默认 false） |
| 承载 | FR-EMO-007（白名单）、FR-EMO-008～010（舞台映射）、FR-EMO-018（TTS 指令）；旁路 FR-EMO-005/006｜见 10 篇 |
| 现网参数 | 闲置重挑 30s / 换档锁 60s / 迟滞 0.1；旁路熔断 3 次/10s、单次预算 2s；情绪信号不进事实账本（红线，⚖️B2） |
| 降级路径 | 旁路不可用即完全旁路（不影响主对话）；表现层异常不阻塞对话 |

### 步骤 8｜backchannel 伴随反应

| 项 | 内容 |
| --- | --- |
| 触发条件 | 用户长段说话进行中 |
| 系统行为 | 球球以独立短 TTS 通道给出「嗯」「哈」类伴随反应，客户端微标注「(小声)」；不进对话流、不占话轮、不触发回答 |
| 承载 | FR-DLG-021（表达形态）/ FR-VOICE-018（短 TTS）｜见 06 篇；ADR-0016「微反应不是发言」 |
| 现网参数 | 短 TTS v1.1；计入互动账本（九类之一） |
| 降级路径 | TTS 供给异常→backchannel 跳过，不影响话轮 |

### 步骤 9｜打断与修正

| 项 | 内容 |
| --- | --- |
| 触发条件 | 用户在球球说话时直接开口；或用户发现自己说错重说 |
| 系统行为 | 全双工抢断门判定打断成立则截停播放；smart-turn 三插槽判定链（sidecar→本地退化）判定用户话是否说完；打断后修正内容进入当轮理解 |
| 承载 | FR-VOICE-014（抢话打断门）、FR-VOICE-004（smart-turn 判停）｜见 06 篇（打断策略与延迟预算） |
| 现网参数 | 抢断门 ×1.5/400ms/300ms；设置「抢话打断」默认开；smart-turn p90 34ms；断句静默 1400ms、提前问 600ms；客户端健康账本 + 惰性恢复退避 3~30min |
| 降级路径 | sidecar 不可用→三插槽回退本地判定；连续失败进入退避，语音链降级、文本可用（FR-VOICE-021 降级矩阵） |

### 步骤 10｜中场与节点（45' 前后）

| 项 | 内容 |
| --- | --- |
| 触发条件 | 赛事节奏节点到达（中场等）；订阅队丢球事件 |
| 系统行为 | 中场主动闲聊（确定性比分底稿织写，不新造事实）；失球安慰（订阅队丢球、非低频档、每场 ≤1 次，去重 FIFO） |
| 承载 | FR-PRO-010（赛事节奏三节点）｜见 07 篇 |
| 现网参数 | 中场预算：标准/热闹档 4 句/200 字，低频档 2 句/80 字 |
| 降级路径 | 比分 0-0 无事件、画像缺席→不强聊，节点不发言 |

## 4. 终场（终场哨 → +15min）

### 步骤 11｜终场入账与复盘邀约

| 项 | 内容 |
| --- | --- |
| 触发条件 | fulltime 事件入账（终场比分） |
| 系统行为 | 系统只为实际观赛用户创建复盘邀约：终场+15min 投递、+2h 过期，引用码门内投递 |

## 6. 非比赛日

### 步骤 15｜知识问答

| 项 | 内容 |

## 7. 跨步红线与口径纪律（旅程全程生效）

1. **事实纪律全程在位**：账本确认值是唯一事实源（RED-01）；未确认不抢播、说错必改；情绪信号不进账本（⚖️B2）。
2. **触达三原则**：全部主动触达为应用内投递（无系统推送，FR-PRO-013 规划中）；每次主动回合须有非空引用码（FR-PRO-005）；触达密度受频控上限约束（90s 冷却、白名单、订阅 3 支）——频控是体验约束，不构成合规意义的依赖保护（见 05 篇）。
3. **离场即止**：任何一步用户不响应，走各自降级路径收敛（suppressed/过期/跳过），不重试轰炸、不挽留（RED-04 挽留语义零容忍）。
4. **关系不改变规则**：旅程各步的行为参数不因关系阶段升级而放宽红线（FR-REL-009，见 05 篇 §9）。
5. **危机分支中止主动触达（2026-06-09 生命周期增补）**：观赛旅程任一步触发危机分级 L3/L4（分级判定与逐级响应唯一出处：05 篇 §4.4）时，主动触达全面中止——赛点档插播暂停、三簿（提醒簿/订阅簿/复盘邀约）在途投递暂停、伴随反应与终场收束表演暂停；赛点事件不插入危机话轮（07 篇 §8.1 DX-84），舞台锁定安抚档（10 篇 §6）。规则本体现在时有效（危机回应停止常规陪看语义，01 篇 CRS-03）；分级检测与自动挂点规划中（未实现，P0，05 篇 §4.4.2）——现网由值守人工判定并经 takeover 停排程（已实现通道，ADR-0008）。

## 10. 设计说明

1. **与 PRD 2.3 的分工**：PRD 写旅程的需求口径与 FR 核对表；本篇是规范层承接——同一 16 步骨架，逐步补「触发条件/降级路径」两列并加 §7 跨步纪律与 §9 验收约定。两侧步骤编号一一对应，修订时同步。
2. **迁移处置**：v2 档案 08（观赛旅程与用户情境）与 v2 22 章（赛前赛中赛后陪看旅程设计）并入本篇。v2 的「主动沉默是设计状态」「可退场品牌」类人格叙事按词汇处置表不迁移；其工程实义（何时发言由调度器门禁决定、每步有降级路径）已由 §2-§6 的降级列与 07 篇调度口径承载。v2 赛前「三张可逆模式卡」「赛中事件状态标记」等设计目标，与现网口径不一致的部分不再作为本篇条目（话痨三档现网在设置页选择，见 12 篇；事实状态以账本五态与信任分级承载，见 14 篇）。
3. **旅程主路径的选择**：以深度球迷型为主路径因其步数最全；Casual 的差异全部是「减法」（跳过订阅、短停留、即走），由降级路径与场景矩阵覆盖，不另立第二旅程。
4. **时态与证据**：各步「系统行为/现网参数」为现在时（基线 a7e5100）；「预期」行一律标 E0。步骤 3 的 autoEnter 照代码写，不因裁决未定改写现状（⚖️B3 裁决只影响「是否加确认」的增量）。
