# 23 部署与环境

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：回答「这套系统装在哪、靠什么配置跑起来、怎么验证装对了、坏了怎么回来」。组件拓扑与包结构归 19 篇，本篇管部署形态、端口、环境变量全集、本地开发可跑通路径、备份与回滚。全部键名、端口、命令以基线代码与 compose 文件为对照源；每一条自检项都可在装完的机器上当场执行。

**导读**：§1 部署形态｜§2 端口登记表｜§3 环境配置全集（九族）｜§4 本地开发路径｜§5 备份、回滚、灰度与迁移规程｜§6 验收（环境自检清单）｜§7 设计说明。

## 1. 部署形态

### 1.1 形态总表

单机 docker compose，无 K8s、无多副本、无 staging（取舍依据见 §7）。组件清单与 19 篇 §1 同源：

| 组 | 成员 | 启动方式 |
| --- | --- | --- |
| 6 常驻 | backend、postgres（pgvector/pg16）、redis、memobase、memobase-postgres、memobase-redis | `docker compose up -d` |
| 3 profile sidecar | turn-sidecar（`--profile turn`）、sensevoice-aed（`--profile ambient`）、voice-input-sidecar（`--profile voice-input`） | 按 profile 显式拉起，默认不启动；URL 留空即旁路停用 |
| compose 之外 | Grafana 本机 3300、本地 TTS 腿 9880（可选）、Ollama 11434（可选） | 各自独立起停，见 §4.4 与 19 篇 §1.3 |

自愈内建：全部服务 `restart: unless-stopped`；healthcheck 只盖数据层——postgres 与 memobase-postgres 用 `pg_isready`、memobase-redis 用 `redis-cli ping`（均 5s 间隔），backend 与 memobase 本体无 healthcheck；backend `depends_on: service_healthy` 等 postgres 就绪才启动，memobase 等自身 pg/redis 健康，对三个 sidecar 无 `depends_on`（旁路断开只降级）。`restart` 只解决「进程死了」，不解决「数据错了」——数据面兜底在 §5 备份恢复。

### 1.2 镜像构建

`backend/Dockerfile` 三阶段：`golang:1.22-alpine` 编译后端二进制 → digest 钉死的 `cirruslabs/flutter:stable` 构建 Flutter web（宿主机无需 Flutter SDK）→ `alpine:3.20` 运行时。最终镜像 = 二进制 + prompts + migrations + Live2D 资产 + web 构建，一个镜像一个容器。sidecar 两个 Python 服务各自带 `backend/cmd/turn-sidecar/Dockerfile`、`backend/cmd/voice-input-sidecar/Dockerfile`（模型不入镜像，`scripts/turn-model/download.mjs`、`scripts/voice-model/download.mjs` 先落盘宿主机再卷挂；voice 模型未就位时 `/affect` 返回 503，Go 侧静默丢弃）。

### 1.3 演示机约束（PG16 portable）

**已知环境约束（NFR-REL-003，如实登记）**：演示机的 PG16 portable 无 pgvector 扩展，migration 001 的 `CREATE EXTENSION vector` 卡住导致全栈起不了；compose 的 pgvector/pg16 镜像形态尚未在该机闭环验证，挂部署轮。该约束不写成已交付。已建的缓解物：`scripts/install-pgvector-windows.ps1`（对已装 PostgreSQL 注入 pgvector 0.8.1，需管理员）；2026-06-03 值班演练即在此约束下改走「Grafana 只读直查 PG 最小表集」完成（记录见 27 篇与 `docs/design/oncall-drill-20261003.md`）。仓库内引用 PG 时一律按文件名：迁移 59 个文件（最高 057，缺 025 号，010-012 同号双文件）。

## 2. 端口登记表

全组件端口与发布面。compose 内部端口（容器间）与宿主机发布面分开登记：

| 组件 | 端口 | 发布面 | 说明 |
| --- | --- | --- | --- |
| backend | 8080（`PORT` 可覆盖） | 宿主机 `${PORT:-8080}:8080` | 唯一应用入口：API/WS/静态托管//mcp |
| memobase | 容器 8000 → 宿主机 **8019** | `8019:8000` | 管理口；backend 默认连 `http://memobase:8000`（compose 内）、本地裸跑默认 `http://localhost:8019` |
| turn-sidecar | 8091（`TURN_SIDECAR_PORT`） | 宿主机 8091 | profile turn |
| sensevoice-aed | 8090（`SENSEVOICE_AED_PORT`） | 宿主机 8090 | profile ambient；占位镜像 |
| voice-input-sidecar | 8092（`VOICE_SIDECAR_PORT`） | 宿主机 8092 | profile voice-input |
| postgres / redis / memobase-postgres / memobase-redis | 5432 / 6379（容器内） | **不发布** | 碰主库走 `docker compose exec postgres psql`；不发布端口是本 compose 最便宜的安全边界 |
| console 开发服务器 | 5173 | 本机 dev only | `npm run dev`；代理 `/api`、`/ws` → `127.0.0.1:18080` ⚖️B11 |
| Flutter web 开发档 | 7357 | 本机 dev only | `backend/.env.example` 的 `ALLOWED_ORIGINS` 预填值 |
| 本地 TTS 腿 | 9880 → 容器 8000 | 宿主机 9880 | CosyVoice3（`docs/deploy/local-tts.md`） |
| Ollama | 11434 | 宿主机 | bge-m3 嵌入；compose 内经 `host.docker.internal:11434` |
| Grafana | 3300 | **仅绑 127.0.0.1** | 本机闭环，不在 compose；`QIUQIU_GRAFANA_URL` 指给 backend 后经 `/grafana/*` 同源反代 |
| Android 模拟器→宿主机 | 10.0.2.2:8080 | — | 模拟器看宿主机回环的约定地址；真机 Android 走应用内 loopback 随机端口（口径见 00 篇） |

## 3. 环境配置全集

### 3.1 两份模板分工

| 模板 | 用途 | 分区 |
| --- | --- | --- |
| 根 `.env.example` | compose 全集（`cp .env.example .env`） | 必填 / 条件必填 / 可选 |
| `backend/.env.example` | `go run` 纯本地开发集 | 平铺；`ALLOWED_ORIGINS` 预填 `http://localhost:7357` |

两者用途不同勿混用。没有配置中心、没有 YAML 层：环境变量即全部配置，`git grep Getenv` 可穷尽全部外部输入面。变量只放部署差异、密钥引用、地址与开关；用户内容与比赛记录永不进环境变量（NFR-SEC-011：密钥一律环境注入，不入库不入 git；非 release 评测档强制清空 DEEPSEEK/MIMO/ELEVENLABS/APISPORTS 四键）。

### 3.3 根 `.env.example` 缺口（如实标注）

根模板自称「docker-compose.yml 所需的环境变量全集」，实登记 26 键；对照 compose 引用全集，**缺 16 键**：旁路三族 URL/超时 7 键（`AMBIENT_AED_URL`、`AMBIENT_AED_TIMEOUT_MS`、`QIUQIU_TURN_SIDECAR_URL`、`QIUQIU_TURN_SIDECAR_TIMEOUT_MS`、`QIUQIU_USER_AFFECT_URL`、`QIUQIU_USER_AFFECT_TIMEOUT_MS`、`QIUQIU_USER_AFFECT_MIN_CONFIDENCE`）、memobase 嵌入形 2 键（`MEMOBASE_EMBEDDING_PROVIDER`、`MEMOBASE_EMBEDDING_API_KEY`）、sidecar compose 形 7 键（`SENSEVOICE_AED_IMAGE`、`SENSEVOICE_AED_PORT`、`TURN_MODEL_ROOT`、`TURN_SIDECAR_PORT`、`TURN_COMPLETE_THRESHOLD`、`VOICE_MODEL_ROOT`、`VOICE_SIDECAR_PORT`）。全部 16 键有代码内默认值且旁路/ sidecar 默认不启用，**6 常驻照常可起**；但要按 §1.1 启用任一 profile 时须手工补键。模板补齐为工程侧待办，本表（§3.2）为准入口径。

### 3.4 生产硬门（三层快速失败）

| 层 | 机制 | 内容 |
| --- | --- | --- |
| compose | `${VAR:?}` 语法 | `APP_TOKEN`、`SESSION_SIGNING_KEY`、`ALLOWED_ORIGINS`、`POSTGRES_PASSWORD`、`MIMO_API_KEY`、`MEMOBASE_POSTGRES_PASSWORD` 六者缺一，`docker compose up` 一个容器都不起 |
| 进程 | `config.Validate()` | `APP_ENV=production` 时 `APP_TOKEN`/`MIMO_API_KEY`/`SESSION_SIGNING_KEY` 任一缺失拒启；签名密钥 <32 字符拒启；`PRIVACY_RETENTION_DAYS` 负值拒启 |
| 登录 | 运行态校验 | 存在任何密码账号时 `QIUQIU_JWT_SECRET` 必需（登录拒绝并提示），因「是否存在密码账号」是运行态 |

分层逻辑：增强型变量（`APISPORTS_API_KEY`、三条旁路 URL、本地 TTS）可以缺——降级路径存在；身份、口令、库与模型密钥缺失时假装能跑，只会把故障推迟到比赛中场。

## 4. 本地开发路径

### 4.1 依赖

Git；Docker（含 Compose v2）；Go 1.22+；Node（评测脚本运行时）；Flutter 3.4+（仅本地跑客户端时）；Grafana OSS 13 Windows zip（仅观测面，§4.4）。compose 镜像内自建 Flutter web，宿主机装 Docker 即可起全栈。

### 4.2 compose 路径（推荐，步骤顺序不可换）

```bash
cp .env.example .env          # 1) 至少填 6 个 :? 必填 + QIUQIU_JWT_SECRET
docker compose up -d --build  # 2) postgres healthcheck 通过后 backend 才起；迁移自动应用
docker compose ps             # 3) 6 常驻全 Up（sidecar 不在列是预期）
curl http://localhost:8080/health
```

验证迁移落位与账本门面：`docker compose exec postgres psql -U qiuqiu -d qiuqiu -c "SELECT count(*) FROM schema_migrations;"`（应等于 `backend/migrations/` 文件数 59）。打开 `http://localhost:8080/`（客户端，自动建匿名身份）与 `http://localhost:8080/console/`（运营台；空表时 `QIUQIU_BOOTSTRAP_OPERATOR=名字:个人令牌` 播种首位运营员，首登强制改密）。`node scripts/demo-seed.mjs` 可播种白名单演示比赛。评测离线档：`npm install && npm run eval:offline`（零密钥基线；四档机制见 24 篇）。

### 4.3 纯本地路径（热迭代）

```bash
# 后端：backend/.env.example 是本地集；不配 DATABASE_URL 时内存态可裸跑
cd backend && cp .env.example .env
PORT=18080 go run ./cmd/server        # ⚖️B11：console 代理打 18080，纯本地路径按此端口起
# 运营台：
cd console && npm install && npm run dev   # 5173；/api、/ws 代理 → 127.0.0.1:18080
# 客户端（Android 模拟器）：
cd client && flutter pub get && flutter run \
  --dart-define=QIUQIU_WS_URL=ws://10.0.2.2:18080/ws/match/test
```

> ⚖️B11 脚注：上面 `PORT=18080` 是缺陷修复前的可跑通写法；端口断裂本体见 §2 脚注。compose 路径无此问题（同源托管，不走 vite 代理）。

开发档专有行为：`AUTH_MODE` 默认 dual、loopback 来源放行、签名密钥自动生成本地值；`QIUQIU_RUNTIME_TTS=1` 注入 mock 音频（生产二进制无此路由）；dev 专页仅非 production 注册。

### 4.4 Grafana 本机启动（as code，Windows）

不在 compose 内。一次性安装与起停（全程 127.0.0.1，不构成暴露面；ADR-0021）：

1. Grafana 13 OSS zip 解压至 `E:\tools\grafana`（注意下载页切 OSS；13 起 `grafana-server.exe` 不存在，server 是子命令）；
2. postgres 起着的状态下执行 `deploy/grafana/init.sql` 建只读账号 `qiuqiu_grafana_ro`（仅 SELECT 四张账本表；GRANT 对已存在的表生效，首次建库要在迁移跑完后再执行一次 GRANT 段）；
3. `custom.ini` 关键项：`http_addr=127.0.0.1`、`http_port=3300`、`root_url`/`serve_from_sub_path` 与后端反代子路径 `/grafana` 对齐（README 示例中的 18090 是 2026-05-29 实测环境的后端端口，按实际改写）、`allow_embedding=true`（console 观测页 iframe）、匿名 Viewer 仅本机可达；

## 5. 备份、回滚与灰度

### 5.1 备份

`postgres_data` 卷是唯一全量事实源（画像、事实账本、知识条目全在整库 dump 内），备份可恢复是本部署形态压倒性优先级：`pg_dump -Fc`（custom 格式，可并行恢复、可压缩），crontab 每日 03:30（`%` 须转义 `\%`）；`backups/` 应同步到宿主机之外——备份与库同盘等于没备份。memobase 的 `memobase_postgres_data` 可由账本重建，不强制定时（ADR-0006 分工）。命令与恢复全手册：`deploy/README.md`。

### 5.2 恢复

两条路径：① 卷完好仅回滚数据——`pg_restore --clean --if-exists` 覆盖恢复；② 卷损坏重建——`compose down` → 删卷 → 单起 postgres 等 healthcheck → `pg_restore` → 全量 up。大版本恢复先在隔离环境走一遍（验业务表行数 + vector 扩展与相似度检索），再切流量。`embedding_moments` 向量默认不迁移（新机随对话再积累，积累前语义召回自动降级关键词路）；跨机带走需两端同为 bge-m3/1024 维。

### 5.3 回滚

- **回滚 = 后端镜像回退 + 数据库备份恢复**。迁移只进不退（无 down 迁移；执行器 advisory lock + `schema_migrations` 账本；只增不删、引用一律按文件名），旧镜像必须能在新库上运行——靠应用层兼容窗口，不回滚 DDL。
- **迁移序号纪律**：`scripts/lint-migrations.mjs` 对既有重号（025 空档、010-012 同号双文件）放行，新重号一律退出 1；迁移引用在文档与代码里一律按文件名。
- **回滚不影响观测面**：Grafana 本机独立，不在 compose 内。

### 5.4 灰度与运行中止血

**按用户比例的灰度机制不存在**（NFR-REL-010，规划中未实现，P1）——单实例 compose 下没有灰度面，开放受控试用前须先立（最小形态：邀请码 + 运营台总量开关）。现网承担同类职责的是分钟级人工收敛，不重新部署：TTS 供给三态切换（本地腿健康门控）、自动化策略 active/paused + 事件白名单 + 冷却、数据源人工接管（takeover→paused）、事实撤回、运营员令牌即时吊销（行删除即刻生效）。用户侧的静音、结束与纠正永远高于运营台任何配置。

**演练记录**：2026-06-03 值班演练全链闭合（20 条真故障注入→firing→钉钉+webhook 实收→恢复→resolved 实收；PG16 portable 约束下改走最小表集），记录归 27 篇，原始档 `docs/design/oncall-drill-20261003.md`。告警规则 4 条的口径与 21 篇同源（`deploy/grafana/provisioning/alerting/rules.yml`）。

### 5.5 迁移规程（模型/供应商迁移 playbook，2026-06-09 生命周期增补）

模型与供应商是本部署形态最大的外部依赖（§3.2 族 C：LLM/ASR/TTS 一体依赖 MIMO 凭证与路由键；§3.2 族 G 三条旁路 sidecar；33 篇 §7.2 模型清单为备案固化口径）。换代/换供应商按以下五道 Gate 顺序执行，**每道 Gate 可逆**——任一道不过即停在原地回退到上一道状态，不允许「走到一半只能硬闯」：

| Gate | 内容 | 通过判据 |
| --- | --- | --- |
| G-M1 盘点受影响面 | 列出该依赖的全部消费方：代码读取点（`git grep` 键名与接口）、文档引用面、备案口径（33 篇 §7.2） | 清单经第二人核对，无「只改一处」假设 |
| G-M2 兼容矩阵 | 新旧供给的接口、参数、行为差异逐项列表（含降级路径在两侧的行为差异） | 每行标注：兼容 / 需适配 / 阻断 |
| G-M3 黄金集双跑 diff | 新旧双路由各跑一遍黄金集与离线评测档（24 篇），diff 逐条归类 | 事实路径零 diff（账本语义不变）；表达面 diff 落在预算/护栏判据内；宪法负例门禁（01 篇 ENF-02）与 safety/boundary 全量在新路由上保持绿 |
| G-M4 灰度 | 受控放量观察 | 观测面（21 篇告警 + §6 自检）无新增异常。灰度机制本体不存在（§5.4）——最小形态：运营台总量开关/白名单先行，或本地腿式健康门控分批切流 |
| G-M5 回滚判据 | 预先写死回滚触发条件（延迟阈值、错误率、事实错误率、用户面症状） | 判据数值入值班手册（27 篇），可执行不争论；演练实际走通「新路由回退旧路由」全链 |

**铁律：回滚演练通过前不下线旧路由。** 旧供给保留至 G-M5 演练实际走通回退全链为止；演练未走通即下线旧路由等于单点化，违规。

**已验证范例（TTS 三态供给实战，commit 2971bbd）**：TTS 云腿/本地腿三态供给与健康门控（`backend/internal/tts/supply.go`、`local_health.go`；§5.4 分钟级人工收敛的承载之一）即按本规程骨架落地——G-M2 兼容矩阵（OpenAI 兼容 `/v1/audio/speech` 统一形态）、G-M3 双跑对照（FunASR/MiMo 对照门思路同源，33 篇 §7.2）、G-M5 健康探测回退（连续 2 次通过才亮门，失败回落云腿）均已在现网闭环（§3.2 族 D 四键）。

**LLM 换代复用本规程**：更换 `MIMO_MODEL` 或推理供应商（33 篇 §4.3 重大变更，同步触发变更备案口径）时，五道 Gate 直接复用；G-M3 的黄金集 diff 须加跑宪法负例门禁与 safety/boundary 全量——表达护栏与新红线承载在新模型上仍闭合，是换代放行的前置而非事后补测。

状态：本规程为 **P1 编制**（现网单实例、外部依赖集中，首次完整执行随首次 LLM/供应商换代触发）；Gate 结构与铁律现在时有效——任何依赖变更（含 sidecar 换代、嵌入模型更换）不得绕过本节直接改 §3.2 键值上线。

## 7. 设计说明

1. **文体判定**：本篇是 reference——登记表（端口、键、自检项）承载事实，§4 的步骤命令按「可跑通路径」口径收录（how-to 要素内嵌于查表框架，不另立叙事）。
2. **与 v2 档案 44/60 篇的差异**：v2 44 篇的「46 个迁移」「四个小工具 cmd」已过时——现网 59 个迁移（缺 025、010-012 同号双文件）、10 个 cmd 入口（含两个 Python sidecar 本体与 fake 双件）；v2 60 篇「没有独立告警系统」已被 Grafana as code 4 条规则 + 双通知通道 + 值班演练取代（NFR-REL-006/007/008）。v3 增补：三 profile sidecar 的 compose 形与模型落盘约束、PG16 portable 演示机约束（NFR-REL-003）、端口断裂 ⚖️B11 登记。
3. **环境变量按族不按文件**：71 键按「九族」组织而非按读取文件罗列——族对应运维心智（起基础栈要 A/B/C/H 四族，开旁路加 G，开本地语音加 D，开观测加 I）；每键给默认值与语义边界，「留空即停用」族统一表述，避免逐键散文。
4. **缺口如实**：根 `.env.example` 缺 16 键、演示机 pgvector 缺失、灰度面不存在，三条都按「现状 + 跟踪去向」登记，不写成已闭环——这是已知缺陷如实登记纪律在本篇的落点（⚖️B9/⚖️B11 脚注，⚖️B9 的 schema 缺陷本体见 19 篇 §3.3）。
5. **备份与回滚合并成节**：v2 分两篇讲的「备份恢复」与「回滚」在现网是同一条链——迁移只进不退成立的前提是恢复可信，拆开写会让人先配回滚后配备份。本篇按依赖顺序合并：备份 → 恢复 → 回滚 →（不存在的）灰度 → 在场的人工收敛。
6. **评测档位只留指针**：四档分层机制归 24 篇；本篇只登记与环境相关的两条事实——离线档零密钥、release 档强制真密钥（NFR-SEC-011 的清键纪律以评测档为界）。
