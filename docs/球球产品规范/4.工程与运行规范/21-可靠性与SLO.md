## 1. SLO 体系

### 1.1 总纲

- **REL-01 无对外 SLA 承诺（现状）**：现网为单实例 compose 部署（6 常驻 + 3 个 profile sidecar，演示/开发环境），不承诺面向公网的可用性 SLO（如 99.5% 一类目标为规划中（未实现，P1），PRD NFR-REL-001）。开放受控试用前须先立 SLO 与容量口径。
- **REL-02 SLO 两面**：可靠性指标分两面——**体验 SLO**（用户侧连接与响应质量）与**数据 SLO**（事实与投递的数据纪律质量）。价值面指标（ECS、留存等）不在本篇，归 28 篇；其采集面待建，归 31 篇。
- **REL-03 测量来源纪律**：每条 SLO 必须标注测量来源（Grafana 面板指针或推导路径）；无采集来源的一律标「待埋点（31 篇）」。无来源的指标不得写进任何对外材料，也不得作为发布门禁判断值。
- **REL-04 目标值纪律**：下表「目标」列在 SLO 立项裁决前一律写「待定」；已运行的告警阈值是**值守判断值**，不是 SLO 目标承诺，两者不得混写（见 §7 设计说明 4）。

### 1.5 SLO 立项模板（REL-05，REL-04 扩展；2026-06-09 对标增补）

SLO 立项裁决的交付物不是「目标列填数」的一张表，而是六件套——本节把六件套定为立项裁决的**交付物清单**（对标 SRE Workbook SLO 文档结构）；裁决前全部目标值维持「待定」（REL-04），其中**预算政策（REL-06）可先于目标值落地为占位骨架**。

| # | 件 | 填法说明 | 球球候选 SLI 示例 |
| --- | --- | --- | --- |
| 1 | SLI 定义与测量点 | 按 REL-03 纪律逐项写：指标定义、分子/分母口径、测量来源（Grafana 面板指针或推导路径）；无采集来源的 SLI 不得进入立项——先补埋点（归 31 篇）再谈目标 | 投递可靠性 SLI＝投递「不重复呈现且更正必达」的比率（源：面板⑤投递七态分布的 failed 态占比；注：client_late 是 delivery_ledger 的 Source 属性而非七态之一，面板⑤按 state 分组出不了该占比——如需纳入须补 Source 维度新面板）；首响达标率 SLI＝语音首响落在 3-7s 预算内的回合比率（源：现网仅 §3.1 告警②（tts_first_audio，休眠保留）承载该锚点，无任何面板——立项前须先补首响面板；P95>3000ms 告警为值守线，不是目标） |
| 2 | 目标（待定 ⚖️） | 一件一个数值＋达标语义（≥/≤）；数值随 SLO 立项裁决给出并挂验收；裁决前一律写「待定」，不得以 §3.1 值守告警判断值冒充目标（§7 设计说明 4 同源） | 待定（随 SLO 立项裁决 ⚖️） |
| 3 | 合规窗口 | SLO 的结算窗口（如 28 天滚动窗）。现网只有告警评估窗（15m 窗，for 5m，§3.1），**无 SLO 合规窗口**——立项时必须给出窗口并落进面板口径 | 例：投递可靠性按 28 天滚动窗结算；窗口内不达标时间即预算扣减单位 |
| 4 | error budget 计算 | 预算＝（1−目标）×窗口，以「允许不达标的时间额度」表达；预算余额可由窗口剩余−已耗推导，落面板 | 例（示意，目标待定 ⚖️）：若首响达标率目标定 95%/28 天窗 → 预算＝5%×672h≈33.6h 不达标额度 |
| 5 | 预算政策（error budget policy） | 预算烧尽时的行动规则；占位骨架见 REL-06（可先于目标落地），**政策生效随目标裁决 ⚖️** | 例：投递可靠性预算烧尽 → 触发 REL-06 三条默认动作 |
| 6 | burn-rate 多窗口告警 | 快慢双窗燃烧率告警（burn rate＝消耗速率/预算速率；如 1h 快窗+6h 慢窗联合判定）。现网 4 条告警全部固定阈值型（§3.1）——立项时新增双窗规则，现值保留为值守判断值不回改 | 例：投递可靠性 1h 窗 burn rate 超快窗阈值且 6h 窗超慢窗阈值 → 页告警（阈值随立项裁决定） |

**REL-06 error budget 政策（占位条款）**：目标未定，政策先立骨架——以下三条在 SLO 立项裁决时随目标值一并生效；**政策生效随目标裁决 ⚖️**，生效前本条不构成任何发布/降级操作的触发依据（如实注记：现网无 error budget 结算面）。

1. **冻结非合规发布**：任一现行 SLO 预算烧尽即冻结新功能发布，仅放行安全与合规修复类变更；解冻条件＝预算随窗口滚动回补，或裁决例外放行（无临场豁免，DL-04 同构纪律）；
2. **降级非核心功能**：按 §5 八层降级序研判，优先保主链路（连接/事实/投递）；非核心能力（如伴随反应、非赛点主动回合）先进降级候选；
3. **复盘强制**：预算烧尽即触发复盘，产出「证据/缺口/复演条件」三产物（形态沿 §3.3 演练收尾三产物），缺口整改挂值班演练复演。

与四道告警的关系：REL-06 生效前，§3.1 四条固定阈值告警仍是唯一值守依据——预算政策不回溯改写告警判断值。

## 2. 可靠性机制与参数

### 2.1 连接保护（握手关）

| 参数 | 值 | 违规反例 |
| --- | --- | --- |
| Origin 校验 | Origin 与 Host 同源放行；跨源比对允许清单；不可信来源 403 | 生产环境回环地址宽松规则关闭；绕过 Origin 直连拿比赛数据属违规 |
| 会话鉴权 | 凭证走 `Authorization: Bearer` 或子协议 `qiuqiu-auth.<base64url>`；生产强制会话令牌 | 查询串拼 token 被测试明确拒绝 |
| 每 IP 连接上限 | ≤5 条，超出 429 | 同机多开形成连接风暴 |
| 单帧读上限 | 1MB（按 15 秒 16kHz 单声道最重合法载荷核定），超限断开 | 协议放大攻击面 |
| 读写超时 | 读 60s（协议层 pong 续期）／写 10s | 写不进去不放弃连接属缺陷 |

### 2.2 心跳与会话看守（三道）

| 道 | 方向 | 周期 | 语义 |
| --- | --- | --- | --- |
| 协议层 ping | 服务端→客户端 | 30s | 浏览器/Flutter WS 栈自动回 pong，续读超时，顺带穿代理保活 |
| 应用层 ping | 客户端→服务端 | 25s（JSON ping→pong） | 客户端以「发得出去」确认连接存活 |
| 会话看守 | 服务端自检 | 30s | 重验会话声明；令牌过期/吊销即下发 `auth_error` 并断开，失效会话不得继续收发 |

### 2.3 客户端重连

| 规则 | 参数 | 反例 |
| --- | --- | --- |
| 自动重连上限 | ≤5 次，超过进入 failed 态、界面明示「连接失败」，重试权交还用户 | 无限后台重试属违规 |
| 指数退避 | 第 n 次等待 2^(n-1) 秒，钳制 1-8s | 弱网硬碰硬重连 |
| 令牌先刷新 | 重连前先走令牌刷新回调，拿新令牌握手 | 「连接好了才发现令牌过期」二次断线 |
| 代际防串台 | 每次连接分配代数（generation），旧连接迟到回调/消息按代数丢弃 | 快速断连重连时旧连接尾巴污染新会话 |
| 未连接不发 | `send()` 未连接直接返回 false；用户语音进补发队列（§2.5） | 断线期假装「已发送」 |
| 状态可见 | 五态状态流暴露给界面 | 用户无从得知当前连接状态 |

重连后服务端在会话绑定（`session_opened`）时做四件事：恢复持久化话痨档位（不重置回默认）、回放未送达回复（§2.5）、重新排程时限内的观察跟进、身份与会话声明不匹配即 `auth_error` 断开（换人不续用旧连接授权）。

### 2.4 幂等投递与保序（deliveryKey 机制）

核心键：`deliveryKey = 事件ID:factRevision:factStatus`。重复被吸收（同 key 只呈现一次），更正能通过（revision 递增或 status 变更生成新 key——更正不是重复）。

| 关卡 | 位置 | 参数 |
| --- | --- | --- |
| 服务端连接级 | 每连接 LRU 已投递集合（pumpMatchEvents） | 容量 512 条 |
| 服务端轮次级 | signalDeduper，键=用户+比赛+信号 | TTL 15 分钟，容量 4096 条——客户端重试同一句话只回答一次 |
| 客户端级 | DeliveryDeduplicator，四类内容（比赛事件/反应/表演/音频）各挂一个；音频按 deliveryKey 配对 | 音频容量 256——重连重放与微反应重投影均不重播 |

保序纪律：客户端为每条事实记录已见最高 revision，更低 revision 直接丢弃——快照、事件、更正无论以什么顺序到达，比分只向前走。撤回是单向门：`match_fact_retracted` 到达后受影响事实（含关联）的待播音频逐条移除、在播反应立即暂停并取消——「这球没算」之后庆祝不得继续响。

过期不补：事件触发的主动话术带 TTL（critical 45 秒／普通 12 秒），过期即弃，重连回放也不含。原则：**用户看到的每一条都成立，优先于每一条都送到**。

时钟并发自愈：比赛时钟唯一权威在后端，导播台推进时钟必须携 expectedVersion，版本不匹配返回 409，前端自动重读最新时钟与版本后操作照常（用户端时钟只读，不存在该冲突面）。

### 2.5 断线补发（双向两条通道）

| 通道 | 规则 | 参数 |
| --- | --- | --- |
| 客户端语音补发队列 | 断线期用户语音兜底条目入 FIFO，仅连接恢复后出队串行发送（发一条、确认送达一条）；用户已松手取消的不进队 | 上限 **4 条**，满淘汰最旧——补的是「你刚说的最后几句」，不是完整录音历史 |
| 服务端未送达回放 | `session_opened` 后扫描该用户本场「已生成但未确认展示」的回复，**只取 resolved 态**逐条以 `event=qiuqiu_reply`（source=recovered_delivery）按原 deliveryKey 重放；时限内的观察跟进同刻重排 | 未解析、来源出错的只留日志不重放——回放「确定该说的」，不是「所有没说完的」 |
| 观察跟进补发 | 重连绑定时对余额在跟进时限内的观察（观察协调七态，细则归 14/20 篇）重新排程；产出经投递 outbox（pending/delivered/suppressed）幂等投递 | 已 suppressed 的不复活 |

一条断线-重连走查（三道关卡合流）：

```text
T0  进球确认，deliveryKey = evt-12:1:confirmed      ——服务端连接级 LRU 记录，推送客户端
T1  订阅重放又送来 evt-12:1:confirmed               ——服务端 LRU 命中，不再推送
T2  弱网客户端重发请求，evt-12:1:confirmed 再到      ——客户端 Deduplicator 命中，跳过
T3  VAR 通过，evt-12:2:reconciled 到达              ——新 key 放行；revision 2 > 1，应用
T4  断线发生，用户补发队列收下最后 2 条语音（≤4 条）  ——未连接不发，界面呈 reconnecting
T5  重连成功（第 2 次尝试，退避 2s），令牌已先刷新    ——session_opened：档位恢复/回放/跟进重排
T6  一条迟到的 evt-12:1:confirmed 最后抵达           ——客户端 revision 守卫：1 < 2，丢弃
```

用户全程只看到一次「进球」和一次「确认有效」；断线期说的话在恢复后按序补上，没有任何重复或回退。

### 2.6 双工抢断门与惰性恢复

- 抢断门三条件联合判定：能量门（空闲阈值 ×1.5 = RMS 0.0225）、时长门（持续语音 ≥400ms）、判定窗（播放起音 300ms squash 窗）；段内一次判定锁存不回退。
- 惰性恢复：双工降级后自动恢复采用退避 **3~30 分钟**惰性调度，不以固定周期反复探测。
- 健康事件上行：`duplex_event` 三事件（self_interrupt_suspected / duplex_degraded / duplex_recovered）+ 嘴型退化事件，共 **6 种客户端健康事件**，全部入 ClientHealthLedger（§2.7）。

### 2.7 健康观测（ClientHealthLedger）

- 服务端 `observation.ClientHealthLedger`：**进程内环形缓冲，重启清零**——是排障观测面，不是持久账本。
- 读取面：`GET /api/console/client-health` + 运营台概览「客户端语音健康」卡。
- 隐私裁剪：wire 事件裁剪至 kind/at/matchId 三字段——无用户身份、无正文。
- 客户端限频：同原因 10 分钟冷却窗内只报一次（防 webview 重载/重进比赛页重复触发）。

### 2.8 运营观测流可靠性（/ws/ops）

| 参数 | 值 | 语义 |
| --- | --- | --- |
| 队列容量 | 256 | 饱和丢弃只计数（`Dropped()` atomic），零订阅同样丢计入——观测流不得反压业务账本 |
| 连接保活 | 服务端 ping 30s | 复用用户面心跳纪律 |
| 广播泵 | 写失败即注销 | 死连接不滞留广播面 |
| 鉴权 | 复用会话鉴权链升级，claims 需 OperatorTraceRead（或 legacy 令牌/开发档）；用户会话拒绝 | 拒绝发生在升级成功后直接断开（ClosePolicyViolation） |
| wire 形状 | 9 字段（kind/matchId/userId/traceId/deliveryState/playbackState/latencyMs/at 等），**正文在结构体层面不存在** | 观测流无正文（ADR-0021 隐私三层之一） |
| 直播监听页消费 | 暂停冻结（入列冻结、WS 保持、暂停期事件丢弃不缓存）；MAX_ROWS=200；重连退避 5s 起步指数封顶 30s；按 traceId 一键回合回放 | 消费端自我保护，不放大服务端队列压力 |

### 2.9 数据面持久性

- **唯一全量事实源**：Postgres（pgvector/pgvector:pg16，卷 `postgres_data`）。账本五态 append-only 是投递与回放的恢复底座——服务端补发（§2.5）与投递七态推进都以此为准。
- **备份恢复**：postgres_data 有成文手册（`pg_dump -Fc` / `pg_restore --clean`），cron 每日 03:30 定时备份；备份是事实源的一部分，不是旁门——「删库跑路」式数据丢失由此兜底（PRD NFR-REL-002，已实现）。
- **已知环境约束**：演示机 PG16 portable 无 pgvector 扩展导致全栈起不了；compose pgvector 镜像形态尚未在本机闭环验证（挂部署轮）。该约束如实登记为已知缺陷，不写成已交付（PRD NFR-REL-003）。
- **降级形态**：无 DATABASE_URL 时隐私 Store 等内存实现可用但进程重启即失——内存形态只服务本地开发，不得用于任何对外承诺场景（见 22 篇 §7）。

## 4. 故障分级（S0-S3 统一刻度）

全库统一事故分级刻度为 **S0=最严重 → S3=最轻**。2026-06 统一裁决（B8）落地收口：v2 资料中「S3=最重」的反义刻度作废，全库按本表口径执行，不再作为裁决点悬挂（登记状态见 37 篇）。

| 刻度 | 定义 | 响应预期 |
| --- | --- | --- |
| **S0** | 服务整体不可用 / 用户数据泄露 / 事实纪律系统性失效 | 即刻响应，全力量处置，事后复盘 |
| **S1** | 核心体验严重受损（语音链路不可用、账本确认停摆） | 值班即时介入 |
| **S2** | 单能力降级（TTS 单腿故障、告警噪声、面板缺数） | 当班处理，可延至次日 |
| **S3** | 观感缺陷（文案旧值、非阻塞 UI 瑕疵） | 进工单池按优先级消化 |

- **与 P0-P3 的映射**：卷首历史「一~四级」与工单优先级 P0-P3 是**工单处理优先级**刻度，与事故等级 S0-S3 是两套刻度——P0≈对应 S0/S1 级事故或合规硬项的工单。全套规范出现的「P0/P1」均指工单优先级，不是事故等级。
- **定级示例对照**（示例为判级参照，非穷举；定级以影响面与纪律面为准，不以组件为准）：

| 事件示例 | 判级 | 判级依据 |
| --- | --- | --- |
| postgres_data 卷损坏且备份不可用 | S0 | 数据面持久性丢失（用户数据） |
| 观测日志出现可对上号的用户私人内容 | S0 | 数据边界失守（22 篇 §4 脱敏纪律） |
| 未确认事实以现网语气批量下发 | S0 | 事实纪律系统性失效（PR-R1） |
| 语音链路整体不可用（ASR 云主路断供） | S1 | 核心体验严重受损 |
| 账本确认双通道停摆（自动+人工均不可用） | S1 | 数据面核心能力停摆 |
| TTS local 单腿故障（cloud 可用） | S2 | 单能力降级，有 L4 退路 |
| 告警规则误报（噪声）或单面板缺数 | S2 | 值守面降级，不影响用户面 |
| rules.yml title/summary 文案旧值（现存） | S3 | 观感缺陷，进工单池 |

- **响应时限**：上表「响应预期」现为定性描述；定量时限（S0 即刻、S1 ≤15min 量级为候选值）、值班职责、升级链与复盘制度归 **27 篇，规划中（未定量）**——上线就绪检查单挂钩项；定量前不得宣称已有响应时限 SLA。
- **降级可见性**（REL-30）：每一次降级在 trace/账本留痕（原因码、回执态），运营经 /ws/ops 与直播监听页可见；「静默降级」属缺陷。

## 5. 降级层级总表（八层）

可靠性设计主基调：**每一层都有退路，用户永远收到可用回应**。现网降级路径按层级归纳（承接 PRD NFR-REL 5.2.2，与 20 篇语音链路降级链互引）：

| 层级 | 故障 | 降级行为 | 状态 |
| --- | --- | --- | --- |
| L1 断句 | smart-turn sidecar 不可用/超时（默认 500ms） | 三插槽判定链回落 VAD 静默 1400ms / 提前问 600ms | 已实现 |
| L2 转写 | ASR 超时 30s / 熔断（3 次/10s） | `voice_status` 三态通知 + `text_fallback` 文字路径 | 已实现 |
| L3 生成 | 润色超时 5s / 护栏拦截 | 回落确定性话术；拒绝原因入 trace 可回放 | 已实现 |
| L4 合成 | 云端 TTS 故障 | 供给三态切换（运营台 PATCH /api/console/tts-supply）；local_first 下本地腿健康门控未过则 409 拒切 | 已实现 |
| L5 数据源 | 赛程源停摆/漂移 | 停摆固定话术 + reason code `schedule_unavailable`；漂移序号否决自动确认；人工接管（takeover→paused） | 已实现 |
| L6 连接 | WS 断线 | 客户端重连 ≤5 次（退避 1-8s）+ 补发队列 4 条；服务端恢复未送达回合；投递七态推进、迟到回执只记 client_late | 已实现 |
| L7 隐私面 | 无 DATABASE_URL | 隐私 Store 降级内存形态（进程重启即失，如实降级，见 22 篇） | 已实现（含边界） |
| L8 观测面 | 未配置 QIUQIU_GRAFANA_URL | 观测页渲染部署指引占位卡，不阻塞其余页面 | 已实现 |

## 7. 设计说明

1. **与迁移源的关系**：本篇承接 v2 卷5《55-WebSocket同步、重连与可靠投递》的机制层与《58》的观测/演练层、《60》的值守层。55 章的全部参数（≤5 次/1-8s/25s/4 条/512/4096/15min/45s·12s）经复核逐值属实，原样入表；58 章的演练方法论（前置清单/不变量/停止条件）归 27 篇，本篇只留演练实证结论与挂钩。
2. **为什么现在没有对外 SLO**：单实例 compose 演示形态下承诺 99.5% 是自欺——没有多副本、没有灰度面、没有容量口径。诚实降级为「已测量的指标+值守判断值」，把 SLO 立项绑在受控试用前置上（NFR-REL-001），是现网为真原则在可靠性篇的直接体现。
3. **「目标值待定」不是缺陷登记**：§1 各表目标列待定，是因为目标承诺必须随 SLO 立项裁决给出并挂验收；先写数字后建采集面是 v2「指标无来源」病根的重演，本篇以 REL-03/04 双纪律阻断。
4. **告警判断值 ≠ SLO 目标**：3000/1800/3/600 是 2026-06-01 裁决跳过观测期直接收紧的值守噪声线；SLO 目标（若立项）可能更严或更宽。首响规则②休眠保留的处理（保留规则+注记而非删除）是为了让句粒度方案重开时有现成锚点——任何一侧（删规则或当活规则用）都是对裁决史的篡改。
5. **落库代理的诚实边界**：熔断器与 poller freshness 是进程内状态，账本里没有它们的列；告警用 `agent_traces.error` 计数与 match_events 停摆做代理，并在文件头登记「这是代理」——宁可告警语义粗一点，也不为凑指标造一张假表。/ws/ops 丢弃不规则化是同一原则的另一半：没有落库面就明说不规则化，而非默默漏掉。
6. **S0-S3 刻度收口**：v2 卷5-62 章的 S3=最重与业界惯例相反，且跨篇漂移；2026-06 统一裁决（B8）定为 S0=最严重。本篇是刻度定义的工程侧落点，响应时限定量归 27 篇并明确「未定量前不得宣称 SLA」，防止刻度统一变成时限承诺的既成事实。
7. **ClientHealthLedger 重启清零是设计不是缺陷**：客户端健康事件是「现在钟不钟」的排障面，持久化它们会造出第二事实源；丢历史的代价由「10 分钟限频+降级可复现」补偿。
8. **为什么预算政策先于目标值落地（REL-05/06）**：对标（SRE Workbook 六件套）显示 SLO 体系若缺预算半边（合规窗口/error budget/预算政策/burn-rate），会被「目标待定」纪律结构性掩盖——即使立项裁决完成，按旧结构也只会产出「目标列填数」，不会自动产出预算政策。把六件套定为立项交付物清单、政策以占位骨架先行，是让「烧尽怎么办」在目标数字出现前就有答案骨架，避免政策在烧尽现场临时拼凑；占位期不构成触发依据（REL-06 时态声明），与「先写数字后建采集面」的 REL-03/04 阻断逻辑同构。
