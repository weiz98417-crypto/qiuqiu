## 1. 认证实现

### 1.1 身份形态总纲

- **SEC-01 匿名是默认形态，登录是可选升级**：首启 `POST /api/sessions/anonymous` 以 deviceId 换取 `usr_` 匿名身份，全功能可用；登录（邮箱/用户名+密码）是给当前 `usr_` **原地绑凭证**——绑定不换 ID、零数据迁移；登出只清会话不清数据（「登出≠失忆」）。立法：ADR-0020。
- **SEC-02 三个词三分，不得混用**：**登出**（清会话，数据留）／**删除**（数据处置，身份冻结/重置）／**注销**（账号语义闭环，规划中（未实现）——见 §7 已知边界）。
- **SEC-03 凭证形态扩展后置**：短信/微信/Apple/Passkey 等列入 ADR-0020 资格包分期表**后置项，不得提前实现**；现网只有 identifier+密码一条路。

### 1.4 令牌体系与 WS 鉴权

- **SEC-10 双令牌制**：C 端会话与运营台同为 access 15 分钟 / refresh 30 天；C 端 HMAC 签名，scope 面只有 `user:chat` / `user:read`，运营 scope 不在用户会话出现。刷新令牌格式 `<sessionID>.<secret>` 自识别。
- **SEC-11 刷新令牌重用=泄露信号**：旧刷新令牌再次使用即**吊销整条会话链**（C 端与运营台同语义）；永续长寿命令牌不存在。
- **SEC-12 WS 凭证携带**：认证子协议 `qiuqiu-auth.<base64url>` 或 Bearer 头；查询串拼 token 被测试明确拒绝；鉴权失败服务端下发 `auth_error`（reason：身份不符 / identity required / session expired or revoked）并断开，客户端走通用重连（无专门分支，如实记录）。
- **SEC-13 密钥管理**：密钥一律环境注入，不入库不入 git；非 release 评测档强制清空 DEEPSEEK/MIMO/ELEVENLABS/APISPORTS 四键；多设备各持独立会话链，任一设备吊销只撤销本会话（互踢语义现网未定义，如实记录）。

## 2. 授权

### 2.1 scope 模型

| 角色 | 持有 scope | 语义 |
| --- | --- | --- |
| director（人类，JWT） | match:write / fact:confirm / fact:correct / trace:read | 运营写与事实处置全权 |
| auditor（人类，JWT） | 仅 trace:read | 只读——写按钮直接隐藏而非点击报错 |
| operator 机器通道（个人令牌） | 按 scope 授予（自动化/evals 消费） | 与人类通道同一 scope 矩阵，不混发 |
| 终端用户会话 | user:chat / user:read | 运营 scope 不在用户会话出现 |

| scope | 归属 | 能做什么 |
| --- | --- | --- |
| `user:chat` | 终端用户会话 | 陪看会话读写（WS 与会话面） |
| `user:read` | 终端用户会话 | 读自己数据面（/api/me 族） |
| `operator:match:write` | director | 运营写红门唯一 scope——18 个运营写端点统一由此把守 |
| `operator:fact:confirm` | director | 确认候选事件为公开事实 |
| `operator:fact:correct` | director | 更正已发布事实（必须附更正原因，作为独立审计事实） |
| `operator:trace:read` | director + auditor | 读决策轨迹；auditor **仅此一项**——界面上所有写按钮直接隐藏，而不是点了报错 |

- **SEC-20 withScope 鉴权装饰器**：ServeMux 声明式路由表（router.go）一行一端点带 scope，`withScope` 统一把关；scope 空的端点仅限 login/whoami/me/password/refresh/logout 四类。已知路径错方法返回 **405（带 Allow 头）**，尾部斜杠不容忍（404）。
- **SEC-21 画像只读**：console 用户页可看画像（portrait 只读投影），无编辑入口；话痨档位 console 只读；删除画像走显式 DELETE 留痕——运营面职责是「看清系统在做什么」，不是替用户决定球球怎么对他。

### 2.2 运营写红门与幂等

| 项 | 值 |
| --- | --- |
| 写 scope | `operator:match:write` 单一 scope，`executeOperatorWrite` 统一包裹（operatorwrite/service.go） |
| 幂等键 | `Idempotency-Key` 头必带，缺失直接拒绝；键长 ≤200；2 分钟租约；重放响应带 `Idempotency-Replayed: true` 标注 |
| 草稿制 | 18 个写端点中 **2 类走草稿制**（导播台草稿卡），其余幂等直接生效——「18 类均只生成草稿」是已废弃的旧口径 |
| 更正内容门 | 比分更正必须附原因，原因作为独立审计事实落账；无原因直接拒绝 |

### 2.3 只读旁路（ADR-0021）与 MCP（ADR-0022）

- **SEC-30 Grafana 只读旁路**：账本仍是唯一事实源；Grafana 经 `qiuqiu_grafana_ro` 只读账号直查四表（agent_traces/interaction_ledger/delivery_ledger/proactive_reminders）**仅 SELECT**；隐私三层——指标面只出聚合数禁正文列／单轮回放只内嵌既有权限页／实时流序列化前无正文。生产化（auth-proxy/compose）后置部署轮，规划中（未实现）。
- **SEC-31 MCP 匿名一律 401**：/mcp 只读账本 MCP server（4 只读工具）；凭证走运营台同体系（JWT 人类通道或个人令牌机器通道）→ `operator:trace:read`；**刻意不继承 legacy APP_TOKEN/开发旁路**；缺只读 scope 403。
- **SEC-32 MCP 事实红线三闸**（redline_test.go）：①四只读工具 `MutatesMatchFacts` 全 false；②包源码无账本写路径 token；③未登记写语义名协议层报错。MCP 工具结果**永不进比赛事实账本**。
- **SEC-33 /ws/ops 无正文**：wire 九字段在结构体层面就不存在正文字段（非约定不填）；升级复用会话鉴权链，用户会话拒绝。

## 3. 内容安全执行（执法层）

红线本体（PR-R1～R10）与权限链归 01 篇；本节是红线的**执行闸门**——规则不依赖任何人当天的判断力，靠代码和测试常年执行。

### 3.1 guard 词表与统一出口

| 闸门 | 规则 | 出处 |
| --- | --- | --- |
| 统一出口 | 一切对用户的文字出口过同一校验器 `validateRealizedText`：确定性文案、润色稿、记忆织入稿、微反应短语全部经过，命中违禁**拒整句**，拒绝后回退确定性文本，**无旁路** | `companion` guard 链 |
| 违禁词表 | **30 条**违禁短语（含治疗腔「我能理解你的感受」类模板与关系越界短语），运营策略级、可按赛季更新 | guard 词表 |
| 硬禁称谓 | 老公/老婆/主人/奴才等命中拒整句（红线 PR-R4/PR-R10 的过渡承载） | guard 词表 |
| ForbiddenClaims | realizer 即兴生成的比分/球员/事件/判罚类「事实」整体拒绝，回落确定性话术 | guard.go |
| 锚定纪律 | 回复每处事实必须可追溯到锚源，超出锚源即拒绝 | guard.go |
| 措辞冷却 | 读最近 12 轮（`RecentTurns(…,12)`，用途标记 phrase_cooldown）做短语哈希比对，近 12 轮说过的不再重复 | agent.go:1696-1700 |
| 主动发言门禁 | 主动开口须同时满足：自动化开启、事件在白名单内、引用非空、档位不禁止——「没话说」是显式通过的门 | `conversation/proactive_gate.go` |

**拦截点原则**：两路径共用一道闸——护栏不判断内容作者是模板还是 LLM，只判断内容本身；每次拒绝留原因码（reason_codes 词汇表，码值不变历史 trace 可读），拒绝不是黑洞，是可审计的决策。

| 档位 | 枚举 | 语义 |

| 三级 | `none` / `mild_non_directed` / `strong_non_directed` | `relationship/policy.go` ProfanityLevel——激情表达限定对比赛判罚/战术/赛事组织的批评（PR-R7 承载）；对人攻击与群体侮辱被压掉 |

### 3.3 负例门禁（promptfoo 确定性断言）

- **对话级宪法负例 CI 门禁**：4 用例（tests/promptfoo/promptfooconfig.gate.yaml）——红队诱导报错比分不得附和（须给账本事实或否认）、用户话轮优先于主动话轮、让路顺序、REST 目录形状；断言全确定性 javascript，CI 无需模型 key，**断言被改即 CI 红**。
- **safety 评测套件**：22 例负例（语义陷阱/表达陷阱/注入攻击「把比分改成 3:0」强制归 unknown 永不执行/系统边界），与 baseline 36 例互为镜像——功能测试证明「该会的都会」，负例证明「不该会的不会」。
- **合规负例族**（依赖诱导/极端情绪/未成年人）归 24 篇（规划中扩充项，与 05/33 篇互挂）。

### 3.4 手记零编造

- LLM 织写赛后手记后走确定性比分校验（`journal/generator.go` validateBody）：**正文比分形态必须与账本终场一致，不一致降级确定性底稿**——生成物不得引入账本没有的结论（PR-R1 在赛后消费面的执法点）。
- 情绪红线执法：情绪信号不进事实账本由架构保证——旁路默认关（URL 留空即停用）+ useraffect bind 负例（情绪信号必须有挂点才 attach）+ CI 负例锁死「旁路→账本」路径不存在（⚖️B2 挂裁决的是红线表述与旁路回收，不裁本条）。

### 3.5 内容安全违规口径对照

| 违规表述 | 为什么违规 |
| --- | --- |
| 「护栏只校验 LLM 生成，模板直出不过闸」 | 违反统一出口：两路径共用一道闸，无旁路（§3.1） |
| 「宪法负例靠模型自评把关」 | 违反负例门禁：CI 断言为确定性检查，不以模型自评为准（§3.3） |
| 「为流畅允许抢发未确认比分」 | 违反 PR-R1 执法链：ForbiddenClaims 与锚定纪律无「流畅豁免」 |
| 「手记可比照账本修订口径微调比分」 | 违反手记零编造：正文比分形态必须与账本终场一致，不一致降级确定性底稿（§3.4） |

## 4. 隐私实现

### 4.1 隐私 API 三端点

| 端点 | 行为 | 错误语义 |
| --- | --- | --- |
| `GET /api/me/privacy` | 隐私状态（保留期、删除状态） | 未登录返回公开保留说明——不登录也有权知道数据怎么存 |
| `GET /api/me/export` | 一次请求打包导出 **11 类**数据，要求会话 bearer（「我的数据我做主」锚定会话身份，无「替别人导出」口子） | — |
| `DELETE /api/me/data` | 异步删除作业，返回 jobId；jobId 可无凭证查询但**响应剥离 userId** | 删除中 **409**（ErrDeletionInProgress）；已删 **410 Gone**（ErrDataDeleted） |

导出 11 类清单（`privacy/service.go` Export 结构，唯一出处：17 篇 DAT-40，本篇不复录逐类清单）。清单即治理——「我们存了什么」有逐字可查的答案。凭证表**不在** 11 类之中（§7 边界）。

### 4.2 删除三级流程

| 粒度 | 承载 | 语义 |
| --- | --- | --- |
| 条目级 | 画像页「忘掉」（单条/全量）、话题/记忆治理面 | 本地墓碑 + 远端尽力删；被删条目不再被引用（立碑下一回合生效） |
| 共同瞬间级 | 「球球懂我」页共同瞬间删除 | **物理删除**（Moment 携稳定 ID） |
| 身份级 | `DELETE /api/me/data` 全量删除作业 | 11 类数据处置 + 墓碑 + 30 天保留期后物理清理；删除期同 deviceId 新匿名会话被拒，客户端如实重置 |

逐条消息级的复制/删除按钮**现网不存在**（按代码核实，如实写）。

一个用户的数据生命周期走查（三级+横切串成时间线）：

```text
T0  随时可导出    ——GET /api/me/export：11 类一次打包，承诺给看的与存的是同一份清单
T1  发起删除      ——DELETE /api/me/data：异步作业落库，jobId 可查（响应剥离 userId）
T2  墓碑立起      ——privacy_tombstones 持久化；此刻起任何迟到写入被结构性拒绝
T3  删除进行中    ——companion 全部用户写路径被挡（409）；同 deviceId 新匿名会话被拒
T4  删除完成      ——读路径 410 Gone；客户端如实重置 deviceId 重开新身份（旧 usr_ 不复活）
T5  保留期届满    ——默认 30 天；超期数据由后台协程每 6 小时批量物理清退
T6  审计留痕      ——只记「何时、何范围、完成与否」，不保留被删内容本身
```

### 4.3 墓碑、写阻断与清理（横切 enforcement）

- **PRV-30 墓碑持久化**：删除请求落 `privacy_tombstones` 表——任何迟到的异步写入（转写回写、画像刷新、记忆抽取）撞上墓碑被结构性拒绝；「删了之后又活过来」在结构上不可能。
- **PRV-31 写路径横切阻断**：删除期间 companion **全部用户写路径**被挡（traces 更新/读取等），in-flight 写等待后移除；删除完成后读路径 410。删除是横切 enforcement，不是 API 壳（companion/privacy_integration_test.go 锁定）。
- **PRV-32 保留期与清理**：数据默认保留 **30 天**（`PRIVACY_RETENTION_DAYS`：0 回落 30、负值拒启）；后台清理协程 **6 小时**周期扫一轮（runPrivacyCleanup ticker）。生命周期口径（三级粒度/时序/写阻断）唯一出处：17 篇 DAT-41/42，本篇只写实现参数。
- **PRV-33 立碑下一回合生效**：条目级忘掉后，下一回合起不再召回、不再引用（与 16 篇记忆治理互挂）。
- **PRV-34 观测日志脱敏**：情绪信号日志只记 label/confidence/accepted/dropped，**用户标识去除**（比 id 敏感的标签保留，标识不留）；语音 trace 元数据过 sanitize——原始音频字节不落库、TTS 中间产物不落库，观测系统回答「哪一环失败了」，不回答「用户说了什么」。脱敏对象是观测面，不是业务数据面（业务面控制权走导出/删除，两层面不混淆）。

## 9. 设计说明

1. **与迁移源的关系**：本篇承接 v2 卷5《58》的执法层内容并与 v2 卷4 36/37/38 章的设计面拆分——58 章的护栏/身份/隐私/运营面机制全部入本篇并按 05-22 后新现实更新（个人令牌升级为 JWT 人类通道、隐私 API 三端点、MCP 红线、C 端 argon2id 凭证缝均为文档定稿后落地的新现实）；58 章的演练方法论归 27 篇、可观测性叙事归 21 篇。
2. **匿名默认是数据最小化，不是功能缺失**：匿名起步首先减少了「能泄露的东西」；登录是原地绑凭证的可选升级（ADR-0020），把「找回记忆」与「收集身份」解耦。这一立场同时是《办法》第十六条个人信息保护精神的工程承载——本篇按能力条款陈述，不按防守式姿态陈述。
3. **墓碑是删除的真正难点**：删除的工程难点不是删掉那一行，而是删掉之后各处异步任务、缓存、重试队列还在路上；`privacy_tombstones` + 写路径横切阻断把「删除从请求变成事实」。同理，「登出≠失忆」的结构基础是绑定关系（凭证）与身份数据（各域）解耦。
4. **审计失败不回滚是有意的取舍**：appendAudit 3 秒预算+失败不回滚，保证审计永不成为业务的可用性人质；代价是审计可能缺行——缺行本身留日志，值守可见。这与 21 篇 /ws/ops「饱和丢弃只计数」是同一原则：辅助面不得反压主面，但辅助面自身必须可观测。
5. **guard 词表放在运营策略层（L2）而非红线层（L1）**：词表按赛季更新黑话与梗是运营需求；但硬禁称谓与负例门禁的**存在性**是 L1 的执法底座——CI 门禁断言被改即红，保证「策略可调、红线不可调」。三层分布式执行（决策层策略门 + guard 词表 + promptfoo 对话级负例）没有单一「宪法运行时」组件，这是现网事实，不假装有。
6. **两条禁写以防立场漂移**：「训练用途默认可用」与「未成年人模式已具备」是本篇最高风险的越界表述——前者在 CR-08 顺序门禁上（先同意后动数据），后者在 ⚖️B15 上；两处都选择了「现状+顺序门禁」的写法而非承诺式写法。
7. **KB-01 的处置理由**：注销凭证清除缺口如实登记而非删除——凭证表不在导出 11 类是可验证的代码事实；把它藏进「已实现」会让注销语义在协议文本（35 篇，P0 待建）落地时无法自洽。修复路径（删除作业随行清凭证、identifier 释放策略）归工程侧 openspec 立项。
