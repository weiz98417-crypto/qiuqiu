# 11 页面与视觉规范

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：球迷在什么界面上与球球相处——客户端十页的职责与导航、陪看主台四区布局、视觉基线（主题 token 现状）、状态与空态、深链进入、PWA 形态与响应式规则。页面承载的业务规则（语音链、表现白名单、事实纪律、记忆治理）不落本篇，一律指针到对应篇；本篇只立「页面承诺什么、不承诺什么」。规则 ID 前缀 UI，引用格式「11/UI-NN」。

**迁移来源**：v2 档案《34-用户端页面与视觉规格》（六屏口径、《43-原型验证设计》（Stitch 原型生产流程，历史存档——其职责已由真实客户端与自动化走查承担）。旧 34 章「六个屏幕」「深链需显式确认」「赛前大厅/比赛进入页」等口径按现网逐一纠正（差异清单见 §8）。

**术语纪律**：页面中文名以本篇 §3.1 清单为准（以 client 路由/文件为工程唯一标识）；「陪看主台」不写「陪看主屏」；未入座态称「数据视图」、入座后称「陪看主台」——「赛前大厅」「比赛进入页」为旧档案用语，不随迁移。运营台（console/）10 页九格归 26 篇，本篇不述。

## 1. 规则与红线

**UI-01 页面全集十页，守恒管理**。客户端页面全集为 10 个（清单见 §3.1），无更多、无更少；新增页面必须先入此表再动工（规划项如投诉表单页落地时先改 FR-UI-001 页面表）。「账号」不是独立页——客户端账号能力在设置页第 11 节内。「事实管理」「推送设置」等同样不是页面——分别内嵌于比赛页时间线与（规划中）设置节。

**UI-02 唯一入口是入口分流页，导航全部压栈**。Flutter 无命名路由，全部页面由 `MaterialPageRoute` 压栈挂载，唯一 home 是入口分流页（MatchEntryScreen）：web 端检测 URL 深链参数决定去向，无深链即进赛程目录。不存在任何绕过入口分流页的常驻入口；深链是唯一直进通道。导航关系总图（压栈方向）：

```
入口分流页 ─┬─(无深链)→ 赛程目录页 → 比赛页（数据视图 ⇄ 陪看主台）
            └─(?matchId= 深链)→ 比赛页（直接入座）
比赛页 ─┬→ 设置页 ─┬→ 登录/注册页
        │          └→（球球懂我入口）球球懂我页 →（手记入口，注入式）球友手记页
        ├→ 球球懂我页（比赛页直达）
        └→ 球友手记页（比赛页直达）
```

**UI-03 强制暗色主题，全局唯一**。全局唯一主题（`AppTheme.dark`），不提供亮色模式，不存在用户可切换主题。视觉基线见 §3.3。

**UI-04 主台四区层级：舞台可失败，输入与控制不可遮挡**。入座后的比赛页自上而下承载四要素——舞台区（Live2D 数字人）、字幕区（球球每句回复同步出字）、输入区（对话坞）、控制与比赛信息区。层级裁决：任何时刻「看比分、说话、退出」三件事必须可达；舞台区指针事件被禁（不截胡交互、不抢焦点），任何元素不得遮挡输入区导致文字输入不可达。反例：全屏庆祝动效盖住对话坞；断线提示遮死返回路径。

**UI-05 声音与字幕永不互斥**。不允许出现「只有声音没有字幕」的回复呈现：球球每句回复同步出字，语音播放失败时字幕兜底强制显示，关闭声音后字幕和文字对话保留——这是无障碍双通道等价的现网基线（细则归 12 篇，页面承载在本条锁定）。语音播放回退到字幕兜底时界面明确呈现该状态，不假装正常。

**UI-06 已入座态的破坏性动作必须确认**。退出陪看、切换比赛在已入座态弹确认框（防误触）；确认围绕数据与服务结果（「将结束本场陪看」），不做情绪化二次挽留、不设置「再看一会儿」式更大主按钮。

**UI-07 事实状态以文字承载，不以颜色或球球表情为唯一表达**。比分头与事实卡的「已确认/待确认/已更正/存在冲突」语义由文字承载（承载规则归 14 篇，页面呈现纪律在本条）：角色庆祝不能与已确认事实共用同一强信号，事实的视觉激烈程度永不比状态文字更肯定。进球烟花 overlay 是唯一的高能视觉事件（§3.2），只在 goal 事件触发且自动消退。

**UI-08 返回语义与栈纪律**。压栈导航的返回=逐级 pop（系统返回手势/按钮）：比赛页返回出栈触发已入座确认（UI-06）；设置页/懂我页/手记页/登录页返回即回到推入方，不重排栈序。手记入口是注入式回调（懂我页的 `onOpenJournal` 由宿主注入，null 即入口隐藏）——入口存在与否是调用方职责，不是懂我页自身状态；不得把它写成懂我页的固定节。

**UI-09 页面即承诺：入口文案不虚构能力**。页面上出现的每个入口都对应现网实有的能力：不出现「推送通知设置」「记忆暂停」「干预级别」类开关（不存在，规划项见 §6）；不出现「客服/帮助中心」死入口（现网无帮助面，FR-UI-015 规划中）；「账号与同步」节的话术承诺（登出≠失忆）与实际登出语义一致（细则归 05/22 篇，页面文案逐字归 13 篇 copy sheet）。

### 3.2 陪看主台四区布局

**UI-31 四区定义与优先级**。入座后的比赛页四区自上而下；比例随屏幕弹性，优先级固定：

| 区 | 内容 | 关键规则 |
| --- | --- | --- |
| 控制与比赛信息区（顶部） | 返回、对阵/比分/比赛状态、断线重连提示、切比赛与退出入口 | 位置稳定不跳动；事实状态文字先行（UI-07）；退出路径永不被覆盖 |
| 舞台区 | Live2D 数字人（web 同源 iframe / Android 内嵌 webview，机制归 10 篇） | 常驻、指针事件禁用（不截胡交互不抢焦点）；可失败组件（10/EMO-61）——加载中「球球正在入场…」、失败态重试按钮 |
| 字幕区 | 球球回复同步出字；语音失败字幕兜底强制显示并明示状态 | 不累计成聊天瀑布；不遮挡控制；与声音永不互斥（UI-05） |
| 输入区（对话坞） | 语音球常驻、文本输入展开收起、连续对话开关、打断动作 | 固定可及，任何动效不得遮挡（UI-04） |

**UI-32 高能时刻的两件配套**。①进球烟花 overlay：goal 事件触发全屏庆祝动效（一次性，自动消退）——比赛页唯一的高能视觉事件，不得用于其他事件或常驻；②振动反馈：goal/penalty/red_card 三事件 90ms，仅 Android（web 无原生振动通道，差异照实登记）。两者都不承载事实语义——比分与状态仍以文字先行。

**四区反例集（违规即改版）**：

| 反例 | 违反条款 |
| --- | --- |
| 舞台加载动画遮挡返回按钮或对话坞 | UI-04 |
| 断线提示浮层永久遮挡比分头且无自动收起 | UI-04/45 |
| 语音失败后只留空白不留字幕、无状态说明 | UI-05 |
| 烟花 overlay 在 var_check/big_chance 等非 goal 事件触发 | UI-32 |
| 事实待确认时烟花或庆祝表情先行于状态文字 | UI-07 |
| 输入区被键盘顶起后字幕区不收缩、无法看到正在出字的回复 | UI-04（四区弹性裁决） |

**UI-33 入座双形态的分界**。未入座=数据视图（比分头+阵容/事件/统计标签页，安静的信息面）；入座=陪看主台（四区全开）。入座动作与手动/深链进入走同一条会话建立链（identify → session_opened），无特权路径。未入座态不靠角色闲聊填满等待。

### 3.3 视觉基线与 token 登记法

**UI-41 两层 token 登记法（方法论）**。设计 token 分两层登记：**primitive 层**是具名原子值（色板/间距/字体/字阶/控件规格，见 §2.2——现网已存在，以 `app_theme.dart` 为唯一代码源）；**semantic 层**是按用途命名的语义令牌（如 confirmed/waiting/conflict/muted-danger），引用语义不引用原始值，换肤只改映射。规则：①新 UI 一律引用 token，不得硬编码色值/字号；②primitive 变更走主题文件单点提交；③semantic 层每新增一个令牌必须登记用途与禁止用法（如「不得以颜色为唯一状态表达」），未登记不得使用。

**UI-42 semantic 层现状：待补（登记在案）**。现网代码只有 primitive 层；「已确认/待确认/已更正/存在冲突」「错误/警示/成功」等状态语义目前直接引用 green/yellow/red 原始值，semantic 层映射未建立——标**待补**（§6），补齐前新页面引用原始值属已知债务而非规范背书。历史对照：Stitch 原型阶段的浅色测试视觉合同（#F7F7F5 底/#2047D4 主操作等）是历史存档口径，已被现网暗色主题整体取代，不得作为视觉依据引用。

**UI-43 排版纪律**。正文不小于 14（bodyMedium 下限）；比分/关键数字用 scoreboard 字体（Barlow Condensed）保证一瞥可读；状态文字用明确词语（「待确认」「连接恢复中」），不写拟人化模糊语；小屏宁可减少一次性信息量，不以极小字号压缩关键状态。字号缩放适配为规划项（§6，FR-UI-014）。

### 3.4 状态与空态规范

**UI-44 加载态**。页面数据加载给稳定占位与「正在准备」类文字，不用角色动作伪装系统进度；舞台加载独立呈现「球球正在入场…」进度态（live region 可读），舞台未就绪不阻塞字幕、输入与比分——陪看主链路不依赖舞台就绪。web 舞台 8s 就绪超时兜底。

**UI-45 断线与重连态**。断线时明确提示「连接中断、正在重连」，说明哪些功能暂不可用，保留上次已知状态标记；重连成功明确告知「已恢复」；不假装实时、不用动画掩盖停滞。话痨档位断线时本地保存回调兜底，重连后以服务端持久层为准（FR-UI-005）。

**UI-46 空态（空目录/空记忆/空手记）**。空态说明原因与下一步，不制造「快来留下回忆」的空缺感；共同瞬间拉取失败静默隐藏该段——可感面宁可缺席不可报错打扰。逐页空态口径：

| 页面/段 | 空态呈现 | 禁止 |
| --- | --- | --- |
| 赛程目录页 | 说明当前无可看比赛，给「查看稍后赛程」类中性出口 | 用推荐位/活动位填空 |
| 球球懂我页（无画像） | 中性说明「球球还没有积累关于你的画像，一起看球会慢慢懂你」类文案 | 制造「快来留下回忆」的空缺感；用角色失落表情填充 |
| 共同瞬间段（拉取失败或为空） | 整段静默隐藏 | 报错横幅打扰；占位 skeleton 常驻 |
| 球友手记页/赛季册 | 中性说明，赛后生成后自然出现 | 倒计时催促；「球球在等你回来看」类文案 |
| 未完话题条（无开放话题） | 不渲染该段 | 保留空壳入口 |

**UI-47 首启态**。首启不设登录墙、不强制填资料：匿名会话由 ensureSession 静默建立（guest-first，启动不拦——存量刷新令牌先 refresh，401 即清档回匿名，会话语义归 05/22 篇）；首次见面（first_meeting）流程完成前不自动开连续对话，完成后按设置自动进入 freeTalk 监听；唤醒词首启有一次一句话引导（`wake_intro_shown` 只出现一次，开关默认关 opt-in）；登录页品牌区背景图约定路径 `assets/images/login-bg.jpg` 文件未入库，探测失败落晚霞渐变+落日辉光占位——视觉未定稿是登记在案的现状，不是缺陷隐瞒。
反例：首启弹登录拦截；引导文案写「开启唤醒词球球才能听到你」（默认关是 opt-in 承诺）；首启引导每次进比赛页重复出现。

### 3.5 深链与进入（⚖️B3）

**UI-21 深链直进是现网行为**。web 端识别 URL 查询参数 `?matchId=`：有值即以 autoEnter=true 直接挂载该场比赛页并入座，无值进赛程目录；退出深链比赛回入口分流并清深链参数（onExit 回调），URL 与导航状态干净、不残留不意外重进。深链仅 web 生效（kIsWeb 分支），Android 壳无 URI 深链注册。深链入座与手动入座走同一条会话建立链，不绕过会话鉴权与匿名身份建立。
⚖️B3：旧档案「深链进入需用户显式确认」的承诺已废弃（显式确认步从未实现）；直进是转化路径最短的现网行为，是否恢复确认步待裁决——裁决前本篇按「直进」书写，任何文档不得以现网语气写「深链需确认」。

### 3.6 PWA 形态与多端差异

**UI-22 web 端是可安装 PWA（现网交付形态）**。web 构建带 manifest：应用名「球球 · 数字人陪看」、standalone 独立窗口、竖屏锁定（portrait-primary）、主题色 #E83A24、背景 #070B12、4 枚图标（192/512 各普通+maskable）；产物由后端静态托管，经浏览器安装流程获得独立窗口；prefer_related_applications=false（安装不引导跳 Android 原生应用）。反例：把 web 形态描述为「仅网页」或把 PWA 写成规划项均失实。

**UI-23 双端差异照实登记，承诺不缩水也不虚报**。web：PWA、同源 iframe 舞台、无唤醒词（stub）、无原生振动与原生音频引擎；Android：应用内 webview+loopback 舞台、唤醒词（sherpa-onnx 本地 KWS）、原生振动。两端路径不对称是**常态而非缺陷**；核心陪看闭环（入座-对话-表达）两端都完整。Android 壳成熟度边界照实登记：release 构建仍用 debug 签名（工程 TODO）、权限最小化（INTERNET+RECORD_AUDIO）。API 基址链两端一致（§2.1）。

**双端差异矩阵**：

| 能力面 | web（PWA） | Android（壳） |
| --- | --- | --- |
| 安装形态 | 浏览器安装独立窗口（standalone） | 应用包 com.qiuqiu.companion |
| 舞台载体 | 同源 iframe + postMessage 桥 | 内嵌 webview + loopback 资产服务器（机制归 10 篇） |
| 唤醒词 | 无（stub，设置开关不出现原生行为） | sherpa-onnx 本地 KWS |
| 振动反馈 | 无 | goal/penalty/red_card 90ms |
| 深链 | `?matchId=` 直进（autoEnter） | 无 URI 深链注册 |
| 录音链 | web 录音器（RMS VAD/流式分片，参数归 06 篇） | 原生采集 |
| 权限 | 浏览器权限模型 | 仅 INTERNET+RECORD_AUDIO |

### 3.7 响应式与断点

**UI-24 竖屏优先，宽屏只做布局层自适应**。manifest 锁定 portrait-primary：桌面宽屏使用时应用仍按竖屏布局呈现，宽屏自适应仅到布局层——现网唯一显式断点是登录页 >900px 左右分栏（品牌区+表单卡；竖屏品牌区在上）；不提供横版专用布局承诺。布局弹性规则：四区比例随屏幕伸缩，但 UI-04 的可达性裁决在任何宽度不变；字号/对比度/读屏适配归 12 篇规划项。

| 环境 | 布局行为 | 明确不做 |
| --- | --- | --- |
| 窄屏/竖屏（基准形态） | 四区自上而下，输入区拇指可及 | 底部面板遮死退出路径 |
| 桌面宽屏（PWA 独立窗口） | 仍按竖屏布局居中呈现；登录页 >900px 左右分栏 | 横版专用布局；多栏仪表盘化 |
| 系统大字号 | 关键状态与控制优先保留（规划细则归 12 篇 FR-UI-014） | 以固定高度截断「等待确认」类关键状态 |
| 触达 | 图标按钮最小 48×48、主按钮 48×52（§2.2 控件 token） | 触达目标小于控件 token 下限 |

## 4. 降级与异常

**UI-51 断线降级**。见 UI-45；断线期间对话不可用时，比分头与数据视图仍以最后快照呈现并标记滞后；重连后档位与会话状态按服务端为准恢复。

**UI-52 语音失败降级**。语音播放失败→字幕兜底强制显示并明示状态（UI-05）；关闭声音→播放队列暂停、字幕与文字对话完整保留；声音与字幕永不互斥。web 端无原生音频引擎属双端差异（UI-23），不写成缺陷。

**UI-53 舞台失败降级**。加载中进度态→失败态「重新请球球入场」手动重试；不自动重试轰炸；比赛页其余三区（比分/字幕/输入）不受影响。静态形象/自动隐藏两种降级形态**规划中（未实现）**（10 篇 §6 同源登记）。白名单外动作名落待机兜底是运行时名称防护，与本条加载失败降级是两条机制。

**UI-54 环境兜底**。API 基址链三级兜底（§2.1）；开发兜底地址仅模拟器回环可用，真机按部署基址——本地端口断裂问题登记 ⚖️B11，本地联调按可跑通的真实路径书写，配置修复另开单。共享环境（投屏/同看）保守呈现为设计目标，现网无独立「共享模式」开关——不虚写（画像是用户主动进入的页面，比赛页不自动展开画像内容）。

**UI-55 帮助与投诉入口：现网不存在**。客户端当前无任何反馈/举报入口；「帮助与投诉」为规划中（未实现，P0，FR-UI-015，《办法》第二十一条承载）——上线前任何材料不得宣称「可在应用内投诉」（§6）。

## 8. 设计说明（与旧 34/43 章的差异，非需求条款）

1. **六屏→十页（本篇最大的结构修正）**。旧 34 章「用户端由六个屏幕组成：比赛目录页、赛前大厅、比赛进入页、比赛页、画像页、设置页」；现网页面全集为 10 个（§3.1）——登录/注册页、球友手记/赛季记忆册页为 05-22 后新增，入口分流页与数据视图在旧稿中被「赛前大厅/比赛进入页」两个旧概念占据。v3 以 client 文件清单为唯一口径：旧「赛前大厅」对应未入座数据视图（MatchLobby），旧「比赛进入页（显式进入+自动进入默认关闭）」整体废弃——现网深链 autoEnter 直进（⚖️B3），手动进入经目录卡片即入座，不存在独立确认页。
2. **深链口径翻转（⚖️B3 显式化）**。旧 34 章 §5.7「无论点按还是深链，进入比赛画面都需要用户在进入页显式确认；自动进入默认关闭」——经代码核查该确认步从未实现，现网为 autoEnter 直进。v3 照现网书写并把差异登记为开放裁决（UI-21），不再保留旧承诺的现网语气。
3. **设置口径对齐**。旧 34 章 §5.6 设置清单五项（话痨三档/连续对话/字幕与声音/昵称/支持球队）且「等待服务端确认回执」；现网设置页为 11 节（补抢话打断、唤醒词、气氛感知说明行、球球懂我入口、账号与同步），且档位真源是本地偏好+服务端持久化组合——`talkativeness_ack` 客户端当前未消费（⚖️B12 关联），「等待服务端确认回执」表述作废。11 节逐节细则归 12 篇，本篇守页面清单口径。旧稿「默认刚好」类默认值按统一口径改写：叙述名低频档（quiet）/标准档（normal，默认）/热闹档（active），UI 文案串「安静/刚好/热闹」照实现网并登记 copy sheet 待统一。
4. **视觉基线从「语义承诺」落到「代码现状」**。旧 34 章 §4 以「不为具体色值做品牌定稿」的语义令牌框架叙述；v3 反转——primitive 层以 `app_theme.dart` 实测值如实登记（§2.2），semantic 层如实标待补（UI-42），不再用未落地的语义框架冒充现状。旧 43 章 Stitch 浅色测试合同（#F7F7F5/#2047D4 等）按历史存档处置：它的职责（原型走查）已由真实客户端+自动化走查承担，其色板与现网暗色主题无关，仅作历史引用。
5. **状态面收窄到现网实有**。旧 34 章 §7 的通用状态表含「语音补发中」「跟进已抑制」「比赛尚未开始倒计时」等条目——现网无语音补发机制、无跟进抑制提示页态。v3 状态与空态（§3.4）只保留现网实有的加载/断线/空态/首启四组；旧稿的「共享显示模式」「减少动效两级切换」等未落地控制面不随迁移（页面级相关规划已收窄到 §6 与 12 篇）。
6. **PWA 与十页同步入文**。web 端是 standalone 可安装 PWA 属现网交付形态（manifest 实测），旧 34 章 §6「响应式与跨环境规则」通篇没有可安装形态记载——v3 以 UI-22 补齐，并把「竖屏锁定+登录页 900px 分栏」定为现网响应式的真实边界，替代旧稿四布局模式的规划性叙述。
7. **旧 43 章的吸收方式**。43 章按历史存档保留于档案区；其「两端隔离合同」「页面验收看结构不看插画好看」的方法论结论被本篇 §3.1 走查口径与 §5 验收表吸收，操作步骤与英文提示词不随迁移。
8. **文体**：本篇为 reference 体。旧 34 章的设计论证（「三秒可见原则」「三门槛走查」）结论固化为 UI-04/07 条款与 §5 验收表；论证背景收本节。指标设计（三秒定位率等候选指标）归 28 篇指标体系，不在本篇立法。
