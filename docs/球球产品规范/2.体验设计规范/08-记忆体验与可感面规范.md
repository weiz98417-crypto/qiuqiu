# 08 记忆体验与可感面规范

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：记忆系统如何被用户「感受到」——球球记得什么、用户在哪里看见、如何修改与删除、记忆在对话里出现时凭什么可追溯。系统侧的写入队列、打分公式、召回融合、反思调度归 16 篇（记忆系统规范）；本篇只立体验契约与逐页规则。规则 ID 前缀 MEX，引用格式「08/MEX-NN」。

**迁移来源**：v2 档案《30-共同记忆与偏好召回设计》体验侧；语义召回、确定性打分、可感面四件（理由入口/话题条/微标注/懂我页总面）为 v2 30 章之后落地的新能力层，为 v3 新增叙述（差异清单见 §8）。

**导读**：§1 规则与红线｜§2 参数与预算表｜§3 交互契约（逐页体验规则）｜§4 降级与异常｜§5 验收与评测挂钩｜§6 规划中（未实现）｜§7 与相邻篇的分工｜§8 设计说明。

## 1. 规则与红线

### 1.1 记忆体验契约

**MEX-01 契约三句（可感/可查/可删）**。球球记得你，且这份记忆满足三个可验收属性：

| 属性 | 一句话 | 现网承载 |
| --- | --- | --- |
| 可感 | 记忆的出现有出处、有来路，不凭空说「我记得你说过」 | 主动引用码非空才放行（01/CITE-00）+ 理由入口（08/MEX-31） |
| 可查 | 用户看到的画像就是每回合注入球球上下文的同一份内容 | 「球球懂我」页（08/MEX-21），无第二个「后台真实画像」 |
| 可删 | 逐条忘掉、全部忘掉、共同瞬间忘掉、手记忘掉、全量导出后删除 | 墓碑立碑下一回合生效（08/MEX-41）+ `/api/me/export`+`DELETE`（08/MEX-45） |

**MEX-02 默认开启 + 事后治理（现网口径）**。自动跨场记忆默认开启（权限链 L5 出厂值）：观察自动入队、自动提取、自动反思，陪看全程对用户零打扰。用户的控制面在「事后」——查看（球球懂我页）、修改（内联编辑）、删除（立碑）、导出（11 类打包）。客户端设置页无记忆开关；记忆治理经球球懂我页与画像页承载，不在设置页 11 节（01/CHAIN-L4a）。

**MEX-03 「记忆可暂停」「逐条许可」= 规划中（未实现），⚖️B4**。现网不存在记忆总开关、写入前逐条/逐类询问、逐条暂停召回。任何文档、界面、客服口径不得以现网语气书写三者（PRD FR-MEM-022 现状红线）。逐条停止引用的合法现网路径是删除（立碑）：改一条、忘一条，引用随操作停止——这是「事后治理」语义，不是「暂停」语义，两者不得混写。

**MEX-04 看到的就是用到的**。「球球懂我」页展示的条目，就是每一回合被注入球球上下文的同一份内容；服务降级时页面如实显示降级后幸存的条目，不假装完整。球球不在对话里炫耀记忆能力、不口头解释内部机制（guard 词表拦截「关系记忆」「记忆库」类内部机制泄漏，01/EXP-G1 词表第 29/30 条）；机制可感性的承载是本篇 §3.4 的理由入口与各页界面，不是球球的口头自述。

**MEX-05 记忆不是拥有（红线 PR-R4 关系侧落点）**。用户删除任何记忆条目不需要理由；球球无情绪反应、无挽留、不把删除描述成伤害，用户的基础体验（事实、陪看、结束会话）不因删除打折扣。反例：删除一条偏好后球球说「我会想我们的回忆的」——违规（挽留叙事，01/RED-04 词表直拦）。

**MEX-06 画像描述选择，不描述人格**。画像条目只描述用户做过的事与选过的东西。「你修改过支持球队」是合格记忆；「你是怕麻烦的人」「你最需要安静陪伴」是系统对人的心理臆断，不写入画像（PRD FR-MEM-009 主张槽位单源：自述主张只落 preferences/user_stated）。用户的新选择永远优先于旧条目，球球按现在的方式服务，不翻旧账。

**MEX-07 第三人隐私不进记忆（红线 PR-R9）**。球球不诱导用户提供第三人可识别信息；已入账的第三人隐私经记忆治理（删除/立碑）清除，观测日志对已删数据脱敏。

**MEX-08 比分永远不进画像**。「球球懂你」的认知里没有比分——比分形态的主张在写回前被确定性红门零 LLM 直接拒绝（PRD FR-MEM-010）。比分只来自事实账本（14 篇）。反例：懂我页出现「你上次记错比分」类条目——违规，红门负例评测锁定。

### 1.2 可感面载体总表

| # | 载体 | 所在位置 | 数据源 | 治理粒度 | 细则 |
| --- | --- | --- | --- | --- | --- |
| 1 | 「球球懂我」页（画像） | 独立页（客户端 10 页之一） | `/api/me/portrait` | 读 / 内联改 / 单条忘 / 全部忘 | 08/MEX-21 |
| 2 | 共同瞬间段 + moments 列举 | 懂我页瞬间段；`GET /api/me/moments` | 向量瞬间库 Moment 投影 | 忘掉=物理删除 | 08/MEX-23 |
| 3 | 手记双 tab（手记 / 赛季记忆册） | 手记页（客户端 10 页之一） | journal API（账本投影+画像口味） | 点赞 / 忘掉（物理删）/ 文本分享 | 08/MEX-25 |
| 4 | 会话内可感三件（理由入口 / 话题条 / 微标注） | 陪看会话内 | reason 字段 / `/api/me/threads` / backchannel 通道 | 只读，续聊即消费 | 08/MEX-31～33 |

**MEX-09 三类阅读面的分野**。画像（「球球怎么看你」）、瞬间（「一起经历了什么」）、手记（「这一场怎么过来的」）是三种不同质地的阅读对象，不混排：画像条目可改可忘且直接改变球球行为；瞬间是账本事件的投影，只可忘（不可编辑——编辑即「造」）；手记是赛后成文，可点赞可分享可忘掉，永不参与对话生成。赛季册是手记+瞬间的装订合辑（只读）。

**MEX-10 失败判据（体验面的结构性失败，不是文案瑕疵）**：

| 失败形态 | 为什么是失败 |
| --- | --- |
| 用户不知道某项个性化从何而来 | 引用无出处、理由入口缺席——可感契约（MEX-01）破洞 |
| 球球因用户删除表现出委屈、挽留或体验降级 | 把权利操作拟人化（MEX-05），抬高撤回的心理成本 |
| 用户为「保住熟悉感」而不敢清理记忆 | 记忆成了关系抵押——治理三权（删/碑/导）失去意义 |
| 删除后旧事仍被提起 | 高严重度问题：先停止引用再修复，不以「偶发」淡化（MEX-57 承接） |

## 3. 交互契约（逐页体验规则）

### 3.1 「球球懂我」页（MEX-21）

**MEX-21a 页面定位**。懂我页是记忆的总可见入口：画像条目（读/改/忘）+ 共同瞬间段。页面首句说明（现网 UI 文案）：「这些是球球记住的关于你的印象，聊天时会自然提起。你可以修改，也可以让球球忘掉——改动立刻生效。」

**MEX-21a-1 页面区块与入口（现网结构）**：

| 区块 | 内容 | 可用操作 |
| --- | --- | --- |
| 画像条目区 | 按主题分组的印象条目，标来源（自动/你修改的） | 内联修改 / 单条忘掉 |
| 共同瞬间段 | Moment 投影倒序列举 | 单条忘掉（物理删） |
| 全部忘掉 | 页面级总开关动作 | 二次确认后本地+远端全删 |
| 入口关系 | 手记页（双 tab）与懂我页是并列的两个导航页；导出/删除入口在账号与隐私面（05 篇） | — |

**MEX-21b 读**。条目按主题分组展示，每条标明来源（自动积累 / 你修改的）。页面展示集合与回合注入集合同源（MEX-04）；「球球懂我」页同时承载共同瞬间段（MEX-23）。

**MEX-21c 改**。内联编辑，保存即写入本地覆盖层，下一回合按新内容注入。用户主动更正是画像权威层的合法入口（PRD FR-MEM-012；《个人信息保护法》第四十六条更正权的产品承载）。

**MEX-21d 忘（单条）**。确认框语义（现网 UI 文案）：「让球球忘掉『××』吗？」——执行后本地墓碑永久生效 + 远端删除 best-effort。下一话轮画像即不含该条。

**MEX-21e 忘（全部）**。确认框语义（现网 UI 文案）：「让球球忘掉这里的一切吗？」——本地与远端全删；远端不可达时如实报错，界面提示与接口返回一致，不谎报成功。

**MEX-21f 删除体验语义**。删除按钮附近无劝阻文案、无「失去默契」类损失暗示、无挽留弹窗（MEX-05）；删除后列表即时移除该条。文案唯一出处归 13 篇 copy sheet。

### 3.2 共同瞬间（MEX-23）

**MEX-23a 自动沉淀**。共同瞬间由系统在比赛共同经历中自动沉淀（已确认、关键、强度 ≥4 且带事件 ID 的比赛事件才入账，PRD FR-REL-003 准入门）。用户不需要、也不可以手工「造」瞬间；无「保存瞬间」按钮是设计而非缺失。

**MEX-23b 列举**。`GET /api/me/moments` 按时间倒序返回，每条携带稳定 ID——用户必须能点名删除某一条，不得无 ID 可指。

**MEX-23c 忘掉=物理删除**。确认框语义（现网 UI 文案）：「这条共同瞬间会被删除，球球之后不会再提起。」删除立即从三个面同时消失：moments 列表、懂我页瞬间段、主动引用候选（`shared_moment:` 钥匙失效）。只隐藏不物理删属违规。

**MEX-23d 引用有度**。球球主动回望共同瞬间必须携带 `shared_moment:<eventID>` 引用码（01/CITE-00）；带调侃的瞬间回忆需球友（watch_buddy）阶段以上且已有任一调侃许可范围（09/REL-23）。无由头不翻旧账。

**MEX-23e 准入的用户感知**。四条件准入（已确认/关键/强度≥4/带事件 ID）的用户感知是「只有一起经历过的关键节点才成为瞬间」——普通传球、普通回合不成瞬间；被修订覆盖的旧瞬间置 revoked 不物理消失（留审计）。准入密度低是有意设计：瞬间越密，「忘掉」的分量越轻，合辑的纪念价值越稀。

### 3.3 手记与赛季记忆册（MEX-25/26）

**MEX-25a 生成时机与频次**。终场事件 → 赛后反思冲洗完成后生成；每用户每场至多一篇（幂等）。0-0 且无事件的空账本不写——不出「空账本成文」的手记。

**MEX-25b 零编造承诺（用户沟通口径）**。手记只写账本里真实发生过的事：素材边界为账本终场投影 + 画像口味 ≤3 条，sources 数组（match: / goal: / portrait:）逐条可回溯。正文比分经确定性校验，与账本不一致整篇降级为确定性底稿（纯账本事实句）；无 LLM key 环境直接出确定性底稿。对用户的承诺口径是一句话：**手记里的每条比分、每个进球，都和比赛事实账本一致**——手记是回忆，不是再创作。

**MEX-25c 用户操作**。点赞、忘掉（物理删除）、文本分享（分享文本带「【球球手记】」头与对阵信息）。忘掉语义与懂我页一致：确认后物理删除，不再出现。

**MEX-25d 阅读面纪律（防自我引用）**。手记是阅读面，不是聊天素材——手记内容不进主动回合话术，球球不在聊天里引用自己的手记当事实源（PRD FR-MEM-015/FR-DLG-016 双条款）。反例：球球在复盘时说「我手记里写过你这场的口味」——违规。

**MEX-26 赛季记忆册**。手记页双 tab 的第二 tab：手记列表 + 每场共同瞬间的装订视图，按 season（该赛季开球年份）过滤、时间倒序；每场装订页含比分 + 手记摘要（首句 ≤60 字）+ 共同瞬间。赛季册只读，治理操作回落到各构成条目（手记/瞬间各自忘掉）。tab 切换不重置手记列表状态；空态文案（现网 UI 文案）：「看完一场球，手记就会出现在这里。」/「赛季册还没有装订页，看一场就有了。」

**MEX-27 赛后三件的分工（手记 / 复盘邀约 / 赛季册）**：

| 载体 | 形态 | 是否触达用户 | 归属 |
| --- | --- | --- | --- |
| 复盘邀约 | 应用内簿子条目，点击回到对话 | 是（终场+15min 投递，+2h 过期） | 主动域（07 篇）/ 阶段语义 09/REL-32 |
| 手记 | 成文阅读面（账本+口味织写） | 否——静待用户翻阅，永不进聊天素材 | MEX-25 |
| 赛季册 | 跨场装订合辑（只读） | 否——季末回翻的阅读面 | MEX-26 |

### 3.4 会话内记忆可感（MEX-31～33）

**MEX-31 理由入口（引用可感性）**。球球提到过去（主动回合、话题接续、共同瞬间回望）时，用户可当场追问「为什么找我聊」——承载是客户端理由入口，不是球球的口头解释：

- 服务端主动回合消息携带可选 `reason` 字段（{codes, citation}），老客户端零感知；
- 客户端把 reason codes 映射为用户话术，以字幕卡内一行小字随消息呈现；未认识的码原样忽略——宁可少说，不说机器话；
- 呈现规则（客户端单源行为）：短语列表取前两条、以「；」连接；映射为空则整行不显示——理由入口只为有码的消息在场，不制造空白占位；
- 现网映射表（客户端单源照录）：`proactive_citation:reminder:` →「这是你之前订的开球提醒」；`proactive_citation:subscription:` →「这是你订阅的球队赛程提醒」；`proactive_citation:pivotal` →「这是关键时刻，我想跟你一起看」；`policy_memory:favorite_team_goal` →「你的主队进球了，我第一时间想到你」；`open_thread_recovery` →「接着上次没聊完的话题」；`favorite_team_goal` →「你的主队进球了」；
- 理由是按需可感的：默认界面不打扰，理由行随消息轻量在场；非空引用码才放行的主动门（01/CITE-G1）保证每个主动回合都有可解释的来路——「凭空说『我记得你说过…』而无可感依据」属违规。

**MEX-32 主动回访与口味偏置的可感边界**。记忆进回合四入口：闲聊、主动回合、事实衔接语、线程回访（PRD FR-MEM-021）。支持队进球的情绪偏置（+0.2/+0.15）留 reason code（`policy_memory:favorite_team_goal` / `favorite_player_scored`）审计可查，且施加于全部压制门之后——被压制的解释不享受加成。用户感知形态：主队进球时球球替自己高兴，且这份高兴可被理由入口解释。

**MEX-32a 记忆出现的入口与其体验边界（现网四入口对照）**：

| 入口 | 记忆以什么形态出现 | 体验边界 |
| --- | --- | --- |
| 闲聊 | 回答自然带上已确认偏好（口径、口味、称呼） | 只在当前话题确实相关时带过，不炫耀、不解释来源（01/EXP-S1）；无画像时零漂移不猜测 |
| 主动回合 | 凭非空引用码开口（open_thread / shared_moment / pivotal / reminder / subscription） | 频控 90s 基线×档位；理由入口可解释；用户沉默不构成开口理由 |
| 事实衔接语 | 比分/事件播报衔接口味（「你的主队…」） | 比分只来自账本；偏置在全部压制门之后施加 |
| 线程回访 | 未完话题补答或接续（「接着上次没聊完的话题」） | Thread TTL 7 天内；过期话题退出候选；每回合补答有频次上限（MEX-P4 核对项） |

**MEX-33 话题条**。`GET /api/me/threads` 只读返回未完话题（Thread 权威账本，TTL 7 天）。体验规则：话题条不是死链接——点击即以话题文本走既有 user_speech 通道续聊，不新开协议，上下文正确承接；过期话题退出主动回访候选（不再被接起），在列表中呈终态（完结/过期双终态分开）。话题条数据与主动回访同源（ActRecall 优先取 Thread 最新开放话题）。

**MEX-34 backchannel 微标注**。比赛中的微反应（伴随反应）带「(小声)…」微标注呈现，与正式发言区分——微反应不是发言，不占回合、不需要引用码（ADR-0016；表现细则归 06/07 篇）。

### 3.5 记忆治理体验（MEX-24/41/45）

**MEX-24 画像保鲜的体验语义**。球球对用户认知的每一条都有保鲜期，且保鲜是自动的：90 天内未被验证的旧条目在反思尾部软封口、退出「球球懂我」输出面；任何一次交互（UPDATE）即自然续期——没有逐条「续约」操作。换主队走即时封口：确认新主张后旧队条目立即退出输出面，球球不再替旧队说话（PRD FR-MEM-011）。用户感知形态：球球的「懂我」始终是现在的我，不是半年前的我；90 天没聊到的旧偏好不再替用户发言。

**MEX-24a 封口不是删除**。软封口条目退出权威输出面，底档与审计保留（90 天窗 + 交互续期是《个人信息保护法》第四十七条最短保存期原则的实现形态）；用户要的是「彻底消失」时走删除（MEX-41）。两者的体验区别：封口后该条不再出现在懂我页输出面、但审计在；删除后立碑，再抽取也无法复活。

**MEX-41 删除与立碑（体验语义）**。删除的承诺是一句话：**下一回合生效**。

- 体验时序：用户在懂我页/瞬间/手记发起删除 → 受理即落墓碑（privacy_tombstones）→ 下一话轮开始，画像与记忆从球球上下文消失——用户不需要等「后台删完」才被忘记；
- 立碑是永久的：即使记忆服务稍后从旧数据重新提炼同样内容，墓碑把它挡在上下文之外——再抽取无法让忘掉的东西复活；
- 后台是异步收尾：清理在 6 小时内执行，全量清除以 30 天保留期为硬上限（数值唯一出处：17 篇 DAT-42）——这两个数字用户不感知，属审计承诺而非等待承诺；
- 全量删除是横切语义（`DELETE /api/me/data`）：画像、瞬间、手记、关系状态、账本族同属删除范围；删除期间球球不再写入任何新记忆（MEX-57）；登出≠失忆，登录是身份升级不是记忆边界（ADR-0020，身份细则归 05 篇）；
- 治理体验细则（合规承载、登出语义、口径沟通）归 05 篇；数据生命周期归 17 篇。

**MEX-45 导出（查阅复制权的产品承载）**。`GET /api/me/export` 一次请求打包 11 类会话与账本族对象（11 类清单唯一出处：17 篇 DAT-40）。体验规则：自助操作、一次打包、不需运营介入；导出内容与删除状态一致——已立碑删除的数据不出现在导出中。边界如实告知：画像、手记、话题、瞬间当前不在导出体，各有独立用户面承载查看与治理（MEX-21/23/25/33）；将其纳入导出属扩展待办（MEX-P2），落地前任何文档不得写「导出含画像/手记/话题」。删除与导出的治理面细则归 05 篇。

### 3.6 典型体验走查（示例，非规范性）

以下用一个虚构用户「老张」走一遍记忆体验的现网时序，用于校准各 MEX 条款的协同方式；每一步均可在前述规则中找到依据：

1. **第一晚（初识）**：老张看皇马的比赛，随口说「我就喜欢看皇马的边路」——观察入队（不打断话轮），打分过门槛后被提取；球球短句快报进球，不追问、不调侃。这晚的进球瞬间因初识阶段权重 0.90 记得较浅（09/REL-33）。
2. **当晚赛后**：终场反思冲洗后生成手记——比分、进球与账本一致，口味素材不超过三条；老张在手记页点赞。0-0 的空场则什么都不会出现（MEX-25）。
3. **第二晚**：不用重新自我介绍——球球按画像口径接话；丢球时老张骂了句粗口，球球按口语分级规则应对，不附和对球员的人格羞辱。
4. **某晚主动回访**：球球提起上次没聊完的话题，字幕卡下的小字行显示「接着上次没聊完的话题」（MEX-31）；老张点话题条直接续聊，上下文正确承接（MEX-33）。
5. **换主队**：老张说「现在我更关注XX队了」——新主张经合并判定写入权威层，旧队条目即时封口，球球不再替旧队说话；90 天没再提的旧偏好不再出现（MEX-24）。
6. **治理时刻**：老张打开球球懂我页，看到「你修改过支持球队」这类条目与共同瞬间段；删掉一条不该记的（下一回合生效），忘掉一个瞬间（物理删除，主动引用随之失效）；发起全量导出拿到 11 类数据包（清单唯一出处：17 篇 DAT-40），再发起全量删除——6 小时内清理、30 天保留期后无残存（数值唯一出处：17 篇 DAT-42），导出端点此后如实返回 data-deleted（MEX-41/45）。
7. **任何时刻**：老张问「你怎么知道我支持皇马」，球球不解释内部机制（guard 拦「记忆库/关系记忆」类措辞），可感解释在懂我页与理由入口，不在话术里（MEX-04/31）。

**验收总口径（补充）**：⑥ 语义路停用/弃权形态下用户无错误感知；⑦ 删除期发起的导出不输出残缺数据。

**三层证明（对用户的可验证性承诺）**：① 每一次记忆动作可回溯——抽取与拒绝、积压与重放、话题终态、每轮反思均有审计记录，任何被引用的记忆答得上来路；② 关键接线有常驻回归看守——画像一致性评测先于用户发现断链；③ 用户可亲手验证——改一条、忘一条，下一句聊天立刻见分晓。若删除后仍被提起、引用无出处，按高严重度问题处置（先停止引用再修复），不以「偶发」淡化。

## 8. 设计说明（与旧 30 章的差异，非需求条款）

1. **语义召回整层为新增叙述**。v2 30 章的记忆管线止步于「账本→异步抽取→画像」，无语义路；v3 收编 2026-06 前后落地的三路召回（contains/pgvector/内容精确）、bge-m3 本地嵌入底座与 τ=14 天时序衰减。本篇按体验面转写其用户可感后果（MEX-51「少一路相关不报错」、旧记忆「只降权不消失」），系统叙述归 16 篇。
2. **确定性打分替代「重要度阈值」含糊叙述**。旧 30 章只说「重要度低于阈值不抽取」；现网为确定性公式（类基分+措辞加成 ×阶段权重，门槛 0.35，可复算可审计）。打分对用户的可感承诺是 MEX-01 的反面：不该记的闲聊不被记（低分观察在最便宜位置被拦下），该记的进球/承诺/偏好不漏。
