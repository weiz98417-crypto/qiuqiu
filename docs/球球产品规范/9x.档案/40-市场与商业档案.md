## 1. 封存声明

**冻结原因**：市场洞察、竞争分析、市场规模、商业模式与 GTM 是**决策时点文档**——它们服务于「是否立项、向哪个市场进入、按什么边界商业化」的一次性判断。产品此后迭代不改变这些判断在当时已经成立的事实；若随产品迭代继续维护，只会制造「看似现行、实为过期」的假活性。2026-06-07 审计对其中四篇（02/03/04/18）判定为「内容现势」，但**现势不等于应维护**——冻结保护的是引用的诚实性：任何引用都被迫先声明这是档案口径。

**三条使用纪律**：

1. **引用须注明档案性质**：写作「档案口径（2026-05-22），非现行承诺」；用于对外材料前须按当时现状复核。
2. **不得作为现网能力依据**：库内篇章引用本档案时，只能作背景与推理链参照，不得据此声明产品能力或承诺。
3. **不回改原文**：发现原文与现状不一致时，不修改原文，在本包档案卡加判定注记；解冻修订是唯一改写原文的合法路径（见第 7 节）。

1. **为什么连「现势」篇也冻结**：审计判定 02/03/04/18 内容现势，说明冻结没有造成信息损失——损失只发生在「有人把档案当现行」的时候。档案头与引用规则就是防这道错；保持冻结同时避免「半维护」状态（改一半、漏一半）重演 v2 的漂移病史。
2. **收录边界沿 v2 卷结构**：卷 1（市场洞察）四篇＋卷 3 商业三篇（18/19/20）归本包；卷 3 验证篇（13/14/15/17）与卷 6 上市三篇归 41 包。18 与 60 的分工沿 v2 原文互相指向的口径：定价假设唯一归 18（本包），付费产品路径唯一归 60（41 包）。
3. **不复制原文**：本包只存清单、档案卡与有效性判定；原文以 `v2-20260922/` 目录与 git 历史为载体，保证「档案不可变」可被 git 强制。
4. **无接续篇的明示**：18 的商业化红线、20 的风险登记册在活规范中没有接续——这是档案策略的预期结果（它们属决策时点内容），本包显式写明，不留哑指针；解冻时重立归属。
5. **与 02 篇的一致性**：02 篇第六节档案指针表列有「战略定位与非目标」随本包冻结；实际处置是 05 篇核心结论由 00 篇继承、市场叙事部分随卷存档（第 3 节关联存档注记），两种表述指向同一批原文，不构成矛盾。
6. **时态纪律延伸到档案卡**：本包对原文内容的转述使用「原文写/原文声明」（过去时指涉文本），对现状判定使用现在时（现势/已建成/未发生）；不出现「将/未来会」句式。
