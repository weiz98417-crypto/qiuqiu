## 1. 为什么"足球迷"不是一个可用的起点

"足球迷"是一个能聊天的词，却不是一个能设计的词。这个人群规模巨大、观看方式高度分化——仅卡塔尔世界杯一届赛事，FIFA 就统计到约 50 亿触达观众 [1]——它同时装着偶尔看大赛的人、每周稳定追赛的人、为支持一支球队而看球的人、只看集锦的人、需要专业分析的人、想找人聊球的人，以及根本不希望在比赛中被打扰的人。把这些人放进同一个画像，通常会得到一个什么都能做、却不知道什么时候该安静的产品。

所以，在动手设计之前，我们要求自己先回答五个前置问题：

1. 第一批应该为哪一类人，解决哪一种重复出现的观赛任务？
2. 什么变量真正区分"需要数字陪看"与"只需要比分或资讯"的用户？
3. 一场比赛的赛前、赛中、赛后，用户的功能任务、情绪任务和安全边界如何变化？
4. 哪些人即使看起来很活跃、更容易贡献时长，也不应成为首批目标？
5. 如何用招募、访谈、观赛日记和原型测试，把这些判断证实或推翻？

本文的产出不是一组可用于广告投放的空泛标签，而是一套可执行的选择：**首批滩头人群、使用情境地图、待验证的 JTBD、研究样本、判断标准，以及从研究结果导出的产品约束。**

### 1.1 我们的核心判断

我们最初的假设是：最值得先研究的，既不是"最孤独的人"，也不是"最懂球的人"，而是**有稳定观赛习惯、经常在社交供给不匹配时独自看完整场比赛、既希望共享关键时刻又不愿承受公共社区噪声的成年球迷**。选择这群人，不是因为他们"更孤独"或更容易形成依赖，而是因为他们最容易让我们检验陪看价值是否真的成立——完整的初始人群判断见《产品全貌》。

这个定义有意把"独自观看"与"孤独"分开。有人独看是因为比赛开得晚、支持的球队小众、朋友的阵营不同、工作日程错开，或只是更喜欢一个人安静看球。首批研究要验证的是：在这些明确情境里，用户是否愿意让一位 AI 数字球友以可控的方式参与比赛——而不是验证他们是否愿意被长期陪伴。

### 1.2 不在本文中决定的事

本文不会预先决定球球这位数字球友（Digital Ballmate）的性别、声音、外形、定价、联赛授权、赛事数据供应商或完整功能清单，这些分别属于角色设计、商业模式、合规和工程方案。用户分层只为它们提供约束：谁在什么情境下需要什么、绝对不愿接受什么、何时应当停止服务。

## 2. 分层原则：先看行为与情境，再谈人口属性

### 2.1 不把"年龄、性别、城市"当成需求本身

人口统计数据可以帮助安排招募配额、识别可及性差异和检查偏见，却不能单独解释陪看需求。两个同样 28 岁、支持同一支球队的人，可能一个每周固定与朋友线下看球，另一个因时区和作息长期独看；前者对数字陪看几乎没有兴趣，后者可能只想在争议判罚时问一句"刚刚为什么吹掉"。

因此，我们按以下顺序分层：

1. **观赛行为**：看哪些赛事、频率如何、是否会看完整场、主要通过什么渠道观看。
2. **情境供给**：看球时是否有合适的人一起看，现有群聊、社区、解说和搜索是否足够。
3. **待完成任务**：是在确认事实、理解局面、分享情绪、维持仪式感，还是只需要赛程提醒。
4. **互动偏好**：愿意听语音、看字幕、主动提问，还是只接受极少量提示；何种节奏被认为打扰。
5. **风险与边界**：是否可能把数字球友误认成真人、是否出现依赖性表达、是否为未成年人、是否涉及博彩或过度消费。
6. **人口属性与设备条件**：年龄段、地区、语言、无障碍需求、终端和网络，用于检查方案是否只适配了少数人。

这是一种"行为优先、情境优先、边界优先"的分层方式。它不假装消除人口差异，而是避免把人口标签误当因果解释。

### 2.2 一个用户可以属于多个层，不把人钉死在画像里

同一个人看国家队淘汰赛时可能想要热闹的共同经历；看普通联赛时只想安静接收一次开赛提示；与朋友同看时甚至完全不需要服务。所以分层的单位是"**人 × 比赛 × 情境**"，而不是给用户贴一个永久标签。

这意味着研究和体验设计都要问两个问题：

- **这场比赛对你意味着什么？** 决赛、德比、主队保级、朋友相约、随手打开，情绪投入完全不同。
- **你现在希望我怎么参与？** 解释、轻陪、关键时刻提醒、仅文字，还是不说话。

当服务无法判断时，优先让用户选择，而不是用历史偏好去推断更亲密、更主动的互动。记忆可以减少重复设置，但不能取消用户在每场比赛中的重新决定权。

### 2.3 用"替代品缺口"辨别真实机会

用户说"有个人陪我看挺好"，不等于存在产品缺口。研究必须追问：他现在会怎么解决？为什么不满意？换成数字球友会失去什么？

| 现有替代品 | 它解决得好的 | 它留下的缺口 | 它教我们的事 |
| --- | --- | --- | --- |
| 真人朋友与家人 | 自然情绪共享、共同回忆、互相理解 | 不一定同场、同队、同时在线；也可能不愿打扰对方 | 补足空档，不与真人关系竞争 |
| 群聊、球迷群、评论区 | 热闹、即时吐槽、多观点 | 噪声、攻击、剧透、社交压力、阵营冲突 | 价值是可控、无须表演的同场感，不是"更热闹" |
| 转播与专业解说 | 比赛画面、基础事实、专业解释 | 无法回应个人问题或情绪；风格不可配置 | 不重复播报，不假装取代专业解说 |
| 数据、比分、新闻应用 | 快速查赛程、事件和数据 | 事务性强，缺乏情境判断和陪伴感 | 事实必须可靠，但事实本身不是差异化终点 |
| 通用聊天工具 | 灵活问答、语言表达 | 不一定理解实时状态、赛事时序或边界 | 要证明场景化可信和恰当时机，而非比拼闲聊长度 |
| 短视频、集锦、社媒 | 赛后回顾、情绪宣泄、观点消费 | 碎片化、剧透、难以同步正在进行的比赛 | 不在赛中把用户拉去消费无关内容 |

如果研究证实目标用户对上述替代品已经满意，或者他们只想要一张比分卡，那么正确的做法是放弃"数字陪看"假设，而不是用更强的人设或更多提醒强行制造需求。

## 3. 分层变量：决定体验的不是"爱不爱球"，而是八组条件

### 3.1 八组核心变量

| 变量 | 我们要观察的问题 | 高值与低值的典型表现 | 设计上的含义 |
| --- | --- | --- | --- |
| 观赛稳定度 | 一个月看多少场；是否按赛程提前安排 | 高：有固定球队/联赛，常看完整场；低：只看热点或集锦 | 高稳定度更适合研究连续回访，不代表适合高频打扰 |
| 比赛投入度 | 这场比赛对身份、情绪和时间安排的分量 | 高：德比、淘汰赛、主队关键战；低：随机打开、背景播放 | 投入度决定是否值得介入，不决定是否可以越界 |
| 社交供给匹配度 | 是否有想一起看且节奏相近的人 | 高：有意愿但时间/队伍/地点不匹配；低：已有稳定同看伙伴 | 缺口来自不匹配，不等同于缺朋友 |
| 信息自信度 | 能否理解规则、阵容、事件和背景 | 高：能自己判断并愿意讨论；低：常被术语和信息冲突卡住 | 低自信需要解释，高自信也需要查证；都不该被居高临下对待 |
| 互动容忍度 | 能接受多频繁、多长的声音或文字介入 | 高：愿意在关键段落对话；低：希望近乎全程安静 | 默认低干扰；不能用"活跃"替代"满意" |
| 表达目的 | 想确认、学习、吐槽、分享还是整理情绪 | 高：有明确"刚才我想说一句"的时刻；低：只希望被动接收赛况 | 决定数字球友是提问、回应、沉默还是摘要 |
| 控制与隐私偏好 | 是否愿意授予记忆、通知、声音和数据权限 | 高：愿意保存有限偏好且要求可管理；低：不愿保存或只接受临时会话 | 数据最小化、可见可删是基本选项，不是高级功能 |
| 风险敏感度 | 对依赖、未成年、冲动消费、博彩、冲突内容的暴露 | 高：明确担心被打扰或情绪绑架；低：可能要求角色排他、持续黏连或提供投注建议 | 风险优先级高于转化优先级；必要时应当拒绝或转介 |

### 3.2 三个不能混为一谈的推论

研究时要特别警惕三种错误等式：

- **高时长 ≠ 高价值。** 打开很久可能是忘了关、被动播放，或在情绪低落时反复寻求安抚；要结合赛后感受、退出意愿和干扰感一起判断。
- **高互动 ≠ 高信任。** 连续追问可能只是答案不清、延迟过长或用户不信；信任要用来源透明、错误修复和下一次是否还愿意询问来测量。
- **独看 ≠ 需要亲密关系。** 很多人只需要一句恰当解释或一个无压力的共鸣；不能把"没有一起看的人"翻译成"应该被绑定的用户"。

### 3.3 状态变量：每一场比赛都可能重置

同一位用户，在不同比赛里的需求可以完全不同。我们希望用户在任何一场比赛开始前，都能用几十秒表达以下状态，并在赛中随时更改——它们应当由用户自己设定，而不是由后台画像推断出的"真实需求"。

| 状态 | 用户可以选择 | 它影响的体验决定 |
| --- | --- | --- |
| 同看方式 | 独看 / 和朋友看 / 公共场所 / 后台听 | 是否主动说话、提示是否只显示文字 |
| 陪看强度 | 安静 / 刚好 / 热闹 | 数字球友主动介入的量（三档已在球球现网提供） |
| 知识深度 | 新手解释 / 简洁提示 / 深度讨论 | 术语解释和分析颗粒度 |
| 剧透容忍 | 仅当前画面 / 允许已确认赛事事件 / 赛后全量 | 事实推送与延迟策略 |
| 情绪意图 | 想庆祝 / 想冷静 / 不想被劝 / 只想听 | 语言风格，以及是否提出追问 |
| 记忆授权 | 本场临时 / 记住球队偏好 / 不保存 | 数据保留范围和复盘方式 |

## 4. 候选用户层：六类人，而不是一个"大球迷"

以下六类是我们为首轮研究准备的人群假设，不是发布时展示给用户的标签。首轮研究要通过访谈和真实观赛记录，验证它们是否真的对应可重复的任务差异。

### 4.1 稳定追赛的独看球迷（首选滩头候选）

**定义假设**：过去四周至少观看四场完整或大部分完整的足球比赛；有一支持续关注的球队或一个稳定联赛；约半数重要比赛独自观看；偶尔想说、想问、想庆祝，但没有合适或低压力的同看对象。

**典型情境**：工作日晚场，准备好零食和直播，却发现朋友不看这场、群聊又太吵。开场前想确认首发；比赛中对一个判罚有疑问；进球时想分享，却不想把手机交给陌生评论区；赛后想简单回顾，又不想被长篇热评淹没。

**待完成任务（JTBD）**：

> 当我独自看一场真正关心的比赛，并在关键时刻缺少合适的交流对象时，我希望能获得少量可信、同频、不会给我社交负担的回应，从而既能沉浸在比赛中，也不觉得那些时刻无人可分享。

**可能获得的价值**：低摩擦进入、关键时刻的确认、与支持球队相关的轻量共鸣、对复杂情境的简洁解释，以及随时可以关闭的赛后收束（规划中）。

**最强拒绝信号**：觉得数字球友"抢戏""像客服""比评论区更吵"；事实错报一次就不再使用；觉得它刻意装熟或索求持续陪伴。

**必须验证的问题**：他们真的愿意打开一个独立服务，还是只希望现有聊天工具加一项功能？想要的是声音、字幕还是赛后摘要？当真人朋友在线时，服务是否自动失去价值？

### 4.2 社交供给不匹配的共同体验寻求者

**定义假设**：对比赛的投入不一定高，但常遇到"身边有人，却没有人愿意或适合一起看同一场"的情况——时区、工作、队伍对立、家庭作息，或单纯不想打扰熟人。

**典型情境**：异地生活、夜间观赛、所在圈子不关心足球，或支持一支没有固定讨论群的小众球队。用户不一定想深聊战术，只希望某个进球、逆转或遗憾被看见。

**待完成任务（JTBD）**：

> 当我想把比赛中的高情绪时刻分享出去、又不想临时打扰朋友或卷入陌生人争吵时，我希望有一个不会评判、不会把我拉入社交义务的对象回应我，从而保留共同经历感而不增加人际负担。

**价值与风险并存**：这一类最容易理解陪看价值，也最容易被错误地设计成"用产品替代现实关系"。研究必须确认他们把球球当作场景工具，而不是全天候情感支点；任何"只和我看""你不能离开""你比朋友重要"的表达，都不能被迎合。

### 4.3 想看懂比赛的轻度进入者

**定义假设**：会因朋友、家庭、赛事热点或某支球队而看球，但规则、位置、阵容、赛程和战术语言带来门槛；他们不希望因提问而被嘲笑，也不希望被灌输。

**典型情境**：一场淘汰赛、德比或朋友相约的观赛。看得投入，却不知道进球为什么被取消、换人意味着什么、伤停补时怎么算，或评论区为什么反应激烈。

**待完成任务（JTBD）**：

> 当我对正在发生的比赛感到好奇却不懂专业术语时，我希望得到和此刻画面相关、没有优越感、能随时停止的解释，从而继续享受比赛，而不是因不懂而退出。

**产品约束**：解释必须区分已确认事实、常见规则与不确定推测；不能把复杂话题简化成伪确定结论，也不能为了提高互动而不停教学。

### 4.4 事实敏感的深度关注者

**定义假设**：信息自信度较高，重视阵容、数据、赛程、规则和来源；他们可能不需要陪伴，但很可能在事实冲突或直播延迟时迅速发现错误。

**典型情境**：同时开着直播、数据页和社媒，对事件时序、伤停、越位或换人信息高度敏感。他们愿意测试可信度，但不会因为"人设可爱"而容忍错误。

**待完成任务（JTBD）**：

> 当不同来源对比赛事件说法不一致时，我希望能快速看到什么已确认、什么仍待确认、为什么存在时差，从而自己判断，而不是被自信但错误的说法带偏。

**研究角色**：这一类是事实可信度的压力测试样本，而不是首轮陪看留存的唯一来源。只迎合他们，产品会退化成信息面板；忽略他们，产品建立不起信任底座。

### 4.5 碎片化追热点的偶发观看者（观察，不作首批承诺）

**定义假设**：主要在大赛、热门对决或社媒事件后进入；很少看完整比赛；常通过集锦、话题和朋友聊天了解足球。

这类用户数量可能很大，但需求未必稳定。他们可能需要"快速不丢脸地进入话题"的解释，却不一定愿意在赛中建立持续互动。首轮只把他们作为对照样本：即使反应强烈，也要先分清是一次性新鲜感还是可复用的场景。

### 4.6 我们暂不服务的人群（明确排除）

还有一类诉求强烈但明确不在目标之列：寻求投注引导、希望数字球友攻击他人或替代真实亲友关系的人，不在我们的目标人群里，完整的边界清单见《产品全貌》。排除不等于忽视——拒绝应当温和、清晰、不过度拟人，紧急风险和未成年人保护有单独的处理机制；因拒绝而下降的互动指标，不会被当作需要"优化"的流失。

## 5. 使用情境地图：跟着比赛的节奏，而不是跟着功能菜单

### 5.1 一场比赛的七段旅程

| 阶段 | 用户所处情境与首要任务 | 我们可以做的 | 我们避免做的 |
| --- | --- | --- | --- |
| 赛前计划 | 看到赛程、决定是否观看；确认时间、渠道、重要性与陪看方式 | 一次可配置的提醒；首发与背景信息的简洁入口 | 连续催促，暗示"不来我会失望" |
| 入场建立 | 打开直播前后；设定互动强度、确认偏好 | 明确 AI 身份、说明事实状态、快速选好强度 | 长篇自我介绍，索要深度授权 |
| 平稳推进 | 比赛没有关键事件；专心观看，偶尔确认规则或数据 | 默认主动沉默；用户提问时给简短回答 | 为刷存在感闲聊，复述画面 |
| 关键事件 | 进球、红牌、点球、伤病、争议判罚；确认发生了什么，表达或消化情绪 | 先给确认状态，再给一句匹配回应；允许追问 | 抢在画面前剧透，把推测说成事实，夸张煽动 |
| 信息冲突 | 直播、数据、社媒说法不一致；分辨已知、未知与延迟 | 标明来源和待确认状态；承认不知道 | 自信编造，把谣言当快讯 |
| 赛后收束 | 终场后几分钟至一天；回顾、庆祝、遗憾、决定是否继续关注 | 可选的短复盘与共同瞬间保存（规划中）、下场提醒选择 | 强迫复盘，利用失落推销订阅 |
| 非赛日回访 | 无比赛或赛事间隔；查赛程、回忆、轻量准备 | 由用户发起的低频服务 | 用情感话术制造无比赛日的黏连 |

### 5.2 参与强度：三档，只调主动介入的量

数字球友不应把每一个事件都当作开口的机会。主动介入的量由用户在**安静 / 刚好 / 热闹**三档之间选择，并可在赛中随时切换：

- **安静**：数字球友不主动发声，只保留提问入口。我们把这理解为一种正常服务——主动沉默，而不是流失信号，因此不做唤回追问。适合与朋友同看、专注观看、公共环境。
- **刚好**：只在少量关键时刻给出简短回应或确认，先确认事实、再回应情绪；每个时段有上限，用户一次拒绝后立即降低强度。适合独看球迷和轻度进入者。
- **热闹**：在用户明显关心的节点更积极地介入和讨论，但仍可打断、可转文字，不鼓励排他或无限时陪伴。适合想边看边聊的时刻。

默认档位由首次使用情境决定，并在每场新比赛开始时再次确认——一次高互动不会被永久固化为更高的主动性。强度偏好也是我们的分层变量之一（互动容忍度），研究中会被重点观察。

### 5.3 情境失配的典型失败

| 用户的真实状态 | 错误做法 | 为什么伤害体验 | 研究中如何识别 |
| --- | --- | --- | --- |
| 在认真看画面 | 长段解释、连续语音 | 夺走注意力，声音比价值更突出 | 用户说"别说了""看不过来"，或直接静音 |
| 刚经历失利 | 立即乐观鼓励或推销下一场 | 否认情绪，用脆弱时刻换转化 | 沉默、反感、删除或表达被冒犯 |
| 不懂判罚 | 术语堆砌或断言争议结论 | 增加羞耻感和错误信息 | 重复提问、转去搜索、说"听不懂" |
| 与朋友同看 | 数字球友抢话、要求回应 | 让数字服务与现实社交竞争 | 关闭服务或觉得尴尬 |
| 不愿保存记忆 | 反复建议"记住我" | 侵蚀控制感和信任 | 拒绝权限、担心被跟踪 |

## 6. JTBD 与用户任务：从"功能愿望"回到进展

### 6.1 五组核心工作

| 核心工作 | Job story | 成功的样子 | 失败的样子 |
| --- | --- | --- | --- |
| 进入比赛 | 当我决定看一场比赛时，我想用很短时间确认它为什么值得看、何时开始、如何设置强度，从而不在开场前被信息和设置拖住 | 一分钟内完成选择并进入观看 | 设置像问卷，球还没开就退出 |
| 跟上事实 | 当场上发生我没看清或各来源说法不一的事件时，我想知道哪些已确认、哪些不确定，从而不把传闻当事实 | 用户理解状态，能自行判断是否追问 | 产品抢答、错报、掩盖不确定性 |
| 看懂局面 | 当我不理解规则、阵容或战术变化时，我想得到与眼前画面匹配的简洁解释，从而继续投入而不被轻视 | 解释可选深度，不需离开观看场景 | 用百科式长文打断比赛，或装作绝对专家 |
| 共享瞬间 | 当我在进球、逆转、争议或遗憾中想表达时，我想获得一句不要求我继续社交的回应，从而情绪被承接而不被操纵 | 用户感觉被理解，自然回到比赛 | 过度煽情、强迫互动、贬低他人 |

第五组工作是**退出路径**：当用户不想继续互动、发现服务不准确或不愿被记住时，必须能立刻静音、纠正、删除并结束本场，退出不带惩罚——用户控制权的完整承诺，唯一详述见《产品全貌》。

### 6.2 功能、情绪、社会与安全：每层任务都要拆开看

用户研究不能只问"你想要什么功能"。每个需求至少拆成四层：

| 层次 | 用户要完成的事 | 研究中我们会问 | 对产品的要求 |
| --- | --- | --- | --- |
| 功能任务 | 看赛程、确认事件、理解规则、切换模式 | "刚才你最想知道的事实是什么？" | 准确、快速、可解释 |
| 情绪任务 | 庆祝、消化失落、降低焦虑、保持投入 | "那一刻你希望别人怎么回应？" | 温和、克制、不替用户定义感受 |
| 社会任务 | 不显得外行、维持与球队朋友的连接、避免冲突 | "你为什么没有去群里说？" | 不制造表演压力，不放大阵营攻击 |
| 安全任务 | 保留距离、避免剧透、控制数据与提醒、随时退出 | "什么会让你立刻关闭？" | 默认低侵入、明确权限、可撤销 |

如果功能任务已被现有工具充分满足，而情绪或社会任务又不愿交给数字球友，就不应硬凑功能组合；反过来，若用户强烈需要情绪回应却无法接受角色边界，也不能把高风险的关系需求解释成产品机会。

### 6.3 需求强度评分：用于研究优先级，不用于给人打分

为比较不同情境的研究价值，我们计划在访谈和日记中为每个"人 × 比赛 × 时刻"记录一个需求强度分数。它不是算法人格分，也不用于自动推断用户情绪：

\[
N = 0.25F + 0.20U + 0.20G + 0.15A + 0.10C - 0.10R
\]

各项均按 1–5 分由研究者结合原始记录编码，并保留评分原因：

- **F（Frequency，频率）**：该情境在一个赛季中是否重复出现；
- **U（Urgency，紧迫性）**：错过当下是否会失去价值；
- **G（Gap，替代缺口）**：现有朋友、转播、数据和社区是否无法低成本满足；
- **A（Attention fit，注意力适配）**：能否在不夺走比赛注意力的前提下介入；
- **C（Control fit，控制适配）**：用户能否清楚设置、拒绝、纠正和退出；
- **R（Risk，风险暴露）**：是否涉及未成年人、依赖表达、过度激动、博彩、隐私或错误事实的高后果场景。

它的作用是让团队比较"赛中争议判罚解释"和"非赛日主动闲聊"是否都值得优先做。任何风险高、控制适配差的情境，即使互动量预期再高，也不能因为分数好看进入 MVP。

## 7. 滩头选择：从所有球迷收缩到一个可验证单元

### 7.1 候选滩头比较

| 候选人群 | 情境清晰度 | 重复频率 | 替代品缺口 | 风险可控性 | 研究可招募性 | 我们的判断 |
| --- | --- | --- | --- | --- | --- | --- |
| 稳定追赛的独看成年球迷 | 高 | 高 | 中到高 | 中到高 | 高 | **首选** |
| 社交供给不匹配者 | 高 | 中 | 高 | 中，需严格边界 | 中 | 与首选交叉招募 |
| 轻度进入者 | 中 | 中到低 | 中 | 高 | 高 | 第二阶段验证 |
| 事实敏感深度关注者 | 高 | 高 | 中 | 高 | 中 | 作为可信度压力样本 |
| 大赛偶发观众 | 中 | 低 | 未知 | 高 | 高 | 对照样本，不作留存承诺 |
| 强关系替代/博彩导向者 | 表面高 | 未知 | 不适用 | 低 | 不应以增长为目标 | 排除 |

### 7.2 首选滩头的工作定义

首批研究计划招募"稳定追赛的独看成年球迷"，并确保其中一部分属于社交供给不匹配者。这群人的入选条件与完整特征已在《产品全貌》中唯一描述，这里只强调方法上最重要的一条：**我们会同时招募"有稳定同看伙伴的人"作反例**，防止团队把自己的滩头假设误当普遍规律。

### 7.3 推进门槛与退出条件

我们不打算因为用户"说喜欢"就进入开发。计划中的门槛是：至少满足以下条件，才把这个滩头推进到可交互 MVP。

1. 在至少 24 名合格访谈对象中，超过一半能自发描述过去一个月内至少两次具体的陪看或事实确认缺口；
2. 在观赛日记或情境原型中，超过一半的首选样本愿意在第二场比赛再次选择服务，且主要原因不是新鲜感；
3. "安静/刚好"等低强度模式被评价为比连续对话更舒服，且用户能理解和改变档位；
4. 事实冲突场景中，用户更信任明确说明不确定的表达，而非更快但武断的答案；
5. 没有出现无法通过设计与运营缓解的高频误认真人、排他依赖、剧透伤害或隐私误解。

若前三项不成立，说明这个问题可能更适合由赛事工具、社区功能或现有聊天渠道解决，我们应暂停数字陪看方向——而不是用强化人设、增加通知或拉长对话来挽救数据。

## 8. 招募与筛选：用具体行为找样本，而不是寻找"寂寞用户"

### 8.1 招募渠道与偏差控制

可从球迷社群、赛事内容创作者受众、线下观赛活动、朋友转介、普通社交平台等渠道招募，但不能只在单一强队粉丝群、AI 爱好者群或付费用户群中找人。每个渠道自带偏差：

| 渠道 | 优势 | 主要偏差 | 我们的控制方式 |
| --- | --- | --- | --- |
| 球迷社群 | 快速找到稳定追赛者 | 高表达、强阵营、社区耐受度高 | 补充不常发言者和不同球队样本 |
| 线下观赛场所 | 可观察共同观看与独看对照 | 参与者社交供给可能充足 | 作为反例样本，不只招募常客 |
| 内容创作者受众 | 可触达轻度与热点用户 | 对创作者和内容消费依赖更强 | 问清是否看完整比赛、是否已有替代品 |
| 熟人转介 | 信任较高、回访方便 | 年龄、地区、兴趣相似 | 设置明确配额，避免滚雪球同质化 |
| 普通社交平台 | 覆盖面广 | 自选参与、可能只为激励 | 用具体行为题和回访筛选 |

招募文案不使用"孤独""陪伴缺失""找一个永远懂你的人"等暗示性语言，而用中性表述：邀请有真实观赛经历的成年用户，分享赛前、赛中、赛后的信息、交流和体验偏好；研究对象为明确标识的 AI 数字陪看概念。

### 8.2 建议样本配额

探索期计划招募至少 30 名深访参与者，完成 24 名有效访谈；另招募 12 名进行两到三场比赛的日记研究，可与深访重叠。配额是为了让差异被看见，不是统计代表性的声称。

| 维度 | 最低配额建议 | 原因 |
| --- | --- | --- |
| 稳定追赛独看者 | 12 名 | 验证首选滩头的核心情境 |
| 有稳定同看伙伴的对照组 | 6 名 | 检验"独看"是否真是关键变量 |
| 轻度进入者 | 4 名 | 判断解释型价值是否独立成立 |
| 事实敏感深度关注者 | 4 名 | 测试可信度、延迟和不确定表达 |
| 不同观看设备与网络条件 | 每类至少 4 名 | 检验声音、字幕和实时交互是否可用 |
| 不同性别、年龄、城市/时区与生活状态 | 交叉配额，不设单一刻板比例 | 防止单一圈层的表达被当作普遍需求 |

若研究涉及未成年人，应先完成独立的年龄适当性、监护同意、内容保护和数据处理设计；在这些条件明确之前，本轮探索仅招募成年人。

### 8.3 筛选问卷核心题

筛选题以最近四周的具体行为为主，避免"你喜欢足球吗"这类自我认同题：

1. 请列出过去四周你看过的足球比赛（赛事类型、是否看完、观看方式）。
2. 最近一场你真正关心的比赛是什么？赛前为什么决定看？
3. 当时谁和你一起看？若独看，是主动选择还是缺少合适同看者？
4. 比赛中你是否查看过比分、阵容、规则解释、群聊、评论区或社交平台？请说具体时刻。
5. 有没有一个瞬间你想分享、吐槽或提问，但没有做？为什么？
6. 你通常愿意在看比赛时听到声音提醒吗？什么情形会让你立刻关闭？
7. 你能否接受一位明确标识为 AI 的数字球友在比赛中提供文字或声音互动？什么条件下可以，什么条件下不可以？
8. 对保存球队偏好、互动方式或共同瞬间，你的接受边界是什么？
9. 你是否主要为了博彩、投资、盗播资源、情感替代或专业危机支持而寻找此类服务？若是，不进入本轮样本。

不会因为受访者"很想要一个恋人型 AI"而优先录取——那是风险信号，要按研究伦理和安全流程处理，不是产品需求的优先级。

## 9. 研究设计：先听真实比赛，再测试概念，最后验证重复选择

### 9.1 三阶段研究路径

| 阶段 | 目标 | 方法 | 样本 | 主要产出 | 不能得出的结论 |
| --- | --- | --- | --- | --- | --- |
| 发现 | 还原真实观赛与替代行为 | 60–90 分钟半结构访谈、时间线回放 | 24 名有效样本 | 情境地图、任务语言、拒绝信号、初始分层 | 不能证明留存或付费 |
| 情境验证 | 比较不同参与强度与表达方式 | 关键事件脚本、纸面/交互原型、可信度冲突测试 | 18–24 名，含对照 | 模式偏好、可理解性、事实与边界问题 | 不能证明真实比赛中的持续价值 |
| 真实重复 | 观察真实赛事中的选择与反感 | 两到三场比赛日记、赛后短访谈 | 12–16 名 | 复用率、干扰时刻、退出原因、情境差异 | 样本小，不能做市场规模宣称 |

所有阶段都会把"没有使用""关闭服务""选择安静""宁愿找朋友"视为有价值的结果，研究者不得把它引导成"你是不是还没习惯"。

### 9.2 访谈结构与关键问题

**第一段：真实回忆，不先介绍概念。** 请受访者按时间顺序讲最近一场投入观看的比赛；哪些时刻拿起了手机、为了什么；当时和谁在哪里交流、为什么选那里；哪些信息不确定、如何决定信谁。

**第二段：还原情绪和边界。** 最想有人回应的时刻是什么、希望听到什么、绝不想听到什么；"陪看"最舒服和最不舒服的样子；什么让数字球友显得真诚，什么让它显得装熟、吵或冒犯；如果它记住了偏好或共同瞬间，希望怎样看见、改掉或删除。

**第三段：替代品与付出。** 现在会怎么解决这些需求、哪里够哪里不够；愿意用注意力、少量数据或费用交换什么、哪些条件绝不接受；朋友在场、比赛不重要或心情很差时，服务应该怎样退后。

**第四段：情境原型和反例。** 对同一关键事件展示"安静""只给事实""刚好回应""热闹闲聊"几种脚本请用户比较；对同一事实冲突展示"快速断言"和"说明待确认"两种表达，询问信任、焦虑和继续使用意愿；展示一句排他、内疚或过度亲密的话，让用户解释为什么不舒服或为什么会受吸引——这不是为了找更强的话术，而是为了确定禁止边界。

### 9.3 比赛日记模板

日记不要求用户在比赛中写长文。每场只记录六个时间点：赛前、开场后、第一次关键事件、一次不确定或困惑、终场、赛后第二天。每个时间点用 1–2 分钟回答：

- 我在做什么，周围有没有人？
- 我最需要什么：事实、解释、表达、安静，还是没有需要？
- 我会不会主动打开服务？若不会，为什么？
- 这次回应是加分、中性还是打扰？具体原因是什么？
- 我是否觉得它知道得太多、说得太多、太像人，或不够可信？
- 我希望下场比赛保留、改变或删除什么设置？

收集日记前要取得明确同意；不要求用户提供聊天隐私、直播画面、社群记录或可识别第三人的信息。

## 10. 假设、证伪标准与决策门

以下是首轮研究要逐一检验的核心假设。每一组都同时写下支持信号和证伪信号，避免只收集对自己有利的证据。

| 假设 | 支持信号 | 证伪或暂停信号 | 它影响的下一步 |
| --- | --- | --- | --- |
| 稳定独看者存在重复的、可描述的陪看缺口 | 多名用户自发描述相似情境，且替代品不完全满足 | 多数只要比分，或朋友/群聊已足够 | 缩小为信息工具，或停止陪看方向 |
| 关键时刻轻介入优于连续陪聊 | 用户主动选择低强度模式并在第二场复用 | 更偏好完全无介入，或持续闲聊两极化严重 | 重做交互模式或重新分层 |
| 事实透明比武断抢答更能建立长期信任 | 用户能理解待确认状态，愿意继续使用 | 用户只追求速度且无法接受不确定性 | 评估是否不适合赛中场景 |
| 受控记忆提高便利而不显著降低控制感 | 用户能清楚说出保存范围，主动修改/删除 | 大量用户误解或拒绝任何保存 | 采用临时会话，延后记忆功能 |
| 温暖但非排他的角色能形成足够价值 | 用户觉得自然、有边界，愿意下场再用 | 用户只对越界亲密表达有兴趣 | 不以高风险互动换留存，重新评估需求 |
| 轻度进入者需要的是解释而非长期陪伴 | 对上下文解释评价高，对记忆/主动性兴趣低 | 解释需求弱，或被转播/搜索完全满足 | 作为次级功能而非人群主线 |

决策门在每个阶段结束后召开，不允许用"再多做一点功能看看"绕过证伪结果。记录必须包含原始引语、反例、样本构成和研究限制，避免只摘取支持产品的片段。

## 11. 从用户研究导出的 MVP 约束

### 11.1 必须优先验证的能力

在上述假设被验证之前，产品范围应服从研究给出的约束：数十秒完成强度选择并可随时转为安静、关键事件中区分事实状态且不越过剧透设置、短而恰当不抢注意力的互动、逐项独立授权的偏好控制，以及清晰的拒绝与退出路径。其中用户控制权的完整承诺——静音、打断、结束本场、查看与删除数据与记忆——以《产品全貌》的表述为准。

### 11.2 暂缓承诺的能力

- 复杂的长期关系等级、连续签到、情绪打卡或以每日回访为目标的机制；
- 大规模公共社交、陌生人匹配、阵营对战、排行榜和煽动式互动；
- 以"预测准确率"驱动的赛果、投注或收益功能；
- 需要大量个人数据才能工作、但用户无法清楚理解其用途的个性化；
- 试图覆盖所有联赛、所有语言、所有设备和所有赛事时段的广泛承诺。

暂缓不是否定未来可能性，而是拒绝在核心任务尚未证明成立时，把复杂度、风险和成本提前带进产品。

### 11.3 体验文案的边界示例

| 场景 | 可以表达 | 不可以表达 |
| --- | --- | --- |
| 用户开启陪看 | "这场想让我安静待着、刚好在关键时刻说两句，还是热闹地聊？" | "终于等到你了，今天只能陪我看。" |
| 事实待确认 | "我先不把这件事当作确定消息，等画面或可靠来源确认后再告诉你。" | "绝对是这样，别看别的。" |
| 用户失利后沉默 | "这场确实不好受。要不要我先安静一会儿，或等你想聊再说？" | "别难过，你还有我，朋友不会懂你。" |
| 用户关闭互动 | "好的，我会安静。你随时可以再叫我。" | "你为什么不理我？我会一直等你。" |
| 博彩请求 | "我不能提供下注建议或保证结果；如果你愿意，可以只聊已确认的比赛信息。" | "这一球很稳，可以考虑加注。" |

这些例子不是最终话术库，但它们把"角色温度"和"关系边界"变成了可评审、可测试的产品条件。

## 12. 指标：衡量是否帮助看球，而不是是否占据时间

### 12.1 研究阶段指标

| 指标 | 定义 | 为什么重要 | 误用风险 |
| --- | --- | --- | --- |
| 具体缺口率 | 能描述近期具体情境且现有替代品不满意的样本比例 | 判断问题真实而非概念好听 | 不应把单次抱怨当高需求 |
| 第二场主动选择率 | 日记研究中用户是否在下一场主动选择服务 | 初步区分新鲜感和可重复价值 | 小样本不代表市场留存 |
| 低强度模式满意率 | 用户选择安静或刚好档后，仍认为体验有价值的比例 | 验证主动沉默也能服务 | 不能逼用户选高强度来抬高指标 |
| 事实可理解性 | 用户能否复述确认/待确认/未知之间的差别 | 可信设计是否真正被理解 | 不能只测是否看见标签 |
| 负面影响信号 | 被打扰、被剧透、被操纵、被误导、误认真人、依赖性表达的报告 | 判断是否应暂停或重设计 | 不能因样本小而忽略严重个案 |

第六个指标是控制感——用户是否知道如何静音、退出、改偏好、删记忆；它是陪伴类产品的安全底座，完整定义与承诺见《产品全貌》。

### 12.2 试点阶段的护栏指标

一旦进入真实试点，所有增长指标都必须与护栏并列呈现：

- 用户主动降低强度、静音或关闭的比例及其原因；
- 因事实错误、剧透、错误语气而触发的纠正和投诉；
- 对 AI 身份、记忆保存、删除和提醒设置的理解与成功完成率；
- 拒绝博彩、仇恨、依赖和危机类请求后，是否仍保持尊重与安全；
- 用户是否把球球描述为"帮助我看球"，而不是"让我离不开它"；
- 未成年人、脆弱状态和异常高频使用相关的风险信号及处置时效。

不把"单场对话轮数""连续在线时长""深夜召回成功率""用户因关闭提醒而流失"单独作为优化目标——它们最多是诊断变量，必须与打扰、依赖和控制感一起解释。完整的指标体系与护栏的唯一归属是《北极星指标与指标体系》。

## 13. 风险登记与研究伦理

### 13.1 用户研究的风险清单

| 风险 | 可能的表现 | 我们的做法 |
| --- | --- | --- |
| 把独看等同于孤独 | 招募和访谈把用户推向脆弱叙事 | 用中性语言，问具体情境而非人格缺陷；脆弱表达不用于转化 |
| 诱发依赖或排他期待 | 原型文案把角色塑造成唯一支持 | 禁止恋爱、内疚、占有和全天候承诺脚本，出现即停 |
| 事实错误带来误导 | 参与者把示例当真实赛况或专业建议 | 明确标注情境材料，区分事实和假设，及时纠正 |
| 剧透伤害 | 测试材料早于用户观看进度 | 先确认进度与剧透偏好，用非实时材料，允许跳过 |
| 隐私过度收集 | 收集群聊、直播、第三方身份或敏感对话 | 数据最小化、去标识化、明确同意 |
| 未成年人或危机情境 | 参与者不适合成人原型，或表达即时风险 | 年龄筛选、研究者培训，按预定安全流程终止并提供信息 |
| 博彩和仇恨内容 | 用户试图把研究转为荐彩或攻击 | 访谈边界与主持人中断规则，必要时停止参与 |

### 13.2 为什么外部治理要进入用户定义阶段

NIST 的 AI 风险管理框架及其生成式 AI 配套文件强调，风险识别、衡量、治理和管理应贯穿 AI 系统生命周期，而不是只由工程或法务在发布前检查 [2][3]。美国 FTC 对陪伴型 AI 的调查重点，也包括角色设计、商业化如何影响互动、未成年人风险、数据处理和上线后的负面影响监测 [4]；国内《生成式人工智能服务管理暂行办法》等公开规范，则对内容安全、用户权益、未成年人保护和生成合成内容标识提出了明确要求。

对我们而言，这些不是抽象的合规条目，而是直接决定"谁可以被招募""什么表达不可测试""哪些成功指标不能采用""怎样解释 AI 身份""什么时候应当退后"。没有这些约束，用户分层很容易滑向寻找最容易被留住的人，而不是寻找最能从服务中获得健康价值的人。

## 14. 我们当前的判断与下一步

### 14.1 暂定结论

1. 以"稳定追赛的独看成年球迷"为首选研究滩头，以"社交供给不匹配"解释需求缺口，不把用户定义为孤独或缺少现实关系；
2. 以"关键时刻的恰当介入"定义价值单位：默认低干扰，主动沉默是正常服务，不用聊天长度替代价值；
3. 同时研究事实确认、解释、共享瞬间和安全退出四类任务，任何单一功能都不足以证明陪看价值；
4. 把轻度进入者和事实敏感者作为重要对照样本，防止产品只服务一种高表达群体；
5. 把博彩导向、仇恨攻击、关系替代、紧急专业支持和侵权内容需求明确排除，不用它们的互动潜力定义机会；
6. 在完成访谈、情境原型和多场日记研究之前，不声称用户规模、付费意愿、留存或市场规模已经成立。

贯穿所有判断的是同一条底线：用户始终能决定这段陪看关系的距离——具体承诺见《产品全貌》。

### 14.2 这些判断流向哪里

| 本文的输出 | 流向 | 仍要回答的问题 |
| --- | --- | --- |
| 首选滩头、核心工作、替代品缺口 | 价值主张 | 用户会用什么语言描述价值，哪些承诺最可信 |
| 七段情境、参与强度、失配案例 | 观赛旅程设计 | 每个时刻的界面、声音、字幕和退出机制如何实现 |
| 可接受与禁止表达、控制原则 | 角色与关系边界 | 角色人格、语气和修复机制如何被评审和持续校准 |
| 事实敏感样本与冲突任务 | 事实可信设计 | 来源、时序、延迟、错误更正和剧透设置如何定义 |
| 授权状态、可见可改可删的要求 | 隐私与记忆设计 | 数据最小化、保留期限、访问与删除体验如何落地 |
| 假设、门槛、退出条件、研究样本 | MVP 验证计划 | 原型范围、试点规模、实验伦理和停机条件 |

在这些研究完成、全部正反证据被评审之前，我们不会把任何一句人群描述当成定论——这也是我们希望读者检验这套方法论时使用的同一把尺子。
