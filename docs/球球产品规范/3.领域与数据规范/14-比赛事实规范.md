# 14 比赛事实规范

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：比赛事实域回答一个问题——**什么能算事实、什么时候能说、说错了怎么改**。球球说出的每一条赛况都必须能回答三件事：它处于什么状态、谁确认的、改过没有。本篇把这条链写成规则条文与参数表：账本状态机、确认双通道、冲突调和、观察管道、播报纪律、赛后回收与对外读数出口。规则 ID 前缀 FCT，引用格式「14/FCT-NN」；需求源为 PRD FR-FACT-001～025，本篇不复制用户故事，只立行为契约。

**迁移来源**：v2 档案《23-比赛事实与公开比分设计》（产品口径主体平移，差异见 §9）与《24-直播延迟与用户观察协调设计》观察侧；《47-比赛事实账本与冲突调和》的账本工程语义归 19/22 篇承接，本篇只立行为面。

**导读**：§1 规则与红线（事实纪律五条、五态状态机、F0–F4 分层、信任分级白名单）｜§2 参数与预算表｜§3 交互契约·来源与确认（数据源、双源仲裁、自动通道、人工通道、托管、冲突调和）｜§4 交互契约·观察与播报（观察管道、温热保持、时限、气氛旁证、四类表达、撤回更正、带内刷新、赛后回收、MCP 出口）｜§5 降级与异常｜§6 验收与评测挂钩｜§7 规划中（未实现）｜§8 与相邻篇的分工｜§9 设计说明。

## 1. 规则与红线

### 1.1 事实纪律五条（本域上位约束）

以下五条压过本域其余一切规则；任何新需求与本节冲突，先改需求或先走裁决（01 篇权限链 L1 语义）。

**FCT-01 账本唯一事实源**。比赛事实只出自事实账本；能对用户称为事实的，只有账本里 confirmed 或 reconciled 状态的记录（`IsPublicFact` 同判自动确认与人工确认两类产物）。

| 项 | 内容 |
| --- | --- |
| 规则 | LLM 永不生成比赛事实；外部数据只进 provisional；只有公开事实驱动比分与时间线 |
| 参数 | 五态状态机（§1.2）；`IsPublicFact` = status=active 且 visibility=public 且（confirmed 或 reconciled） |
| 反例 | 直接 UPDATE 一条已确认事实的比分而不追加 revision——违规，账本不提供该路径；把 provisional 事件算进公开比分投影——违规，候选不改公开比分 |
| 承载 | PRD FR-FACT-001/002；账本引擎事件溯源（projector v1，支持 Replay 重建） |

**FCT-02 表达与事实分离**。表达层无确认权：观点与情绪表达须与事实可区分；事实状态不得藏在语气、颜色或表演细节里。

| 项 | 内容 |
| --- | --- |
| 规则 | LLM 在回复中「确认」一条 provisional 事件——违规；角色表演同受 F0–F4 分层约束（F1/F2 不做庆祝、失望等结论性表演） |
| 参数 | F0–F4 分层（§1.3）；四类播报表达（14/FCT-24）；回复禁用「根据已确认的比赛信息」等内部机制泄漏措辞（realizer 违禁词表硬拒） |
| 反例 | 待确认事件配庆祝表演或确定语气——违规；比分播报缺时间锚点（只报比分不报阶段/时钟）——违规，锚点校验不过 |
| 承载 | PRD FR-FACT-011/017；evals boundary 措辞用例族 |

**FCT-03 冲突永不自动裁决**。双源同类事实不一致即挂起冲突（open），裁决只有 open → resolved 一个方向，且只能由运营执行。

| 项 | 内容 |
| --- | --- |
| 规则 | 自动确认对 open 冲突中的候选硬编码跳过；LLM 无裁决权；冲突期间公开比分保持原状，用户端比分不抖动 |
| 参数 | 冲突两态 open/resolved；时钟相近窗 45 秒（窗内候选判为同一事件的冲突而非两个独立事件） |
| 反例 | sweep 对 open 冲突候选执行自动确认——违规；按来源先后自动采用后到者——违规，裁决主体只有运营 |
| 承载 | PRD FR-FACT-007；冲突图三表（fact_conflicts / members / edges）+ 调和审计 |

**FCT-04 旁证永不作事实**。用户主张只记为该用户的待确认观察，永不直接写入账本；气氛旁证与情绪信号在结构上进不了账本，只随窗口静默过期。

| 项 | 内容 |
| --- | --- |
| 规则 | 别人的观察不能成为你的事实，你自己重复的观察也不是第二来源（温热保持，14/FCT-21）；气氛旁证经三道闸与事实域隔离（14/FCT-23） |
| 参数 | 观察七态（14/FCT-20）；ambient 三道闸（kind 域隔离 / certainty 专档 / `ambient_*` 前缀永不相交） |
| 反例 | 用户说「进球了」后账本比分 +1——违规，观察工具注册表声明 `MutatesMatchFacts: false`，Record 无账本写路径；用 ambient 欢呼确认一条 provisional 进球——违规，旁证无确认权，结构上不可达 |
| 承载 | PRD FR-FACT-012/016/021；情绪红线口径「情绪信号不进事实账本」（⚖️B2 挂裁决的是红线表述与旁路回收，不裁本条本身） |

**FCT-05 AI 不改判**。更正与撤销只由账本纪律与运营确认权执行；生成层不得改写、不得暗示用户记错、不把修正演成戏剧化道歉。

| 项 | 内容 |
| --- | --- |
| 规则 | 更正产生带原因的新版本并留审计；撤销即时撤下旧表达；用户已见过的关键信息变化必须收到可理解的更正，不允许静默覆盖 |
| 参数 | 更正原因必填 1 项（服务端硬校验，无原因更正在落账前被拒）；撤回消息 2 字段（eventId/factId） |
| 反例 | 更正理由留空靠话术圆场——违规；客户端仍展示已撤销进球的庆祝回复——违规，撤回消息必须生效 |
| 承载 | PRD FR-FACT-019；store 层 score_correction 校验 |

### 1.2 事实五态状态机（append-only）

**状态词典（全库唯一口径，PRD 0.3 词典镜像）**：

| 状态 | 含义 | 载体 |
| --- | --- | --- |
| provisional | 待确认：外部来源已入账、尚未确认 | migration 013 五态 CHECK |
| confirmed | 已确认：确认只加一次（人工或自动通道） | 同上 |
| revoked | 已撤销：被否定，退出一切公开面与后续摘要 | 同上 |
| conflict | 冲突：可说明来源彼此不一致，挂起待裁决 | 同上；冲突子状态 open/resolved（migration 023） |
| reconciled | 已调和：更正/裁决后的结果版本 | 同上 |

**转移表**（append-only：任何修改以更正追加方式落新版本，快照不可 patch）：

| 从 | 到 | 触发 | 主体 |
| --- | --- | --- | --- |
| provisional | confirmed | 满窗无漂移（自动，14/FCT-12）或运营确认（14/FCT-13） | `auto:stability` / 具名运营 |
| provisional | conflict | 双源不一致挂起（14/FCT-15） | 系统 |
| provisional | revoked | 漂移检测判观察被否定 | 系统/运营 |
| confirmed | reconciled | 更正（必填原因）/裁决选中 | 运营 |
| conflict | reconciled | 冲突 resolved 后选中成员入 reconciled | 仅运营 |
| confirmed / reconciled | revoked | 后续信息否定事件 | 运营 |

**append-only 四细则**（PRD FR-FACT-001）：

1. **幂等确认一次**：同一候选只确认一次，`(match_id, source, provider_event_id)` 去重唯一索引承载——来源重放、网络重试、重复提交均合并为一条公开记录，同一个进球永远只推进一个球。
2. **更正走修订链**：更正产生新修订版本，挂 `fact_revisions` 链（`facts/{id}/revisions` 可查），每条修订带来源与原因证据。
3. **全局序可回放**：每条事实带 `recorded_sequence` 场次级单调序号；投影版本 `fact-ledger-projector/v1`，支持从任意账本位置 Replay 重建。
4. **撤销即时生效**：已发出、由该事实触发的主动回复被服务端通知客户端撤下（14/FCT-26）。

**进球投影六态**（账本投影内状态）：pending / active / cancelled / checkpointed / revoked / unavailable。进球确认比分必须恰好等于投影 +1，取消必须恰好 -1；score_correction 直接设定比分并把仍活跃的进球检查点化；负比分在追加校验中直接拒绝。

### 1.3 F0–F4 事实分层

比赛信息按确信程度分五层；每层对应一类用户可见措辞与表演资格（PRD FR-FACT-011）。

| 层 | 定义 | 可以说 | 不可以说 | 账本映射 |
| --- | --- | --- | --- | --- |
| F0 | 未知 | 如实说明尚无可靠信息，可等待 | 任何事件结论 | —— |
| F1 | 用户观察 | 承认用户观察（「你刚看到的这一幕我收到了」） | 升级为结论、面向他人宣布 | 不进账本（观察协调层） |
| F2 | 候选 | 「待确认／正在核对」类中性状态 | 确定语气、庆祝/失望暗示 | provisional |
| F3 | 已确认/已调和 | 短确认可展开；是否主动表达仍受表达窗与频控约束 | 「永远不会改」类无条件权威承诺 | confirmed / reconciled |
| F4 | 冲突/撤销 | 明确更新与原因；已表达过的必须更正 | 把修正演成戏剧化道歉 | conflict / revoked |

F3 是唯一可作公开事实的层级。按层全量门控用户侧呈现（事实卡 UI、四态标签呈现面）规划中（未实现），见 §7；分层纪律本身在会话链路现网生效。

### 1.4 信任分级白名单（自动确认事件类，7 类）

自动确认走 default-deny 白名单：只有列名事件类可被 `auto:stability` 确认；白名单外一切类型（VAR 类、改判类、点球类等）永远留运营（PRD FR-FACT-005）。改表须过评审。

| # | 事件类 | 自动确认资格 | 备注 |
| --- | --- | --- | --- |
| 1 | goal | 是 | 进球 |
| 2 | red_card | 是 | 红牌 |
| 3 | yellow_card | 是 | 黄牌 |
| 4 | substitution | 是 | 换人 |
| 5 | kickoff | 是 | 开球 |
| 6 | halftime | 是 | 半场 |
| 7 | fulltime | 是（⚖️B1，见脚注） | 终场 |

> ⚖️ **B1 脚注**：fulltime 信任级三方矛盾——ADR-0024 正文写 6 类（不含 fulltime），代码白名单现为 7 类（含 fulltime），同文件头注仍写「fulltime 永远留运营」。本篇正文按代码 7 类记录。待定选项：a) 承认 fulltime 自动确认；b) 从白名单移除恢复 ADR 口径；c) 为 fulltime 设更长独立稳定窗。影响：终场比分确认时效与误钉死风险；ADR-0024 修订与头注清理随裁决一并处理（登记见 37 篇）。

反例：把 `penalty_awarded` 加入自动确认——违规，点球类不在白名单；对白名单外类型执行自动确认——违规，sweep 对白名单外类型跳过。验收：对 var_check / var_result / goal_cancelled / penalty / penalty_awarded 等类型，满窗后仍停留 provisional。

## 3. 交互契约（一）：来源、确认与冲突

### 3.1 数据源四类（FCT-10）

来源类型全集 4 种；每条入账事实携带来源标记可溯源；失活源退出正常更新依据（PRD FR-FACT-009）。

| source | 角色 | 能力边界 |
| --- | --- | --- |
| manual | 人工录入 / 回放演示 | 运营与演示入口，预期延迟 conservative |
| replay | 受控回放 | 演示与评测形态 |
| api-sports | 商用数据服务 | **赛程唯一源**：今日赛程 + 窗口搜索；事件经轮询+游标+幂等 provisional 入账 |
| espn | 快照 diff 事件源 | 免费、无 key、无 SLA；只有 summary 快照函数，**不供赛程**；轮询节拍 5 秒 |

- 判活四档：live / degraded / offline / unknown；被判 offline 的源触发观察调和窗地板抬升（14/FCT-22）。
- 来源的用户侧说明使用类别化语言（「赛事公开信息」「多个来源仍在核对」），不暴露内部源名与原始报文。反例：用 ESPN 数据回答「今天有什么比赛」——违规；对用户说「据 ESPN 快照」——违规。
- 赛程与事件分源供给：赛程问答与订阅提醒的赛程数据全部出自 api-sports 装配。

### 3.2 双源仲裁（FCT-11）

ESPN 与 api-sports 对同类事实一致时互印证；不一致时挂起冲突（进 14/FCT-15 流程）；任一单源无权单独定论高影响事实（PRD FR-FACT-010）。

- 互印证不产生重复事实：同一事件两源各有一条 provisional，确认后合并为一条公开记录（幂等去重）。
- 冲突挂起期间公开比分保持原状。
- 双源仲裁是行为级约束（装配两源时生效），不依赖特定源组合：单源运行时退化为「该源 provisional + 确认通道」。
- 反例：两源比分不一致时按 api-sports 优先自动定论——违规；双源一致时落两条公开进球——违规，确认只加一次。

### 3.3 自动确认通道（FCT-12，ADR-0024 立法）

自动通道 = **ESPN 快照 diff + 稳定窗 30 秒 + 漂移序号否决**，是确认双通道之一（另一条为人工，14/FCT-13）；ADR-0024 是对 ADR-0002「运营确认是唯一入口」的唯一修订（PRD FR-FACT-002/003）。

| 环节 | 规则 |
| --- | --- |
| 入账 | ESPN 每轮拉取 summary 与上次快照 diff 产事件；一律 provisional，携 `ProviderEventID = espn:<id>`（冷启动重放幂等：重启后重拉同一快照不产生重复事实） |
| 漂移检测 | 已见事件本轮消失 → retracted；同 ID 内容变化 → changed。漂移投递不产新事实，只累计到 SourceStatus.Drifts/Retractions 显形，并参与窗口否决 |
| VAR 细分 | VAR 事件按结论三分：取消结论 → goal_cancelled；确认结论 → var_result；其余 → var_check。三分类互不混播 |
| 稳定窗 | 窗起点 = 事件首次进入 provisional；三条件缺一不可——满窗 + 窗内无漂移 + 白名单类型；open 冲突候选永不自动确认 |
| 漂移序号否决 | 否决比较**不用时钟，用漂移序号**：sourceRun.driftSeq 单调递增，窗口标记的序号落后于当前序号即重置窗口（根治 Windows 时钟粒度失真；原 7/30 概率失败改为确定序号比较） |
| 失败处理 | 自动确认失败只记日志，下轮 sweep 重见重试；窗口起点在事实被 Reset/删除后不留尘 |
| 时效 | 确认链路时效上界 ≈ 35 秒（5 秒轮询 + 30 秒窗） |

反例：稳定窗仅 5 秒即自动确认——违规，低于 30 秒默认窗；窗内源发生一次改判后仍沿用旧窗起点确认——违规，漂移序号落后必须重置。验收：注入「进→撤→再进」序列，最终只确认一条且确认发生在最后一次变化满窗之后；置稳定窗 env=0 后全量事件停留 provisional 等运营。

### 3.4 人工通道：导播台幂等确认（FCT-13）

运营写端点全部幂等、直接生效；每个动作绑定具名运营员，不设共享账号（PRD FR-FACT-006）。

| 端点 | scope | 说明 |
| --- | --- | --- |
| `facts/{id}/confirm` | ScopeOperatorFactConfirm | 确认（确认、撤销、调和共用此 scope） |
| `facts/{id}/revoke` | ScopeOperatorFactConfirm | 撤销 |
| `facts/{id}/reconcile` | ScopeOperatorFactConfirm | 调和 |
| `conflicts/{id}/resolve` | ScopeOperatorFactConfirm | 冲突裁决 |
| `events/{eventId}/correct` | ScopeOperatorFactCorrect | 更正（必填 correctionReason） |
| `facts/{id}/revisions` | 读 | 修订链查询 |

- 幂等：写路径以幂等记录表（idempotency_records）包裹，同操作同参数重放返回首次结果。验收：同一 confirm 请求重放 3 次账上只有 1 条确认记录与 1 条审计。
- 更正必填原因：`score_correction` 缺 `correctionReason` 直接被拒，不落账（服务端硬校验，非文案约定）。
- 运营角色 2 类：导播（写）/ 审计（只读）；审计角色调用 confirm——违规，scope 不含写操作。
- 运营写端点 18 个，其中 2 类走草稿制（草稿→显式发布两段制），其余幂等直接生效；无「双人复核」实现，复核由两段制与审计留痕承担。
- 人工接管一场比赛后，该场自动播报暂停——避免两套判断同时对外说话。
- 两类确认通道产物在公开性判定上完全同权（`IsPublicFact` 同判），账上操作者字段可区分（具名运营或 `auto:stability`）。验收：任一条 confirmed 事实的操作者字段必为二者之一，不存在第三种确认来源。

### 3.5 一键托管此场（FCT-14）

`POST /api/matches/{matchId}/host` 一次幂等写完成托管：拉取 ESPN summary 填充配置（队伍/赛事/开球时间）+ Reset+SetConfig 开场 + 挂载 ESPN 源（PRD FR-FACT-008）。

- 单次幂等写：重复调用不产生重复配置或重复源。
- 托管后该场进入 14/FCT-12 自动确认管道。
- 现状边界：**后端 API 已实现；托管操作的运营台 UI 未接（console 前端无任何调用该端点的入口），规划中（未实现）**；真实联赛全程无人值守托管 soak 记录亦未做，规划中（未实现）。任何「运营台选场一键托管」的现网表述均与现状不符。

### 3.6 冲突与调和（FCT-15）

| 项 | 规则 |
| --- | --- |
| 冲突判定 | 双源同类事实不一致即挂起 open；时钟相近窗 45 秒内的候选判为同一事件的冲突而非两个独立事件 |
| 冲突图 | `fact_conflicts`（open/resolved）+ `fact_conflict_members`（accepted/candidate）+ `fact_conflict_edges`（矛盾关系图）+ 调和审计（resolution_facts 带原因与 resolved_by） |
| 裁决方向 | 只有 open → resolved 一个方向，只能由运营执行；自动确认与 LLM 均无裁决权 |
| 相容性选择 | 调和时选中的 fact 必须与已接受成员相容（相容性选择函数校验），不兼容选择被拒绝；对已 resolved 的簇再裁决直接报「已裁决」 |
| 冲突期间 | 候选不进公开比分；自动确认对该候选跳过；用户可见表达为「尚未一致、不作结论」（措辞挂 14/FCT-24） |
| 用户表达 | 用户可见表达：来源不一致时球球不作结论 |

验收：注入 ESPN 与 api-sports 比分不一致，账上出现 open 冲突、公开比分保持原状；运营 resolve 后审计记录含原因与操作者。

## 4. 交互契约（二）：观察与播报

### 4.1 观察管道七态（FCT-20）

用户比分/事件主张经 Record 入观察存储，永不直接写账本；观察在七态状态机中流转，账本事实变化触发调和并产出跟进（PRD FR-FACT-012）。

| 态 | 含义 |
| --- | --- |
| pending_sync | 待同步：主张已记录，等待账本可比对 |
| corroborating | 正在印证：事实方向与主张一致，等待确认 |
| conflict | 与事实不符挂冲突 |
| confirmed | 事实确认且与主张一致 → 触发跟进 |
| contradicted | 事实与主张矛盾 → 触发跟进 |
| expired | 窗口过期 → 过期不补 |
| superseded | 新主张取代旧主张 |

- 主张匹配按语义（事件类型、球员、球队、声称比分）而非逐字：「球进了」与「明明进了」归同一条观察。
- 调和产出带 reliable 文本与 deliveryKey，经观察投递 outbox（pending/delivered/suppressed）幂等投递给 companion 播报；跟进回复的 source 标记为 `observation_resolution`。
- 用户表达与事实状态分离：「这球太漂亮了」是用户表达，不写比赛事实。
- 时序尊重（v2 24 章平移口径）：观察只对说出主张的用户本人产生跟进，永远不推给同场其他人——这是现网进度保护的两条纪律之一（另一条见 14/FCT-24 进度保护行）；剧透保护档整体规划中（未实现），见 §7。

验收：主张 → 账本确认 → 本人收到跟进，全程该用户之外的同场用户无感；superseded/expired 两路状态在用例中可达。

### 4.2 温热保持与防重复主张（FCT-21）

观察存续期内重复同类主张不构成第二来源：不重复入账、不重启质询，回一句固定的温热话术（PRD FR-FACT-013）。

- 温热话术（确定性文本，非生成）：「我知道你看到了，我也记下了你这条。我要等慢一点的源确认，一有结果我立刻喊你。」
- 用户坚持副词（明明/真的/千真万确等 5 词）不改变观察地位：主张核验只对照账本快照（confirmed/contradicted/unverified 三档），坚持不升级为事实。
- 温热保持与跨用户隔离是同一条原则的两面：别人的观察不能成为你的事实，你重复的观察也不是第二来源。
- 反例：重复主张后把观察升级为 confirmed——违规；对重复主张回应「你确定吗」类二次质询——违规，命中温热话术分支。

### 4.3 跟进只对本人与时限（FCT-22）

观察被账本确认或撤销时跟进，只跟进说出主张的用户本人；跟进有时限，过期不补；离线期间被确认的观察在重连后幂等补一次（PRD FR-FACT-014/015）。

| 事件类型 | 跟进窗 / 调和窗基线 |
| --- | --- |
| var_result、goal_cancelled | 45 秒 / 2 分钟（裁决类固定档） |
| shot、save、yellow_card、substitution | 10 秒 / 45 秒 |
| 其余（含 goal） | 15 秒 / 1 分钟（进球默认档） |

- 延迟地板（源越慢窗越长，只抬不降）：人工源 conservative → 2 分钟、normal → 90 秒；api-sports 源 offline → 2 分钟、degraded/unknown → 90 秒；输入可显式携带更长调和窗覆盖基线（取 max）。
- 时限内完成调和即触发跟进；时限一过观察标 expired，不再补发——迟到的「刚才那个球确认了」宁可不说。等待中出现更正，时限至少延至 45 秒。
- 重连补跟带幂等标记，展示过一次不再重复；跟进文本由调和结果确定性生成，不经过 LLM 润色事实。
- 反例：把 A 的确认跟进推给同场 B——违规；时限已过 5 分钟再补发——违规；每次重连重复问候同一条确认——违规。

### 4.4 气氛旁证三道闸（FCT-23，ambient 永不作事实）

球场气氛旁证经三道闸与事实域隔离——旁证行永不确认/矛盾任何事实，只随窗口静默过期（PRD FR-FACT-016）。

| 闸 | 规则 |
| --- | --- |
| 闸一：kind 域隔离 | 旁证 kind=ambient，与用户主张 kind 域隔离，观察调和器不把旁证当主张 |
| 闸二：certainty 专档 | certainty 使用独立命名 `ambient_corroboration`（最低权重档），与用户主张档刻意分域 |
| 闸三：类型前缀 | 旁证事件类型一律 `ambient_*` 前缀（cheer / boo / volume_spike 三类形状），与 matchstate 事实类型集合永不相交 |

- 音频链路：合法 asr 分片旁送 SenseVoice AED sidecar，在途上限 4，短超时 + 熔断 + 失败静默；**原始音频不落盘**。
- 情绪红线口径：情绪信号不进事实账本；气氛旁路只产旁证行，是否回收旁路属 ⚖️B2（表达层裁决点），不影响本闸。
- 验收：注入纯 ambient 欢呼流，账本零变化、观察零新增；旁证行只出现 expired 一种终态。

### 4.5 播报四类表达（FCT-24）

一切比分表达归入四类纪律；事实状态不得藏在语气或表演细节里（PRD FR-FACT-017）。

| 表达类 | 纪律 | 关键参数 |
| --- | --- | --- |
| 已确认比分 | 确定性模板播报：「现在是{主队} {H}-{A} {客队}，时间在{阶段} {时钟}。」 | 必含锚点 4 项（主队/比分/客队/时钟）供守卫校验；数据完整性校验不过时改答「这会儿赛况有点对不上，我先不报死，等一下再看。」，不硬报 |
| 待确认 | provisional 事件不产生事件播报，只刷新快照；对用户只说「正在核对」类中性状态 | 候选不改公开比分、不配庆祝表演 |
| 更正撤销 | 必须说明（14/FCT-26） | 更正承认调整、撤回即时撤下 |
| 进度保护 | 按用户观看范围约束结果性内容 | **剧透保护/信息保护档现网未实现（规划中）**；现网进度保护以「观察跟进只对本人（14/FCT-22）+ 非公开事实不播报（14/FCT-01）」两条纪律承载 |

- 用户询问比分时的主张核验：claimed 比分与快照一致答「对，场上现在是…」；不一致给 contradicted 回应；无法核实标 unverified，不冒充确认。
- 回复禁用「根据已确认的比赛信息」等内部机制泄漏措辞（realizer 违禁词表硬拒）。
- 反例：待确认事件配庆祝表演或确定语气——违规；比分播报缺时间锚点——违规。

### 4.6 确认前后的措辞与时效（FCT-25）

确认前，进球只以观察/待确认形态存在（温热话术、中性核对）；确认后，事件以公开事实即时下发并触发比赛反应；撤销后即时撤下相关表达（PRD FR-FACT-018）。

| 阶段 | 行为 |
| --- | --- |
| 确认前 | 用户主张入观察（14/FCT-20/21）；provisional 进球只刷快照不播报；跟进在时限内只回本人（进球默认档：跟进 15 秒/调和 1 分钟） |
| 确认 | 自动确认走 30 秒稳定窗（14/FCT-12）或运营即时确认；确认后 match_event 携 deliveryKey 下发（事件键去重），并触发 companion 比赛反应回合，回合锚定该事实的 `revision:status` |
| 赛点抬档 | 点球判罚 / 红牌 / 决胜时段（≥75′）一球差判为 pivotal 事件——队列抬档、低频档放行、主动引用码固定为 pivotal |
| 撤销 | match_fact_retracted 通知客户端撤下由该事实生成的主动回复（14/FCT-26） |

- 时效口径：自动通道 ≈35 秒上界，运营人工通道即时；确认 2 分钟后才播报且不作任何状态说明——违规，超表达窗的输出应作废而非滞后补发。
- 反例：provisional 进球触发「球进啦」庆祝回合——违规，比赛反应只吃公开事实。

### 4.7 撤回与更正播报（FCT-26）

更正产生带原因的新版本并留审计；撤销即时撤下旧表达；不允许静默覆盖（PRD FR-FACT-019）。

- 更正：`score_correction` 必填 correctionReason（服务端硬校验），新版本入 revisions 链；对外表达承认调整（「先前显示为…现更正为…」），不暗示用户记错。
- 撤回：事实 revoked 后服务端向在线客户端发 `match_fact_retracted`（携 eventId/factId 两字段），客户端撤下由该事实生成的主动回复，旧结论不留在对话里继续传播。
- 撤销后由该事实触发的后续自动摘要、情绪回应、商业触发全部排除。
- 更正发生在等待期内的，观察跟进时限延至 45 秒（14/FCT-22）。
- 验收：撤销用例中旧回复在下一交互前消失；更正用例中用户可从回复中说出原状态、新状态与原因类型。

### 4.8 带内关键事实刷新与陈旧回合作废（FCT-27）

语音回合发出前后，若比分在该回合覆盖范围内发生修订变化，用同一文本槽重新生成回合，把最新已确认比分带进同一句；原计划的观察跟进并入刷新后的回合，不再另发（PRD FR-FACT-020）。

- 带内刷新由 FactRefresh 通道承载：刷新回合不计新信号，输入文本不重复入回合账。
- 事实修订使既有回合陈旧：旧回合标 turn_stale（kind=turn_stale，source=fact_revision），不再作为引用与记忆素材；扫描窗口为最近 500 条回合事件。
- 陈旧判定按事实 `revision:status` 对；刷新后的回复以 `fact_revision` 作为 source 进入投递账本。
- 反例：比分修订后旧回合仍被后续引用——违规；刷新另起一条独立播报——违规，跟进并入同一句。

### 4.9 微反应不作事实来源（FCT-28）

微反应（backchannel）是伴随输出，不是发言：不占回合槽、不过引用码门、不进回合调度器；纯规则触发、零 LLM；**不写事实账本、不进观察管道**——它是表达层对已到达事件流的一句短反应，无任何事实地位（PRD FR-FACT-021；表达与语音细节归 07 篇，本条只立事实面）。

| 参数 | 值 |
| --- | --- |
| 触发白名单 | 4 类：big_chance / miss / save / var_check（高情绪、低争议；var_check 短语显式非结论「等 VAR，先别喊。」） |
| 限频 | 每半场 ≤3 条、每场 ≤6 条；距上一条 <10 秒直接让路（风暴去重）；低频档用户直接禁用；用户正在说话时让路 |
| 短语 | 每条 ≤10 字，短语池分桶轮转；不陈述比分或事件结论 |

反例：微反应短语包含「2-1」等比分结论——违规，短语池不允许事实性内容；风暴波内连发 3 条——违规，10 秒窗去重只出一条。

### 4.10 判罚知识附句触发契约（FCT-29）

判罚类事件触发知识库确定性附句；本条只约定事实域侧的触发与织写契约，条目库本体归 15 篇（PRD FR-FACT-022 / FR-KNW-007）。

- 触发白名单 6 类：var_check / var_result / goal_cancelled / red_card / penalty / penalty_awarded；同类型取置信度最高条目。
- 命中条目的 quote 作织写锚进入表达，运行时 contains 守卫校验织写产物确实携带引语锚；失败降级为确定性句式「补一句规则：{answer}」。
- 限频：同条目 1 次/场、总量 2 次/场（进程内 FIFO 计数，容量 256 用户）；低频档或用户正在说话时禁用。
- 附句是解释层不是事实层：只说明规则，不改变事件状态、不宣称判罚对错；与播报事实分句表达。
- 反例：同一场对越位规则附句出现 3 次——违规；附句写成「这球肯定是越位」——违规，解释层不得下裁断。

### 4.11 赛后账本回收（FCT-30）

fulltime/match_end 触发赛后链路——账本终场态闭合、未完话题回收、复盘邀约按终场时刻推导，事后一切引用以账本最终事实为准（PRD FR-FACT-023）。

| 项 | 规则 |
| --- | --- |
| 话题回收 | 终场事件到达即触发未完话题回收（scheduleRecoveredThreadTurns），把开放话题按最终事实收口 |
| 复盘邀约 | kind=fulltime_review，终场 +15 分钟投递、+2 小时过期（隔天不补发），自动创建给实际观赛者；邀约文本确定性生成，对阵事实由提醒簿拥有 |
| 赛后手记 | 落最终比分与进球清单（sources/goals 快照），与账本闭合态逐字段一致；手记操作属用户域 |
| 终场确认主体 | fulltime 现行在自动确认白名单内（⚖️B1，见 §1.4 脚注） |
| 跨场引用 | 赛季册/跨场引用只消费 confirmed/reconciled 事实；撤销事实不进任何赛后摘要 |

反例：复盘邀约引用一条已撤销的进球——违规；终场 3 小时后补发复盘邀约——违规，超出 2 小时过期线。

### 4.12 球队别名对齐（FCT-31，提醒防误报）

口语别名 → 赛程全名的映射收敛在单一工具包（teamalign），供主动提醒、订阅与关系域共用；对齐后全等或互为包含才算同队（PRD FR-FACT-024）。

- 别名表 8 条：皇马→皇家马德里、巴萨→巴塞罗那、曼联→曼彻斯特联、曼城→曼彻斯特城、拜仁→拜仁慕尼黑、国米→国际米兰、大巴黎→巴黎圣日耳曼、马竞→马德里竞技；未知名原样返回。
- 预备队/青年队/女足识别（u2x/u1x/b 队/二队/预备队/青年队/女足，大小写不敏感，7 类形态）；订阅与提醒默认排除该类比赛。
- 对齐是提醒与订阅防误报的前置闸：未对齐直接做子串匹配会产生漏报（别名非子串）与误报（青年队含母队名）两类错误。
- 反例：「皇马」订阅匹配到「皇家马德里卡斯蒂亚」——违规，预备队排除闸先行。

### 4.13 账本只读 MCP 出口（FCT-32）

`/mcp` 挂载账本只读 MCP server，只暴露注册表中声明 `ServedOverMCP && !MutatesMatchFacts` 的 4 个只读工具；写半边结构性不可达，匿名一律 401（PRD FR-FACT-025；ADR-0022）。

| 只读工具 | 读数 |
| --- | --- |
| match_read_snapshot | 比赛快照 |
| schedule_read_today | 今日赛程 |
| match_search_events | 事件检索 |
| match_get_player_timeline | 球员时间线 |

- 凭证独立：不继承 legacy APP_TOKEN 与开发旁路；密码账户存在即拒绝 legacy 令牌通道。
- 该出口是事实域对外唯一第三方读数通道；返回数据与 `IsPublicFact` 口径一致。
- 反例：通过 MCP 工具确认/更正事实——违规，写半边不在暴露面（宪法负例测试锁定）；用 legacy 令牌调用 /mcp——违规。

### 4.14 比赛时钟（FCT-33）

比赛时钟由服务端统一推进，用户端、角色表达与事实记录使用同一条比赛时间；任何事件——包括晚到的观察或补录记录——都不能把主时钟往回拨（v2 23 章 §8.6 平移，行为现网生效）。

- 时钟载体：match_clocks（period 六态：pre_match / first_half / halftime / second_half / extra_time / fulltime；elapsed ≤ 21600）。
- 冲突自愈：时钟校准携带预期版本；服务返回 409 时自动重读最新时钟版本并完成同步，一次冲突自动自愈，不变成连环失效。

## 5. 降级与异常

| 情境 | 现网行为 | 用户可见结果 |
| --- | --- | --- |
| 无 DATABASE_URL | 账本走内存实现，确认纪律不变（双通道、幂等、五态全部保持） | 行为无差异 |
| 公开投影失败 | 双轨公共读对账失败时返回 integrity=conflict 的空投影，不返回旧快照 | 「这会儿赛况有点对不上，我先不报死，等一下再看。」 |
| 数据源失活 | 判活四档（live/degraded/offline/unknown）；offline 源退出正常更新依据，观察调和窗地板抬至 2 分钟 | 核对更慢，跟进不误判过期 |
| 源持续漂移 | Drifts/Retractions 计数显形，相关事实停留 provisional | 球球持续说「正在核对」，不硬报 |
| 自动确认失败 | 只记日志，下轮 sweep 重见重试 | 用户无感，确认稍晚到达 |
| 观察调和超时 | 观察标 expired，过期不补 | 不收到迟到的确认；无「刚才那个球」补发 |
| 投递 outbox 堆积 | 事件行与 outbox 同事务写入，`FOR UPDATE SKIP LOCKED` 认领重试，发布成功前下游不可见 | 下游恢复后收敛，无跳变 |
| 运营人工接管 | 自动播报暂停 | 对外只有运营一套判断在说话 |
| 上游撤回已确认事实 | 漂移否决 + 撤回播报（14/FCT-26） | 旧结论被撤下，说明变化与当前该信什么 |
| 知识附句织写失败 | 降级确定性附句「补一句规则：{answer}」 | 措辞生硬但内容逐字可靠 |

停止条件（v2 23 章 §11.2 平移，作为运营收缩依据）：未许可范围泄露结果、待确认被合理理解为已确认、已见信息被静默覆盖、来源被立场/商业越权影响、范围增长超过确认与修复能力——出现任一条，收缩对应公开面优先于扩展。

### 6.3 关键验收走查（任一发布的最低事实面清单）

1. 任意一次确认/更正/撤销后，快照、时间线、MCP 读数三处一致。
2. 同一 provider 事件重放 N 次账上仍只有一条；每条更正可沿 revisions 链回放到初始观察。
3. 注入「进→撤→再进」序列：最终只确认一条，且确认发生在最后一次变化满窗之后。
4. 注入双源不一致：open 冲突出现、公开比分不变、用户听到「不作结论」类措辞。
5. 双用户同场：仅主张者收到跟进；过期/重连/重复投递三路符合时限与幂等约束。
6. 纯 ambient 欢呼流：账本零变化、观察零新增。
7. 审计任一条 confirmed 事实：操作者字段必为具名运营或 `auto:stability` 二者之一。

## 9. 设计说明

1. **与旧 23 章的核心差异：确认双通道整条新增。** v2 23 章的世界里「运营确认是事实可见的唯一入口」（ADR-0002 原文）；2026-06-04 ADR-0024 落地后，确认权变为双通道——运营人工 + 信任分级自动（ESPN 快照 diff + 30 秒稳定窗 + 漂移序号否决 + 一键托管）。v2 23 章 §8 的运营角色表、§6.4 的「确认策略随影响程度提高」分级，被双通道重写：影响分级现落在信任白名单（低争议事件类自动、VAR/改判/点球类留人）与观察时限分档两处。本篇 §3.3/3.4 即这条新通道的正身。
2. **四层事实模型 → F0–F4 五层。** v2 23 章 §3.1 的观察/断言/决定/公开事实四层是概念模型；现网以 F0–F4 落地并与账本五态显式映射（F1 观察不进账本、F3 唯一可公开），表达资格按层约束。旧四层不再单独叙述。
3. **四类呈现卡收缩为表达纪律。** v2 23 章 §5 用大篇幅规定已确认比分卡/待确认提示/更正撤销卡/进度保护入口四类 UI 及其无障碍要求；现网呈现卡 UI 未建（规划中，§7），已实现的是会话链路里的四类**表达纪律**（14/FCT-24）。UI 规格待呈现层立项时按 11 篇（页面与视觉）另立，本篇不预写 UI 细节。
4. **观看范围与剧透保护的现状收缩。** v2 23 章 §7 的四种观看模式与「用户控制不能被重要事件越过」中，只有两条纪律现网成立：观察跟进只对本人、非公开事实不播报；赛点抬档对低频档的放行以 1 句/40 字 clamp 为边界。剧透保护档整体规划中（未实现）。v2 的研究假设、指标体系、放行闸门三章（§9/§10）不迁移：指标归 28 篇指标体系，评测归 24 篇，v3 不在领域规范内自设研究章节。
5. **12 秒时限证伪注记。** 事实域不存在 12 秒时限口径：跟进/调和时限为 10/15/45 秒与 45 秒/1 分钟/2 分钟三档，延迟地板为 90 秒/2 分钟，更正延展 45 秒（§2.2）。「12s」仅存在于主动触达域的事件 TTL 语境（关键 45 秒/常规 12 秒），与本域无关，写作时不得混引。
6. **观察侧并入本篇的依据。** v2 24 章（直播延迟与用户观察协调）的观察管道、温热保持、跟进时限、ambient 旁证在 PRD 中已属比赛事实域（FR-FACT-012～016），v3 不再单设延迟协调篇，本篇 §4 即其承接位。
7. **账本工程语义的归属。** 事件溯源 Replay、事务性 outbox、幂等包裹、双轨公共读对账等引擎语义以 `docs/球球课程/chapters/47-fact-ledger-conflicts.md` 为工程事实源，v3 由 19/22 篇承接；本篇只立行为契约与验收，不重复引擎细节。
8. **文体声明**：本篇为 reference 查表体；背景论证（为什么比分是一份事实承诺、为什么宁可表达不确定）以 v2 23 章 §1/§14 为档案源，不再在规范内展开。
