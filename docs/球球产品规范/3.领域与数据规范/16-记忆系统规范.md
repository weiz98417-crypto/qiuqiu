# 16 记忆系统规范

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：记忆系统的工程侧全链路规范——观察如何入队、如何打分、如何召回、如何反思、如何写回画像、删除如何立碑。用户可感的体验契约（可感/可查/可删、懂我页、理由入口、话题条）归 08 篇；本篇只立系统语义。规则 ID 前缀 MEM，引用格式「16/MEM-NN」。

**导读**：§1 规则与红线（写入→打分→存储→召回→反思→画像→话题账本→手记→删除→消费纪律→全链路走查）｜§2 参数与预算表｜§3 交互契约（接缝四方法/审计 reason code/表登记/嵌入部署/反思手记时序/运营台契约）｜§4 降级与异常｜§5 验收与评测挂钩｜§6 规划中（未实现）｜§7 与相邻篇的分工｜§8 设计说明。

**事实依据**：本篇全部参数与行为以基线代码为准——`backend/internal/memory`（queue/heuristic/portrait_ops/threads/memobase）、`backend/internal/embedding`、`backend/internal/journal`、`backend/cmd/server/main.go`（反思 beat 装配）；表结构以 `backend/migrations` 对应迁移文件为准。

## 1. 规则与红线

### 1.1 总纪律（四条红线）

**MEM-01 接缝单源**。上层对记忆的全部访问经记忆接缝的四个方法——观察 Observe / 召回 Recall / 画像 Portrait / 话题 Threads——不直连存储、不绕过队列。接缝有三件实现：Memobase adapter（生产）、Queue（编排+降级）、Fake（测试与无库开发）。反例：会话层直接读写 portrait_overlays 表属违规。

**MEM-02 记忆永不写比赛事实**。记忆系统（含 Memobase）可以从互动账本引用已记录的公开事实，永不制造、修改或断言比赛事实；比分只来自事实账本（14 篇）。这是记忆与事实链之间的单向关系（ADR-0006 接缝地基）：记忆系统的故障域被限制在「球球不够懂你」，永不外溢到「球球说错比分」。

**MEM-03 账本是原件，记忆是投影**。球球对用户的全部了解从追加式互动账本（17 篇）出发；Memobase 合成库不参与全量备份、可重建，账本才是原件。画像条目必须有账本出处；球球不自行「领悟」用户新的敏感偏好。

**MEM-04 删除是横切语义**。删除（条目级立碑 / 身份级全量）作用于记忆全链路：读路径（下一回合生效）、写路径（删除期阻断）、导出（已删数据不出现）、观测日志（已删数据脱敏）。细则见 §1.9；本条为红线级：任何「边删边写」复活路径属违规。

### 1.2 写入链：异步队列与 backlog-first

**MEM-10 异步观察队列**。话轮内只做「入队」，观察提取与落库在话轮外完成（PRD FR-MEM-001）。

- 队列有界，容量 256；队列满时丢弃新观察并计数（可观测），绝不阻塞话轮。
- 队列由进程内单个消费者排空（drainer 单 goroutine）。
- 入队即返回：写入成败对话轮零反馈义务。

**MEM-10a 观察来源全集**：

| 来源 | 触发 | 备注 |
| --- | --- | --- |
| 话轮内容 | 用户回合管线（user_speech 处理后） | 主来源；偏好/边界/承诺/情绪交流的观察从此产生 |
| 比赛事件回调 | 账本事件确认后回调 | 进球/红牌等高基分类观察 |
| 主动系统转写 | 提醒簿 SweepLoop（开球+30min 未送达翻 suppressed 后转记忆素材，importance 0.6） | 「开球前没等到你…」类素材，Q13 口径 |
| 共同瞬间 | 瞬间入账同步入队 | 与 embedding_moments 投影同源 |

**MEM-11 backlog-first 积压重放**。首次写入失败即落 PG 持久积压（memory_backlog，`039_memory_observations.sql`）：先落库后重试，不丢不覆（PRD FR-MEM-002）。

- 重试按指数退避：首试 30 秒，封顶 10 分钟；单条最多 10 次，超过即终态（不再重放，留审计）。
- 积压为持久层承载，服务重启后继续重放。
- 终态条目不删除，以审计行留痕。
- 无数据库配置时降级 Ledger-only：记忆增强缺席，账本兜底——服务可用性不依赖记忆链路。

**MEM-12 全量审计留痕**。每条观察的处理去向全量落 memory_extraction_audit（`039_memory_observations.sql`），reason code 全集见 §3.2。入队时的重要性与账本序号为入队时值，Memobase 永不改写。

### 1.3 确定性打分与提取门槛

**MEM-20 打分公式（可复算可审计）**。score = clamp01(类别基分 + 措辞加成) × 关系阶段权重（PRD FR-MEM-003）。

| 成分 | 取值 |
| --- | --- |
| 类基分 | 进球类 0.90／红牌·VAR 0.80／承诺 promise 0.80／用户事实 user_fact 0.70／情绪交流 0.60／黄牌 0.55／其他 0.30 |
| 措辞加成 | 偏好/边界措辞 +0.10；承诺措辞 +0.10；高唤起措辞 +0.05 |
| 阶段权重 | first_meeting 0.90／familiar 1.00／watch_buddy 1.05／old_ballmate 1.10 |

**MEM-21 提取门槛 0.35**。低于门槛的观察不发起提取 LLM 调用，直接审计为 rejected_low_importance——低分观察在最便宜的位置被拦下，不产生 LLM 成本。

**MEM-22 三因子两腿同代**。召回侧打分因子为 recency × importance × relevance；衰减时间窗（DecayDays）对 adapter 腿与向量腿同源下发——两腿用同一窗口，分数可同代比较。改衰减窗即同时改两腿，不允许单腿独改。

**MEM-23 打分不引入模型主观评分**。打分是确定性公式，同一观察重复打分结果一致；阶段只调权重，不存在「关系阶段影响记忆写入概率」的随机机制。

### 1.4 召回三路融合与时序衰减

**MEM-30 三路融合**。召回固定三路，结果按内容去重合并（PRD FR-MEM-004）：

| 路 | 载体 | 特性 |
| --- | --- | --- |
| ① adapter contains 路 | Memobase 检索 | 保序在前 |
| ② pgvector 向量路 | Postgres+pgvector（embedding_moments，`046_embedding_moments.sql`），余弦相似 | 语义路 |
| ③ 内容精确腿 | Focus 原文匹配 | 稀有实体兜底，不依赖嵌入服务可用性 |

配额规则：向量路或内容路有结果时，adapter 路配额降为 limit − limit/2；向量路弃权（端点不可用/超时/并发超限）时 adapter 路独享全量配额——**弃权 = 现状，配额不得回退**（防低质结果灌顶）。召回条数默认 top-k 5。

**MEM-31 时序衰减 τ=14 天**。向量路召回结果施加 weight = score × exp(−age/τ)，τ = RECALL_DECAY_DAYS（默认 14 天）；衰减只重排不丢条——超龄记忆降权，不删除（PRD FR-MEM-006）。

**MEM-32 语义嵌入底座 bge-m3 本地优先**（PRD FR-MEM-005）：

| 项 | 值 |
| --- | --- |
| 模型 / 部署 | bge-m3 @ 宿主机 Ollama，OpenAI 兼容端点 `host.docker.internal:11434/v1`（2026-05-22 裁决「本地模型无 key」） |
| 维度 | dim=1024 |
| 客户端 | 最小实现，默认超时 2s；文本超 2000 rune 截断（模型上限 8192 token） |
| 向量化范围 | 知识库条目仅 topics 字段；记忆向量路对入库的记忆/瞬间文本 |
| 消费点 | 同一嵌入服务同时支撑知识库检索与记忆向量路（一处部署、两处消费） |
| 开关 | EMBEDDING_BASE_URL 留空 = 语义路整体停用（随开随用） |

**MEM-33 向量库双形态**。向量库主存为 Postgres+pgvector；无向量库时退化内存向量库。Memobase 服务端自带的事件嵌入开关（MEMOBASE_ENABLE_EVENT_EMBEDDING）默认关闭——生产语义路是后端自管的 pgvector 双路，不是 Memobase 嵌入；文档写「语义记忆」时指前者。

### 1.5 反思（Reflection beat）

**MEM-40 双触发调度**（PRD FR-MEM-007）：

| 触发 | 节奏 | 门槛 |
| --- | --- | --- |
| idle | 每 15 分钟一轮（内部 2 分钟 ticker 检查） | 只反映「自上次 beat 新增 importance 累计 ≥1.5」的用户（≈0.5 级 ×3 条） |
| post_match | 终场事件（match_end / fulltime）观察者驱动，终场即反思 | 不受 idle 重要性门槛 |
| 低活跃兜底 | 每 5 个 idle 轮（至多约 75 分钟）强制全量一次 | 无门槛 |

**MEM-41 反思流程固定**：取出并清零 importance 累计 → 取引用序列 → 冲洗写入积压 → 画像主张合并（冲突操作集，MEM-50）→ 画像按年龄巩固（MEM-52）→ 画像刷新 → 反思审计落库。引用序列（citations）写穿持久层 memory_citations（`054_memory_citations.sql`，user+ledger_sequence 主键）——服务重启审计链不断。

**MEM-42 赛后归因（只记你看过的球）**。post_match 反思的审计标签取「用户实际互动过的最近终场比赛」；没有观看则空标签；归因窗口为最近 8 场（PRD FR-MEM-008）。不把别人的比赛挂到用户头上。

**MEM-43 归因窗口**。反思只在工作窗口内运转：256 用户、每用户 8 场、64 引用。

### 1.6 画像（Portrait）：权威层、冲突操作集与写回

**MEM-50 画像权威层合成**。画像 = 远端综合（Memobase synthesis）+ 本地覆盖层（portrait_overlays，`041_portrait_overlays.sql`）按（主题，子主题）确定序合并输出；隐私墓碑命中时下一话轮即空。覆盖层已时间化（`051_portrait_temporal.sql`/`052_portrait_open_slot_unique.sql`）：行以 id 为主键、携带 valid_from/valid_to 时间窗、同槽至多一条开放行（部分唯一索引）。

**MEM-51 冲突操作集**。用户自述类事实（user_fact）先进待合并主张账本（每用户上限 16 条）；反思时经结构化判定产出操作集 ADD / UPDATE / DELETE / NOOP 落权威层（PRD FR-MEM-009）。

- 主张槽位固定：preferences/user_stated——自述主张只落这一个位置。
- 高敏槽位默认遮蔽：favorite_team、favorite_player 两槽的新主张先进遮蔽，经合并判定后才可改写权威层（防一句话被误改主队）。
- 无 LLM key 环境（CI/评测）退化为同槽盲 ADD/UPDATE 收口——已知的评测形态行为，与线上行为可区分。
- 冲突不即兴裁决：每个判定留审计（portrait_op_applied / portrait_op_noop / portrait_op_skipped / portrait_shadow_applied / portrait_shadow_skipped）。

**MEM-52 写回 dry-run 与比分红门**（PRD FR-MEM-010）：

- 主张落库前执行写回审查（dry-run 预演）：低温度（0.1）、短预算（约 120 token）的 LLM 审查员复核主张，拒绝则记 NOOP 并留 `writeback_rejected:` 审计。
- 确定性比分红线：比分形态的主张零 LLM、直接拒绝（比分形态识别先行于 LLM）——比分永远来自事实账本，不进画像。
- 审查服务故障不阻断画像维护主流程（放行并记日志）；比分红门是纯确定性规则，任何时候都在。

**MEM-52a 写回管线门序**。一条主张从入账到落库经过固定的门序列，次序不可调换：

```
隐私前置（墓碑命中即拒绝）
  → 比分形态识别（matchScorePattern，确定性红门，零 LLM 直接拒）
  → LLM 写回审查（dry-run，temperature 0.1 / 120 token；拒绝 = NOOP + writeback_rejected: 审计）
  → 同槽合并判定（操作集 ADD/UPDATE/DELETE/NOOP；遮蔽槽经判定才可改写权威层）
  → 落 portrait_overlays（时间窗行，UPDATE 即续期）
```

比分红门在 LLM 之前：审查器任何形态的故障都不影响红门生效；红门是纯确定性规则，任何时候都在。

**MEM-53 时间窗与按年龄巩固**（PRD FR-MEM-011）：

- 换主队后，旧队相关画像条目即时封口（时间窗机制）：球球不再替旧队说话。
- 画像衰减窗 90 天（PORTRAIT_DECAY_DAYS）：反思尾部对超窗未续期条目软封口；任何 UPDATE 即续期；确认无逐条信号面——不要求用户逐条「续约」。
- 软封口不是删除：封口条目退出权威输出面，底档与审计保留。

**MEM-54 画像用户面**。`/api/me/portrait` 三操作：读 / 改 / 忘（PRD FR-MEM-012）。单条忘 = 本地墓碑永久 + 远端删除 best-effort；全量忘 = 本地与远端全删，远端不可达时如实返回 5xx，不谎报成功。

### 1.7 未完话题账本（Thread）

**MEM-60 双账本并存、单权威**。本地 Thread 账本（open_threads，`040_open_threads.sql`）为权威；relationship 状态内的开放话题条目为存量回退（兼容旧数据）。ActRecall 优先取 Thread 最新开放话题，账本缺席时回退 relationship 条目。

**MEM-61 TTL 7/14 双轨**。Thread 权威账本 TTL 7 天（DefaultThreadTTL = 7×24h）；relationship 存量条目 14 天——数值不一致是有意保留，权威面归 Thread（PRD FR-MEM-017）。

**MEM-62 生命周期与终态**。kind 四类（CHECK 约束）：unanswered_question / promise / emotional_moment / prediction；state 三态：open / addressed / expired——过期与已答是两个不同的终态，分别写审计（thread_opened / thread_addressed / thread_expired，过期不静默）。话题过期由反思 beat 每拍执行清理（ExpireStaleThreads）；过期话题退出 ActRecall 候选，不再被主动接起。

**MEM-63 词表单源**。开放话题标记词表单源维护（承诺类别名并入同一源），只改一处、两账本同时生效。

> **已知缺陷（⚖️B9，修复跟踪在工程侧）**：代码域存在第五类 `unroutable`（意图路由漏斗），超出 `040_open_threads.sql` 的四类 CHECK——PG 下该类写入被约束拒绝、错误被静默吞（只记日志）；测试走内存实现故假绿。本条不改变正文行为口径（权威账本按四类运行），修复（放宽 CHECK 或 AppendThread 过滤）另开工程单。

### 1.8 手记与赛季记忆册：反思产能的消费面

**MEM-70 数据流（teammate-journal，ADR-0023 第 2 条）**：

```
终场事件 → Queue.NotifyMatchEnded → post_match ReflectNow 冲洗完成后
  → journalService.afterPostMatch
  → 素材 = 账本终场投影 MatchFacts（0-0 且无事件则不写，防空账本成文）+ 画像口味 ≤3 条
  → journal.Generate（LLM 织写；无 key = 确定性底稿）
  → validateBody 确定性比分后校验（正文比分形态必须与账本终场一致，否则整篇降级 DeterministicDraft）
  → 落库 journal_entries（056_journal_entries.sql，同 user+match 幂等一篇）
```

**MEM-71 零编造与幂等**（PRD FR-MEM-015）。手记只引账本真实行与画像条目（sources 数组：match: / goal: / portrait:），永不产生新比赛事实；同用户+同场至多一篇（落库层设防）；任何失败只记日志，绝不影响反思主体——手记是消费面，不是关键路径。

**MEM-72 阅读面纪律**。手记是阅读面不是聊天素材：不进主动回合话术，不作为记忆被引用（防自我引用循环）。用户操作：点赞、忘掉（物理删除）、文本分享。

**MEM-73 赛季记忆册**（PRD FR-MEM-016）。BuildAlbum = 手记列表 + 每场共同瞬间的装订视图（瞬间数据经适配层接入，避免阅读面反向依赖记忆内部）；按 season（该赛季开球年份）过滤、倒序；摘要 = 首句 ≤60 字；赛季册只读，拉取失败 = 空视图，不拖垮手记主列表。

### 1.9 删除与立碑（横切机制）

**MEM-80 立碑语义**（PRD FR-MEM-018）。用户删除受理即落墓碑（privacy_tombstones，`013_trusted_interaction_foundation.sql` 建、`016_privacy_lifecycle.sql` 扩）：墓碑下一回合生效——画像与记忆在下一话轮即从上下文消失。立碑是永久的：即使记忆服务稍后从旧数据重新提炼同样内容，墓碑把它挡在上下文之外——再抽取无法让忘掉的东西复活。

**MEM-81 后台清理**。删除受理后由后台任务执行清理与到期物理清除（清理周期 6 小时、保留期硬上限 30 天——生命周期数值唯一出处：17 篇 DAT-42，本条不另设口径）。墓碑状态三态（CHECK）：pending / completed / failed。

**MEM-82 写路径阻断**。删除期内 companion 侧全部用户写路径被阻断——立碑与清理完成前，记忆/画像写路径一律拒绝，防止「边删边写」复活数据。有专项集成测试守护。

**MEM-83 各对象族删除语义**：

| 对象 | 删除语义 |
| --- | --- |
| 画像单条 | 本地墓碑永久 + 远端 best-effort（MEM-54） |
| 画像全量 | 本地+远端全删；远端不可达如实 5xx |

### 1.10 消费纪律：回合经济与进回合

**MEM-90 回合经济**（PRD FR-MEM-020）。同一回合同一 (用户, 焦点) 的 recall 与 portrait 恰好拉取一次：结果缓存挂回合上下文（不落全局字段），回合结束即失效；话轮内预算 recall 300ms / portrait 300ms。

**MEM-91 记忆进回合四入口**（PRD FR-MEM-021）。记忆不只是检索结果，还织进措辞层；现网四入口：

| 入口 | 系统行为 |
| --- | --- |
| 闲聊 | 回答织入已确认偏好（口径、口味、称呼） |
| 主动回合 | 主动话术带记忆来路（引用码 + reason 字段） |
| 事实衔接语 | 比分/事件播报衔接口味（比分仍只来自账本） |
| 线程回访 | 未完话题补答或接续（Thread 最新开放话题） |

措辞层边界：仅在润色器可用且召回材料非空时织入，guard 通过才采用，超时/失败/拒绝一律原样返回底稿（决策层不动，措辞层受限入口）。

**MEM-92 口味偏置门序**。ADR-0019：支持队进球 valence +0.2、支持球员进球 +0.15（clamp [−1,1]）；偏置在全部限制门（输出关/低频档/冷却）之后施加——被压制的事件不享受加成；留 reason code（policy_memory:favorite_team_goal / favorite_player_scored）审计可查。

**MEM-93 画像缺席 = 零漂移**。画像信号提取 300ms 超时；画像缺席时召回与表达照常，只是不带画像偏置——不猜测偏好。

### 3.5 反思与手记的时序契约

终场前后的三个异步阶段有固定次序，保证消费面看到冲净后的状态：

```
match_end / fulltime 账本事件
  → 事件观察者调 Queue.NotifyMatchEnded（登记 post_match 反思 + 终场归属）
  → 反思 beat 执行 ReflectNow：冲洗写入积压（backlog flush）→ 画像主张合并 → 巩固 → 审计落库
  → 冲洗完成后 journalService.afterPostMatch 才取材（取的是 flush 后状态 + 账本终场投影）
```

两条纪律：① 手记永远在反思冲洗之后取材（保证口味素材与画像一致，MEM-70）；② 手记任何失败只记日志，绝不影响反思主体（消费面不在关键路径上，MEM-71）。post_match 反思不受 idle 重要性门槛拦截（MEM-40）。

### 3.6 运营台契约（只读旁路 + 治理入口）

记忆系统对运营台的暴露面全部为只读或治理动作，无记忆内容写入口：

| 面 | 能力 | 边界 |
| --- | --- | --- |
| 概览记忆健康格 | 队列积压深度、降级徽标直出 console 概览 | 运维不翻库即可判断记忆链路健康；不含任何用户记忆内容 |
| 话题台账页 | 开放话题列举 + PATCH 关闭（手动标记已答/过期） | 两个动作走不同审计路径；话题内容可见但不可编辑 |
| 引用审计页 | 主动发言引用码审计，按引用前缀深查 trace | 只读；「能解释的主动才是健康的主动」 |
| 用户层画像视图 | 画像只读 | 确需按用户利益删除单个条目走独立接口：二次确认、记审计（17 篇 §1 系统级边界 2） |

## 8. 设计说明

1. **与 08 篇的切分**。v2 档案 30 章把记忆的体验与机制混写；v3 按 Diátaxis 切开——08 篇立体验契约（MEX 规则族），本篇立系统语义（MEM 规则族）。两篇互引不重复：同一参数在 08 篇只写用户可感语义，在本篇写值与出处。
2. **全链路一图**：写入（队列 256·满丢弃→失败 backlog 30s→10m·10 次）→ 打分（确定性公式·门槛 0.35）→ 存储（Memobase + pgvector 双库）→ 召回（三路融合·配额规则·τ=14 天衰减）→ 反思（idle 15min·阈值 1.5·兜底 5 轮·终场驱动）→ 写回（操作集 ADD/UPDATE/DELETE/NOOP·dry-run·比分红门·90 天巩固）→ 消费（回合经济 300ms·四入口·门后偏置）。删除（立碑/6h/30 天/写阻断）是横切这条链的第四维。
3. **三因子两腿同代是 memory-scoring 收编（2026-06-06）的既定口径**：衰减窗对 adapter 腿与向量腿同源下发，使两腿分数可比较——此前两腿各配各的窗，召回排序不可复算；该修复与反思重要性阈值 1.5、写回 dry-run 同 change 落地。
4. **bge-m3 本地优先是裁决不是默认值**（2026-05-22 裁决「本地模型无 key」）：嵌入输入含用户话语，本地化处理降低对第三方提供的风险；《个人信息保护法》最小必要原则的工程承载。Memobase 服务端嵌入维持默认关，生产语义路是后端自管 pgvector——文档写「语义记忆」时须指明是后者。
5. **Thread TTL 双轨是有意保留**：本地 Thread（7 天）为权威、relationship 存量条目（14 天）为回退，数值不一致源自账本统一（memory-surfacing）的历史分层；统一到单一 TTL 属行为变更，须走 openspec，不在文档层私自抹平。
6. **⚖️B9 脚注的处置**：open_threads 代码域第五类 unroutable 与 040 CHECK 冲突，PG 下写入被静默拒绝——按重写章程 B9 处置「不进正文、已知缺陷脚注一句、修复跟踪在工程侧」；本篇在 MEM-62 落脚注、§6 登记 MEM-P6，正文口径（权威账本按四类运行）不受影响。
7. **幻影处置**：「记忆可暂停」「逐条许可」「不保存记忆」家族（旧稿误写为已具备）按 ⚖️B4 全量降级规划——本篇只在 §6 以规划语气出现，正文不保留现网语气。手记与赛季册为 2026-06-06 新增能力（teammate-journal），旧 30 章无对应节，本篇 §1.8 为 v3 新增叙述。
8. **参数唯一口径**：本篇 §2 与 PRD 4.4.2 域级参数总表、规范附录 B 同源；发现冲突先修源表再修各篇。评价性数字（如「≈0.5 级 ×3 条」）是对阈值 1.5 的解释性注记，非独立参数。
