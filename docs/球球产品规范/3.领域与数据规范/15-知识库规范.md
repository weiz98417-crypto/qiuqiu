# 15 知识库规范

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：知识库是球球的第二事实域（ADR-0017）：静态规则、术语、赛制与球员/球队档案以**条目**为唯一形态入库，检索命中**逐字作答**，库里没有的**诚实说不知道**。它与 14 篇比赛事实域分工互斥——知识答「什么情况下判点球」，账本答「刚才那球判没判点」；两者冲突时事实优先。本篇把条目结构、门判守卫、双路检索、非生成式作答、判罚附句、生命周期管道与策展流程写成规则条文。规则 ID 前缀 KNW，引用格式「15/KNW-NN」；需求源为 PRD FR-KNW-001～013。

**立篇说明**：v2 资料包无知识库篇——知识域的全部现网能力（05-22 策展 MVP 起，至 06-07 条目库 121 条与参数学收口）都在 v2 定稿之后落地，v3 新立本篇承载（依据详见 §8）。

**导读**：§1 规则与红线｜§2 参数与预算表｜§3 交互契约（条目结构、检索、作答、附句、生命周期、策展）｜§4 降级与异常｜§5 验收与评测挂钩｜§6 规划中（未实现）｜§7 与相邻篇的分工｜§8 设计说明。

## 1. 规则与红线

### 1.1 域级规则

**KNW-01 知识以条目为唯一形态**。全库 121 条 = rules 100 + players 21；全部条目可解析、id 零重复；库里没有的知识不现编。

| 族 | 条数 | 分工 |
| --- | --- | --- |
| rule-* | 38 | 答「规则是什么」——越位、红牌、点球、手球、VAR 等 IFAB 规则 17 章细化 |
| terms-* | 29 | 答「这个词什么意思」——足球术语科普 |
| format-* | 22 | 答「这个杯怎么踢」——各大联赛与杯赛赛制 |
| judgment-* | 5 | 判罚场景的规则注解，判罚附句（15/KNW-16）的主力供给 |
| faq-* | 6 | 高频常识问答 |
| players/team-*（players 族） | 21（球员 9 + 球队 12） | 答「这人是谁」「这队什么来头」 |

- 计数为 2026-06-07 仓库实测（rules 38+29+22+5+6=100，players 21）。
- 二期扩容目标 200 条，登记不设门（15/KNW-12）。
- 反例：「刚才那场几比几」不属知识域——单场实况归事实账本（15/KNW-04）；库里没有的知识现编——违规（15/KNW-03）。

**KNW-02 非生成式立场**。知识问答是「单条目检索命中 → 逐字作答」；检索增强的是「查找」，不是「生成」。现网不存在生成式 RAG（top-K 召回 + LLM 拼装），任何「已支持 RAG 检索增强生成」的表述均与现网不符（放开须重开裁决 ⚖️B18，见 §6）。

**KNW-03 零编造三门**。① 来源必填（source 可校验，无来源不得入库）；② 置信度门 0.6（低于不出答案）；③ 话术兜底（无命中诚实说不知道，15/KNW-15）。

- 实仓条目置信度全部 0.85–0.95；录入侧表单与后端同约束校验（15/KNW-19）；消费侧门判对最终入选者执行，后处理管道不改判置信度。
- 大模型在知识回答路径上无生成权（15/KNW-14），编造在结构上不可达；附句路径同受约束——降级附句逐字、织写锚硬校验（15/KNW-16）。
- 反例：置信度 0.59 的条目即使检索排名第一也不出答案；任何「模型补一句」都不允许出现在知识答案里。

**KNW-04 域边界：知识=静态，事实=实况，冲突事实优先**。

| 维度 | 知识域（本篇） | 事实账本（14 篇） |
| --- | --- | --- |
| 内容形态 | 静态规则、术语、赛制、球员/球队档案 | 单场实况：比分、事件、判罚结果 |
| 产生方式 | 运营策展录入，人工审核上架 | 数据源入账 + 信任分级自动确认/运营人工确认 |
| 正确性机制 | 来源必填 + 置信度门 + 逐字作答 | 账本状态机 + 冲突永不自动裁决 |
| 时效性 | 跨场恒定（转会窗复查制度兜底） | 每场实时，改判走修正追加 |
| 回答方式 | 检索命中逐字答 / 判罚附句 | 账本投影播报 |
| 冲突裁决 | **事实优先**（条目说 VAR 只管四类，本场实际判罚以账本为准） | —— |

- 知识问答不依赖比赛会话——非比赛日同样可问，属于训练日/休赛期的知识陪伴面。
- 判罚附句是对判罚事件的**规则注解**，不是判罚事实本身——判罚事实仍只出自账本。
- 反例：「现在几比几」走事实账本不走知识域；「VAR 判没判点」答账本实况、「什么情况判点球」答知识条目——同一场比赛里两问两答互不串。

**KNW-05 知识管道不碰事实通道**。检索后处理管道（15/KNW-18）只作用知识条目注入，永不触碰比赛事实通道。

**KNW-06 知识无用户数据依赖，不产生引用码**。知识问答非登录状态同样可问；知识回答不产生引用码——引用码是事实引用机制，知识靠溯源字段（来源+置信度）自证；附句限频与生命周期状态按用户隔离但不落盘，删除流程不涉知识域。用户观察与气氛旁证同样不进知识域——它们是事实账本的旁证通道（14/FCT-20/23）。

## 3. 交互契约

### 3.1 条目结构（KNW-10）

条目结构 = 正文八字段 + 检索后处理五参数（057 号迁移入库，全部带默认值，默认即现状行为）。

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| id | 是 | slug，新建时前后端同一校验 |
| topics | 是（至少 1 个） | 检索打分面：关键词路双向包含、语义路向量化的对象都是它——无 topics 等于不可检索 |
| answer | 是 | 唯一对外口径：知识问答逐字作答它，附句降级也逐字携带它 |
| quote | 选填 | 附句织写锚——表达织写时必须**引号原样携带**，运行时有携带守卫（15/KNW-16） |
| triggers | 选填 | 触发事件类型，只配在判罚族条目上（现仓 5 条） |
| source | 是 | 来源必填（零编造第一门） |
| confidence | 是 | 0–1；消费侧门 0.6 |
| effective_at | 选填 | 转会窗复查制度落点：生效日早于最近窗闭即标「待复查」（15/KNW-19） |
| priority / inclusion_group / sticky_turns / cooldown_turns / probability | 参数学五字段，全默认 | priority=0、互斥组空、sticky=cooldown=0、probability=1；默认值下管道输出与检索冠军逐字节一致（15/KNW-18） |

反例：无 topics 的条目无法被检索命中；无来源的条目不得上架；topics 为空数组过不了表单校验。评测档内嵌条目即按此结构书写。

### 3.2 存储与种子：YAML=seed、DB=事实源（KNW-11）

- 条目 2026-05-30 起入库化（053 号迁移，knowledge_entries 表）：仓库内 YAML 仅是**种子**——按 id 幂等导入，已存在的一律跳过；**运营库是事实源**，运营在策展台的编辑永不被种子覆盖。
- 存储双实现（Store 接口）：有 DATABASE_URL 走「seed 导入 + 运行时读 DB」；无库降级为 YAML 直读，行为一致。
- 反例：种子重放回滚运营改动——违规。

### 3.3 门判门槛 100（KNW-12）

常驻门判守卫对生产同路径做全量导入计数，**条目数 <100 即红**（2026-06-07 起此前门槛 50）。

- 门判防「删条目悄悄破门」：一次改动删除 30 条术语条目——守卫变红、合入被挡。
- 门判走与生产完全相同的导入路径——能过门=能上线；本版门槛 50→100 对应 52→121 的扩容（覆盖完整第一版：规则 17 章×3 + 术语 + 赛制 + 常识）。
- ⚖️B17：门槛是否再调属开放裁决点（登记见 37 篇）——默认按代码现行值（100）书写，调整须先过评测门。
- 200 条二期扩容只登记、不设门；新增评测套件与此门无关、互不干扰。

### 3.4 双路评分融合检索（KNW-13）

检索 = **关键词路 + 语义路并行打分，条目总分 = 两路取 max**。「关键词命中即短路」的旧制已退役（2026-06-05），换说法的问句不再依赖关键词碰巧对上。

| 路 | 打分规则 |
| --- | --- |
| 关键词路 | topics 双向包含（归一化后互含即命中）+ 正文/引语锚命中加权（+0.5） |
| 语义路 | 问句嵌入对条目 topics 向量的余弦相似度，过阈值（默认 0.55）才计分——不过阈值不算分，避免弱相似硬凑 |

- 两路并列取声明序（条目录入顺序）；检索可给出候选序列（消费口取前 8 名进后处理管道，15/KNW-18），**最终作答仍是单条冠军**。
- 语义模型 bge-m3 本地部署；**仅 topics 参与向量化**（正文/引语锚进向量路是规划项，§6）；知识域不建向量库（内存缓存，重载全清重建；pgvector 仅记忆域使用）。
- 示例：「VAR 是什么」关键词路直接命中 rule-var-scope 的 topics「VAR」；「视频裁判都管哪些」靠语义路兜住换说法——两路取 max 后冠军同为一条，答案逐字相同。
- 反例：同义改写命中同一冠军条目（正确行为）；极端错别字允许无命中——诚实回答优先于硬凑。

### 3.5 非生成式作答：逐字回答（KNW-14）

知识问答检索命中即**逐字作答条目正文**；表达润色器（realizer）与大模型不触碰知识答案（润色关闭、确定性拼装）。

- 单条目、无多条拼装、无 LLM 生成——口吻、语气、长短都是策展时定稿的样子。
- 回答路径在追踪中记录知识作答工具调用（条目 id + 置信度）并标记确定性原因 `knowledge_policy`，全程可审计。
- 示例（评测档实录）：问「什么情况下判点球」→ 命中 rule-penalty → 回答与条目正文一字不差，回合痕迹含知识作答工具调用。
- 反例：不把两条条目缝成一段新话；不把「大概率」润色成「肯定」；不为口吻改一个字；不在答案后面自由补一句「顺便说」。
- 验收：回答文本与条目正文逐字节一致；评测档以 exact 断言锁死措辞。

### 3.6 无命中诚实回答（KNW-15）

检索无命中、或最终入选条目置信度低于 0.6，一律回诚实话术。**「不知道」好过「不太对」。** 话术本身也是确定性的，不经过生成。

| 场景 | 现网话术 |
| --- | --- |
| 知识库未接入 | 「知识库还没接上，这块我先不敢乱说。」 |
| 无命中或低置信 | 「这个我还真不敢乱说，等我把功课补上再答你。」 |

反例：话术不因问法刁钻退化为含糊其辞的「可能吧」；生僻问题不触发猜测性作答。

### 3.7 判罚时刻知识附句（KNW-16）

**6 类判罚事件白名单**触发条目查找：同类型取置信度最高者。命中条目的 quote 作为**织写锚**进入表达（硬指令：引号原样携带），运行时校验织写产物确实携带引语锚；织写失败降级为确定性附句「补一句规则：+正文」。

| 触发事件 | 附句主题（现仓对应） |
| --- | --- |
| var_check | VAR 回看（VAR 范围注解） |
| var_result | VAR 结果 |
| goal_cancelled | 进球取消 |
| red_card | 红牌（「直接红牌针对严重犯规、暴力行为或破坏明显进球机会」） |
| penalty | 点球 |
| penalty_awarded | 点球判给 |

- 附句是搭判罚反应回合便车的**追加句**，不是独立主动回合——不走引用码门机器，独立于插话计数。
- 白名单设计原则：只留给「等用户问就晚了」的规则时刻；进球时播报球员简历这类语用**明确不做**。
- 引语锚守卫是硬校验：织写产物里找不到原样引语即判失败，走降级附句——宁可生硬，不可走样。
- 附句内容同样受零编造约束：正文逐字、来源在库（15/KNW-03）。
- 反例：普通进球不触发附句；白名单外的事件类型（如换人、角球）永不触发。

### 3.8 附句限频与静音门（KNW-17）

附句限频 = **同条目每场 1 次、附句总量每场 2 次**；**低频档或用户正在说话时禁用**。

- 限频状态是「每用户每场」的计数，住进程内有界 FIFO map——容量 256 用户，超限淘汰最旧；重启清零是如实语义，不是缺陷：重启后最多多讲一次，不会错讲。
- 静音门优先于限频判定：正在说话或低频档时事件到达即静默放弃，不排队、不补讲。
- 反例：同场两次 VAR 回看只附句一次；总量用满后第三类判罚事件不再附句。
- ⚖️ **B23（判罚知识附句限频策略）**：限频为 Q28 初值——待定选项（随比赛密度自适应 / 按条目族分档 / 维持初值）→ 影响（附句打扰感与知识覆盖率的平衡）。

### 3.9 条目生命周期与检索后处理管道（KNW-18，057 参数学）

检索后处理管道四段依序——**预算裁剪 → 互斥消歧 → 生命周期状态机 → 概率掷骰**。五参数全默认时，管道输出与检索冠军逐字节一致——**管道是可选层**，存量 121 条零感知。

| 段 | 规则 |
| --- | --- |
| 预算裁剪 | 按 priority 降序累计答案字节，预算耗尽即停；sticky 活跃条目豁免（无条件存活、不计预算，豁免与停机点位置无关） |
| 互斥消歧 | 同一 inclusion_group 内多条命中只留排序最高的一个（互斥是策展显式意图，sticky 不豁免） |
| 生命周期状态机 | cooldown 条目冷却中剔除（不重复作答）；sticky 条目命中后 N 轮内置队首且免概率骰 |
| 概率掷骰 | 确定性骰（种子×轮次×条目 id），未中即弃；种子按用户派生——同一用户同一轮同一结果（重放一致），跨用户独立 |

- **状态归属**：条目库全局跨用户、永不感知用户；生命周期轮次状态住**陪护层每用户有界 FIFO map**（容量 256 用户，进程内存，重启归零）；管道是纯函数——状态进、状态出，跨用户不串味。
- 每个知识问答轮推进一轮状态；置信度门不在管道内——仍由消费口对最终入选者执行（15/KNW-03/15）。运行时注入预算当前不限。
- 反例：管道永不触碰比赛事实通道；全默认条目永不因管道落选。
- ⚖️ **B24（worldinfo 生命周期参数学归属）**：五字段已建成、存量条目全默认、运行时预算不限——待定选项（何时给策展条目配参、是否设注入预算）→ 影响（多轮知识对话的重复感与答案稳定性）。

### 3.10 策展流程：策展台一键到生产（KNW-19）

知识策展台（运营台内的知识策展页）承担条目全生命周期操作：**列表 / 待复查过滤 / 新建 / 编辑 / 上架**；**保存即生效**——写入运营库并全量换血重载，下一问即用新答案；不需要发版、不需要重启。

| 环节 | 规则 |
| --- | --- |
| 新建 | 条目 id 走 slug 校验（前后端同一约束，非法 id 双端同拦） |
| 表单校验 | 与后端同一口径：置信度 ∈[0,1]、topics 至少一个关键词、probability ∈[0,1]（0 归一为必中）、sticky/cooldown 非负整数 |
| 待复查过滤 | 转会窗复查制度（ADR-0017 2026-05-30 修订）：生效日早于最近转会窗闭窗即标记——档案类条目（球员转会、球队阵容）到期显形提醒复查，而不是靠人记 |
| 权限与留痕 | 写入需运营权限、读取留痕 |
| 档案来源 | 球员/球队档案类条目源于公开资料调研、人工策展入库（2026-05-23 起），不从外部源自动写入 |

- 示例（一键到生产）：运营新建「越位新规」条目（填 topics/正文/来源/置信度）→ 保存即生效 → 球迷下一句「越位是怎么回事」即答新条目；夏季窗关闭后，生效日早于窗闭的档案条目在列表中标「待复查」。
- 反例：「保存后要重启才生效」的流程不存在；无来源条目过不了表单。
- 验收：「录入 → 生效 → 双路检索命中 → 事件触发」全链可验证（录入消费验证，显式开关才跑）。

## 4. 降级与异常

| 情境 | 现网行为 | 用户可见结果 |
| --- | --- | --- |

## 8. 设计说明

1. **新立篇依据。** v2 资料包 89 篇没有知识库篇：知识域全部能力都在 v2 定稿（2026-05-22）之后落地——05-22 策展 MVP 与 ADR-0017 立法恰在定稿当日、05-23 档案入库与判罚附句、05-30 条目库入库化与策展台、06-03 新建入水口、06-05 双路评分融合、06-07 条目库 121 条与参数学（057）收口。v3 大纲提案将「31-知识库规范」列为新立八篇之一，本篇即其落位；v2 迁移源为空，内容全部以 PRD 第四章 4.7 与 ADR-0017（含两次修订）为上游重写。
2. **非生成式是立场不是妥协。** ADR-0017 第二波决策确立「检索增强查找、不增强生成」：单条目命中逐字作答、无向量库、无 LLM 生成。这使知识答案天然可溯源（来源+置信度自证，不需要引用码），也让「编造」在结构上不可达。是否长期维持属 ⚖️B18；放开生成即重立门禁。
3. **「结构先于用法」的三项裁决（⚖️B18/B23/B24 的共同背景）。** 条目库、管道、状态机、策展台全部就位，而策展参数与限频都停留在保守初值：附句限频是 Q28 初值（⚖️B23）、参数学五字段全默认与注入预算不限（⚖️B24）。B23/B24 裁决的本质是决定「这套已建成的机器，开多大的量」；是否引入生成式 RAG（⚖️B18）则是另一维立场裁决。
4. **ADR-0017 两处正文滞后注记。** ① 决定 2「知识条目策展于 repo、错误走 git 修正」已被 2026-05-30「YAML=seed、DB=事实源」修订（053 迁移 + 策展台），ADR 内以注记存在、正文未改写——引用时以本篇 15/KNW-11 为准；② 决定 3「关键词命中优先，向量补换说法」已被 2026-06-05 双路评分融合取 max 取代（关键词一票短路退役）——引用时以本篇 15/KNW-13 为准。ADR 正文修订随 ⚖️B6（ADR 维护约定）一并处理。
5. **与 14 篇的写作分工。** 判罚附句在两篇各立一半：14/FCT-29 立事实域侧的触发白名单、限频与「解释层不是事实层」边界；本篇 KNW-16/17 立条目查找、织写锚守卫、降级话术与静音门。两篇参数一致（6 类、1 次/场条目、2 次/场总量、256 容量），修改须同步。
6. **文体声明**：本篇为 reference 查表体；「为什么零编造」「为什么逐字」的论证以 ADR-0017 为立法记录，不在规范内重复展开。
