# 17 数据模型与生命周期

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：全库数据对象的登记簿与生命周期规范——每一张表是谁的陈述、服务什么任务、关键约束是什么、何时过期、如何删除。领域行为的系统语义归各领域篇（14 事实 / 15 知识 / 16 记忆 / 18 协议）；本篇立对象边界、枚举唯一口径、保留策略与隐私横切。规则 ID 前缀 DAT，引用格式「17/DAT-NN」。

**表引用纪律**：迁移 59 个文件（001–057；025 缺号；010/011/012 同号双文件），本篇引用表一律按迁移文件名（如 `056_journal_entries.sql`），不写「第 N 个迁移」。

**导读**：§1 规则与红线（对象族总纲/陈述隔离/三条系统级边界/枚举唯一口径/权限链落点）｜§2 对象族登记表（44 表全量+聚合边界）｜§3 生命周期与保留策略（含状态机、走查与降级异常归并）｜§4 隐私横切（导出/删除立碑/第三方禁令/训练同意/权限矩阵/办法十六条映射）｜§5 迁移纪律（59 文件里程碑）｜§6 验收与评测挂钩｜§7 与相邻篇的分工｜§8 设计说明。

## 1. 规则与红线

### 1.1 对象族总纲

**DAT-01 对象边界先于数据积累**。数据模型首先是一套产品边界与用户权利模型：每个对象必须说明它是谁的陈述、服务什么任务、能否跨场、如何被用户看见、何时过期、怎样撤回。不以一个统称「上下文」或「用户画像」的对象替代对象族（PRD FR-IDN 域边界口径）。

**DAT-02 禁止词对象**。不建立以下对象：隐形亲密度、依赖等级、情绪价值分、留存风险分、脆弱性分、消费潜力分、孤独度、关系热度、用户可被打扰程度等——它们把不确定的人类行为压缩成高影响标签。若需要回答「现在能不能主动说话」，查用户设置、关系状态、事实状态与频控参数，不调用用户人格分数。

**DAT-03 新增字段审议**。任何新增字段、扩大关联、延长保留、放宽跨场引用的变更，须说明用户价值、风险、删除路径与回退条件——「只是多加一个字段」不能降低审议要求；一个字段若让服务从「知道你喜欢什么球队」变成「猜测你何时脆弱」，不应批准（新增对象族走 openspec change 并回写本篇登记表）。

### 1.2 三类陈述隔离（事实/观察/表达）

**DAT-10 事实与观察不混写**。「第 72 分钟比分变为 2:1」只有在来源与确认状态足够明确时才是事实（账本五态，14 篇）；「这次换人改变了中场保护」是观察或观点。事实可以更正，观察可以被讨论，但不能混写；任何一类不能自动升级为另一类。

**DAT-11 观察与表达标明身份**。球球的观察必须显式标为观点或可能性，不得伪装成比赛事实；用户的观察属于用户，默认只在本场使用，只有进入画像条目或开放话题这类用户可见、可控的对象才可跨场。

**DAT-12 画像与风险材料目的隔离**。球球自动记住「你支持的球队」是画像条目（用户可查改忘）；用户投诉「不要再用这个称呼」是风险材料——后者在配置层停止行为，不被球球拿来制造「我记得你」的语境。风险事件不进画像；研究材料不改变服务待遇；语音转写不自动成为画像条目；运营配置不生成用户价值标签。

### 1.3 三条系统级边界（与 §2 任何一格同等效力）

**DAT-20 记忆服务永不写比赛事实**。记忆系统（含 Memobase）只从互动账本提炼画像条目，可引用已记录的公开事实，从不制造、修改或断言比赛事实——记忆与事实链之间是单向关系（16/MEM-02 同源）。

**DAT-21 运营台对画像只读**。运营人员可以看到球球对用户的理解，但不能编辑；确需按用户利益删除单个画像条目时走独立接口——二次确认、记入审计、不支持导出内容。

**DAT-22 运营写全部幂等**。每个逻辑写请求自带幂等键，服务端识别重放即返回上一次的结果——同一次操作无论网络抖动多少次，账上永远只落一条（幂等载体：idempotency_records，`013_trusted_interaction_foundation.sql` + `017_operator_idempotency_outbox.sql`）。

### 1.5 权限链在数据面的落点

权限链五级（01 篇）在数据对象上的落点：上层压下层，任何下层配置不得解锁、削弱或重新解释上层约束。

| 层级 | 数据面落点 |
| --- | --- |
| L1 平台红线 | 情绪信号不进事实账本；第三人隐私不入画像；比分不进画像——任何配置不可绕过（PR-R 系红线的数据承载） |
| L2 运营策略 | 知识条目与 ops_settings 即改即生效且实名留痕；运营台对用户档位只读不写（owner 红线） |
| L3 角色人设 | banter_level/analysis_appetite 的出厂值与 clamp 在系统默认层，画像槽位遮蔽属人设保护面 |
| L4 用户设置 | user_preferences/user_character_settings 即改即生效；画像读/改/忘三权；删除/导出自助 |
| L5 系统默认 | 各表 DEFAULT 值（talkativeness 'normal'、expires_at 30 天、Thread TTL 7 天）——用户未表达时按保守默认 |

| --- | --- | --- |
| 比赛聚合 | F1 全部 + F2 | 事实、候选、时钟版本与可用性一致；用户数据（情绪、偏好、画像）永不混入比赛事实 |

**DAT-31 配置非法拒绝启动**。保留期由配置决定；配置出非正值时服务在校验阶段直接拒绝启动——宁可起不来，不可悄悄改规则。

**DAT-32 无数据库降级边界**。隐私存储在无数据库配置时降级为进程内存实现：进程重启即失（已知边界照实写）；任何「声明合规能力」的表述须带此前提。

**DAT-33 到期语义统一**。「保留期」的语义是到期退出可读范围并按清理机制物理清除，不是标记软删后无限期滞留；「到期自动退出可读范围」与「后台清理周期」是两个承诺，分别可审计，不得混写成「立即删除」。

### 3.1 关键对象的状态机

**DAT-34 事实修订链（五态，append-only）**。从待确认候选开始，每一步推进都是追加新版本入账，不涂改旧记录：

```
provisional（观察入账，来源可说明）
  → confirmed   支持充分且无关键冲突（确认只加一次，幂等落账——同一进球永远只推进一个球）
  → conflict    可说明来源不一致（永不自动裁决，调和前公开比分保持原状）
  → reconciled  逐项调和（更正必须填写原因，无因不落账）
  → revoked     后续信息否定事件（撤销后受影响的主动回复即时撤下）
```

已调和或已撤销的事实不得继续作为球球庆祝、通知、舞台动作或总结的基础；自动确认通道（ADR-0024 双源+稳定窗）与运营人工确认构成双通道，全程留痕可溯（行为细则归 14 篇；fulltime 信任级 ⚖️B1）。

**DAT-35 待确认观察七态机**。pending_sync → corroborating → confirmed；任何态可入 contradicted / conflict；未被接住的观察 expired；被新观察取代的 superseded——七态全集见 §1.4（CHECK 约束，`018_pending_match_observations.sql`）。观察结果经 observation_resolution_outbox 投递（pending/delivered/suppressed），不阻塞话轮。

**DAT-36 删除作业状态机**。

```
发起 → 墓碑 pending（受理即立碑，下一回合生效；写路径阻断）
    → completed（清理完成；进入保留期，到期物理清除）
    → failed（任务状态如实显示失败与可重试项；屏障保持——失败不解除阻断）
```

重复发起=409；已删数据读路径=410；jobId 可无凭证查询（响应剥离 userId）。失败时优先保持撤回屏障（停止读取/停止新引用/迟写阻断三方向），不静默等待问题自行消失。

**DAT-37 开放话题双终态**。open → addressed（被真实回答接住、闭环）或 expired（TTL 7 天未被接住）；过期不等于已回答——两种终态分别记录、分别审计（thread_addressed / thread_expired），运营台可手动标记（两个动作走不同审计路径）。

**DAT-38 画像覆盖层时间窗行**。每行以 id 为主键、携 valid_from/valid_to；同槽至多一条开放行（部分唯一索引）。写路径：新增主张→操作集判定（ADD/UPDATE/DELETE/NOOP）→落行即开窗；UPDATE 即续期；90 天超窗未续期→反思尾部软封口（退出输出面、底档保留）；用户删除→deleted+墓碑，永不复活。

**DAT-39 账本单调序与播放回执**。match_events.recorded_sequence 保证事件账本单调（`022_fact_ledger_recorded_sequence.sql`）；客户端播放回执经 delivery_ledger 按 deliveryKey 去重，playback_state 六值（§1.4）记录真实发生的播放结果——回执是互动账本 playback_result 事件的来源。

### 3.3 一条数据的生命周期走查（示例，非规范性）

以「用户在比赛中说『我支持皇马』」产生的数据走全生命周期：

1. **产生**：话轮全文落 conversation_turns（F3，30 天语义）；互动账本追加 signal 事件（F4，expires_at 30 天）；agent_traces 留回合决策轨迹（F3）。
2. **提炼**：观察经队列打分过门槛 → Memobase 提取 → 主张入账（遮蔽槽）→ 反思操作集 UPDATE → portrait_overlays 开窗落行（F7，90 天窗）。
3. **使用**：下一回合画像合成输出「支持皇马」口径；支持队进球时偏置在压制门之后施加（16/MEM-92）；懂我页展示同一份内容。
4. **续期或封口**：90 天内任何相关 UPDATE 即续期；超窗未续期→反思尾部软封口（退出输出面、底档保留）。
5. **治理**：用户忘掉→墓碑落库（F10）→下一回合画像即空；后台 6 小时内清理、保留期 30 天硬上限。
6. **期满**：未治理且用户长期流失时，conversation_turns/agent_traces/interaction_ledger 各自到期退出可读范围并按清理机制清除；审计类长期留痕，答得上来路。

### 4.2 删除与立碑（删除权承载）

**DAT-41 三级删除粒度**：

| 粒度 | 语义 | 入口 |
| --- | --- | --- |
| 条目级 | 画像条目忘掉=立碑（本地墓碑永久+远端 best-effort），下一回合生效 | 球球懂我页 `/api/me/portrait` |
| 对象级 | 共同瞬间/手记忘掉=物理删除 | moments / journal DELETE |
| 身份级 | `DELETE /api/me/data` 异步作业（jobId 可查，响应剥离 userId）；删除期写路径一律阻断、读取一律 410、在途写等待后移除；完成后进入保留期，到期物理清除 | 账号与隐私面 |

**DAT-42 删除作业时序**：发起删除 → 返回 jobId → 删除期写入一律 409、读取一律 410 → 墓碑持久化 → 保留期（默认 30 天）内状态可查 → 清理周期（6 小时粒度）到期物理清除 → 同 deviceId 此后只能开新身份。重复发起=409（删除进行中）；已删数据读路径=410（数据已删）。

**DAT-43 写路径横切阻断**。删除期间陪伴引擎侧全部用户写路径（痕迹更新/读取等）被拒绝——「边删边写」复活数据属红线违规；有专项集成测试常驻守护。

**DAT-44 观测日志脱敏**。观测日志不打用户标识（情绪信号日志仅记录标签、置信度、接受/丢弃结果）；画像存储侧配套脱敏。脱敏对象是观测面，不是业务数据面——业务数据控制权走导出/删除，两层面不混淆。

**DAT-45 会话隔离**。全部用户面数据按 `usr_` 身份隔离，跨设备、跨会话不可互读；隔离面覆盖即导出 11 类清单；隐私删除的读阻断（410）以身份为边界，不影响其他用户。session-isolation E2E 常驻守护。

### 4.3 交互数据第三方禁令（《办法》第十六条 / CR-06）

**DAT-50 交互数据不出第三方**。交互数据不得向第三方提供（法定情形除外）；现网无任何向第三方共享、转售交互数据的产品面与数据通道——架构性承载，不是承诺性表态。

- 数据面自托管：交互数据存自建存储组合，不出自建边界。
- 云端推理供应商按处理者边界管理：ASR 云主路、LLM 经统一兼容传输层、TTS 云端态，均为提供服务之必要的处理，不构成「向第三方提供」的产品行为；供应商清单与协议要求归 33 篇（数据流登记）。
- 观测面无外发：监控栈本机部署、观测日志脱敏（DAT-44）；客户端无第三方统计/广告 SDK 与外发埋点通道。
- 流程约束：新增任何第三方 SDK 或上报通道，须过 30 篇上线门禁合规评审，未过不发布。

### 4.4 训练数据单独同意（《办法》第十六条 / CR-08）

**DAT-51 默认不进训练=现状事实，同意机制=规划中（未实现，P1）**。

- 现状两面照实写：①「默认不进训练」为真——现网不存在可消费交互数据的训练管线，这是「无此用途」的事实陈述，不是「已获同意」的合规声明；②同意机制未建——无开关、无撤回面。
- 顺序约束（不可倒置）：任何训练用途立项前，先落单独同意机制（独立于用户协议的一次明示同意、默认关闭、随时可撤回）再动数据。
- 口径澄清：现网模型为外部已备案模型推理消费，交互数据用于当轮推理生成不构成「训练用途」——推理与训练的边界归 33 篇。
- 反例：以「已脱敏」替代单独同意属违规（脱敏不等于同意）；默认勾选「同意用于训练」属违规。

### 4.5 复制删除权的产品形态（《办法》第十六条 / CR-07）

**DAT-52 复制=导出承载，删除=三级粒度**。用户获得聊天记录的现网方式是全量导出（覆盖全部对话轮与代理痕迹，机可读）；删除走三级粒度（DAT-41）。逐条消息级的复制/删除按钮现网不存在——逐条增强为规划项（非合规缺口，权利通道已在），落地前任何文档不得写「用户可逐条复制/删除聊天记录」。

### 4.6 对象族权限矩阵（现网治理动作版）

用户的治理动作是现网实有的三权（查看/修改/删除+导出）；「暂停」类控制面不存在（⚖️B4），不出现在矩阵中。

### 4.7 数据归属与删除边界

**DAT-53 公共数据与用户数据分界**。比赛事实账本是公共任务对象（所有观众共享同一事实源），不是任何用户的私有数据：导出 11 类中的 matchStates/interactionLedger 等以「与该用户关联的投影」形式导出；身份级删除以身份为界，不影响账本本身（账本是比赛事实源，PRD 4.9 接口口径同源）。

**DAT-54 删除传播**。删除一个对象后，其派生引用、提醒、舞台状态、导出内容与人工视图全部停止使用它：未送达提醒转记忆素材的路径在删除期被写阻断一并拦下（DAT-43）；已排程的主动触达随身份失效；墓碑挡住「再抽取复活」路径（16/MEM-80）。

**DAT-55 备份与重建姿态**。账本是原件，记忆投影可重建：Memobase 合成库不参与全量备份、可从账本重建；Postgres 主存（44 表）按部署侧备份策略处置（归 23 篇）。任何备份副本在恢复时同样受墓碑约束——已删数据不得借恢复流程复活。

## 8. 设计说明

1. **与旧 41 章的差异**：v2 档案 41 章以「七个现网核心对象」立骨架（互动账本/画像条目/开放话题/待确认候选/更正审计/时钟版本/deliveryKey），其「阶段规划」把 subscription/reminder/trace 列为规划对象——这三者在基线已全部落地（`047_subscriptions.sql`/`045`+`050`/`001`+`030`+`044`），v3 全部转入 §2 正式登记（F8 族与 agent_traces），规划字段合同与已实现 schema 的差异以现网为准。这是「规划段已落地」的最大翻转。
