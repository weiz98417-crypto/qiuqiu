# 38 假设与验证台账

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：产品假设的活页台账，全套资料中所有验证假设的编号、证据等级与升降级的唯一来源。H1-H15 自 v2 档案 13 章转正，每条补「工程侧证据」列（evals/盲测/演练等已有什么）；**用户研究证据列全部为「未执行」**——这是本台账当前最重要的事实。台账是活页：假设升降级、证伪记录、派生假设入册都在本篇流转，03 篇画像卡与 04 篇旅程随本台账同步刷新证据等级。

导读：§1 台账制度｜§2 证据等级约定（E0-E3）｜§3 H1-H15 全量台账（含派生假设占位区）｜§4 升格与证伪流程（含七问判分表）｜§5 台账维护流程｜§6 设计说明。

## 1. 台账制度

1. **登记字段**：每条假设登记——假设 ID / 内容 / 假设组 / 优先级 / 首选验证方式 / 工程侧证据 / 用户研究证据 / 当前等级 / 升格门槛 / 负责人 / 复核日期 / 下一步决定。后四字段在首批研究立项前全部留白，不预填。
2. **派生编号**：主假设 H1-H15 之外，画像卡与旅程条目具体化的假设按 `Hx-y` 派生编号入册（如 H9-1「订阅存续即第二场回访的先行指标」），与主假设同流程流转；派生假设须注明父编号。
3. **假设组**：需求与替代（H1-H3）｜入口与陪伴形态（H4-H6）｜记忆与边界（H7、H8）｜回访与连续性（H9-H11）｜商业与范围（H12、H13）｜风险与合规（H14）｜场景延展（H15）。
4. **使用纪律**：任何假设未达升格门槛，不得在任何篇章被写成事实、承诺或规模预测；「足球很受欢迎」「演示看起来不错」与「存在可持续需求」严格区分（沿 v2 档案 13 章立场）。
5. **证伪优先**：台账对每条假设的第一使用问题是「什么观测会推翻它」——引用任何假设进承诺面前先答其证伪判据（§3 表两列增补列）；判据列为空的条目不得进入 02 篇路线图的承诺面。

## 2. 证据等级约定（E0-E3）

| 级 | 名称 | 证据类型 | 能支持什么 | 不能支持什么 |
| --- | --- | --- | --- | --- |
| E0 | 假设（未验证） | 团队猜想与设计意图 | 提出研究问题、立项与研究设计 | 任何「已成立」表述 |
| E1 | 二手信号 | 行业报告、公开讨论、竞品评论、监管文件 | 界定机会、风险与样本语言 | 「目标用户真的会使用」 |
| E2 | 受控验证 | 受控情境中的行为证据：工程侧（评测/盲测/演练/门禁）或用户研究（意向、原型任务、受控观察） | 能力与交互成立（工程侧）；情境与交互对目标用户成立（用户研究） | 真实使用中的重复选择与规模化需求 |
| E3 | 已验证 | 真实使用中的有代价重复选择与无激励持续行为（跨场回访、订阅存续、付费意愿、自然留存+安全指标稳定） | 重复价值与交换意愿；支持扩张类决定 | 永久稳定、所有人群可复制 |

收并说明：v2 档案 13 章的 E0-E5 五级在 v3 收并为 E0-E3 四级——旧 E2（受访者意向）与旧 E3（受控情境观察）并入新 E2；旧 E4（有代价重复选择）与旧 E5（无激励持续行为）并入新 E3；旧 E0/E1 语义不变。各假设的升格门槛按新梯改写（见 §3 表「升格门槛」列）。

**分界纪律**：工程侧证据（E2 内的评测/盲测/演练/门禁）只证明**能力成立**，永不升格**用户价值假设**——能力已验证不等于价值已验证（PRD 第二章 2.0 证据声明同源）。价值升格的唯一路径是用户研究或真实使用行为（E2 用户研究腿 → E3）。

**证伪与等级的关系**：证伪不是等级降级——「已证伪」是独立于 E0-E3 的状态迁移（§4 第 3 条），条目保留原等级列并加「已证伪」标注；已证伪条目退出一切引用面（画像卡/旅程/路线图承诺），但保留在本台账供复盘追溯，不得删除或改写为「从未登记」。

### 3.1 派生假设与新增假设占位区（H16 起 / Hx-y）

## 4. 升格与证伪流程

1. **证据入库**：每条证据附来源/方法/样本/时间与反例记录；入库检查沿七问（参与者是否属目标情境、行为是否发生在真实比赛、是否受激励扭曲、材料是否暗示正确答案、是否记录拒绝与退出、结论是否跨用户/场次/方法复现、反例如何解释）。没有反例的研究先查记录方式，不当作「结论一致」。七问按下列判分表逐问判定，判分结果随证据登记入册，七问全过才进入升格评估：

   | 问 | 判分 | 不通过处置 |
   | --- | --- | --- |
   | ① 参与者是否属目标情境 | 是 / 否 / 不适用 | 否→证据降级为探索材料，不参与等级评定 |
   | ② 行为是否发生在真实比赛 | 是 / 否 / 不适用 | 否→只作能力面记录，不支撑价值假设 |
   | ③ 是否受激励扭曲 | 否 / 是 / 不适用 | 是（受激励扭曲）→证据不入册，重做无激励版本 |
   | ④ 材料是否暗示正确答案 | 否 / 是 / 不适用 | 是→按「记录方式失真」退回，重做后再收 |
   | ⑤ 是否记录拒绝与退出 | 是 / 否 / 不适用 | 否→研究记录不完整，退回补记后重评 |
   | ⑥ 结论是否跨用户/场次/方法复现 | 是 / 否 / 不适用 | 否→标记「单点信号」，不得写「结论一致」 |
   | ⑦ 反例如何解释 | 已解释 / 无法解释 | 无法解释→按本节第 3 条进入证伪评估 |

2. **升格**：达到升格门槛且经跨方法复现，由本篇维护人改「当前等级」并记依据；03 篇画像卡证据等级列同步刷新；价值假设的升格只认用户研究腿或真实使用行为（§2 分界纪律）。
3. **证伪**：反例成立时状态改「已证伪」并记录——不删条目；受影响篇章（02 篇路线图、03 篇画像、04 篇旅程）按证伪结论重估，涉及范围收缩的按 00 篇 §3.6 失败收缩顺序执行。证伪判据以 §3 表「证伪判据」列为判定锚：观测达到判据所述状态即触发本条流程，不允许以「再观察观察」搁置已达判据的反例。
4. **复核节奏**：首批用户研究立项时全表复核一次；此后每赛季复盘（02 篇赛季运行日历，规划中）带一次台账走查。
5. **判据维护**：「证伪判据」「所需样本/证据量」是活列——研究立项卡定稿正式样本量时回写 §3 表并记修订；判据本身变更视同口径变更，须说明对已入库证据的影响，不允许为回避反例而放松判据。
6. **与 37 篇联动**：假设的验证路径受开放裁决点影响时（如 H9 回访行为数据依赖 ⚖️B22 埋点选型、H8 说明页依赖 ⚖️B7、H11 触达口径挂 ⚖️B20/B21），台账复核同步查 37 篇状态——裁决翻转改变的是验证路径与时间表，不直接改变任何假设等级（等级只认 §2 分界纪律）。

## 5. 台账维护流程（谁、何时、怎么增改）

### 5.1 动作—时机—执行人对账表

| 动作 | 触发时机 | 执行人 | 落点与留痕 |
| --- | --- | --- | --- |
| 新增主假设（H16 起） | 研究立项、路线图新增滩头或产品身份面变化时 | 本篇维护人（产品负责人面；人员落名归 27 篇职责表） | §3.1 占位表补行→5 个工作日内补齐全字段→篇末修订记录 |
| 派生假设入册（Hx-y） | 03 篇画像卡/04 篇旅程新增可验证条目时 | 提出方起草，维护人登记 | §3.1 占位表；父编号必填；03/04 篇正文挂引用 |
| 证据入库与七问判分 | 一份用户研究/受控观察报告定稿时 | 研究执行方填判分表，维护人复核 | §4 第 1 条判分表随证据归档；「下一步决定」列回填 |
| 等级升格 | 达到升格门槛且跨方法复现 | 本篇维护人 | 「等级」列改写＋记依据；03 篇画像卡证据等级列同步刷新 |
| 证伪登记 | 观测达到 §3 表证伪判据 | 本篇维护人 | 状态改「已证伪」＋反例记录；02/03/04 篇按 §4 第 3 条重估 |
| 全表复核 | 首批用户研究立项时（此后每赛季一次） | 维护人＋研究执行方会审 | 复核结论（含未动条目的「复核无变化」声明）记篇末修订记录 |

### 5.2 增改纪律

1. **谁可改**：等级变更与证伪登记只归本篇维护人；03 篇画像卡与 04 篇旅程是引用面，只随动刷新证据等级列，不得自行改等级（§6 第 4 条同源）。
2. **何时改**：事件发生后 5 个工作日内回写；升格/证伪不允许追溯补记到事件之前的日期。
3. **怎么留痕**：每次增改记篇末修订记录一行（动作、涉及假设号、依据）；等级变更与证伪登记同时检查 §3.1 派生条目是否随动。
4. **不得事项**：不得删除条目或复用编号；不得在证据未入库（七问未判分）时改等级；不得以工程侧证据（§2 分界纪律）升格价值假设；不得把「占位行」当正式条目在任何篇章引用。

## 6. 设计说明

1. **转正与重述边界**：H1-H15 的编号、优先级与验证方式语义沿 v2 档案 13 章不变；重述仅两处——H5 去「安静优先」遗产措辞（词汇处置表，00 篇 §7.2），H7 从「控制有限记忆」改为「事后治理三权」（对齐 ⚖️B4 现网口径：暂停/逐项许可不存在）。研究方法论全文（招募原则、访谈设计、实验卡模板、不做虚假 A/B）仍在 v2 档案 13 章供取用，首批研究立项时按需激活，不在本篇复制。
2. **为什么补工程侧证据列**：v2 台账只有用户研究设计、零工程视野，而 05-22 以来工程验证轨道（评测 249 用例、promptfoo 门禁、韵律盲测、值班演练）已并行运转——不登记该列，「已有什么验证」就只存在于工程文档，产品侧无从对账。列入后两者的分界（能力 vs 价值）才可见。
3. **全 E0 不是保守姿态而是事实**：截至基线日无任何用户研究实证；工程侧证据再厚也不改变价值假设的等级（§2 分界纪律）。首条升格预计发生在首批受控试用产生真实使用行为之后（02 篇路线图阶段 1）。
4. **与 03/04 篇联动**：03 篇三画像卡与 04 篇旅程「预期」行的 E0 标注是本台账的引用面；升格/证伪以本篇为源，两篇随动刷新，不允许各自改等级。
5. **为什么补证伪判据与样本量两列**：升格门槛只回答「什么算证实」，不回答「什么算推翻」——v2 档案 13 章只立了证据阶梯，反例处理散落在流程句里，没有逐假设的可执行证伪面。两列增补后，每条假设自带「可推翻性」声明：引用者能看见它在什么观测下失效，防止假设只被证实性引用；候选样本量则把「要多少证据才说话」从事后争论提前为研究设计的先验承诺。
