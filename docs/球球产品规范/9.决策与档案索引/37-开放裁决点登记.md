## 1. 裁决点制度

### 1.1 定义

开放裁决点是**真实开放、尚未拍板的产品决策**：现状与选项都已查清（以代码现实为对照源），但选择会影响需求口径、篇章写法或施工顺序，且选择权在产品侧。登记一条裁决点 = 承认「这里没定」；正文按**默认写法**书写，不假装已定，也不因未定而拒写现状。

### 1.2 生命周期

| 状态 | 含义 | 约束 |
| --- | --- | --- |
| open（待裁决） | 登记在册，选项未收口 | 正文按默认写法书写；受影响条目挂「依赖 ⚖️Bx」注记 |
| ruled（已裁决，落地中） | 选择已作出，默认写法让位于裁决结果 | 本篇记录裁决结果、日期与落点（ADR 或篇目）；受影响篇按修订纪律改写 |
| closed（收口） | 裁决结果已在受影响篇/ADR 落地并回写 | 条目保留作档案；正文不再悬挂该注记 |

同义口径对照：PRD 8.1 的「待裁决」= open；「默认写法执行中」= ruled（按默认写法执行、裁决本身仍可在工程侧数据齐后重开）；「已收口」= closed。⚖️B10 为特殊态「另案」——不悬挂于本表（见 §2 表内注记）。

### 1.3 与 ADR 的关系

裁决闭环路由（00 篇 §6.7）：裁决结果需要立法级的（改变不变量/信任模型/域边界）→ 落 ADR（36 篇 §4 流程）；行为级的 → 直接改受影响篇并回写修订记录。两条路的终点都是本篇状态改 ruled/closed。裁决不是 ADR 的前置审批——裁决本身是产品选择，ADR 是选择的立法载体。

## 3. 新增裁决点收编流程

1. **发现**：写作组或实施中发现「真实开放且影响口径/施工」的决策点（含域内登记点），先查本表与 PRD 8.1 确认无既有条目可挂。
2. **提案**：按 §2 表列口径写六要素——事项/现状（附代码或文档对照源）/待定选项/影响（受影响篇与 FR/CR 编号）/默认写法/建议状态；缺现状对照源的不予登记。
3. **登记**：分配下一顺位编号（现用至 B24，新点自 B25 起）；写入本表并在 PRD 8.1 同步（PRD 侧由 PRD 维护人执行）；来源篇章元数据「裁决点」字段补该编号。
4. **正文纪律**：相关篇章正文按默认写法书写并挂「⚖️Bx」引用；不得在登记前以现网语气书写任何一侧选项。
5. **裁决与流转**：裁决作出后——本篇记结果与落点（ADR 编号或篇目锚点），状态 open→ruled；受影响篇改写完成并回写修订记录后转 closed。closed 条目不再出现在任何篇章正文注记中。
6. **销号纪律**：不允许删除条目或跳号；作废的裁决点标 closed 并记「并入 ⚖️By」。
7. **判据登记（2026-06-09 起）**：新增裁决点入册时同步填写「裁决判据/所需证据」列——无判据的登记视为不完整，维护人退回补齐后再收编；判据无法给出的（确无数据可依的纯价值选择），写「无数据判据，凭产品立场裁」并注明理由。

## 4. 裁决后回写路径

### 4.1 五步回写链（裁决作出后按序执行，顺序不可换）

1. **记账**：裁决内容、日期、裁决人角色与依据证据（对照 §2「裁决判据/所需证据」列核验齐备性）记入本篇 §2 对应行，「状态」open→ruled；默认写法列让位于裁决结果。
2. **立法级分流**：裁决结果需要立法级的（改变不变量/信任模型/域边界）→ 落 ADR（36 篇 §4 流程），新 ADR 编号回填本篇对应行；行为级的直接进第 3 步（§1.3 路由同源）。
3. **受影响篇改写**：受影响面以 §2「影响」列为准逐篇回写——每篇修订记录注明「依据 ⚖️Bx 裁决」；各篇正文的「⚖️Bx」悬挂注记随改写同批清理，不单开批次。
4. **状态翻转 ruled→closed**：核验条件=受影响篇全部回写完成＋（若立 ADR）36 篇 §2 索引行已更新＋销账判据（本表「——」列指向）达成；三者齐备才转 closed，closed 条目不再出现在任何篇章正文注记中。
5. **PRD 8.1 同步**：PRD 维护人按 §3 第 3 步把裁决结果与状态同步回 PRD 8.1——既有待同步事项（B22-B24 三行入 PRD 8.1）已于 2026-06-09 复评残留清零时核验完成（两处选项逐字一致）；后续裁决回写按本步执行，同步后两处逐字一致（§5 第 1 条同源）。

### 4.2 回写核对纪律

1. **对账页**：每次裁决回写完成，本篇修订记录登记一行（裁决号、受影响篇清单、状态迁移、PRD 同步与否）——37 篇修订记录是裁决闭环的对账页。
2. **两账分开**：裁决改变事实口径不等于改变假设等级——03/04 篇随裁决改写时，同步核对 38 篇台账证据等级列是否受影响；裁决只改「写法」，不改「等级」，等级变更只走 38 篇 §4 流程。
3. **跨点联动**：一次裁决牵动其他裁决点时（如 ⚖️B22 选型落地解锁 ⚖️B20/B21 的判据数据、⚖️B14/B15 联动 CR-03/CR-04），被牵动点的「现状」列与判据列在同一次修订中刷新，并在修订记录注明联动关系。
4. **判据不齐的处置**：判据未齐期间默认写法持续有效，受影响篇不因裁决悬置而停写；以「判据难齐」为由要求删除注记、改现状语气或跳过证据核验的提议，按 §3 提案流程反向评审，不构成裁决。
5. **证据时效**：判据证据以产生时点计效，跨基线引用须带时间戳（00 篇 §6.4 基线规则同源）；过期证据（早于当前基线一个以上版本锚）须重采后方可用于裁决。

## 5. 设计说明

1. **转正口径**：本表内容与 PRD 8.1 逐字同步转正（B4 事项名沿用 PRD 修订后版本）；PRD 8.1 是需求侧唯一权威，本篇是流转台账——两者冲突时先修源表（PRD 8.1）再修本篇，不允许两处各自演化。
2. **为什么不收敛为「全部 open」**：B5/B6/B9/B11-B13 的默认写法已定为执行口径（文档侧已按此书写完毕，剩余动作在工程侧），如实标 ruled 而非 open——裁决点登记的价值在如实反映「哪里没定、哪里在执行」，不在于把未决面做大。
3. **B8 收口依据**：事故分级在 v3 直接统一（S0=最严重，28 篇口径），不构成产品权衡，故本版收口不再悬挂。
4. **B10 特殊处置**：库外文档的地图与判定已落 39 篇，执行责任与节奏另案——本表保留一行指针以保编号连续，不参与 open/ruled/closed 流转。
5. **与 36 篇分工**：本篇管「未决与已决的产品选择」；36 篇管「已立法的决策记录」。裁决升格为 ADR 后，裁决点条目只保留指针，不复制 ADR 内容。
6. **B22-B24 收编依据**：B22 由 31 篇按 §3 流程登记（v3.0 初版未及入表，2026-06-09 复核补齐）；B23/B24 系 15 篇域内裁决点（附句限频、参数学启用）在初版误挂 B17/B18、与 PRD 8.1 canonical 定义冲突，复核后按原义改挂新号收编——编号唯一性恢复。PRD 8.1 侧已同步收录 B22-B24（选项与 37 §2 逐字对齐，2026-06-09 核验），两侧以本表为流转权威、内容一致。
7. **待派号跟踪行**：登记表末设「⚖️待派号」行承接已立项待编号的事项（首条：29 篇 §4.6 投诉处理时限 SLA 定标）——占位期间不预占 B 号、不计入 open/ruled 分布统计；正式编号按 §3 流程分派后转为常规行。
7. **为什么逐条写裁决判据**：登记表此前的六要素回答「哪里没定、定了我改写什么」，但不回答「凭什么能定」——没有判据列，裁决容易被催成拍脑袋，或反过来以「数据永远不齐」无限期搁置。逐条落证据清单后，每条裁决点的推进条件是可对账的：数据缺哪一窗口、评审缺哪一份记录一目了然；判据同时是反拖延装置（齐了就该排裁决）与反草率装置（不齐不许裁）。
