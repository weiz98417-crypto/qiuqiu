# 28 指标体系

> 本篇基线：2026-06-07 仓库 a7e5100。

**本篇定位**：指标的口径细则与治理篇。回答四个问题：指标分几层、每个指标口径是什么、现网实有采集面有什么、指标怎么治理与复盘。指标定义的唯一出处是 PRD 第六章；本篇承接为运营细则——分层视角、指标定义总表、实有采集面逐格对账、治理纪律与复盘节奏。埋点的事件 schema、命名规范与 QA 流程归 31 篇（埋点与数据采集规范）；SLO 与告警的工程口径归 21 篇；值守响应归 27 篇。规则引用格式「28/M-NN」。

**导读**：§1 分层总则与判读纪律｜§2 指标定义总表（北极星层／护栏层／守门层／运营层，含数据质量风险登记）｜§3 实有采集面对账（Grafana 6 面板／运营台九格／账本四表与实时流）｜§4 指标治理（新增流程／口径变更／与 31 篇的先后）｜§5 复盘节奏｜§6 验收｜§7 设计说明。

**事实依据**：本篇全部「已运行」声明以 2026-06-07 仓库 a7e5100 为对照源，逐格可指认到 `deploy/grafana/provisioning/`、`console/src/pages/Overview.tsx` 与账本表；无采集来源的指标一律标「待埋点（31 篇）」，不写模糊时态。

## 1. 分层总则与判读纪律

### 1.1 四层分层

| 层 | 回答的问题 | 与 PRD 第六章三面的对应 |
| --- | --- | --- |
| 北极星层 | 产品是否成立（价值是否发生） | 价值面核心（6.2.1） |
| 护栏层 | 产品是否作恶或退化（以什么代价换读数） | 护栏面全量（6.2.2）＋依赖保护类护栏 |
| 守门层 | 系统现在是否健康（要不要人介入） | 运行面中挂告警规则的子集（6.2.3） |
| 运营层 | 运营台此刻看得见的聚合面 | 运行面其余（面板、九格、实时流） |

分层是运营评审视角，不是第二套口径：任何指标的口径定义、公式与采集来源以 PRD 第六章为准；本篇定义表与 PRD 冲突时，以 PRD 为准并修订本篇（见 §6）。

### 1.2 判读纪律（三条，评审时逐条执行）

1. **运行面已出数 ≠ 价值面已验证**。守门层与运营层全部已运行；北极星层与护栏层主体为零采集面。已运行面板的读数不得用作价值面结论的证据。
2. **价值与代价同权**。每个北极星与价值指标至少配一个护栏反指标；护栏恶化压过任何正向读数（保护指标否决权，见 §4.3）。
3. **待埋点不冒充达成**。「待埋点（31 篇）」指标不得出现在任何对外汇报或放行材料中作为「已达成」证据；上线就绪检查单 #18（最小埋点面）未关闭前，价值面全部读数缺位是如实状态。

### 2.6 数据质量风险登记（抽 10 项，2026-06-09 增补）

> 口径定义之后的第一失效模式是**读数被误读**与**事件面缺口被当零**。本节抽 10 项登记其数据质量风险与防错纪律——7 项已运行（代理口径/落库代理/进程内面各有陷阱）＋3 项待埋点（事件缺失即读数缺位）；未抽到的指标不豁免同类风险，新增指标按 §4.1 问题卡「偏差风险」栏自登记。

| ID | 数据质量风险 | 防错纪律 |
| --- | --- | --- |
| M-01 | 事件缺失：session_entered/turn_completed 未上线前任何「ECS」读数均无采集面；口径误读：「有效话轮 ≥3」被误读为「消息 ≥3 条」（话轮以 ASR 成功转写＋球球完成为准） | 埋点 QA 通过前禁出任何 ECS 数字；对外引用 ECS 必须带三条件全口径，不得缩写为「会话数」 |
| M-04 | 分子混流：复盘邀约自动创建与用户显式接受混流即虚高行动率（⚖️B20）；送达不等于接受 | 分子只计显式接受；任何引用并陈「自动创建/显式接受」两个分母口径 |
| M-07 | 代理口径误读：播放期打断率 ≠ 意外打扰率全量（后者含非播放期覆盖）；playback_state 缺失时段若计为「无打扰」即稀释分母 | 读数必须带「播放期代理口径」限定词；interaction_ledger 缺 playback_state 的回合单独计数，不进分母 |
| M-08 | 归因误读：unknown 命中被读成「用户乱说」，实为「没接明白」（含 FAQ 缺条目）；24h 滚动窗导致日内时段不可比 | 命中样本须回流未答问题循环看内容分布；跨日比较只同比同时段 |
| M-16 | 小样本分位抖动：低流量时段 P95 由极少数慢回合决定，误报延迟退化；latency_ms 只覆盖有 trace 的回合 | 分位数并陈 P50 与样本量；样本量 <30 的窗口标「低置信」，不触发阈值调整讨论 |
| M-18 | 间接口径：熔断器落库是错误计数的代理——错误计数 ≠ 错误率（无总量分母），熔断器快速开合可能漏记 | 读数表述为「错误计数」不表述为「错误率」；与供应商侧账单/后台对账时以对方口径另算 |
| M-19 | 双成因混同：10 分钟无 provider 事件既可能是 poller 停摆、也可能是上游数据源本身停发——告警口径不区分成因 | 告警处置（27 篇）首查先区分「本侧进程在不在」与「上游有没有事件」，不直接归因 poller |
| M-24 | 分母误读：送达率分母含 suppressed 与 missed——读数被误读为「触达成功率」会掩盖抑制与丢失；自动创建邀约计入分母（⚖️B20 关联） | 读数必须带「delivered ÷ 全部（含 suppressed/missed）」口径；suppressed 激增时先查 quiet 双门与节拍配置再谈送达质量 |
| M-26 | 分母低估：拒绝路径无痕（backchannel 未发出即无记录），24h 对比的基数是「白名单事件数」而非「应发数」；不承诺限频归因 | 只作「发出量 vs 白名单事件量」对比读，不作「限频命中率」读；两值差异不得解释为丢失 |
| M-27 | 重启清零：进程内环形缓冲重启即失——重启后读数为零是「无数据」不是「健康」；嘴型退化遥测依赖客户端进程存活 | 读数为零先查进程存活时长；面板对「零读数」与「满读数」同警示，不把零当优 |

## 4. 指标治理

### 4.1 新增指标流程（四步）

1. **问题卡**：新增指标先填指标问题卡——决策问题（影响哪个继续/收缩/停止决策）、用户结果（关联哪项观看任务或控制权）、公式（分子/分母/时间窗/纳入排除）、观察来源、偏差风险、对应反指标、负责人、复审日期。回答不完整的只能留在探索笔记，不得成为团队目标或对外承诺。
2. **采集来源核对**：先埋点后指标——无采集来源的指标不得立项为正式指标，只能以「待埋点（31 篇）」登记并进 31 篇排期；禁止先立指标后造数。
3. **试运行一轮**：新指标以试运行状态出现一轮，确认定义与采集偏差后才进正式视图与周度评审。
4. **回填登记**：转正式时回填 §2 定义表（ID/口径/来源/复核频率/owner），并记篇末修订。

### 4.2 口径变更纪律

- 修改公式、阈值、分层或采集范围须留四项：修改日期、修改原因、对历史可比性的影响、新定义起用时间。
- 必须同时并陈旧定义最后一次读数与新定义第一轮读数，并写明不可直接比较的部分；禁止读数不理想时无痕改分母、排除困难样本或更换成功标准。
- 参数值冲突以规范附录 B（参数总表）为唯一裁决口径；单篇不得私设与源表冲突的数字。

### 4.3 否决权与评审纪律

- **保护指标否决权**：护栏层任一指标恶化时，扩张与放量决策不得通过——即使北极星与价值读数上升（00 篇 §3.6 配套判断规则的指标面落地）。
- **不做个人奖惩**：任何指标不得直接绑定个人奖金；连续使用、总时长、消息数、角色好感不设为目标类指标（Goodhart 防护）。
- **指标服务于决策**：每张视图的数字对应一个明确动作（继续/收缩/调查/修复/暂停/扩大）；没有动作的数字不进周报。

### 4.4 与 31 篇的先后关系

- 28 篇管**口径与治理**；31 篇管**采集实现**（事件 taxonomy、命名规范、公共属性 schema、触发时机、owner 指派矩阵、QA 流程）。
- 翻牌规则（PRD 6.3.3）：§2 各表「待埋点」指标在其依赖事件全部实施并通过 QA 后，方从「待埋点」翻为「已采集」，同时修订本篇与 PRD 对应行。
- 实施顺序随 PRD 6.3.3：P0 批＝北极星链路（session_entered/turn_completed/session_exited）＋护栏代理对照＋F 组随对应 CR 功能同批；P1 批＝其余。上线就绪检查单 #18（最小埋点面，P1 未完成）以 P0 批跑通为关闭条件。
- 采集红线（约束一切指标数据）：不传消息正文与 PII；标识只用匿名伪标识；自托管为前提（CR-06 交互数据不出第三方）；埋点消费面只出聚合数。

### 4.5 仪表板显示纪律

指标进视图（Grafana 看板、周报、里程碑材料）统一遵守：

1. 每张图可复述分子、分母、时间窗、样本量与上次定义修改日期；复述不了的图撤下。
2. 护栏恶化与红线事件固定在视图第一屏显眼处，不折叠进「异常」标签。
3. 总体读数旁至少保留一个关键分层（优先按任务与媒介条件）；小群体与敏感特征读数聚合、模糊化或不展示。
4. 允许显示「未知」「样本不足」「无法比较」——不为填满仪表板计算伪精确比例。
5. 平均值不掩盖尾部：关键分位、异常时段与个案复盘通道并陈；静音用户、纯文字用户、退出者不被平均数吸收。

## 5. 复盘节奏

四种节奏回答不同时间尺度的问题；其中里程碑复盘的记账口径以 02 篇为准。

| 节奏 | 回答的问题 | 看哪些指标 | 产出 |
| --- | --- | --- | --- |
| 比赛中（值守） | 现在是否伤害用户或无法兑现承诺 | 守门层 M-16~M-19＋运营层九格；告警联动 27 篇 | 处置动作（降级/接管/撤回），不做归因与增长判断 |
| 赛后复盘（每比赛窗口） | 本场用户是否得到可控、可信的陪看 | M-07/M-08/M-23/M-24＋投诉与风险样本（29 篇） | 异常摘要、用户可见影响与临时动作、高风险个案跟进、下场前必须关闭项、评测新样本 |
| 周度指标评审 | 哪些读数改变下一步决策 | §2 全表已运行行＋已上线埋点行 | 一个明确动作；无行动项的审阅不算闭环 |
| 里程碑复盘 | 是否跨越一道门（02 篇里程碑表） | 北极星层 M-01~M-06＋成本反指标 M-15 | 里程碑表回写（只收已落地并有评测或演练实证的能力）；阶段评审按证据包召开，不按日历 |

周度评审固定顺序（六步，顺序不可换）：①先报红线与暂停状态——有未解除限制先讨论保护与修复，不讨论增长读数；②再报证据质量——样本情境、缺失与未进入者；③只看本轮预先登记的主问题；④价值与代价同时出现——任一面缺失视为证据不完整；⑤听定性反例——至少一正一负一无法判断；⑥形成一个明确动作（继续/收缩/补研究/暂停/停止），不以「继续观察」代替决策。P1 组动工前的三道复盘工序（结果合同→无责复盘→提案审查）按 02 篇执行，本篇不重复。

评审就绪清单（未满足项按右列处理，不带病上会）：

| 检查项 | 未满足时的处理 |
| --- | --- |
| 本轮主指标与配对护栏已登记 | 数字只作探索材料，不得宣称支持假设 |
| 分子、分母、排除项可复述 | 暂停比较，先修记录方式 |
| 待埋点指标未混入结论 | 剔除该结论；走 31 篇排期 |
| 退出者、静默用户、未使用原因有 seen | 不得把使用量解释为价值 |
| 高风险事件有独立复核与暂停负责人 | 不进入扩张议题 |
| 本轮只改一个主要变量 | 拆分比较，避免无法归因的组合变化 |

分层阅读规则：先看绝对数量与缺失、再看百分比，小样本不作强结论；任一分层的高严重度事件单独审查，不因总体平均而消失；差异只出现在单场比赛、单设备或单一情境时，优先视为情境信号而非人群特征。

留存类口径一句话立此：留存按比赛窗口理解，不按连续天数；被动回流（提醒带入）与自主复用分开计量，风险回流（怕被忘记、怕球球难过类理由）计为安全信号而非留存成功。增长与生命周期运营的展开归 32 篇。

## 7. 设计说明

1. **与旧 16 章的核心差异：从「将采集」到实有面板对账**。v2 档案 16 章是研究期候选口径——ECS 按「成年同意＋主动任务＋控制完整＋无未解决高严重度事件」定义，配 L0-L4 证据层级与四类目标，通篇是「业务指标将随首批用户测试开始采集」的姿态。v3 的 ECS 口径由 PRD 6.2.1 转正为可采集定义（语音会话＋有效话轮≥3＋时长≥5 分钟），三条件全部对应 31 篇事件；本篇第一节先盘清现网**实有**采集面（Grafana 6 面板、九格、账本四表逐格对账），再立待建清单——「将采集」式时态在全篇禁用。v2 的 L0-L4 证据层级随研究期框架留在档案；问题卡、口径变更四留痕、保护指标否决权三条治理条款收编为 §4。
2. **与旧 64 章的归并**。v2 档案 64 章（指标复盘与规模化决策）的复盘节奏收编为 §5（四种节奏与周度六步）；其留存重定义（比赛窗口口径）一句话立此、展开归 32 篇；其「扩大什么就重新证明什么」的证据包方法并入 02 篇里程碑与 30 篇上线交付的验收语境，不在指标篇重复。
3. **四层分层与 PRD 三面的关系**。PRD 6.1 立三面（价值/护栏/运行）是需求侧分类；本篇拆四层是运营消费侧视角——守门层独立成层的理由是它有明确的消费场景（告警→27 篇值守→S0-S3 响应），与「面板巡检」类运营指标的处置节奏不同。两层映射表见 §1.1，防止出现第二套口径。
4. **M-17 首响告警的休眠保留**。句粒度流式经韵律盲测 80% 嫌弃裁决拆除后，tts_first_audio 锚点不再产生；规则保留是为了锚点回引（若未来重建流式）并留评审入口，不构成「首响有告警护航」的现网声明——首响现网接受现实为整段投递 3-7s（06/20 篇）。
5. **/ws/ops 饱和丢弃的诚实降级**。丢弃计数在内存、无落库面，Grafana 第 5 条告警明确不建（不造代理凑数）；M-10 因此只有周度人工查看，无告警联动。这条「有意不规则化」如实保留，是采集面对账纪律的样本：面板上没有的，指标表上就不能有。
6. **owner=待指派的写法**。全表 owner 留待指派是当前单团队阶段的组织现实；假装指派（写具体角色名而无对应机制）会复制 v2「纸面 owner」病史。指派动作与 31 篇 owner 指派矩阵同批执行，回填走修订记录。
