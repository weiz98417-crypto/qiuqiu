# 设计—项目事实对齐矩阵

> 审查日期：2026-09-02  
> 用途：记录产品设计目标态与项目事实的关系，帮助区分“设计问题”和“实现/工程差异”。  
> 边界：本材料可以引用代码、接口和测试；这些信息不回写 `docs/球球全套资料/4.产品设计` 正文。  
> 结论原则：设计领先项目实现是允许状态，不自动构成设计缺陷。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 对齐 | 设计主张与可核验项目事实在本次检查范围内一致 |
| 部分覆盖 | 项目已有相关能力，但未覆盖设计要求的全部粒度或入口 |
| 设计领先 | 设计明确提出目标态，项目事实尚不能证明全部覆盖；不修改设计 |
| 待核验 | 需要进一步运行走查、端到端测试或补充证据，不能直接判定冲突 |
| 独立设计问题 | 设计内部自相矛盾，即使项目尚未实现也应修正文档 |

## 不应混淆的结论

- F-01、F-02、F-03、F-04、F-08 是“设计领先或部分覆盖”，不是要求删除设计内容；
- F-05、F-06、F-07 的核心原则已有较强对应，但仍需通过端到端和真实环境评测证明；
- PD-001～PD-005 是设计内部合同问题，即使项目暂未覆盖，也应单独处理；
- 本矩阵不承担发布门禁、修复进度或责任分派功能。

## 生产版本拓展的对齐边界

生产版本章节描述目标能力，不因项目当前覆盖范围较小而删除或降级。其与项目事实的关系统一标记为“设计领先”，并由后续工程交接、POC 和评测材料分别核验：

| 目标能力 | 设计锚点 | 对齐处理 |
| --- | --- | --- |
| 自动事实发布与更正 | `20/23/24/41/42/45` 生产版本设计拓展 | 设计领先；需以来源资格、误剧透率和更正链路评测，不回写实现状态。 |
| 订阅提醒与赛后回顾 | `21/22/31/40` 生产版本设计拓展 | 设计领先；需核验授权、时间窗、取消和跨比赛隔离。 |
| 可管理长期连续性 | `29/30/38/41` 生产版本设计拓展 | 设计领先；不等同无限期自动记忆，需核验来源、有效期、删除和防回写。 |
| 语音/舞台主体验 | `25/26/32/33/34` 生产版本设计拓展 | 设计领先；媒介顺序可变，但关键事实、控制、错误和退出必须有等价路径。 |
| 受控工具与外部动作 | `20A/33A/42/46` 生产版本设计拓展 | 设计领先；工具不是并列 Agent，需核验授权、审批、幂等、撤销、预算和回滚。 |
