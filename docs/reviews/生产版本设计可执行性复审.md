# 生产版本设计可执行性复审

> 初次复审日期：2026-09-02  
> 最近复审日期：2026-09-03  
> 复审对象：`docs/球球全套资料/4.产品设计` 中新增的“生产版本设计拓展｜能力深化知识”章节  
> 复审目的：判断这些内容是否达到可以交给产品、体验、工程、测试和运营继续落地的设计颗粒度  
> 结论性质：设计质量复审，不代表任何能力已经实现或上线

## 1. 结论

初次复审结论为：**未达到可直接执行落地的标准**。2026-09-03 完成针对该结论的定向补强后，核心生产主链已达到“可拆分为产品、体验、工程、测试和运营任务”的设计合同标准；仍需在后续专题迭代中补充具体页面线框、工程容量参数和真实用户证据，这些不属于本次合同收口的阻断项。

之前的检查只确认了章节存在、关键词齐全、链接和格式正常，没有按原有设计文档的完整颗粒度检查“谁在什么条件下做什么、状态怎样变化、页面怎样承载、接口怎样交接、失败怎样收回、用什么门槛放行”。因此之前将其称为“复审通过”是不准确的；本次已按该缺口补充中央合同并重新检查。

当前生产拓展的主要问题不是方向错误，而是大量内容仍停留在原则、愿景和检查项层面，不能直接形成任务、原型、接口、测试用例或运营值班动作。

## 2. 可执行设计的最低合同

参照本资料包原有的旅程、主动性、语音、事实、隐私和 Agent 文档，一项生产能力至少需要同时具备以下九类内容：

| 合同部分 | 必须回答的问题 | 可交付产物 |
| --- | --- | --- |
| 目标与范围 | 为谁解决什么问题？本次不解决什么？ | 用户任务、非目标、适用人群和赛事范围 |
| 角色与权限 | 用户、Agent、工具、运营、人工分别能做什么？ | 责任矩阵和授权边界 |
| 触发与前置 | 什么事件触发？需要哪些事实、设置、身份和许可？ | 前置条件与资格链 |
| 流程与状态 | 从开始到结束有哪些状态？何时转换、失效或重试？ | 流程图、状态机、转换表 |
| 用户体验 | 用户看到什么、点什么、听什么、如何取消？ | 页面、文案、交互和媒介规格 |
| 数据与协议 | 读写哪些对象和字段？如何版本、幂等、审计？ | 数据字段、消息合同、Trace 关联 |
| 异常与撤回 | 等待、冲突、失败、超时、删除、退出怎样处理？ | 失败矩阵、撤回传播和终态规则 |
| 评测与放行 | 用什么样本、指标和硬门判断是否可用？ | 场景卡、阈值、阻断条件和复审周期 |
| 运营与回滚 | 谁审批、谁暂停、谁恢复？回滚到哪一版？ | 值班动作、版本策略和恢复手册 |

只写“需要有资格链、可回滚、要评测”不等于完成上述合同；这些词必须落到具体条件、字段、动作和责任人。

## 4. 必须补齐的高优先级问题

### E-001：生产能力没有统一的可执行功能卡

自动事实、提醒、长期连续性、语音主出口、舞台主出口、工具动作各自使用不同粒度描述，无法直接拆成同一套产品任务、研发任务和测试任务。

**必须补充：** 为每项能力建立一张统一功能卡，至少包含目标用户、非目标、触发事件、前置条件、用户步骤、Agent 决策、工具调用、输出、失败、撤回、指标、负责人和回滚版本。

### E-002：关键能力没有状态机

目前只有少量场景表，没有自动事实、提醒、资料、工具动作和生产 run 的完整状态与转换；“取消”“撤回”“超时”“部分完成”因此无法执行或测试。

**必须补充：** 每项能力至少定义 `候选 → 待确认 → 已授权 → 执行中 → 已完成/失败/取消/撤回/部分完成` 等状态、进入条件、退出条件、幂等行为和终态优先级。

### E-003：用户界面与内容没有落到可制作规格

“显示来源”“提供取消”“保留等价路径”仍无法让设计师制作页面或让测试判断是否通过；缺少组件、字段、按钮、文案、焦点和媒介状态。

**必须补充：** 在 21、25、33、34、35、40 中补充页面结构、状态变体、按钮动作、确认文案、字幕/声音/动效同步和无障碍验收。

### E-004：Agent、工具、数据和协议没有闭环

33A、41、42 已分别提到 run、对象和消息族，但生产拓展没有把它们绑定到同一条可执行链路，缺少字段级输入输出和错误语义。

**必须补充：** 为自动事实、提醒、资料、工具动作各给出一条端到端序列：输入对象 → 资格裁决 → Agent 决策 → 工具请求 → 回执 → 用户输出 → Trace → 撤回/终态。

### E-005：评测没有可计算阈值和放行责任

“误剧透率”“取消成功率”“恢复时间”等指标目前没有公式、分母、样本、阈值、观察窗口和责任人，不能形成发布决定。

**必须补充：** 45 为每项指标定义计算公式、样本来源、硬门阈值、体验门阈值、报告格式、审批人和复审周期；44、43 使用同一指标定义。

### E-006：回滚和运营动作仍是口号

“一键回滚”“人工暂停”“自动收缩”没有说明谁操作、操作对象、传播延迟、用户看到什么、如何恢复和怎样防止旧任务复活。

**必须补充：** 36、39、42、46 给出分级暂停、配置版本、传播顺序、SLA、恢复前检查和演练记录模板。

## 5. 后续修改顺序

1. 先在 `20` 建立生产能力目录和统一功能卡模板，但不把模板原文复制到每篇产品文档；
2. 以自动事实、提醒、长期连续性、语音/舞台主出口、工具动作五条主链分别补齐 21–42 的状态、体验、数据和协议；
3. 在 `43` 为每条主链制作可走查原型脚本，在 `44` 制作对应技术实验，在 `45` 固化指标公式和放行门；
4. 在 `36/39/46` 补生产暂停、人工交接、故障域、恢复和回滚演练；
5. 修改后再次按本报告九类合同逐篇复审，只有所有主链都能从用户动作追到终态和回滚，才可称为“可执行设计”。

## 6. 初次复审结论（历史记录）

初次复审不修改产品方向，也不因项目当前实现范围较小而删掉生产设计；当时新增内容仍是“生产能力扩展提纲”，不是“可直接落地的生产设计”。该结论已由第 7 节所述定向补强复审更新。
