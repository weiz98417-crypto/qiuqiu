# 产品设计完整升级方案

> 文档类型：产品设计资料包的系统升级与生产版拓展方案  
> 编制日期：2026-09-02  
> 适用范围：`docs/球球全套资料/4.产品设计` 及其索引、评测、研究和审查材料  
> 关联审查：[`产品设计审查标准`](./产品设计审查标准.md)、[`产品设计问题清单`](./产品设计问题清单.md)、[`设计—项目事实对齐矩阵`](./设计—项目事实对齐矩阵.md)、[`AI数字人Agent设计对标审查`](./AI数字人Agent设计对标审查.md)  
> 方案性质：修改计划与设计沉淀方案，不是实现清单，不代表当前项目交付状态。

## 1. 方案结论

本套产品设计不需要推倒重写，也不需要为了对标外部 Agent 平台而增加多 Agent、强拟人化或无限期自动记忆。

本次升级分为四层：

1. **审计纠偏**：修复已确认的术语、默认值、状态映射、协议边界、追溯关系和导航问题；
2. **基础设计深化**：把比赛理解、个人味动态、注意力节奏、事实更正和多模态体验写进基础产品设计本体；
3. **生产版本设计拓展**：描述产品成熟后如何扩大自动事实发布、提醒、长期连续性、工具能力、外部动作和多模态主体验；
4. **生产治理与复审**：为生产版能力补充授权、资格、风险、评测、Trace、成本、延迟、版本和回滚条件。

升级后的设计不是“Agent 什么都不能做”，而是：

> 生产版数字球友可以自动化、可以有个人味、可以提醒、可以保留受控的长期连续性、可以调用工具，也可以让声音和动态成为主要体验；但每项扩展都必须有清楚的用户授权、事实资格、风险边界、可撤回路径、可观察结果和回滚机制。

## 2. 统一表达规则

### 2.1 三种内容层级

每份被升级的设计文档都应明确区分三种内容，不再把它们混成一层：

| 层级 | 作用 | 写法 | 是否代表当前实现 |
| --- | --- | --- | --- |
| 基础产品设计 | 定义产品当前必须成立的核心价值和用户边界 | 原有章节中直接描述产品行为 | 否 |
| 基础设计深化 | 将已经确定的产品方向写得更完整、更可理解 | 原有章节内扩写或新增基础章节 | 否 |
| 生产版本设计拓展 | 描述产品进入生产阶段后可增加的自动化、连续性和规模能力 | 在相关文档后新增统一标题 | 否 |

生产版统一标题：

> ## 生产版本设计拓展｜能力深化知识

统一说明：

> 本节描述产品进入生产阶段后的能力扩展、体验深化和治理要求，不代表当前实现状态，也不限定 MVP 必须采用全部能力。

不得使用以下容易误导的表述：

- “已实现/未实现”；
- “当前版本支持/当前版本不支持”；
- “代码已经具备/代码尚未具备”；
- “由于工程暂时做不到所以保留”；
- “MVP 永远不能使用”。

### 2.2 生产版能力的共同字段

每个生产版扩展至少写清以下字段：

1. 用户问题与产品价值；
2. 使用情境和触发事件；
3. 用户可见的行为和结果；
4. Agent 或服务的决策规则；
5. 事实、权限、记忆、关系和媒介边界；
6. 正常、等待、冲突、失败、撤回和退出路径；
7. 用户授权和可撤销操作；
8. 外部副作用和责任归属；
9. 评测指标、反例和阻断条件；
10. 版本、生效范围、回滚和复审规则；
11. 与其他设计文档的唯一锚点；
12. 与 MVP 基础设计的差异说明。

## 4. 第一层：审计纠偏方案

这一层不新增生产能力，目标是让现有设计合同先达到统一、可读、可追溯。

### 4.1 正式枚举与默认向量

**修改文档：** `20/21/24/35/43`

**统一决策：**

- 陪看密度正式枚举：安静 / 只回应 / 有限提示；
- 信息保护正式枚举：严格防剧透 / 事实优先；
- 声音方式正式枚举：仅文字 / 点按播放 / 自动声音；
- 动态强度正式枚举：低动态 / 标准动态；
- 基础规范默认向量：安静 + 严格防剧透 + 仅文字 + 低动态。

其他“安静看球”“只回应我”“本场有限提示”“事实优先模式”等表达，只能作为解释文案、场景描述或研究处理组，不得继续充当正式模式名、接口值或评测标签。

**验收：**

- 同一个正式枚举在所有文档中名称、行为、默认值和作用范围相同；
- 四个维度可分别调整，不被重新合并成未定义的总模式；
- 研究变体明确标为研究条件，不改变规范默认；
- 用户文案、协议字段、原型标签和评测标签均可回指 `20`。

### 4.2 四维控制的进入契约

**修改文档：** `21/35/43`

在赛前进入节点建立统一的“本场设置”卡，四个维度同时出现。每个维度包含：

| 字段 | 说明 |
| --- | --- |
| 当前值 | 进入本场时的实际选择 |
| 默认值 | 若用户不操作，系统采用的值 |
| 本场影响 | 影响哪些内容和媒介 |
| 立即结果 | 点击后页面、声音、动作和主动计划如何变化 |
| 结束范围 | 仅本场、长期设置或一次性动作 |
| 恢复方式 | 用户如何重新开启 |
| 保护提示 | 选择如何影响剧透、共享设备和隐私 |

信息保护必须在最接近比赛进入的节点完成知情选择；如果允许延后设置，也要说明未选择时使用严格防剧透默认。

### 4.3 领域状态到用户状态映射

增加唯一状态映射表：

| 领域状态 | 用户可见状态 | Agent 可否作为事实引用 | 是否允许结果型通知 | 是否允许角色/舞台表现 | 终态或后续 |
| --- | --- | --- | --- | --- | --- |
| 候选 | 默认不展示；必要时显示正在核验 | 否 | 否 | 否 | 待确认、确认、冲突或不可用 |

| 已确认 | 已确认 | 是 | 依用户许可 | 依媒介资格 | 可被更正或撤回 |
| 冲突 | 来源不一致，暂不作结论 | 否 | 否 | 否 | 确认、更正或不可用 |
| 已更正 | 当前以新版本为准 | 只能引用新版本 | 依用户可见范围 | 旧表现失效 | 保留更正链 |

## 5. 第二层：基础产品设计深化

这些内容属于产品设计本体，不应统一推迟到生产版本。

### 5.1 比赛理解能力

**修改文档：** `23/24/27/33A`

#### 基础产品目标

数字球友不仅对比赛做反应，还帮助用户理解比赛。基础设计至少覆盖：

- 发生了什么；
- 当前事实是否已经确认；
- 为什么重要；
- 对比赛阶段或走势有什么影响；
- 这是事实、分析还是推测；
- 用户如何主动展开解释。

#### 用户场景

1. 新用户问“刚才发生了什么”；
2. 用户看到比分变化但不了解原因；
3. 用户问“为什么这次进攻危险”；
4. 用户要求“一句话解释”；
5. 用户要求“展开讲战术”；
6. 事实冲突时用户问“到底哪个是真的”；
7. 用户处于严格防剧透模式，只想知道背景而不想知道结果。

#### 基础 Agent 行为

- 先判断用户允许看到的事实范围；
- 先给最小事实，再给可选解释；
- 将事实、观点、推测和角色反应分层；
- 不以角色激动程度替代比赛重要性；
- 不在事实未确认时生成结果性分析；
- 用户要求深入时才增加战术细节；
- 用户说“简单点”“少一点”后立即收缩；
- 事实更正后使依赖旧事实的解释失效。

#### 基础验收

- 用户能说出“发生了什么”和“这是不是已经确认”；
- 用户能区分事实与分析；
- 严格防剧透时不会因解释而得到未授权结果；
- 用户可以从一句话解释进入更深层说明，也可以不展开；
- 文字、语音和角色表现中的事实资格一致。

### 5.2 个人味动态进行时

**修改文档：** `28/31/32/33/34`

`32` 不是生产版才新增的能力，而是基础产品差异化的核心。基础设计应把“个人味”定义为表达风格、节奏、观察角度和状态过渡，而不是私人生活或真实情绪。

#### 基础表达维度

| 维度 | 基础设计要求 |
| --- | --- |
| 语言气质 | 稳定、克制、有辨识度，不依赖口头禅堆砌 |
| 比赛观察 | 对节奏、空间、攻防和关键转折有稳定关注角度 |
| 情绪变化 | 紧张、克制、释然、回到观看状态之间有连续性 |
| 用户响应 | 承认用户感受，但不索取用户安慰 |
| 沉默 | 是合法的陪看状态，不表达角色受伤或等待 |
| 视觉表现 | 动作与事实状态一致，低动态时可收敛 |
| 用户控制 | 少说、静音、低动态和结束立即覆盖旧计划 |

#### 基础禁止

- 不虚构角色现实经历；
- 不把动作写成真实身体感受；
- 不以嫉妒、失落、孤独、等待和挽留制造关系压力；
- 不因用户沉默自动增加表现；
- 不因用户停留、回复或消费改变关系判断；
- 不让角色动作承担事实、控制、错误或退出说明。

### 5.3 注意力与节奏控制

**修改文档：** `20/21/24/31/35`

基础设计应明确用户可以分别控制：

- 陪看密度；
- 信息保护；
- 解释深度；
- 声音方式；
- 动态强度；
- 自动发言；
- 赛后回顾。

关键事件后可以出现“展开说明”入口，但不能以默认自动长篇解释抢夺用户注意力。

### 5.4 多模态一致性

**修改文档：** `25/26/32/33/34/42`

基础原则统一改为：

> 事实、控制、错误和退出优先；媒介顺序可以由体验设计决定，但关键任务必须具备文字或结构化等价路径。

因此基础设计允许：

- 语音作为主要表达出口；
- Live2D 作为主要氛围出口；
- 文字作为字幕、状态和控制出口；
- 用户在不同媒介之间即时切换；
- 声音或舞台失败后回到可理解的文字和控制。

## 6. 第三层：生产版本设计拓展

本层是本方案的核心新增内容。每项扩展均应放入对应文档后部，并使用统一标题“生产版本设计拓展｜能力深化知识”。

### 6.1 生产版比赛理解引擎

**落点：** `23/24/27/33A`

#### 产品目标

将数字球友从“事件回应者”拓展为“比赛理解伙伴”，让用户可以根据自己的水平和当下注意力选择不同解释深度。

#### 能力分层

| 层级 | 用户问题 | 输出内容 |
| --- | --- | --- |
| L0 状态 | “现在什么情况？” | 最小确认事实与比赛阶段 |
| L1 事件解释 | “刚才发生了什么？” | 事件、时间、相关对象和状态 |
| L2 重要性解释 | “为什么重要？” | 对当前阶段、节奏或局面的影响 |
| L3 战术解释 | “为什么会这样？” | 阵型、空间、压迫、转换、选择和替代方案 |
| L4 赛后复盘 | “这场怎么总结？” | 事件链、战术转折、已确认事实和可选观点 |

#### 用户控制

- “一句话”；
- “讲简单点”；
- “只讲事实”；
- “只讲战术”；
- “展开”；
- “别告诉我结果”；
- “这场少说一点”。

#### 生产版自动化

- 关键事件后自动生成可选解释卡；
- 根据用户订阅的球队、赛事或战术主题筛选解释；
- 赛后生成分层摘要；
- 允许用户对解释标记“太复杂”“太长”“不准确”；
- 将用户主动选择的解释深度作为可管理设置，而非心理标签。

#### 风险与边界

- 分析不能升级事实确定性；
- 未确认事件不进入结果性复盘；
- 不把模型观点写成官方裁判意见；
- 不输出博彩建议或保证性结论；
- 用户处于严格保护时，解释不得绕过观看范围。

#### 生产评测

- 事实与分析区分率；
- 解释层级选择成功率；
- 用户主动展开后的任务完成率；
- 解释过长、过难和打扰比例；
- 事实更正后旧解释失效率；
- 不同媒介的解释一致率。

### 6.2 生产版事实自动发布与更正链

**落点：** `23/24/41/42/46`

#### 产品目标

允许生产版在可信来源和资格链通过后自动发布事实，减少人工等待，同时保持事实可追溯和可更正。

#### 自动发布流程

```text
来源接入
  → 标准化
  → 新鲜度与范围检查
  → 多来源一致性判断
  → 事件状态确认
  → 用户进度与模式资格判断
  → 自动发布或进入人工复核
  → 版本记录与 Trace
```

#### 发布条件

- 来源类别在允许范围内；
- 事件类型和比赛对象可识别；
- 时间和版本完整；
- 与已发布事实不冲突，或冲突已进入复核；
- 当前用户有资格看到该信息；
- 没有场次级安全暂停；
- 自动发布策略版本有效。

#### 不允许自动做的事

- 由 Agent 自行确认来源真实性；
- 把用户观察升级为公共事实；
- 以角色语气补全缺失数据；
- 在撤回后继续播放旧声音或旧动作；
- 在严格保护下向用户展示未授权结果。

#### 更正体验

更正必须说明：

1. 哪个状态发生变化；
2. 当前以哪个版本为准；
3. 是否影响此前的角色反应或时间线；
4. 用户是否可以查看详情；
5. 后续哪些旧呈现已经失效。

#### 生产评测

- 自动发布事实准确率；
- 候选误发布率；
- 冲突状态阻断率；
- 撤回后旧呈现清理率；
- 用户对更正内容的理解率；
- 事实版本端到端可回放率。

### 6.3 生产版提醒与主动触达

**落点：** `21/31/40`

#### 可提供的提醒

- 开赛提醒；
- 阵容发布提醒；
- 用户订阅球队或赛事的关键事件提醒；
- 赛后回顾提醒；
- 用户主动保存的比赛摘要提醒。

#### 订阅合同

每项提醒必须包含：

- 订阅对象；
- 触发条件；
- 频率上限；
- 有效时间范围；
- 免打扰规则；
- 关闭入口；
- 失败重试策略；
- 重复提醒去重规则；
- 是否允许跨设备同步。

#### 主动性规则

- 订阅是主动触达的资格来源；
- 沉默、失落、夜间使用和停留时间不是触达资格；
- 用户关闭提醒后立即停止相关计划；
- 用户不回应提醒不触发角色挽留；
- 赛后回顾可跳过，跳过不降低后续体验；
- 提醒内容与角色关系表达、商业推荐分离。

#### 生产评测

- 提醒相关性；
- 误触达率；
- 重复提醒率；
- 关闭生效时延；
- 免打扰遵守率；
- 用户对提醒原因和关闭路径的理解率。

### 6.4 生产版可管理长期连续性

**落点：** `29/30/38`

#### 产品定义

生产版可以提供可持续的用户设置和有限共同资料，但它们属于用户可见、可管理的数据对象，不是角色的情感记忆。

#### 可保存对象

- 解释长度偏好；
- 战术解释偏好；
- 默认声音和动态选择；
- 关注球队和赛事；
- 用户主动保存的比赛笔记；
- 用户主动保存的共同瞬间；
- 用户允许的赛后回顾设置。

#### 不自动保存对象

- 完整对话；
- 原始语音和环境声音；
- 用户沉默；
- 情绪推断；
- 依赖或脆弱标签；
- 家庭、健康、财务和危机内容；
- 角色对用户的心理判断。

#### 资料字段

| 字段 | 说明 |
| --- | --- |
| 内容 | 用户知道服务保存的具体文字 |
| 来源 | 用户输入、用户主动保存或明确确认 |
| 用途 | 下一场默认、提醒、筛选或用户主动查看 |
| 作用域 | 本场、指定赛事、跨场设置或用户主动查看 |
| 状态 | 候选、待确认、已保存、已暂停、删除处理中、已删除 |
| 有效期 | 到期、复核或持续到用户删除 |
| 读权限 | 哪类 Agent 工具可读取 |
| 写权限 | 哪种用户动作可创建或修改 |
| 更正关系 | 是否被新选择覆盖 |
| 审计线索 | 许可、修改、暂停和删除的关联记录 |

#### 生产版长期连续性规则

- 默认不扩大保存范围；
- 到期前提示用户复核；
- 用户的新选择覆盖旧选择；
- 删除先停止读取和召回，再完成清理；
- 共享设备默认不展示跨场资料；
- 账号或设备不确定时停止跨场召回；
- 记忆冲突时以用户明确选择和最新资料为准；
- 错误资料不进入后续 Agent 上下文；
- 角色不能把资料说成“我拥有的回忆”。

### 6.5 生产版个人味与动态增强

**落点：** `28/31/32/33/34`

#### 可拓展能力

- 多套表达风格但共用同一人格宪法；
- 不同比赛阶段的连续情绪节奏；
- 事实、声音、字幕和动作的同步编排；
- 用户可选择偏分析、偏轻松或偏安静的表达气质；
- 用户调整强度后保留风格但降低存在感；
- 角色在关键事件后的停顿、恢复和转场更自然；
- 赛前期待、赛中观察、赛后回收具有一致语气。

#### 表现资格

任何动作或语音都必须同时满足：

1. 事实状态允许；
2. 用户模式允许；
3. 当前会话有效；
4. 安全和关系边界通过；
5. 文字或结构化状态已具备；
6. 动作可以被停止和收敛；
7. 不会制造真人、官方或现实关系误认。

#### 生产版评测

- 个人味辨识度；
- 表达连续性；
- 动作与事实一致率；
- 用户对角色身份的持续理解；
- 角色拟人化误认率；
- 用户降低强度后的收敛成功率；
- 用户被打断、被挽留或被要求照顾角色的事件率。

### 6.6 生产版受控工具和外部动作

**落点：** `33A/42/44`

数字球友仍然是单 Agent。工具、事实服务、记忆服务、语音、Live2D、导演台和协议适配器不是并列 Agent。

#### 工具分类

| 工具类型 | 示例 | 默认风险 |
| --- | --- | --- |
| 事实查询 | 查询比分、阵容、事件和时间线 | 低，需资格检查 |
| 解释生成 | 生成战术解释和赛后摘要 | 中，需事实和输出检查 |
| 用户控制 | 设置安静、声音、动态和结束 | 低，用户明确触发 |
| 资料管理 | 保存、修改、暂停、删除资料 | 中，需逐项授权 |
| 提醒管理 | 创建、修改、取消订阅 | 中，需确认和可撤销 |
| 呈现控制 | 文字、语音、字幕和舞台输出 | 中，需媒介资格 |
| 支持路由 | 进入人工支持或投诉路径 | 中，需隐私最小化 |
| 外部动作 | 分享、保存到第三方或其他服务 | 高，需明确确认或人工审批 |

#### 工具合同

每个工具必须定义：

- 工具名称和用户语言；
- 触发条件；
- 输入参数和必填条件；
- 授权范围；
- 返回结构；
- 错误结构；
- 是否产生副作用；
- 风险等级；
- 是否需要确认；
- 是否支持撤销；
- 超时、重试和幂等；
- 审计字段；
- 对用户的结果说明。

#### Agent 可执行的生产版动作

- 在事实资格链通过后自动发布赛事事实；
- 根据用户订阅发送提醒；
- 根据用户明确授权保存或修改资料；
- 根据用户请求生成并保存赛后摘要；
- 根据用户明确指令调整本场控制；
- 根据用户明确授权执行分享或第三方服务动作。

#### Agent 不得绕过的边界

- 不能自行确认公共事实；
- 不能把角色意见写入公共事实；
- 不能把沉默或情绪转为提醒许可；
- 不能把一次保存许可扩展到全部对话；
- 不能在用户拒绝后继续尝试；
- 不能在审批、授权或资格不明时执行副作用动作。

### 6.7 生产版多模态主体验

**落点：** `25/26/32/33/34/42`

生产版可以让语音或 Live2D 成为主要体验出口，具体由用户偏好、设备能力、比赛节奏和产品实验决定。

#### 三种体验形态

| 形态 | 主要出口 | 必须保留 |
| --- | --- | --- |
| 文字主导 | 文字卡片和时间线 | 语音/舞台可选 |
| 语音主导 | 语音和字幕 | 停止、字幕、文字状态 |
| 舞台主导 | Live2D、语音和状态动作 | 事实卡、控制和错误说明 |

#### 生产版多模态合同

- 同一回应计划驱动文字、语音和舞台；
- 语音和动作不能携带唯一事实；
- 用户打断时取消所有相关媒介；
- 事实更正时使旧呈现失效；
- 用户关闭声音或动态后不减少核心信息；
- 弱网、低动态、读屏和共享设备下仍有完整路径；
- 自动播放、麦克风和摄像头权限不因角色需要自动开启。

### 6.8 生产版赛前—赛中—赛后服务链

**落点：** `21/22/40/43`

#### 赛前

- 选择比赛；
- 查看赛前看点和阵容状态；
- 选择观看进度保护；
- 选择解释深度和提醒；
- 预览本场陪看方式；
- 选择声音、字幕和动态；
- 明确是否沿用长期设置。

#### 赛中

- 可信事实更新；
- 关键事件解释；
- 用户订阅提醒；
- 用户主动提问；
- 个人味动态反应；
- 用户随时收缩、切换、暂停或结束。

#### 赛后

- 停止新增自动反应；
- 提供用户主动打开的比赛回顾；
- 分层展示事实、战术和角色观察；
- 允许用户保存一条笔记或共同瞬间；
- 允许用户设置下一场提醒；
- 不因用户不回顾而追问或挽留。

### 6.9 生产版运行、成本和复杂度治理

**落点：** `20A/33A/44/45/46`

#### 单 Agent run 状态

```text
接收触发
  → 建立本次运行上下文
  → 资格判断
  → 选择工具或生成回应计划
  → 工具结果校验
  → 输出与媒介再资格化
  → 呈现
  → 完成 / 取消 / 收缩 / 失败 / 等待审批
```

#### 每次 run 必须可回答

- 为什么启动；
- 当前由谁负责；
- 使用了哪些工具；
- 是否产生外部副作用；
- 运行何时结束；
- 因什么原因停止；
- 是否可以恢复；
- 恢复是否会重复副作用；
- 花费了多少时间和资源；
- 用户看到了什么结果。

#### 预算维度

- 最大模型调用次数；
- 最大工具调用次数；
- 最大循环次数；
- 最大墙钟时间；
- 最大令牌或费用；
- 最大并发任务数；
- 语音生成和播放时限；
- 提醒和主动输出频率。

预算耗尽后的默认结果是：保留已知事实、文字状态、控制和退出入口，停止非必要生成、语音、舞台和主动触达。

### 6.10 生产版安全、人工和运营治理

**落点：** `36/39/45/46`

#### 四个护栏位置

1. **输入护栏**：用户输入、外部资料、记忆和权限进入 Agent 前；
2. **工具护栏**：工具参数、调用身份、工具结果和副作用执行前；
3. **输出护栏**：文字、语音、字幕和舞台发送前；
4. **人工暂停护栏**：高风险、不可逆、投诉、危机或政策不确定时暂停并转人工。

#### 生产版人工介入

- 人工可以暂停某场自动呈现；
- 人工可以发布事实更正；
- 人工可以收缩提醒、声音或舞台能力；
- 人工可以处理用户投诉和支持请求；
- 人工不能读取无关私人内容；
- 人工不能针对脆弱用户定向提高关系压力；
- 人工不能绕过事实状态直接发布候选；
- 人工操作必须带责任、范围、理由、版本和回滚方式。

## 7. 第四层：生产版评测与治理方案

### 7.1 生产版评测分类

| 评测域 | 关键问题 | 典型指标 |
| --- | --- | --- |
| 比赛理解 | 用户是否真的理解比赛 | 事实理解率、解释完成率 |
| 事实可靠 | 自动发布是否可信 | 误发布率、更正率、撤回清理率 |
| 个人味动态 | 个人味是否有价值且不越界 | 辨识度、连续性、误认率 |
| 节奏控制 | 用户能否掌握存在感 | 控制成功率、打扰率、收敛时延 |
| 提醒 | 提醒是否相关且可控 | 相关性、误触达率、关闭生效率 |
| 连续性 | 长期设置是否有用且可撤回 | 召回可解释率、删除后不再出现率 |
| 多模态 | 主出口切换是否稳定 | 语音/文字一致率、降级完成率 |
| 工具 | Agent 是否正确使用工具 | 工具选择率、参数错误率、副作用错误率 |
| 运行 | 单次 run 是否可控 | 终止率、循环次数、延迟、费用 |
| 安全 | 高风险是否及时收缩 | 阻断率、升级率、错误恢复率 |

### 7.2 生产版场景卡模板

每个新增生产能力都要建立场景卡，至少包含：

- 场景编号和版本；
- 用户任务；
- 前置事实和会话状态；
- 用户授权状态；
- 触发事件；
- Agent 输入范围；
- 允许使用的工具；
- 预期用户可见结果；
- 禁止结果；
- 失败、取消、撤回和恢复路径；
- 观察方法；
- 规则门；
- 体验门；
- 证据等级；
- 放行、收缩、暂停或重做规则。

### 7.3 生产版硬门

以下任一失败，不能用满意度、互动量或角色自然度抵消：

- 自动发布候选事实；
- 更正后仍播放旧内容；
- 用户关闭提醒后继续触达；
- 删除后继续读取或召回；
- 用户关闭声音后关键事实消失；
- 用户结束后仍有语音、动作或主动触达；
- 工具副作用未经授权执行；
- 角色以拟人化语言施压或挽留；
- 高风险内容没有支持或退出路径；
- 运行无限循环或预算失控。

### 7.4 Trace 与审计字段

在 `45/46` 统一定义以下关联字段：

- 场景编号和版本；
- run 关联 ID；
- Agent 产品版本；
- 人格/表达规则版本；
- 工具名称和工具版本；
- 工具调用次数；
- 事实版本和状态；
- 控制版本；
- 记忆许可版本；
- 护栏结果；
- 人工审批或介入结果；
- 终止原因；
- 延迟；
- 令牌或费用；
- 回退动作；
- 用户可见结果摘要。

Trace 不保存不必要的私人原文、原始音频或完整关系推断。

## 11. 明确不做的误读

本方案不意味着：

- 把所有生产版能力都塞进 MVP；
- 用外部 Agent 平台的 API 字段替代用户语言；
- 引入多 Agent、manager 或 handoff；
- 让数字人伪装真人或现实朋友；
- 自动积累完整对话和情绪档案；
- 让自动提醒变成关系挽留；
- 让语音和动画替代事实、控制和退出；
- 用工程当前覆盖情况削弱生产版设计目标；
- 用“生产版本”标签宣称功能已经交付。

## 12. 最终交付形态

完成后，产品设计资料包应能同时回答四个问题：

1. **基础产品是什么？** 一套帮助用户理解比赛、表达感受和控制陪看的单 Agent 数字球友；
2. **它为什么有个人味？** 因为有稳定、克制、连续的比赛表达和动态进行时，而不是因为假装拥有真人生活；
3. **生产版如何扩大能力？** 通过自动事实发布、提醒、有限长期连续性、受控工具、外部动作和多模态主体验；
4. **怎样保证扩大后不失控？** 通过事实资格、用户授权、工具合同、护栏、人工介入、评测、Trace、预算和回滚。

最终结构应呈现为：

> **基础价值明确，基础体验完整，单 Agent 合同清楚，生产版拓展具体，治理与评测可执行。**
