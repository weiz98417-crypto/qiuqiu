# AI 数字人 Agent 设计对标审查

> 审查日期：2026-09-02  
> 审查对象：`docs/球球全套资料/4.产品设计` 中数字球友 Agent 相关设计  
> 外部基线：[`AI数字人Agent设计对标研究`](../research/AI数字人Agent设计对标研究.md)  
> 审查依据：[`产品设计审查标准`](./产品设计审查标准.md)  
> 本文性质：外部 Agent 设计能力与本套产品设计的差距审查；不把设计领先实现视为缺陷，不修改产品设计正文。

## 1. 结论摘要

本套设计不是“缺少 Agent 设计”，而是已经形成了一套以用户主权、事实资格和安全收缩为中心的产品级 Agent 契约。与公开的 AI Agent 设计文档相比，项目在以下方面达到或超过常见基线：

- **身份与边界**：明确是 AI 数字球友，不是真人、赛事官方、治疗者或现实关系替代；形象、声音和舞台不能抵消身份告知。主要见 `28`、`33`、`34`。
- **事实与多媒介**：事实状态先于角色表达，文字是完整基线，语音和 Live2D 只能消费同一回应计划；更正、撤回、静音、结束和断线会使旧呈现失效。主要见 `23`、`24`、`26`、`33A`、`42`、`46`。
- **用户控制与退出**：安静、仅文字、低动态、严格保护、暂停、删除和结束均被视为正常产品结果，而不是异常分支。主要见 `20`、`31`、`35`、`38`、`43`。
- **关系、记忆与人工收缩**：禁止用沉默、脆弱、消费或互动量推断关系；记忆有用户可见的保存、暂停、修改和删除路径；导演台只能发布公共事实和收缩安全上限。主要见 `28`、`30`、`36`、`39`、`33A`。
- **评测治理**：已有场景卡、规则门、体验门、阻断条件、收缩/暂停/重做决定，以及 Trace、审计和回退闭环。主要见 `45`、`46`。

这里的“记忆”特指 `30` 设计的有限、用户主动、可撤回的偏好或共同瞬间，不是无限期自动长期记忆；这里的“角色表达”特指 `32` 设计的比赛情境化、低打扰、可暂停的动态状态，不是强拟人化人格。

外部对标后留下的不是方向性缺陷，而是六个需要产品负责人确认的**结构化合同差距**，以及一项已经明确“不适用”的外部能力。前三项在 Agent 能力扩展前应优先处理；其余项可作为补强或边界记录：

1. 是否需要一张可审阅的 Agent manifest，把身份、触发、能力、输出、所有权和版本集中成唯一入口；
2. 工具是否作为一等设计对象，具备类型、返回、错误、副作用、风险等级和审批合同；
3. 是否把“单次 Agent run”从会话生命周期中独立出来，规定最大轮次、时间/费用预算、暂停恢复和终止后果；
4. 记忆是否需要补充字段级的来源可信度、读写资格、过期/租户隔离和记忆污染反例；
5. 护栏是否明确覆盖 input、tool call/result、output 三个边界，并把人工审批作为可恢复的暂停状态；
6. Trace、评测和变更治理是否补充 Agent/run/tool/guardrail 关联、令牌/费用/耗时、循环次数和配置 diff。

这些差距不意味着需要把外部平台的 API 字段、模型名称或实现状态写进产品设计正文。它们只说明产品合同是否足够集中、可评审和可验证。

## 2. 审查方法

### 2.1 外部基线

外部研究只采用官方一手资料：OpenAI Agents SDK、Agent definitions、运行时、编排与交接、Guardrails 与人工审查、评测与可观测性；Anthropic *Building Effective Agents*；Microsoft Azure Agent Orchestration Patterns；Google Agent design patterns；Google Agent Platform Memory Bank；Yellow.ai Conversational Agents；NIST AI RMF/GenAI Profile；Microsoft 合成声音与数字人透明说明。

这些资料支持“成熟 Agent 通常如何定义能力、风险和运行边界”，不能证明球球的用户偏好、留存、长期关系价值或法律合规结果。完整来源、访问日期和证据边界见研究报告。

### 2.2 本地设计核对范围

重点核对：

- `33A-数字球友Agent运行时与决策编排设计.md`：Agent 产品定义、输入合同、优先级、回合状态机、回应计划、主动性、失败收缩和工程交接；
- `42-API与实时协议设计.md`：资源动作、消息族、版本、顺序、取消、更正、实时会话和失败语义；
- `45-产品评测体系设计.md`：产品要求、场景卡、硬门、体验门、评测交接和放行决定；
- `46-系统架构图集.md`：运行时、记忆许可、删除屏障、Trace、供应商降级、版本和回滚；
- `28`、`30`、`31`、`36`、`38`、`39`：身份关系、记忆、主动性、安全、资料权利和人工运营边界。

## 4. 按审查标准 A–G 的判断

### A. 产品命题与用户价值

**判断：通过且有明显优势。** 外部 Agent 文档常从“Agent 能做什么”开始，而本项目把 Agent 约束为“用户在一场比赛中允许它做什么”，并把比赛进展、事实可信和用户自主作为价值中心。当前没有因外部对标而需要重写产品命题的问题。

需要保持的边界：不能因为外部平台拥有更多工具、更多 Agent 或更大的记忆范围，就把它们转化为球球的产品价值承诺。

### B. 术语、模式与跨文档一致性

**判断：已有原有 P1，Agent 对标新增的是 manifest 入口问题。** 外部文档通常把 Agent 名称、触发描述、工具、输出和版本集中在一个定义对象中；本项目相关内容分布在 `20`、`28`、`33A`、`42`、`46`。这提高了专题自治，但增加了跨篇维护成本。多 Agent handoff 不属于本项目的补充方向。

建议将 AG-01 作为“唯一 Agent 合同入口”讨论，不要直接照搬 `name`、`handoffDescription` 等平台字段。正式枚举、模式和默认值仍以原有问题清单 PD-001～PD-003 为准。

### C. 旅程、交互与状态完整性

**判断：用户可见状态和媒介降级已达到高水平；run/工具失败合同仍可补强。** `33A` 的回合状态机和 `42` 的实时生命周期能覆盖控制、事实、语音、重连和结束，但外部 Agent 基线还要求把“工具循环、审批暂停、最大轮次、预算耗尽、恢复同一 run”作为单独的可观察状态。

这不是要求用户看见内部技术名词，而是要求设计能回答：运行何时算结束、为何停止、是否还能继续、继续是否会产生重复副作用。

### D. AI 身份、关系边界与内容安全

**判断：通过，且不应因对标而增强拟人程度。** `28`、`33`、`34` 已覆盖 Microsoft 数字人透明基线所关心的合成身份、能力限制和真人误认风险；`33A` 进一步规定角色表达不能替代事实、控制和错误说明。

需要补的不是更多身份文案，而是 AG-06 的工具调用/结果护栏，以及 AG-05 的记忆污染反例，使内容安全从“禁止表达”延伸到“输入如何进入 Agent”。

### E. 数据、隐私与用户权利

**判断：用户权利设计强；有限资料的 Agent 读写资格还需统一。** `30` 和 `38` 已经把“用户主动保留一小段资料”拆成内容、来源、范围、状态、控制、删除和防回写，优于许多只写泛化记忆价值的 Agent 文档。

外部 Memory 文档提供的补充审查点是：每个 Agent/工具能否读写某类记忆、不同身份是否隔离、过期后是否自动失效、恶意或错误记忆是否会污染未来上下文。建议把这些作为字段和反例补充，而不是增加收集范围。

### F. 技术约束、媒介等价与降级

**判断：媒介等价和供应商降级已覆盖；成本、延迟和循环预算需要与 Agent 运行合同关联。** `42`、`46` 已定义版本、取消、超时、供应商替换、文字回退和不扩大权限的失败路径。外部基线新增的重点是：多 Agent/工具链的每一步都应有最大时间、费用和复杂度预算，预算触发后要进入确定的降级或终止状态。

这类内容可以放在 Agent run 合同和技术约束交接中，不应把供应商 API 或实现状态写回产品设计正文。

### G. 评测、指标与决策治理

**判断：治理框架完整，但 Agent 粒度的运行指标还不够集中。** `45` 已将产品要求转为场景、观察方式、阻断条件和放行决定；`46` 已建立 Trace 与审计关联。与外部 Agent 评测基线相比，仍可明确：一次 run 的工具调用数、handoff 次数、循环终止原因、审批等待时间、令牌/费用、端到端延迟，以及这些字段如何关联到具体场景和配置版本。

互动量、停留时长、好感和角色发言次数仍不能替代上述风险和控制指标。

## 6. 不应因为对标而修改的内容

- 不把 OpenAI、Anthropic、Microsoft、Google 的字段名或 SDK 结构直接写成用户界面或产品承诺。
- 不为了“像成熟 Agent”而增加多 Agent、无限期/自动记忆、自动触达、工具数量或更强拟人表演。
- 不把模型、TTS、向量库、框架、供应商和当前接口覆盖写进产品设计正文，除非它们改变用户任务、控制或风险边界；技术实现盘点继续放在独立工程/对齐材料。
- 不把设计领先实现改写成“未实现”、交付状态或限制清单；领先项仍按目标态审查。
- 不用外部官方文档证明用户喜欢某种陪伴、愿意保存记忆或会长期使用；这些只能由本项目的受控研究与评测回答。
