# 唤醒词评估迭代记录（wake-word-kws 10.1 评估门）

评估集：`dataset/manifest.json`（正样本 30 = 候选短语 {嘿球球/嗨球球/你好球球} ×
双音色{冰糖,Chloe} × 5 语气；负样本 26 条足球语境「球球」句 + 近失混淆，总时长
53.1s → 1 次误触 ≈ 67.8 次/小时折算基数）。合成源 MiMo TTS（mimo-v2.5-tts），
生成脚本 `generate-dataset.mjs`。判据：安静唤醒率 >95% / 足球语境误触 <1 次/小时
折算 / cooldown 后二次唤醒 ≥2。runner：`run-eval.mjs`（sherpa-onnx node 绑定，
与 python 包同 C++ 核心/同模型/同 KWS 解码语义）。

**定稿词表 = 「你好球球」**（`n ǐ h ǎo q iú q iú @你好球球`），keywords_score=1.8，
keywords_threshold=0.3（通过带 0.25–0.35 的中点，两侧留量），cooldown=1.5s。
最终记录：`results/FINAL-nihao-s1.8-t0.3.json`。

「嘿球球」失败根因（转写探针）：模型常听不见「嘿」——一条正样本被同模型转写为
"bēi jiù qiú qiú"，TTS 对语气词「嘿」的渲染不稳定；「你好」是该 KWS 模型关键词
训练分布内的强引导（上游示例词表 全部「你好×」式），声学证据稳定。

## 代理评估边界（如实记）

- TTS 合成集是代理：真实用户音色/语速/麦克风信道未覆盖；人群真实唤醒率留真机
  人耳确认尾项（与 turn-detection 15 用例同纪律）。
- 负样本只含 TTS 语音：球场噪声/电视解说混响未覆盖——误触折算按语音负样本口径，
  环境音频的真机验证留尾。
- 评估引擎走 node 绑定（本机无可用 python），与端上 flutter 插件同 C++ 核心；
  端上 int8 量化路径与本评估一致，但 Android 端整链（录音→KWS→唤醒）留真机尾。

## 已知评估事故（如实记）

中途一版 runner 重构使负样本被跳过解码，产生过一批假的「0 误触」结果
（iter2/iter3/probe 系列）；用独立最小复现（standalone decode neg_07 命中）抓到，
修复后所有入库结果全部重跑。当前 `results/` 只保留有效运行。
